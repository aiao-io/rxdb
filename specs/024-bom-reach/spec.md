# Feature Specification: BOM 物料级可达性

**Created**: 2026-10-18  
**Status**: Done；功能/性能、Reach52、真实PG12、共享51/demo24、最终351任务与8包严格覆盖率全部通过，见[quickstart](quickstart.md)。
**Input**: 用户本轮要求完成 BOM 全部待办，继续处理 US-510 阶段 B，以及 US-507 AC#13、US-509 AC#8/#14～#16 的可达性追加验收。沿当前分支实施，不因补规格创建分支或提交。

## 决策与证据边界

✅ 值得推进测量和实现设计。用户的全量完成要求是本轮新增驱动；历史规格中的“where-used 成为实测热路径”仍须用真实数据证明。主数据真实基线与隔离原型已完成，索引收益与闭包收益分别归因，默认不启用读取剪枝；实例反查不混入主数据测量。

基线已证明：1万物料的主数据反查 p95 为236.24ms，最小子件索引降到7.60ms；20菱形的10000路径返回反而出现索引后回退。默认读取采用最小子件索引，完整候选裁决与路径预算仍由现有内核负责；可达性用于存储维护与判环。读取剪枝只作独立原型对照，未经额外收益证明不启用。物化表、写入维护或查询加速没有执行、没有通过，均不得提前记为 Done。

## User Scenarios & Testing

### US0 用真实反查工作负载证明收益（Priority: P0）

计划员反查一个停产零件影响的整机，希望得到与现有结果相同的发生项路径，并知道加速是否值得增加写入维护。

**Independent Test**: 同一数据、同一上下文与预算，分别记录现有主数据反查、仅补必要索引、物化候选剪枝三种方案；预热后留原始时延、返回路径数、截断原因和查询计划，不用安装事实或单次演示耗时替代。

1. 对树、共享装配、多重边、串联菱形和大量无关物料，结果逐路径相同。
2. 优化前后都记录实际收益、写放大和存储量。没有改善的场景照实记录，未通过门槛时不切换默认读取路径。

### US1 结构变化原子维护可达性（Priority: P1）

工程师新增、删除或替换一个 consume 发生项，可达对必须与提交后的真实并集图一致。

**Independent Test**: 在两种本地后端通过仓储及直连 SQL 做同一批增删改；每次提交后将可达对与独立递归结果逐对比较，失败事务前后整表内容相同。

1. 组织和 BOM 类型构成独立作用域；相同物料对在不同作用域可以有不同结果。
2. 插入只补受影响祖先与后代的组合；不清空或重算无关范围。
3. 删除一条重边或菱形支路时，仍有其他发生项连通的物料对保留；最后一条连通路径消失时才移除。
4. 修改子件端点或在 consume 与非 consume 之间切换，与删除旧边、加入新边同一结果；两个步骤同事务提交。
5. draft 头和 draft ECN 中已接受的发生项立即进入并集；ECN 取消或撤回实际删除发生项时，相应可达对同步退出。

### US2 上界剪枝保持上下文和路径结果（Priority: P1）

计划员按历史日期、修订、备选、配置、序列及批次解析和消费BOM。各入口保持既有合同：`resolveBom`与完整消费入口裁决备选并保留未裁决候选；`expandBom/whereUsed`保留首轮多头路径，继续按原有日期、ECN、配置、序列和批次规则过滤。Reach不能将并集命中冒充上下文已裁决。

**Independent Test**: 让并集可达、具体上下文不可达的行分别来自草稿、过期、未来、未发布ECN、配置和序列/批次分段；另由`resolveBom`核对未选/已选备选与完整消费守卫，逐路径保留`expandBom/whereUsed`的多头基线。加速前后完整结果、候选、顺序与截断标记一致。

1. 可达性不带日期、修订或候选裁决；它只能排除不可能到达的物料，不能证明某条上下文路径有效。
2. 同一物料的三条发生项和共享子装配的两条路径继续独立返回，不按物料对合并。
3. 改用量、损耗、生效期、ECN 日期或状态、修订发布及 phantom 默认值，均不重写可达性；已有解析与数量仍正确更新。
4. 浏览仍保留未解析候选；数量、成本与导出遇未解析或截断继续拒绝。

### US3 存储层判环和有界工作量（Priority: P1）

绕过仓储直接插入成环边仍被拒绝；复杂 DAG 不因路径数指数增长而物化百万条路径。

**Independent Test**: 已有 A→B→C 时直连插 C→A，以及草稿自环、ECN 反向边、非 consume 反向行；比较错误合同和事务回滚。20 个串联菱形同时验证物化规模和原有路径预算。

1. 索引命中负责确定是否成环；需要报告错误路径时只求一个有界见证，保留 `BomCycleError` 的 message/code/payload 与 `unionOnly` 语义。
2. 归属列不可改的拒绝结果不变，被拒写入后可达表零变化。
3. 20 串联菱形只有 61 个物料、80 条边、1810 个正长度可达对；不为 1,048,576 条根至末端路径各存记录。
4. 深度、展开数、返回路径数与取消预算继续硬停；维护或判定无法在硬限制内完成时拒绝整次写入，不提交不完整派生数据。

## Requirements

- **FR-001**: 实现前先建立主数据 where-used 基线和收益比较，记录环境、预热、原始样本、查询计划与结果正确性。
- **FR-002**: 可达性只表示同一 `(bomType, orgId)` 内当前仍存储的 consume 发生项组成的物料级并集图；删除最后支持边后不再保留历史可达事实。
- **FR-003**: 每个作用域/祖先物料/后代物料仅一条正长度可达记录；不存路径、路径数、用量、损耗、日期、修订、备选或最短/最长深度，不持久化自反对。
- **FR-004**: 发生项插入、删除、子件变更和方向变更在存储层增量维护；仓储、历史装载、导入及 ECN 级联遵守同一不变量。
- **FR-005**: 用量等非拓扑更新对可达表 INSERT/UPDATE/DELETE 次数均为零；只比较最终行数不足以验收。
- **FR-006**: 查询仍经过现有上下文裁决和完整性守卫，不把可达记录当成有效发生项或完整数量结果。
- **FR-007**: 已有库通过显式、原子的数据迁移建立完整初值，再启用索引判环；不得把空表、缺表或半回填当成“不可达”。
- **FR-008**: 保留 SQLite/PGlite 一致性、128 层判环硬限制，以及远端 PostgreSQL 的作用域锁与 Read Committed 隔离级别合同。
- **FR-009**: 保持现有公开查询签名与三端消费行为；派生数据不成为用户可编辑、同步、ERP 导入或导出的主数据。

## Success Criteria

- **SC-001**: US-510 阶段 B、US-507 AC#13 与 US-509 AC#8/#14～#16 追加段全部有双后端真实断言，不用生成 SQL 字符串检查代替业务证明。
- **SC-002**: 四种图形的确定性随机增删改后，可达对与独立递归 oracle 100% 一致；无关范围零写入，非拓扑更新整表零写入。
- **SC-003**: 20 串联菱形物化恰好 1810 对；既有深度 50、展开数 100000、路径数 10000 的查询仍恰好返回 10000 个节点并标 `paths` 截断。
- **SC-004**: 宣称改善的普通主数据热场景 p95 相对基线至少改善20%，并满足预热查询<16ms、常用写操作<100ms。输出10000路径的预算场景记录完整耗时和截断证据，不将其当成16ms的普通查询，也不把路径枚举成本宣称为物化必然可优化。读取原型无额外收益时记录结论并保持默认读取，不为关闭任务强行启用。
- **SC-005**: 非核心包四项覆盖率 ≥80%，如实际修改核心则对应 ≥90%；strict、零警告 lint、构建、既有领域/三端/远端并发回归及受影响门禁通过。

## Edge Cases 与边界

- 同一作用域多修订、备选和 ECN 产生相同物料边；删一条不能删掉其余支持路径。
- `consume → produce/by_product/scrap_out` 退出并集，反向切回 consume 必须先判环；方向枚举以当前主线实际交付为准。
- 子件更新后的判定必须在排除旧发生项后的图上执行，不能让旧边造成误拒，也不能在失败后留下删了一半的可达对。
- ECN 撤回/取消、导入事务失败和显式 rollback 都包含在原子性验收中。
- 实例安装记录独立；只改实例不写主数据可达性。
- 本阶段不引入路径物化、按日刷新、累计数量、后台轮询或新的三端 UI。
