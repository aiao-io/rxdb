# Feature Specification: BOM 热字段透明索引

**日期**：2026-10-18。**状态**：Done。功能、性能、最终完整351任务及8包严格覆盖率全部验收通过，见validation.md。

**驱动**：用户要求处理本轮 BOM 全部剩余待办，包含此前价值待证的 [US-519 AC#3/#7](../../requirements/stories/domain/US-519-bom-extension-attributes.md) 与其前置 [US-030 阶段 D / AC#5](../../requirements/stories/core/US-030-declarative-storage-constraints.md)。本切片沿当前分支，不创建分支或提交；实现和验收均沿本分支完成，不创建分支或提交。

## 用户场景与验收

### US1：热字段提升，调用方继续读写 ext

物料、BOM 头和发生项上的已声明扩展属性变热后，应用显式声明只读 JSON 标量生成列与 B-tree 索引。调用方仍写原来的 `ext`，仍调用 `db.bom.filterByAttr(scope, filters)`，不写派生列、不改过滤参数、不手工回填历史值。

1. 同一批持久化数据，在未启用与启用提升时执行相同过滤，结果 ID、排序、公开字段和值逐项相同；三层作用域独立。
2. 热字段 `eq` 由查询编译器透明改写为已声明生成列比较，两端实际查询计划均命中该新索引；仅创建生成列、仍查询旧 JSON 表达式不算通过。
3. 写入、更新、清空和删除 `ext` 中的键后，生成值与索引自动同步；缺键、JSON null 与 SQL NULL 继续等价，`exists` 均不匹配，`ne` 也不匹配缺值。

### US2：PGlite JSON 包含查询命中 GIN

应用对 PGlite 显式启用 `ext` 文档表达式上的 GIN。非热字段的合法 `eq` 查询使用同形 JSONB 包含谓词；SQLite 继续提供相同查询结果。

1. 当前 `ext` 的物理类型保持字符串：PGlite 对 `(("ext")::jsonb)` 建 GIN，查询使用 `(("ext")::jsonb) @> <有类型的单键 JSON 对象>`，不能把 `->>` 等值比较当作 GIN 命中证据。
2. GIN 开启和关闭时结果相同；字符串、有限 number、boolean 不互相转换，包含引号、点、反斜线的属性 code 按字面键处理。
3. `date eq` 按既有时间语义比较，不改成按日期字符串字节包含；`ne`、范围、`exists` 不虚称命中 GIN。

### US3：显式升级持久库，漂移和重放可审计

旧库不因启动而执行表重建或全表索引创建。应用通过既有用户迁移显式增加生成列与索引，失败整批回滚；迁移后再进入只读漂移检查。

1. 缺失、残留、同名换表达式、列类型、索引方法、运算符类或生成模式不符均拒绝连接并准确点名；旧 `idx_`、外键、系统和 FTS 对象不进入新管理范围。
2. `saveMany`、直接仓储保存、undo/redo、切分支和已有备份恢复流程只重放原字段；派生值由数据库重算，变更日志与导出格式不增加热字段。
3. 同一实体类在两个数据库中使用不同索引配置时互不污染；索引能力未启用的既有应用保持原行为。

## 功能要求

- **FR-001**：核心新增声明式 JSON 标量生成列、表达式索引与索引方法；普通 `properties` / `normalized` / 条件唯一 `where` 声明保持兼容。
- **FR-002**：生成列独立于可写 `propertyMap` 和 `computedProperties`，不成为实体输入、补丁、导入、日志或重放字段。公开查询不得因 `SELECT *` 多出内部派生列。
- **FR-003**：最小生成表达式只支持同一行 JSON 对象的单个字面键及 `string` / `number` / `boolean` 标量。缺值生成 SQL NULL，值类型不得隐式转换。数组、对象、跨表、任意 SQL、生成列链式依赖、加密源、默认值/可写声明冲突在元数据期拒绝。
- **FR-004**：`date` 的既有过滤行为保留；本最小生成列 DSL 对 `date` 提升在两端明确拒绝。PG 的 `text::timestamptz` 不是可直接承诺的 immutable 生成表达式，不以虚假 IMMUTABLE 标注绕过限制。该限制不阻止以字符串热字段关闭 US-519 AC#3。
- **FR-005**：方法支持既有默认 B-tree、PG GIN，以及 PG 标量 GiST 的明确能力声明。GIN 仅接受 JSON 文档表达式；标量 GiST 仅接受已验证的 `btree_gist` 类型，复用扩展装载机制。SQLite 上实际生效的 GIN/GiST 声明必须在 DDL 前失败。
- **FR-006**：PG 专属优化必须显式限定方言；限定范围之外不构成该后端的能力声明。BOM 不默认安装 GIN，不因 SQLite 没有 GIN 拒绝整个扩展属性功能。
- **FR-007**：索引配置按数据库冻结，不能改写类共享元数据。BOM 热字段定义包含 `scope/code/dataType`，查询时与真实 `attr_def` 对照；字典改成不兼容类型时拒绝，不继续使用失配生成列。
- **FR-008**：重写优先级固定：匹配的标量生成列 → 已启用 GIN 的合法非日期 `eq` → 既有类型化 JSON 提取。先执行原有作用域、类型、操作符校验，再选 SQL；没有索引声明不是错误。
- **FR-009**：所有原有操作符两端逐行等价；过滤 `"3"` 对 number、`1` 对 boolean、非法日期、null 比较值、未知 code 与跨作用域条件继续抛 `BomExtAttrError`。`in: []` 继续为空结果。
- **FR-010**：持久升级前审计被提升键的存量 JSON 及类型；坏值拒绝迁移、点名表/行/键，不把坏数据转换为 NULL 后宣布成功。无需手工回填不等于没有 DDL 扫描与索引构建成本。
- **FR-011**：新托管列/索引具备确定性定义哈希与目录验真。连接阶段只读检查；PG `reconcileEntityIndexes` 不得自动创建、替换或修复这些对象。旧普通索引的处理方式不变。
- **FR-012**：SQLite 用可索引的 VIRTUAL 生成列，PG 用 STORED 生成列；用户迁移负责安装。SQLite 宿主共用既有 ≥3.47 门槛，不要求只有更高版本才支持的表变更语法。

## 测量与关闭条件

- 计划命中 fixture 至少 10,000 行、选择率不高于 1%，先采集统计信息。SQLite 保存 `EXPLAIN QUERY PLAN` 的 SEARCH/索引名；PG 保存 `EXPLAIN (FORMAT JSON)` 的 Index Scan 或 Bitmap Index Scan 及索引名。正常规划器设置下通过；强制关闭顺序扫描只能作诊断。
- 原调用、生成列和 GIN 三种路径保存同一过滤输入与逐行结果；GIN 测试使用未提升的键，避免被生成列优先级抢走。
- 已连接预热后热等值查询 p95 ≤16ms、单条 `ext` 保存 p95 ≤100ms；记录原始样本、p50/p95/max、数据量、后端/宿主与索引配置。迁移扫描和索引构建单独记录耗时，不混入查询样本。
- 先证明功能红，再实施；核心四项覆盖率 ≥90%，适配器/BOM 四项 ≥80%；strict、零警告 lint、相关持久化/重放/约束回归与受影响 Nx 门禁通过后，才能回写 US-030 D 和 US-519 #3/#7。

本轮不修改整个引擎的 JSON 物理映射，不开放通用任意 SQL 表达式，不制作属性字典 UI；也不把未运行的计划断言或持久升级记为验收完成。
