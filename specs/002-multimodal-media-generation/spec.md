# Feature Specification: Aiao Media 多模态媒体生成

**Feature Branch**: `002-multimodal-media-generation`

**Created**: 2026-11-20

**Status**: Draft

**Input**: User description: "aiao-media 需要 TTS、ASR、生成音乐、生成视频的功能"

**Product Story**: [MEDIA-US-111 TTS、ASR 与音乐/视频生成](../../aiao-media/requirements/stories/generation/MEDIA-US-111-multimodal-generation.md)

## User Scenarios & Testing

### User Story 1 - 文本转语音 (Priority: P1)

登录且拥有可用积分的媒体创作者选择 TTS 能力、模型、语言、声音和语速，输入文本并提交生成任务。任务完成后，创作者可以试听、下载并保存音频到当前设备。

**Why this priority**: TTS 是最小可交付的音频创作入口，也能验证媒体目录、积分、异步任务和本机交付的共同链路。

**Independent Test**: 使用一个受支持的文本、语言和声音完成一次 fixture 任务，验证任务状态、音频播放、真实 MIME/时长、积分流水和 RxDB/OPFS 保存。

**Acceptance Scenarios**:

1. **Given** 用户已登录、余额足够且 TTS 模型目录可用，**When** 用户提交合法文本和允许的语言、声音、语速，**Then** 服务端创建一个媒体任务并按目录参数生成可播放音频。
2. **Given** TTS 任务返回可交付音频，**When** 用户预览、下载并保存，**Then** 结果包含真实 MIME、字节大小和时长，刷新后仍可从本机历史找回。
3. **Given** 用户提交的文本或参数超过目录限制，**When** 用户提交任务，**Then** 客户端给出可操作的校验提示，服务端拒绝非法请求，不调用上游且不扣积分。

### User Story 2 - 语音转文本 (Priority: P1)

登录的媒体创作者上传平台目录允许的音频，选择识别语言或使用服务端语言识别，提交 ASR 任务并查看、复制和下载识别文本。

**Why this priority**: ASR 直接关闭音频内容无法检索和复用的用户问题，输入校验和文本结果的本机持久化可以独立验收。

**Independent Test**: 使用一段受支持音频完成一次 fixture 识别，验证输入限制、文本结果、任务状态、语言信息、本机保存和错误处理。

**Acceptance Scenarios**:

1. **Given** 用户已登录且音频格式、大小和时长符合目录限制，**When** 用户提交 ASR 任务，**Then** 系统返回可复制、可下载的识别文本和任务语言信息。
2. **Given** 用户上传不受支持或超限的音频，**When** 用户提交识别，**Then** 系统在调用上游前拒绝请求，保留明确的限制提示且不扣积分。
3. **Given** ASR 返回明确失败，**When** 用户查看任务，**Then** 任务显示失败原因，不伪造空文本，不自动重发。

### User Story 3 - 音乐生成 (Priority: P2)

登录且拥有可用积分的媒体创作者输入音乐提示词并选择目录允许的音乐参数，提交生成任务，预览、下载并保存生成的音乐。

**Why this priority**: 音乐生成扩展音频创作场景，复用 TTS 的媒体任务、积分和本机交付契约即可独立交付。

**Independent Test**: 使用一个受支持的音乐提示词和参数完成一次 fixture 任务，验证音频结果、状态恢复、积分结算和本机保存。

**Acceptance Scenarios**:

1. **Given** 音乐模型和参数在平台目录中可用，**When** 用户提交合法提示词，**Then** 系统创建任务并返回可播放、可下载的音频结果。
2. **Given** 音乐任务返回结果，**When** 用户保存并刷新页面，**Then** 本机历史保留真实 MIME、字节大小和时长，重新下载不重新生成。
3. **Given** 音乐任务被上游拒绝或超时，**When** 用户查看余额和任务，**Then** 任务进入明确失败或待核查状态，结算遵守预占、释放或未决规则。

### User Story 4 - 视频生成 (Priority: P2)

登录且拥有可用积分的媒体创作者输入视频提示词，选择目录允许的画幅和时长，提交视频生成任务，预览、下载并保存视频。

**Why this priority**: 视频生成是独立的高成本媒体交付类型，需要验证大结果、真实时长与画幅记录以及任务续接。

**Independent Test**: 使用一个受支持的视频提示词和参数完成一次 fixture 任务，验证视频播放、结果元数据、刷新续接、积分结算和本机写入恢复。

**Acceptance Scenarios**:

1. **Given** 视频模型和画幅、时长参数在平台目录中可用，**When** 用户提交合法提示词，**Then** 系统创建异步任务并返回可播放的视频结果。
2. **Given** 视频任务在生成中，**When** 用户刷新、关闭页面或经历短暂断网后重新进入，**Then** 系统使用原任务 ID恢复状态，不重复调用上游或重复扣费。
3. **Given** 视频结果已返回，**When** 用户查看详情并下载，**Then** 系统显示实际 MIME、字节大小、时长和画幅，数据不使用请求参数冒充实际结果。

### User Story 5 - 统一媒体任务与本机交付 (Priority: P1)

创作者使用四类能力时，都能看到输入、任务、结果和本机保存的独立状态。用户可以在结果待核查、保存失败和删除中断时恢复到一致状态。

**Why this priority**: 四类能力共享任务、积分和本机存储边界。统一状态是避免重复生成、重复扣费和虚报保存成功的基础。

**Independent Test**: 通过双击、刷新、短暂断网、上游失败、保存失败和删除中断场景验证同一任务身份、积分幂等、本机恢复和凭据隔离。

**Acceptance Scenarios**:

1. **Given** 任一媒体任务已提交，**When** 用户双击提交、在两个标签页操作或刷新页面，**Then** 服务端只接受一个有效任务身份，积分最多产生一次有效结算。
2. **Given** 上游返回成功结果，**When** 本机保存失败，**Then** 结果保持可见并提供只重试本机写入的入口，重试不重新调用上游。
3. **Given** 任务结果待核查，**When** 用户查看任务、余额和流水，**Then** 系统保持未决状态，不把结果标记为成功，不静默重发或重复扣费。
4. **Given** 已保存的音频、视频或 ASR 文本，**When** 用户删除并在删除过程中刷新或重开，**Then** 关联文件、任务记录和本机索引最终一致，删除失败可见且不影响其他作品。

## Edge Cases

- 用户未登录或积分不足时，入口显示登录/余额要求，服务端不调用上游、不创建可扣费任务。
- 模型目录在页面打开后发生变化时，服务端按最新能力和参数重新校验，客户端不能绕过限制。
- 输入格式、大小、时长或文本长度超限时，在上游调用前拒绝并保留用户输入。
- 上游返回 4xx、5xx、超时、空结果、无法解码的媒体或与声明 MIME 不一致的结果时，任务进入明确失败或待核查状态。
- 页面关闭、刷新、短暂断网、重复点击或双标签页同时提交时，任务 ID、上游调用和积分账本保持幂等。
- 结果可见但 RxDB/OPFS 写入失败、磁盘空间不足或删除 journal 中断时，用户仍能区分“已生成”和“已保存”。
- ASR 识别失败时不能以空字符串替代失败结果，音频输入不能写入任务日志或备份作为隐式长期留存。
- 平台凭据、会话和服务端密钥不能出现在客户端构建物、任务快照、队列消息、日志、备份或同步数据中。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 为 TTS、ASR、音乐生成和视频生成提供统一的媒体能力目录，声明模型、输入输出限制、参数和单次积分消耗。
- **FR-002**: 系统 MUST 要求用户登录并拥有可用积分后才能提交需要平台调用的媒体任务。
- **FR-003**: 系统 MUST 在服务端重新校验能力、模型、参数、输入格式、输入大小、文本长度和时长限制。
- **FR-004**: 系统 MUST 支持 TTS 文本、语言、声音和语速输入，并返回可播放、可下载的音频结果。
- **FR-005**: 系统 MUST 支持 ASR 音频输入和语言设置或识别，并返回可复制、可下载的文本结果及任务语言信息。
- **FR-006**: 系统 MUST 支持基于文本提示词和目录参数的音乐生成，并返回可播放、可下载的音频结果。
- **FR-007**: 系统 MUST 支持基于文本提示词和目录参数的视频生成，并返回可播放、可下载的视频结果。
- **FR-008**: 系统 MUST 为每个媒体请求创建稳定任务 ID，并支持刷新、关闭页面和短暂断网后的同任务状态恢复。
- **FR-009**: 系统 MUST 使用幂等身份防止双击、双标签页和重试造成重复上游调用或重复扣费。
- **FR-010**: 系统 MUST 在任务提交前原子预占积分，只有校验通过的可交付结果才结算，明确失败或拒绝释放预占，结果待核查时保持未决。
- **FR-011**: 系统 MUST 区分输入已接收、任务执行、结果待核查、结果已生成、本机保存、保存失败和删除状态。
- **FR-012**: 系统 MUST 将已确认的媒体结果和 ASR 文本保存到当前设备的 RxDB/OPFS 或等价本机存储，并记录真实 MIME、字节大小、时长和视频画幅等适用元数据。
- **FR-013**: 系统 MUST 在本机保存失败时保留可用结果和只重试本机写入的入口，不能通过保存重试重新生成或再次扣费。
- **FR-014**: 系统 MUST 支持删除已保存的音频、视频和 ASR 文本，并在删除中断或重启后恢复一致的文件、记录和索引状态。
- **FR-015**: 系统 MUST 确保平台凭据、会话和服务端密钥不进入客户端产物、任务快照、队列、日志、备份或同步数据。
- **FR-016**: 系统 MUST 对上游拒绝、超时、5xx、空结果、无法解码和未知回执提供明确状态与原因，且不能自动重发可能产生费用的任务。
- **FR-017**: 系统 MUST 在用户下载结果时使用实际媒体格式和实际结果元数据，不以请求参数替代服务端返回的 MIME、字节大小、时长或画幅。

### Key Entities

- **Media Capability Catalog**: 平台可用的 TTS、ASR、音乐和视频能力，包含模型、参数约束、输入输出限制和积分消耗。
- **Media Task**: 一次媒体提交的稳定身份、能力类型、参数快照、输入引用、任务状态、幂等键、结果引用和错误信息。
- **Credit Reservation and Ledger Entry**: 任务的积分预占、结算或释放记录，以及用户可见的余额变化和任务关联。
- **Media Asset**: 已确认并保存到本机的音频或视频文件，包含 MIME、字节大小、时长、画幅、摘要和来源任务。
- **Transcript**: ASR 任务产生的文本、语言信息、来源任务和本机保存状态。
- **Local Delivery Journal**: 本机文件写入、回读、删除和恢复操作的状态记录。

## Success Criteria

### Measurable Outcomes

- **SC-001**: TTS、ASR、音乐生成和视频生成各有至少一条可重复的真实服务验收路径，能够从提交走到结果查看、下载和本机保存。
- **SC-002**: 在双击、双标签页、刷新、短暂断网和任务重试测试中，每个请求最多产生一个有效上游调用和一笔有效积分结算。
- **SC-003**: 在结果返回但本机写入失败的测试中，100% 的重试只执行本机写入，不产生新的上游调用或积分流水。
- **SC-004**: 在预定的输入超限、供应商拒绝、超时、5xx、空结果、无法解码和未知回执场景中，100% 保留可观察的任务状态与错误原因。
- **SC-005**: 通过客户端构建物、任务快照、队列消息、日志、备份和同步数据扫描，平台凭据与服务端密钥出现次数为 0。
- **SC-006**: 生成结果和 ASR 文本在本机保存、刷新、重开、下载和删除恢复测试中保持文件、元数据、任务记录和索引一致。

## Assumptions

- 复用现有平台账号、积分账本、服务端任务续接和本机 RxDB/OPFS 交付边界。
- 平台目录由服务端配置维护，客户端不能提交上游地址、供应商凭据或未声明参数。
- 首阶段使用异步任务，TTS、ASR、音乐和视频均需要联网调用平台服务。
- 首阶段交付当前设备本机保存，音视频原文件跨设备同步由后续故事单独评审。
- 首阶段不包含声音克隆、实时语音、说话人分离、逐字时间轴、图生视频和视频编辑。
- 具体供应商、模型名称、积分单价、输入上限、输出格式和保留期限需要在实现前由平台能力目录确定。
