# Feature Specification: 移植 rxdb-model 实体模型库与三框架 UI 组件集

**Feature Branch**: `002-rxdb-model-port`

**Created**: 2026-09-18

**Status**: Draft

**Input**: User description: "将企业版 @aiao/rxdb-model（框架无关实体模型核心：entity-field/value 工具、structural-equal、entity-form、entity-detail、entity-table VTable 基础设施与编辑器、query-builder 引擎）与 @aiao/rxdb-model-angular（Angular 组件层：EntityDetail/EntityDialog/EntityForm/EntityList/EntityTable/QueryTable + query-builder 组件树）移植到开源 monorepo 的 packages/rxdb-model 与 packages/rxdb-model-angular。框架策略：Angular 先行，React/Vue 绑定（rxdb-model-react/rxdb-model-vue）为同一 epic 后续阶段，三端 API 对称。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 实体元数据驱动的核心能力库 (Priority: P1)

应用开发者定义一次实体模型（属性类型、校验规则、关系），即可从元数据派生出表单字段配置、详情页 Tab 结构、可编辑表格列配置与查询条件树，并得到字段值的解析、格式化与校验能力。这是纯逻辑层，不依赖任何 UI 框架，可被任何前端技术栈消费。

**Why this priority**: 它是所有 UI 组件与查询构建器的引擎。没有它，表单/表格/查询能力无从谈起；单独交付它即可让框架无关工具链（校验、转换、查询条件构建）先落地并被测试锁定。

**Independent Test**: 仅凭单元测试即可完整验证——给定实体元数据与输入值，断言产出的表单字段、详情 Tab、表格列、查询树与校验结果。不依赖任何 UI 渲染。

**Acceptance Scenarios**:

1. **Given** 一份包含类型化属性、计算属性与关系定义的实体元数据，**When** 以 create / edit / view 三种模式请求表单字段配置，**Then** 返回对应模式的字段列表，且系统字段（id、创建/更新时间等）被过滤。
2. **Given** 原始输入值（日期字符串、逗号分隔数组、JSON 文本、UUID 等），**When** 解析、格式化或校验，**Then** 产出正确类型值、展示字符串或结构化错误（含字段路径与原因），绝不抛出未捕获异常。
3. **Given** 一个实体实例与其表单数据，**When** 双向转换，**Then** 只产出实际变化的字段，未变化的字段不产生写入。
4. **Given** 两个键顺序不同但内容相同的对象，**When** 做结构相等比较，**Then** 判定相等；含循环引用的对象比较不进入死循环。
5. **Given** 实体元数据，**When** 构建详情页结构，**Then** 生成一个基础表单区块，并为每个一对多/多对多关系生成一个表格区块。
6. **Given** 实体元数据，**When** 构建可编辑表格列，**Then** 每种属性类型对应合适的单元格编辑器；只读记录降级为无编辑能力；含操作列与时间列。
7. **Given** 一组查询条件（规则、AND/OR 分组、嵌套），**When** 增删规则、改分组组合、移动条目、与仓库查询格式双向转换、逐规则校验，**Then** 状态变更正确、非法值立即给出可读错误、超过最大嵌套深度被阻止。
8. **Given** 表格运行时的单元格数据、剪贴板内容与键盘操作，**When** 编辑、复制/粘贴、删除行、拖拽重排，**Then** 单元格值、剪贴板内容与行顺序按预期变化，且批量编辑合并为一次写入。

### User Story 2 - 实体管理 UI 组件集（Angular 先行） (Priority: P2)

Angular 开发者通过声明式组件即可搭建实体管理界面：无限滚动的可编辑实体列表（行内编辑、撤销/重做、筛选弹层、级联新增、多对多选择模式）、Tab 式实体详情（基础表单 + 关系表格，草稿实体保存编排）、元数据驱动的表单（按模式渲染约 12 类字段输入）、可拖拽缩放全屏的对话框外壳、带筛选状态栏的查询表格，以及完整的可视化查询构建器（AND/OR 分组、拖拽重排、字段/操作符/值输入选择器、子查询、可注入主题）。组件样式遵循类名约定，由消费方应用的样式管线生成，组件包不发布编译样式。

**Why this priority**: 这是终端开发者直接感知的价值层——从元数据到可交互界面的零手写渲染逻辑。P1 是引擎，P2 是引擎在存量最大的框架上的交付。

**Independent Test**: 在真实渲染环境中挂载每个组件（真实组件 + 真实核心服务，仅浏览器能力缺失处打桩），断言输入输出、交互与渲染结果；另在演示应用中以真实数据源做端到端冒烟。

**Acceptance Scenarios**:

1. **Given** 实体列表组件与实体命名空间/名称，**When** 渲染，**Then** 显示无限滚动表格；修改单元格值后数据被保存；Ctrl/Cmd+Z 与 Ctrl+Shift+Z 撤销/重做；筛选弹层可编辑查询条件并过滤数据。
2. **Given** 实体详情组件与实体标识，**When** 打开，**Then** 按 Tab 展示基础表单与关系表格；create 模式先在内存中生成草稿实体，保存时才落库；表单校验失败阻止保存并展示错误。
3. **Given** 表单字段配置与数据，**When** 以 view 模式渲染，**Then** 全部字段只读；edit/create 模式下按字段类型渲染对应输入控件（布尔开关、枚举下拉、日期、数组、JSON、键值、关系选择等）。
4. **Given** 查询构建器组件与实体元数据，**When** 用户添加规则、分组、切换 AND/OR、拖拽重排、选择操作符与输入值，**Then** 实时发出查询变更与校验结果，并可从既有查询回填组件状态。
5. **Given** 深色与浅色主题环境，**When** 渲染表格与查询构建器，**Then** 视觉一致、可读性达标；键盘可完成焦点导航与全部核心操作。
6. **Given** 一个没有样式管线的消费方，**When** 使用组件，**Then** 文档明确说明所需类名约定与样式接入步骤（无样式管线时组件以无样式形式渲染，这是文档化行为而非缺陷）。

### User Story 3 - React 绑定层 (Priority: P3)

React 开发者获得与 Story 2 同等能力的组件集：实体列表、详情、表单、对话框、表格与可视化查询构建器，API 命名、行为与 Angular 端保持功能等价。

**Why this priority**: 仓库宪法要求三框架能力对称，React 是第二大体量的目标生态。按既定策略，Angular 先行、React/Vue 为同一 epic 的后续阶段，但在 epic 关闭前必须补齐，否则不视为完成。

**Independent Test**: 以 React 惯用的测试方式真实渲染组件，执行与 Story 2 相同的验收场景矩阵；跨框架一致性由对拍测试验证（相同数据 → 相同输出）。

**Acceptance Scenarios**:

1. **Given** 相同的实体元数据与数据，**When** 在 React 应用中渲染实体列表、详情、表单与查询构建器，**Then** 能力面与交互行为同 Angular 端一致（场景同 Story 2 的 1–5）。

---

### User Story 4 - Vue 绑定层 (Priority: P3)

Vue 开发者获得与 Story 2 同等能力的组件集，API 命名、行为与 Angular/React 端保持功能等价。

**Why this priority**: 三框架对称的最后一环；按既定策略为同 epic 的后续阶段。

**Independent Test**: 以 Vue 惯用的测试方式真实渲染组件，执行与 Story 2 相同的验收场景矩阵；跨框架对拍测试验证视觉与行为一致。

**Acceptance Scenarios**:

1. **Given** 相同的实体元数据与数据，**When** 在 Vue 应用中渲染实体列表、详情、表单与查询构建器，**Then** 能力面与交互行为同 Angular 端一致（场景同 Story 2 的 1–5）。

---

### Edge Cases

- 字段值为空、格式错误、超出范围、枚举非法值时，校验必须返回结构化错误而非崩溃；错误信息包含字段与原因。
- 只读行、新建行（未保存草稿行）在行内编辑、删除、拖拽重排时按各自规则降级或禁止。
- 查询条件树到达最大嵌套深度时，进一步的嵌套操作被阻止并提示；存在性子查询内部同样受深度限制。
- 剪贴板不可用（浏览器拒绝）时，表格复制/粘贴仍通过内部剪贴板可用。
- 深色/浅色主题切换过程中表格与浮层组件无闪烁、无样式残留。
- 消费方未接入样式管线时组件无样式渲染（文档化行为），接入后样式完整。
- 关系字段引用尚未加载的目标实体时，选择器与表格降级为空态并给出加载路径。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 核心库 MUST 支持从实体元数据构建表单字段配置，覆盖 create / edit / view 三种模式，并过滤系统字段。
- **FR-002**: 核心库 MUST 提供字段值解析、格式化与校验，错误以结构化形式返回（含字段路径与原因），不得抛出未捕获异常。
- **FR-003**: 核心库 MUST 支持实体与表单数据的双向转换，且只产出实际变化的字段。
- **FR-004**: 核心库 MUST 提供结构相等比较，键顺序无关，循环引用安全。
- **FR-005**: 核心库 MUST 支持从实体元数据构建详情页 Tab 结构：一个基础表单区块 + 每个一对多/多对多关系一个表格区块。
- **FR-006**: 核心库 MUST 支持从实体元数据构建可编辑表格列配置：属性类型对应合适的单元格编辑器、只读记录降级、操作列与时间列。
- **FR-007**: 核心库 MUST 提供查询条件树的完整操作面：规则/分组增删、AND/OR 组合切换、条目移动、最大嵌套深度限制、与仓库查询格式双向转换、逐规则即时校验。
- **FR-008**: 核心库 MUST 提供表格运行时能力：单元格编辑与批量合并、系统剪贴板复制/粘贴（不可用时内部剪贴板兜底）、键盘导航、行删除、拖拽重排、单元格错误提示。
- **FR-009**: Angular 组件集 MUST 覆盖：实体列表（无限滚动、行内编辑、撤销/重做、筛选、级联新增、多对多选择模式）、实体详情（Tab 结构、草稿保存编排）、实体表单（按模式渲染全部字段类型）、对话框外壳（拖拽、缩放、全屏）、查询表格（筛选状态栏与插槽）、可视化查询构建器（分组/规则/拖拽重排/字段/操作符/值输入/子查询/主题注入）。
- **FR-010**: 组件样式 MUST 遵循文档化的类名约定并由消费方样式管线生成；组件包不得发布编译样式。
- **FR-011**: React 与 Vue 绑定层 MUST 提供与 FR-009 同等的能力面，公共 API 命名、行为与状态语义三端功能等价；本 epic 关闭前三端不得存在单端缺失。
- **FR-012**: 所有新包的全部公开导出 MUST 提供文档注释；新包与新增导出 MUST 纳入 API 基线门禁。
- **FR-013**: 单元测试 MUST 直接验证库源码（真实渲染组件、真实调用服务）；不得以复制被测逻辑的假测试充数。
- **FR-014**: 全部用户可见组件 MUST 定义加载、空、错误与可访问性行为，满足 WCAG 2.1 AA：键盘可达、焦点管理、屏幕阅读器可达语义。
- **FR-015**: 新核心包 `rxdb-model` 的四项覆盖率指标 MUST 达到仓库非核心包门禁（≥80%）；演示应用 MUST 提供实体列表/详情/表单/查询构建器的可运行页面。

### Key Entities _(include if feature involves data)_

- **实体元数据（Entity Metadata）**：实体的权威描述——类型化属性、计算属性、校验规则、关系定义。所有派生能力的唯一输入源。
- **表单字段配置（Form Field Config）**：元数据在表单场景的投影，含模式（create/edit/view）、可见性与校验规则。
- **可编辑表格列配置（Editable Column Config）**：元数据在表格场景的投影，含列类型、单元格编辑器与只读规则。
- **查询条件树（Query Rule Tree）**：用户可视化构建的结构化查询——规则、AND/OR 分组、嵌套；与仓库查询格式互为可转换表示。
- **实体管理 UI 组件集（Entity UI Components）**：跨框架（Angular/React/Vue）的元数据驱动界面组件——列表、详情、表单、对话框、表格与查询构建器。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 核心包与各框架绑定包的全部单元测试通过，且测试直接覆盖库源码——旧式假测试重写后，源码行/分支覆盖率达到仓库门禁（核心包 ≥80% 四项指标）。
- **SC-002**: 新包通过 API 基线门禁：lint 零警告、TypeScript strict 零错误、构建成功。
- **SC-003**: 三框架演示页面在相同实体与数据下渲染输出一致，跨框架对拍测试全绿。
- **SC-004**: 新包发布产物体积符合仓库预算（单包 gzip < 50 KB；表格引擎等外部依赖以对等依赖形式由消费方提供，不计入）。
- **SC-005**: 本地数据上的交互预算：行内编辑提交、查询条件变更、校验反馈在 100 ms 内完成；演示应用首次绘制 < 1.5 s。
- **SC-006**: 开发者凭文档与示例可在 30 分钟内为一个新实体搭建出列表 + 详情 + 表单 + 查询构建器的可运行页面。
- **SC-007**: 表格与查询构建器的全部核心操作（编辑、复制/粘贴、删除、重排、条件构建）可仅凭键盘完成，WCAG 2.1 AA 检查通过。

## Assumptions

- **三框架策略**（已确认决策）：Angular 先行交付（Story 2），React（Story 3）与 Vue（Story 4）为同一 epic 的后续阶段；epic 关闭前补齐三端对称，单端缺失视为未完成。
- **表格引擎选择**：保留企业版的技术选型（VTable 引擎），版本锁定 1.26.x 系列；仓库现有的另一表格方案仅用于既有演示原型，不重复建设编辑器体系。
- **样式策略**：消费方样式管线约定为 Tailwind + daisyUI 类名；组件包不发布编译 CSS。无样式管线的消费方渲染无样式组件，属文档化行为。
- **图标库**：使用仓库既有标准图标包，替换企业版的旧包名依赖；图标数据格式不变。
- **文案**：界面与错误文案沿用中文（仓库现行惯例）；如未来需要国际化另行立项。
- **测试重写**：企业版 6 个旧式「内联复制被测逻辑」的测试文件在移植时按真实源码测试模式重写，不计入既有测试资产。
- **API 兼容面**：核心库依赖的实体元数据与查询格式接口在开源核心包中已存在且语义兼容（已核对），移植不修改核心包公开 API；如移植暴露缺口，通过既有插件/扩展机制解决而非修改核心契约。
