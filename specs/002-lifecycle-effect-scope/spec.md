**Feature Branch**: `002-lifecycle-effect-scope`

**Updated**: 2026-08-16（对齐 US-013 / US-014 的决策表：命名裁决 D1、幂等口径 D3、实例身份 vs 纪元资源 D8、跨纪元 Observable D9、US-015 拆分）

**Status**: Draft

**Input**: User description: "epic-008 生命周期作用域：把「登记副作用 → 拆卸时逐一撤销」这件在仓库里被手工写了九遍的事，收敛成一个原语（作用域），并据此重写插件的安装/拆卸契约与依赖装卸时机。来源文档：requirements/epics/epic-008-lifecycle-scope.md"

> **分支目录名说明**：`002-lifecycle-effect-scope` 创建于命名裁决（US-013 D1）之前，目录名不重命名以免打断分支。
> 全文一律以 `LifecycleScope` / `acquire()` 为准；**规格内不再出现 `EffectScope` / `effect()` 这组名字**——
> 它们与 Vue 3.5 的 `EffectScope`/`effectScope()`、Angular 的 `effect()` 同名不同义，而 `@aiao/utils` 同时被 `rxdb-vue` 使用。

## 概述

让「一段代码活多久」成为可声明、可组合、可验证的东西。

今天每一个会产生副作用的构件都各自维护一份「安装时做了什么 → 拆卸时逐一撤销」的手工账本：
账本是自由格式的，编译器不检查，测试很难覆盖，唯一的保证是作者当时记得写对称的那一半。
本特性把这份账本收敛成**一个原语**——获取资源时就同时登记它的释放方式，作用域结束时逆序自动释放——
并把插件契约改写到这个原语上，最后让插件能声明「我需要什么才能工作」，由宿主决定安装与释放的时机。

目标状态是：新增一处资源获取**没有地方**可以忘记写它的释放。

本特性**不新增任何用户可见能力**：查询、变更、事务、同步的语义与签名都不变。它改变的是这些能力的装卸方式，
以及**三处今天就能复现的缺陷**——它们的共同形状是同一个：**资源的获取点与释放点寿命不同**。

| #   | 缺陷                                     | 今天的表现                                                                                                                                                                                                                                               |
| --- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | graph 插件的撤销**无处可写**             | `install()` 经 `rxdb.repository()` 写进 `#repository_config_map`，而该 Map 只有 `.set` / `.get`，宿主根本没有反注册入口；`destroy()` 只能是空实现                                                                                                        |
| 2   | storage 插件断连后**属性永久消失**       | `new RxdbFileStorage(...)` 与 `Object.defineProperty(rxdb, 'storage', …)` 在构造器（`#plugin_map` 缓存，只跑一次），`Reflect.deleteProperty` 在 `destroy()`（每次停机都跑）——连→断→连之后 `rxdb.storage` 是 `undefined`，且底层实例已 `destroy()` 为终态 |
| 3   | workspace 插件断连后**整体处于已销毁态** | `#destroyed` 是终态标志、从不复位；`readonly #indexedDBStore!: WorkspaceStore` 在类型上就无法重新赋值                                                                                                                                                    |

这三条不依赖依赖图、纪元调度或框架宿主，**US1 + US2 交付后即全部关闭**。

### 术语（唯一口径）

| 概念                  | 中文           | 含义                                                                         | 状态             |
| --------------------- | -------------- | ---------------------------------------------------------------------------- | ---------------- |
| `LifecycleScope`      | 生命周期作用域 | 一段代码的存活期；资源获取登记在它上面，它结束时逆序释放                     | 本特性新契约     |
| `acquire()`           | 取得所有权     | 一次「取得某种所有权（资源、注册项、监听器）+ 如何放弃它」的成对登记         | 本特性新契约     |
| `child()`             | 建子作用域     | 在当前作用域内开一个更短命的作用域；它在父作用域的登记序列中占**创建位置**   | 本特性新契约     |
| `dispose()`           | 释放           | 结束一个作用域：逆序、串行执行全部撤销；唯一的异步形态，结果被缓存且幂等     | 本特性新契约     |
| `ScopeDisposer`       | 撤销句柄       | 撤销单次登记的函数；可提前单独调用，也由作用域释放时统一调用                 | 本特性新契约     |
| 连接纪元作用域        | —              | `init()` 创建、停机释放的容器层；重连创建全新的一个                          | 本特性新契约     |
| 插件激活作用域        | —              | 每一次插件安装一个，挂在当次连接纪元作用域下                                 | 本特性新契约     |
| `lifecycle: 'scoped'` | 作用域化标记   | 插件声明「我用 `install(scope)` 登记全部副作用」；宿主据此不再调 `destroy()` | 本特性新契约     |
| dependency (`inject`) | 依赖           | 插件声明的、安装前必须就绪的东西；取值是封闭联合，不接受任意字符串           | 本特性新契约     |
| dependency epoch      | 依赖纪元       | 依赖提供者的身份标识；纪元变化即视为「依赖换了一个」                         | 本特性新契约     |
| install / destroy     | 安装 / 拆卸    | 插件生命周期的两端；本特性把「拆卸」并入「安装时登记的撤销」                 | 既有契约，被改写 |

「作用域」只指**进程内的存活期**，不指数据的可见范围，也不指任何持久化概念。已有的多实例可见性问题
（同一进程内多个宿主实例如何互不串扰）是另一件事，不在本特性内解决。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 资源获取与它的释放写在一起（Priority: P1）

库的实现者在需要获取资源时，把「取得什么」和「怎么放弃」写在同一处登记给一个作用域；作用域结束时，
全部登记按登记的逆序自动释放。异步的释放动作被串行等待，其中一个失败不会连累其余。

**Why this priority**: 这是后两个故事的地基。没有一个语义被测试冻结的原语，「把插件的副作用收进作用域」
只是把九份手工账本换成第十份写法。

**Independent Test**: 单独交付即可用——在 `@aiao/utils` 内构造作用域，登记若干副作用（含嵌套子作用域），
释放后逐项验证撤销顺序、幂等性、错误隔离与嵌套传播，全程纯内存、不涉及数据库、不涉及 DOM 与计时器。

**Acceptance Scenarios**:

1. **Given** 一个作用域上按 A、B、C 顺序登记了三项，**When** 释放该作用域，**Then** 撤销按 C、B、A 执行；首个撤销执行前状态已是「释放中」，全部完成后为「已释放」。
2. **Given** 若干撤销动作返回未结算结果，**When** 释放作用域，**Then** 串行等待——后一个的结算早于前一个的开始；释放返回的结果在全部结算后才完成。
3. **Given** 已拿到某项登记的撤销句柄，**When** 调用它两次再释放整个作用域，**Then** 底层清理只执行一次；该项已从清单摘除，释放时不再涉及它。
4. **Given** 一个已释放的作用域，**When** 再次释放它（含并发同时调用两次），**Then** 拿到**同一个**结果对象，撤销总执行次数不变。这条对成败一视同仁：
   - 首次释放**成功**时，重复释放同样成功，不抛错；
   - 首次释放**失败**时（场景 6 / 7 的结果已被捕获），重复释放拿到的是**同一个失败结果**——同一个错误对象、聚合错误的成员集合不变；失败项不被重试，也不新增错误。**不得**把它替换成一个成功的结果。
5. **Given** 一个已释放或正在释放的作用域，**When** 在其上登记新的副作用（含在某个撤销动作内部登记），**Then** 抛出专用的、可判别的错误，且 **setup 不被执行**——不静默丢弃，也不「先执行再撤销」；错误消息含作用域标签与本次登记的标签。
6. **Given** 三个撤销动作中第 2、3 个抛错，**When** 释放作用域，**Then** 三个全部被调用（不短路），以聚合错误结束并按执行顺序保留；作用域仍进入「已释放」。
7. **Given** 三个撤销动作中恰好一个抛错，**When** 释放结束，**Then** 原样抛出该错误，不包一层聚合错误。
8. **Given** 父作用域上依次登记 A、子作用域 S、B，S 上登记 s1、s2，**When** 释放父作用域，**Then** 顺序为 B →（s2 → s1）→ A：子作用域在**它被创建的那个位置**整体释放。
9. **Given** 子作用域已独立释放（无论其内部撤销是否抛错），**When** 随后释放父作用域，**Then** 它不被二次释放，已从父清单摘除，父的其余项照常释放。
10. **Given** setup 同步抛错，**When** 登记，**Then** 错误原样抛给调用方，该项**不进入**清单，作用域仍为「活跃」。
11. **Given** setup 未返回撤销动作（无需释放的副作用），**When** 释放作用域，**Then** 不抛错、不调用任何东西；该项的撤销句柄可安全调用且为空操作。
12. **Given** 手动调用某个撤销句柄且底层清理抛错，**When** 捕获后释放整个作用域，**Then** 该项在调用底层清理**之前**已摘除并标记已执行，**不回滚**回清单，释放时不重试它。

### User Story 2 - 插件不再自己维护拆卸清单（Priority: P1）

插件作者在安装入口拿到一个作用域，把每个资源获取和它的释放方式写在一起；宿主负责在正确的时刻、
按正确的顺序释放。停机后，插件在安装期对宿主做的每一件事都回到安装前的状态；重新连接时，
**同一个插件实例能再装出一套活资源**。既有插件不改一行代码也能继续编译与运行。

**Why this priority**: 它把原语真正用起来，并直接关闭概述表里的三处缺陷。这三处不是作者疏忽：
第 1 处是宿主没提供撤销入口，第 2、3 处是构造器只跑一次而 `destroy()` 每次都跑——
补上入口、把纪元资源移进安装入口、补上契约必须同时发生。

**Independent Test**: 可独立验证——安装若干插件后触发停机，逐项断言宿主状态回到安装前（激活期实例属性、
实体注册、事件监听、订阅、仓库注册），断言释放顺序为注册逆序且串行；再断言连→断→**再连**之后
三处缺陷的症状全部消失；最后断言一个未修改的旧插件实现仍能编译并被正常拆卸。

**Acceptance Scenarios**:

1. **Given** 按 A、B、C 顺序注册了三个插件并完成连接，**When** 断开全部连接，**Then** 三者的激活作用域按 C、B、A 逆序、串行释放（不并发）；旧契约插件的拆卸入口同样按此逆序串行调用，不存在「旧插件并行、新插件串行」的双路径。
2. **Given** 一个插件已安装过一次，**When** 断开后重新连接，**Then** 本次安装拿到全新激活作用域，且它挂在全新的连接纪元作用域下；上一轮登记已全部释放且不会被二次释放，不产生双份注册。
3. **Given** 宿主已初始化，**When** 此时注册一个新插件，**Then** 它立即安装并同样获得独立激活作用域，参与后续的逆序释放。
4. **Given** 停机正在进行，**When** 此时注册新插件，**Then** 它只被登记、不启动安装；下一个连接纪元才安装。
5. **Given** 某插件声明了作用域化标记且**同时**实现了废弃的拆卸入口，**When** 触发停机，**Then** **只**释放作用域，拆卸入口**不被调用**——双版本插件在新宿主上只清理一次。
6. **Given** 某插件**未**声明作用域化标记（旧插件），实现了拆卸入口，**When** 触发停机，**Then** 先释放它那个（通常为空的）激活作用域，再调用拆卸入口；**就该插件自身而言**（是否被调用、调用次数、入参、错误出口）与升级前一致——插件**之间**的顺序与并发是本特性有意改变的（场景 1 与 FR-022）。
7. **Given** 某插件**只**声明了作用域化标记、**不**实现拆卸入口，**When** 触发停机，**Then** 不抛类型错误——宿主对拆卸入口的调用必须是可选调用（今天是无保护调用，契约一改成可选就会崩）。
8. **Given** 一个未做任何修改的既有插件实现（安装入口无参、实现了必选的拆卸入口），**When** 升级依赖后编译并运行，**Then** 编译通过，拆卸入口仍被调用，该插件自身的行为与升级前一致（同场景 6 的口径）。
9. **Given** graph 插件已迁移，**When** 完成一次连接与断开，**Then** 它注册的仓库配置在连接期间可查询、停机后不可查询——**概述表第 1 处缺陷被证伪**。
10. **Given** 同名仓库已被后来者以不同配置覆盖注册，**When** 先注册者的作用域释放，**Then** 按配置对象身份守卫——不是自己那份就不撤销，后来者的注册保持有效。
11. **Given** storage 插件已迁移，**When** 连接 → 断连 → **重新连接**，**Then** `rxdb.storage` 与实体注册在每一轮连接期都存在、每一轮断连后都消失，且重连后拿到的是**可用的新实例**而非已销毁的同一份——**概述表第 2 处缺陷被证伪**。
12. **Given** workspace 插件已迁移，**When** 连接 → 断连 → **重新连接**，**Then** 全部订阅已退订、store 与通道每纪元新建，写操作在第二轮连接期正常可用——**概述表第 3 处缺陷被证伪**；终态标志已从源码删除。
13. **Given** search 插件已迁移，**When** 安装 → 拆卸，**Then** 全部实体事件监听器被解绑，手工监听器清单字段已从源码删除；且 `install()` / `ready` 的对外时序与迁移前**逐字保持一致**（连接返回即全文检索可用是既有的用户可见保证）。
14. **Given** 某插件在登记 A、B 之后其安装入口抛错（同步抛或异步拒绝），**When** 连接，**Then** 已登记的 B、A 逆序释放；安装错误**原样**传播给连接流程，与本特性前一致。
15. **Given** 承接上一条且回收期间某个撤销动作也抛错，**When** 观察结果，**Then** 连接流程收到的仍是**安装错误**（原因），清理错误不得覆盖它；清理错误按既有口径在宿主边界记录。
16. **Given** 承接上两条，**When** 检查该插件状态，**Then** 其激活作用域已释放且**不进入**已安装集合；下一个纪元使用**全新**作用域重试，不复用失败的那个。
17. **Given** 初始化过程中插件安装之后的任一步抛错，**When** 捕获后检查状态，**Then** 连接纪元作用域已释放并置空、已安装插件已回滚；**When** 修复后重新初始化，**Then** 插件被重新安装到全新的连接纪元作用域下，不产生双份监听或双份仓库注册。
18. **Given** 已连接且插件均已安装，**When** 停机后再次连接，**Then** 重连创建的是**全新**连接纪元作用域，而不是在已释放的作用域上创建子作用域。
19. **Given** 某插件的一个撤销动作抛错，**When** 停机继续，**Then** 同插件其余撤销照常执行，其他插件的释放不受影响，宿主对外的成败表现与本特性前一致。
20. **Given** 全部插件已迁移，**When** 审阅各插件源码，**Then** 原有的**副作用清单**字段（拥有权布尔、注册布尔、监听器数组、订阅表、手写 rollback）已删除，而不是与作用域并存；承担 `ready` 语义的安装阶段字段不强制删除，但**终态标志**（「本实例已永久销毁」）已删除，其守卫改由「本纪元是否有活着的作用域」回答。
21. **Given** 插件契约的成员签名被故意改坏，**When** 运行类型契约测试，**Then** 测试失败——导出表面基线只记录名称与种类，对这类变化不产生差异，因此不能作为契约未变的证据。
22. **Given** workspace / search 已迁移，**When** 连接 → 断连 → 检查两个注册期实例属性 → 重新连接，**Then** 属性在停机后**仍然存在**且仍指向同一个插件实例（不被尝试删除）；此时调用其业务方法抛「本纪元未安装」而**不是**「实例已永久销毁」；重连后同一实例恢复可用——注册期发布的是**实例身份**，不是纪元资源。
23. **Given** 在首次连接期订阅了 workspace 的公开变更流，**When** 断连 → 重新连接，**Then** 该订阅既未收到终结也未收到错误，断连期间静默；重连后**同一条流、同一个订阅**继续收到新纪元的事件；流的引用身份跨纪元不变。

### User Story 3 - 插件声明适配器依赖，由宿主决定装卸时机（Priority: P2 · **条件性，非本特性的交付承诺**）

> **口径声明（与 epic-008 的差异，须显式知晓）**：epic-008 把本组内容列在
> 「**已冻结契约，但尚无可交付切片**」之下——承诺的交付只有 US-013 与 US-014；
> 承接它的故事文件 `US-015a` **至今未创建**。因此本节（连同 FR-034～FR-045、SC-013～SC-015）是
> **契约的规格化预写**，用途是防止 US1 / US2 做出与之冲突的设计决策，**不构成排期承诺**。
> `US-015a` 落盘、并在其中写出「今天用户踩得到的具体症状」之前，本节 MUST NOT 进入实现计划；
> `US-015a` 落盘时，本节 MUST 与之逐条对齐后才升级为承诺范围。
> 这是本规格相对来源 Epic **唯一有意的口径扩展**，其余部分与 Epic 一致（见 Traceability）。

插件声明「我需要哪个适配器才能工作」，宿主在该适配器真正可用后才安装它、在它消失时释放插件的作用域、
在它重新出现时重装。插件不再需要自己写「等依赖 → 判断有没有被中途拆掉 → 记录失败态以便重试」的状态机，
也不会因为等一个由连接流程自己提供的依赖而把连接流程等死。

**Why this priority**: 价值真实但可延后——US1 + US2 交付后三处已知缺陷已全部关闭，本故事解决的是**复杂度**与
一处今天完全没有信号的场景（本地与远端都连着、只断开其中一个）。它必须排在后面：依赖消失时的「释放」
以插件副作用已全部收进作用域为前提，否则只能释放掉一半。

**范围**：本故事只交付**适配器类别**的依赖（`adapter:local` / `adapter:remote`）与纪元调度骨架。
依赖取值类型一次定义完整（含 `plugin:*` 形态），但**插件间依赖的解析、名字索引、重名裁决、拓扑排序与环检测
不在本故事**——见〈待证附录〉。

**Independent Test**: 可独立验证——构造一个声明适配器依赖的插件，分别在依赖缺席、就绪、消失、再现四种时序下
断言其作用域的存在与身份；并断言声明了本次不会连接的适配器时连接流程照常完成。

**Acceptance Scenarios**:

1. **Given** 某插件声明依赖某个尚未连接的适配器，**When** 完成初始化，**Then** 该插件不安装、不产生作用域、不报错；未声明依赖的插件照常立即安装。
2. **Given** 承接上一条，**When** 该适配器完成连接，**Then** 该插件自动安装并获得新作用域，安装完成早于连接流程结束。
3. **Given** 某插件依赖一个本次不会连接的适配器，**When** 连接另一个适配器，**Then** 连接流程正常完成、不挂起——依赖未满足的插件不进入宿主的安装等待集合，宿主只等待已经启动的安装。
4. **Given** 适配器实例存在但引导链（建表、迁移、写者租约、索引对账）尚未跑完，**When** 判定依赖是否就绪，**Then** 判定为**未就绪**——「实例已构造」不算可用；就绪点是引导链全部跑完、该适配器名进入已连接集合之后。
5. **Given** 本地与远端都已连接、某插件只依赖其中之一，**When** 断开它依赖的那个（另一个仍连着，不触发整体停机），**Then** 该插件的作用域被释放，其余插件不受影响，插件注册本身保留。
6. **Given** 承接上一条，**When** 观察释放与断开的先后，**Then** 先释放依赖方的作用域、再让依赖本身失效——撤销动作不得跑在一个已经断开的适配器上。
7. **Given** 承接第 5 条，**When** 该适配器重新连接，**Then** 该插件以全新作用域重新安装，不出现双份注册或重复监听。
8. **Given** 依赖的提供者被替换成另一个实例但名称不变，**When** 宿主判定依赖是否仍是同一个，**Then** 按提供者身份（纪元）判定为已变化并触发释放与重装，不因名称相同或布尔就绪位为真而漏判。
9. **Given** 某插件的依赖永远不会满足，**When** 完成连接，**Then** 连接正常完成，并有一次明确列出缺失项的诊断提示，不静默。
10. **Given** 一次延迟安装抛错，**When** 观察后续行为，**Then** 该插件被标记失败并释放其作用域，同一依赖纪元内不自动重试、不引入计时器与退避；依赖纪元变化后重新尝试。
11. **Given** 宿主维护的插件激活状态，**When** 另一个插件按依赖判定它是否可用，**Then** 只有处于「已激活」的插件才算依赖已满足；「已注册」「等待中」「安装中」都不满足。
12. **Given** 依赖取值类型，**When** 运行类型契约测试，**Then** 裸名、任意字符串、大写开头的插件名与非字面量赋值全部被编译期拒绝，只有封闭联合内的取值被接受。

### Edge Cases

- 撤销动作内部又在**同一个**作用域上登记新副作用会怎样？——按 FR-006 拒绝（释放中状态下登记即抛错），不产生「释放永不收敛」的循环。
- 插件在安装入口之外（例如后台续做的异步安装）还要登记副作用怎么办？——作用域按参数继续向下传递；任何把作用域存进实例字段的写法都会在下一次重装时拿到已释放的旧作用域。
- 停机与一次尚未结算的安装同时发生会怎样？——作用域释放对已登记项立即生效；跨 `await` 的资源获取本特性不提供专用出口（见〈非目标〉S-008），插件不得依赖「我是不是已经被拆了」的手工重查。
- 依赖在一次安装尚未完成时就消失了会怎样？——该次安装的作用域按 FR-041 释放，安装结果丢弃；依赖再次出现时是一次全新的安装，而不是续做。
- 同一个插件被注册两次会怎样？——沿用既有行为（按工厂函数身份去重），本特性不改变它。
- 插件既声明了作用域化标记又保留了废弃的拆卸入口会怎样？——**只**释放作用域，拆卸入口不被调用（FR-017）；漏声明标记的失败模式是安全的：退回到调用拆卸入口，与升级前一致。
- 注册期挂上的实例属性（`rxdb.workspace` / `rxdb.searchPlugin`）能被自动释放吗？——**不应该释放**。它们发布的是**插件实例身份**而非纪元资源（FR-027a 判据其三），跨纪元本就该保持可达；`configurable: false` 是这一事实的结果，不是理由。要在停机后彻底摘掉它们，需要先有宿主级的销毁/反注册入口，本特性不提供，也不宣称它们已纳入自动释放。
- 那停机后调用 `rxdb.workspace` 的方法会怎样？——抛「本纪元未安装」，重连即恢复；**不再**是今天的终态 `#destroyed`「这个实例永远死了」（FR-027a 判据其四）。这是本特性有意改变的三处可观察行为之一（SC-018）。
- 停机会终结 `workspace.changes$` 吗？——**不会**（FR-027b）。若每纪元重建这条流，停机前建立的订阅会永久停在一条已终结的流上而毫无信号——正是本特性要消灭的失败形状。代价是一次有记录的行为变更：这条流不再随停机 complete。
- 宿主对外的断开操作在插件拆卸失败时是否会失败？——不会，与本特性前保持一致（FR-031）。改变它是独立的破坏性变更，不在本特性内。
- graph 插件声明了但从未赋值的实例属性怎么办？——是另一条遗留缺陷，不在本特性内顺手修；本特性只修它的仓库注册泄漏。

## Requirements _(mandatory)_

### Functional Requirements

#### A. `LifecycleScope` 原语（US1）

- **FR-001**: 作用域 MUST 允许在取得一项所有权的同一处登记放弃它的方式，并返回一个可单独调用的撤销句柄。
- **FR-002**: 作用域释放 MUST 按登记的**逆序**执行全部撤销。
- **FR-003**: 释放 MUST 幂等，且**成功与失败一视同仁**：首次释放的结果 MUST 被缓存，重复释放（含并发重复调用）MUST 返回**同一个**结果对象——首次失败时返回的就是那个**同一个失败结果**（同一错误对象；聚合错误的成员集合不变）。重复释放 MUST NOT 重复执行任何撤销动作、MUST NOT 重试失败项、MUST NOT 新增错误。此处「不抛错」只指**重复调用本身不引入新的错误**，MUST NOT 被实现成「把失败的首次释放替换为成功的后续释放」——那会在防御性重复释放（如停机路径）中静默吞掉首个真实故障。重复调用同一撤销句柄同理（见 FR-012）。
- **FR-004**: 某个撤销句柄被提前单独调用后，作用域整体释放时 MUST NOT 再次执行它。
- **FR-005**: 撤销动作返回未结算结果时，释放 MUST 串行等待其结算后再执行下一个；释放本身 MUST 可被等待。
- **FR-006**: 在已释放或正在释放的作用域上登记 MUST 抛出专用的、可判别的错误，且 setup MUST NOT 被执行；MUST NOT 静默丢弃，也 MUST NOT 先执行再撤销。
- **FR-007**: 某个撤销动作抛错时，其余撤销动作 MUST 照常执行（不短路）。
- **FR-008**: 全部撤销执行完毕后，恰好一个错误时 MUST 原样抛出该错误；多于一个时 MUST 以聚合错误抛出并按执行顺序保留。
- **FR-009**: 作用域 MUST 可嵌套；子作用域 MUST 随父作用域释放而释放，并在父作用域的登记序列中按其创建位置参与逆序；子作用域独立释放后 MUST 从父清单摘除，无论其内部撤销是否抛错。
- **FR-010**: setup 同步抛错时，错误 MUST 原样抛给调用方，该项 MUST NOT 进入清单，作用域状态 MUST 保持活跃。
- **FR-011**: setup 未返回撤销动作时 MUST NOT 抛错；该项的撤销句柄 MUST 可安全调用且为空操作。
- **FR-012**: 无论手动调用还是作用域释放，条目 MUST 在执行底层清理**之前**从清单摘除并标记已执行；失败 MUST NOT 回滚回清单，MUST NOT 重试。
- **FR-013**: 作用域 MUST 暴露只读的三态状态（活跃 / 释放中 / 已释放），且该状态 MUST 与 FR-006 的判定一致；作用域与每次登记 MUST 支持可选标签，标签 MUST 出现在释放期错误的诊断信息中，MUST NOT 参与身份判定。
- **FR-014**: 原语 MUST 落在通用工具包并从其主入口导出；MUST 零外部依赖；MUST NOT 引入进程级单例注册表、`WeakRef` 或 `FinalizationRegistry`。
- **FR-015**: 释放入口 MUST 只有一个异步形态，MUST NOT 提供第二套同步语义；原语 MUST NOT 感知响应式订阅类型（订阅由调用方在 setup 里自行返回其退订动作）。

#### B. 插件作用域契约（US2）

- **FR-016**: 插件安装入口 MUST 接收一个作用域；插件在安装期产生的全部副作用 MUST 通过它登记。契约 MUST NOT 要求插件保存作用域引用——作用域只经安装入口传递。
- **FR-017**: 契约 MUST 新增一个可选的作用域化标记；声明该标记的插件在停机时 MUST **只**释放作用域，其拆卸入口 MUST NOT 被调用。标记的取值 MUST 是封闭字面量，MUST NOT 用函数形参个数等可被转译/压缩改变的信号代替。
- **FR-018**: 既有的拆卸入口 MUST 变为可选并标注废弃；**未**声明作用域化标记的插件在废弃周期内 MUST 仍被调用，且 MUST 在该插件作用域释放**之后**调用。
- **FR-019**: 宿主对拆卸入口的调用 MUST 是可选调用——契约把该成员从必选改为可选后，只实现安装入口的插件 MUST NOT 在拆卸路径上抛类型错误。
- **FR-020**: 契约变更 MUST NOT 破坏既有插件的编译与行为：既有的无参安装实现与既有的必选拆卸实现都 MUST 继续通过类型检查并按原语义运行；因此本次变更 MUST NOT 需要破坏性版本。
- **FR-021**: 宿主 MUST 建立三层作用域边界：注册期（今天无释放点）/ 连接纪元作用域（初始化时创建、停机时释放并置空、重连创建全新的一个）/ 插件激活作用域（每次安装一个，挂在当次连接纪元作用域下）。宿主 MUST NOT 在已释放的作用域上创建子作用域。
- **FR-022**: 停机时宿主 MUST 按插件注册的逆序、**串行**释放各插件作用域；旧契约插件的拆卸入口 MUST 走同一逆序串行路径，MUST NOT 保留并发拆卸的第二条路径。
- **FR-023**: 在宿主初始化之后注册的插件 MUST 同样立即安装并获得独立作用域，参与后续释放。
- **FR-024**: 停机进行中注册的插件 MUST 只被登记、MUST NOT 启动安装；下一个连接纪元才安装。
- **FR-025**: 仓库注册入口 MUST 提供把注册与撤销一次写完的形态（追加可选的作用域形参），其既有签名与链式返回值 MUST NOT 改变；撤销 MUST 按配置对象身份守卫，只撤销调用方自己登记的那一份；MUST NOT 新增裸的公开反注册方法（那会造出又一组需人工配对的 API）。
- **FR-026**: 停机后，插件在安装期对宿主所做的每一项登记 MUST 回到安装前状态，至少覆盖：**激活期**实例属性注入、实体注册、事件监听、订阅与仓库注册。**发布插件实例身份**的注册期实例属性（本仓库中恰好是 `rxdb.workspace` 与 `rxdb.searchPlugin`，两者均为不可配置）MUST NOT 被移进安装入口、MUST NOT 被尝试删除，也 MUST NOT 被宣称已纳入自动释放；它们在停机后 MUST 保持可达且指向同一实例。
- **FR-027**: 构造器 MUST 只创建插件对象本身（基类调用、纯配置解析、常量）；**需要释放的东西** MUST 移进安装入口。作用域释放之后，**同一个插件实例 MUST 能再安装出一套可用的资源**——终态销毁的服务 MUST 每纪元新建。
- **FR-027a**: 「改写宿主」这一条 MUST 按**写入值的寿命**而非「是否改写了宿主」来判定，四条判据 MUST 逐点应用于每一处宿主改写：
  1. 需要在停机时释放的 → 安装入口；
  2. 改写宿主且**写入值是纪元资源**（随停机失效、随重连新建）的 → 安装入口（`rxdb.storage` 属此类：它发布的是一个可被终态销毁的服务）；
  3. 改写宿主且**写入值是插件实例自身**（跨纪元不变、随宿主实例存活）的 → 留在注册期，MUST NOT 移进安装入口（`rxdb.workspace` / `rxdb.searchPlugin` 属此类）；
  4. 终态标志（「本实例已永久销毁」）MUST 删除，由作用域状态回答「本纪元是否已安装」——停机后调用业务方法 MUST 抛「本纪元未安装」而非永久已销毁，重连后 MUST 恢复可用。

  判据 MUST NOT 由属性当前的 `configurable` 取值倒推（不可配置是「发布的是实例身份」的结果，不是理由）。

- **FR-027b**: 跨纪元存活的**公开响应式流**（本仓库中为 `workspace.changes$`）MUST 与插件实例同寿：作用域释放 MUST 只退订其内部订阅，MUST NOT 终结（complete）或错误终结该流，也 MUST NOT 每纪元重建它。停机后该流 MUST 保持沉默而非终结，重连后 MUST 在**同一条流**上继续发射；停机前建立的订阅在重连后 MUST 仍然有效。
- **FR-028**: 概述表的三处缺陷 MUST 各有直接断言：graph 的仓库配置停机后不可查询；storage 的实例属性与实体注册在**重连后恢复且可用**；workspace 在重连后写操作正常、终态标志已删除。
- **FR-029**: 安装半途失败时，宿主 MUST 释放该次安装已登记的条目（逆序），MUST 把**原始安装错误**原样传播（清理错误 MUST NOT 覆盖它，按既有口径在宿主边界记录）；失败插件的作用域 MUST 进入已释放且 MUST NOT 进入已安装集合，下一纪元 MUST 使用全新作用域重试。
- **FR-030**: 初始化在插件安装之后的任一步失败时，宿主 MUST 释放并置空连接纪元作用域、回滚已安装插件，然后才复位初始化标志；重新初始化 MUST 拿到全新纪元，MUST NOT 产生双份注册或双份监听。
- **FR-031**: 单个撤销动作抛错 MUST NOT 阻止同插件其余撤销与其他插件的释放；错误在宿主边界的处置方式 MUST 与本特性前保持一致，MUST NOT 把停机路径从「一定成功」改成「可能失败」。
- **FR-032**: 仓库内全部插件包 MUST 迁移到新契约；迁移 MUST NOT 改变各插件的公开签名与错误类型，对外行为的差异 MUST 限于 FR-022 / FR-027a 判据其四 / FR-027b 这三处、且 MUST 全部写入迁移文档（SC-018）。特别地，search 插件的安装/就绪对外时序 MUST 逐字保持不变——「连接返回即全文检索可用」是既有的用户可见保证。
- **FR-033**: 迁移后各插件的**副作用清单**字段（拥有权布尔、注册布尔、监听器数组、订阅表、手写 rollback）MUST 被删除，MUST NOT 与作用域并存。承担**就绪语义**的安装态字段（如 search 的安装阶段枚举）本特性 MUST NOT 强制删除，其收敛属后续故事；但**终态标志** MUST 删除（FR-027a 判据其四）——它表达的是「实例永久死亡」，与「实例跨纪元存活」直接冲突。

#### C. 适配器依赖与纪元调度（US3 · **条件性附录，非交付承诺**）

> 本段全部条目以 `US-015a` 落盘为前置（见 US3 的口径声明）。它们冻结的是**接口形状与不变量**，
> 使 US1 / US2 不至于做出与之冲突的设计；在 `US-015a` 存在之前，本段 MUST NOT 被排期，
> 「本特性已完成」的判定 MUST NOT 依赖本段任何一条。

- **FR-034**: 插件 MUST 能声明一组依赖；取值 MUST 是封闭联合（两个适配器类别 + 带前缀的插件名），MUST NOT 接受裸名、任意字符串、大写开头的插件名或非字面量赋值。类型 MUST 一次定义完整，其中插件类别的**解析**归后续故事。
- **FR-035**: 依赖就绪 MUST 判定为「消费者可以立即使用它」而非「它存在」：适配器 MUST 以引导链（建表、迁移、写者租约、索引对账）全部跑完、该适配器名进入已连接集合为准；MUST NOT 以适配器实例流发出或全局连接布尔为准。
- **FR-036**: 依赖未全部就绪的插件 MUST NOT 被安装且 MUST NOT 产生作用域；该状态本身 MUST NOT 被视为错误。
- **FR-037**: 依赖全部就绪时，宿主 MUST 自动安装该插件并为其创建新作用域。
- **FR-038**: 依赖未满足的插件 MUST NOT 进入宿主的安装等待集合；连接流程 MUST 只等待已经启动的安装。该性质 MUST 由结构保证，MUST NOT 依赖调用方自觉。
- **FR-039**: 「依赖是否仍是同一个」MUST 按提供者身份（纪元）判定，MUST NOT 仅按名称或布尔就绪位判定。
- **FR-040**: 宿主 MUST 为每个插件实例维护激活状态（已注册 / 等待中 / 安装中 / 已激活 / 已失败 / 释放中），状态 MUST 只由调度器改写；MUST 只有「已激活」对外算依赖已满足。
- **FR-041**: 任一依赖消失时，宿主 MUST 释放该插件的作用域，同时 MUST 保留插件注册本身；释放 MUST 先于依赖本身失效——撤销动作 MUST NOT 跑在一个已断开的提供者上。
- **FR-042**: 依赖重新就绪时 MUST 以全新作用域重新安装，且 MUST NOT 产生重复注册或重复监听。
- **FR-043**: 依赖永不满足时 MUST 产生一次列出缺失项的诊断提示，MUST NOT 静默跳过。
- **FR-044**: 延迟安装失败时 MUST 标记该插件失败并释放其作用域；同一依赖纪元内 MUST NOT 自动重试，MUST NOT 引入计时器与退避语义；依赖纪元变化后 MUST 重新尝试。
- **FR-045**: 本故事开工前，四个后续故事文件（两个依赖子故事、停机收敛、三框架宿主）MUST 先落盘为存根，以消除文档死链；落盘 MUST NOT 被读作对它们的排期承诺。

#### D. 横切约束

- **FR-046**: 全部新增公开导出 MUST 补齐 TSDoc 并登记进 API 基线。
- **FR-047**: 插件契约的成员签名变化与依赖取值的封闭性 MUST 由编译期类型契约测试守护；导出表面基线只记录名称与种类，成员签名变化不产生差异，因此基线通过 MUST NOT 被当作契约未变的证据。
- **FR-048**: 该类型契约测试 MUST 能在签名被改坏时失败，并 MUST 在交付前以一次故意改坏的红测试证明。
- **FR-049**: 废弃成员 MUST 走仓库既定的废弃周期：至少保留一个次版本，移除时在迁移文档记录。
- **FR-050**: 公开文档 MUST 说明新契约写法、作用域化标记的含义、双版本插件的写法、废弃成员的过渡期、依赖声明的语义，以及「不要在安装入口里自己等依赖」的指引。迁移文档 MUST 逐条列出 SC-018 的**三处有意行为变更**——只列新写法而不列行为变更，下游遇到的第一个意外就是没人预告过的那个。
- **FR-051**: 覆盖率 MUST 满足仓库既有的分层门槛（宿主核心包 90%，通用工具包与四个插件包 80%），本特性 MUST NOT 下调任何门槛。
- **FR-052**: 宿主对外生命周期方法的签名与可见语义 MUST NOT 改变。

### Key Entities

- **LifecycleScope（生命周期作用域）** — 一段代码的存活期。持有按登记顺序排列的撤销清单与零或多个子作用域，暴露只读三态与可选标签。清单以「自增序号 → 条目」组织，使单条摘除为常数开销。释放一次且仅一次生效。
- **Acquisition（所有权登记）** — 一次「取得某种所有权 + 如何放弃」的成对记录：可选标签、撤销动作、是否已执行。
- **ScopeDisposer（撤销句柄）** — 撤销单次登记的入口；可提前单独调用，调用后该项从释放序列中出局，失败也不回滚。
- **连接纪元作用域** — 与初始化标志寿命完全相同的容器层；持有本纪元全部插件激活作用域。
- **插件激活作用域** — 一次安装的全部登记；跨断连重连不复用，每次安装是一个新的作用域。
- **PluginActivation（插件激活记录）** — 插件实例、当次激活作用域、依赖纪元快照、激活状态、失败标记。
- **RxDBPluginDependency（依赖项）** — 封闭联合的一个取值：适配器类别或带前缀的插件名。
- **DependencyEpoch（依赖纪元）** — 依赖提供者的身份标识；用于判定「依赖是否换了一个」，不使用名称或布尔就绪位。

## 范围边界

### 明确不做（非目标）

- **跨 `await` 的资源获取专用出口**（异步登记 + 取消信号）。本特性全链条的**四个迁移点资源获取全部是同步的**，零调用方；它是纯可加性 API，出现真实调用方时再补，对已发布的同步入口零影响。释放侧的异步性保留（真实调用方存在）。
- **插件间依赖的解析**：名字索引、重名裁决、拓扑排序、环检测——见〈待证附录〉。
- 依赖注入容器与动态服务注册表；依赖取值扩大到任意字符串键
- 用代理追踪「谁在调用我」来推断作用域归属（归属一律靠显式传参）
- 长异步栈追踪（把释放期错误指回登记点的调用位置）
- 全局作用域注册表 / 开发者工具中的作用域树可视化
- 超时强制释放（不把确定性原语变成靠时间赌的原语）
- 词法多实例隔离（作用域的**可见性**问题，与**存活期**正交）
- 宿主自身停机复位路径的收敛（本特性只改插件侧契约与内部记账）
- 三框架绑定挂接到同一原语
- 注册期实例属性（`rxdb.workspace` / `rxdb.searchPlugin`）的释放——它们发布的是**插件实例身份**，
  按 FR-027a 判据其三本就不该随纪元释放；要彻底摘掉需先有宿主级销毁入口，本特性不提供
- 改变插件拆卸错误在宿主边界的出口（吞掉 / 传播）
- 立即移除废弃的拆卸入口（本特性只让它变可选并进入废弃周期）
- 延迟安装失败后的定时退避重试
- graph 插件「声明了却从未赋值的实例属性」这条遗留缺陷（属另一个故事）

## Assumptions

- **「用户」是使用本库的应用开发者与插件作者**，不含最终用户；本特性没有界面，也不改变任何面向最终用户的行为。
- **原语落在通用工具包**：它不依赖宿主的任何类型，而该包已经承载了带生命周期的运行时构件（异步队列执行器、领导者选举、广播通道池）——加入本原语是补齐这一类的公共底座，不是定位漂移。具体包内路径与文件布局在计划阶段冻结。
- **命名已在故事层一次裁决完毕**，实现期不再重开：类型名、四个方法名、错误类型名均已冻结；规格只约束语义与不变量，内部字段命名、文件布局与错误码文本在计划阶段冻结。
- **作用域是进程内概念**：不持久化、不跨实例、不跨标签页；它与既有的跨实例协调机制正交。
- **插件安装的并发模型不变**：本特性改变的是释放的顺序与串行性，不改变无依赖插件之间的并发安装行为；US3 引入的串行化只发生在存在依赖关系的插件之间。
- **依赖的封闭取值当前只有两个适配器类别与带前缀的插件名**；扩大取值范围必须另起故事并说明理由。
- **既有插件的兼容性结论必须由真实编译用例证明**，不能靠「给函数加形参、把必选成员改为可选对实现方无影响」这一推断代替（FR-020）。
- **「基线绿」不是契约未变的证据**：本特性会制造一次成员签名变更，而导出表面基线对它零差异——这是仓库门禁的一个已知盲区，由本特性就地补类型契约测试，不扩大公开 API 门禁 Epic 的范围。
- 覆盖率、TDD 红→绿顺序、零 ESLint 警告、TSDoc 齐全与跨框架对称等仓库级铁律默认适用，本规格不重述。
