# Feature Specification: 生命周期作用域

**Feature Branch**: `002-lifecycle-effect-scope`

**Created**: 2026-08-15

**Status**: Draft

**Input**: User description: "epic-008 生命周期作用域：把「登记副作用 → 拆卸时逐一撤销」这件在仓库里被手工写了九遍的事，收敛成一个原语（作用域），并据此重写插件的安装/拆卸契约与依赖装卸时机。覆盖 US-013、US-014、US-015 的完整范围。来源文档：requirements/epics/epic-008-lifecycle-scope.md"

## 概述

让「一段代码活多久」成为可声明、可组合、可验证的东西。

今天每一个会产生副作用的构件都各自维护一份「安装时做了什么 → 拆卸时逐一撤销」的手工账本：
账本是自由格式的，编译器不检查，测试很难覆盖，唯一的保证是作者当时记得写对称的那一半。
本特性把这份账本收敛成**一个原语**——登记副作用时就同时登记它的撤销方式，作用域结束时逆序自动释放——
并把插件契约改写到这个原语上，最后让插件能声明「我需要什么才能工作」，由宿主决定安装与释放的时机。

目标状态是：新增一个副作用**没有地方**可以忘记写它的清理。

本特性**不新增任何用户可见能力**：查询、变更、事务、同步的语义与签名都不变。它改变的是这些能力的装卸方式，
以及一处**既有泄漏**——图数据插件的拆卸是空实现，且宿主契约里根本没有位置可写那段撤销。

### 术语（唯一口径）

| 概念              | 中文        | 含义                                                            | 状态             |
| ----------------- | ----------- | --------------------------------------------------------------- | ---------------- |
| effect scope      | 作用域      | 一段代码的存活期；副作用登记在它上面，它结束时逆序释放          | 本特性新契约     |
| effect            | 副作用登记  | 一次「做了某事 + 如何撤销」的成对登记，返回可单独调用的撤销句柄 | 本特性新契约     |
| disposer          | 撤销句柄    | 撤销单次登记的函数；可提前单独调用，也由作用域释放时统一调用    | 本特性新契约     |
| dependency        | 依赖        | 插件声明的、安装前必须就绪的东西；取值是封闭集合                | 本特性新契约     |
| dependency epoch  | 依赖代次    | 依赖提供者的身份标识；代次变化即视为「依赖换了一个」            | 本特性新契约     |
| install / destroy | 安装 / 拆卸 | 插件生命周期的两端；本特性把「拆卸」并入「安装时登记的撤销」    | 既有契约，被改写 |

「作用域」只指**进程内的存活期**，不指数据的可见范围，也不指任何持久化概念。已有的多实例可见性问题
（同一进程内多个宿主实例如何互不串扰）是另一件事，不在本特性内解决。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 副作用与它的撤销写在一起（Priority: P1）

库的实现者在需要产生副作用时，把「做什么」和「怎么撤销」写在同一处登记给一个作用域；作用域结束时，
全部登记按登记的逆序自动撤销。异步的登记与异步的撤销都被正确等待，其中一个撤销失败不会连累其余。

**Why this priority**: 这是后两个故事的地基。没有一个语义被测试冻结的原语，「把插件的副作用收进作用域」
只是把九份手工账本换成第十份写法。

**Independent Test**: 单独交付即可用——在通用工具包内构造作用域，登记若干同步/异步副作用（含嵌套子作用域），
释放后逐项验证撤销顺序、幂等性、错误隔离与嵌套传播，全程不涉及数据库。

**Acceptance Scenarios**:

1. **Given** 一个作用域上按 A、B、C 顺序登记了三项副作用，**When** 释放该作用域，**Then** 撤销按 C、B、A 执行。
2. **Given** 一个已释放的作用域，**When** 再次释放它，或再次调用其中某个撤销句柄，**Then** 不重复执行任何撤销动作，也不抛错。
3. **Given** 某个撤销句柄已被提前单独调用，**When** 之后释放整个作用域，**Then** 该项不再被撤销一次，其余项照常按逆序撤销。
4. **Given** 若干撤销动作是异步的，**When** 释放作用域，**Then** 逐个串行等待其结算后再进行下一个；释放完成的时机晚于最后一个撤销动作结算。
5. **Given** 一次异步登记的 setup 还没结算，作用域已被释放，**When** setup 随后结算并返回撤销动作，**Then** 该撤销动作被立即执行，不留下悬挂的副作用。
6. **Given** 释放过程中第二项撤销抛错，**When** 释放继续，**Then** 第一项与第三项仍被执行；释放结束后抛出错误。
7. **Given** 释放过程中恰好一个撤销抛错，**When** 释放结束，**Then** 原样抛出该错误；**Given** 多于一个抛错，**Then** 抛出聚合错误并保留原始顺序。
8. **Given** 一个作用域下创建了子作用域，**When** 释放父作用域，**Then** 子作用域在父作用域的登记序列中按它被创建的位置参与逆序释放，其内部登记同样逆序撤销。
9. **Given** 一个已释放或正在释放的作用域，**When** 在其上登记新的副作用，**Then** 抛出一个专用的、可判别的错误；不静默丢弃，也不「先执行再撤销」。
10. **Given** 登记与作用域都带了标签，**When** 释放期间发生错误，**Then** 诊断信息中包含相应标签。

### User Story 2 - 插件不再自己维护拆卸清单（Priority: P1）

插件作者在安装入口拿到一个作用域，把每个副作用和它的撤销方式写在一起；宿主负责在正确的时刻、
按正确的顺序释放。停机后，插件在安装期对宿主做的每一件事都回到安装前的状态——包括今天**无处可撤销**的
仓库注册。既有插件不改一行代码也能继续编译与运行。

**Why this priority**: 它把原语真正用起来，并直接修掉一处既有泄漏。九处手工账本里最严重的一处不是作者疏忽，
而是宿主没有提供撤销入口——补上入口与补上契约必须同时发生，否则「把副作用收进作用域」在该插件上无法落地。

**Independent Test**: 可独立验证——安装若干插件后触发停机，逐项断言宿主状态回到安装前（实例属性、实体注册、
事件监听、订阅、仓库注册），并断言释放顺序为注册逆序且串行；再断言一个未修改的旧插件实现仍能编译并被正常拆卸。

**Acceptance Scenarios**:

1. **Given** 按 A、B、C 顺序注册了三个插件并完成连接，**When** 断开全部连接，**Then** 三者的作用域按 C、B、A 逆序、串行释放（不并发）。
2. **Given** 一个插件已安装过一次，**When** 断开后重新连接，**Then** 本次安装拿到全新作用域；上一轮登记已全部释放且不会被二次释放，不产生双份注册。
3. **Given** 宿主已初始化，**When** 此时注册一个新插件，**Then** 它立即安装并同样获得独立作用域，参与后续的逆序释放。
4. **Given** 某插件仍实现了已废弃的拆卸入口，**When** 触发停机，**Then** 先释放它的作用域、再调用该入口；两者都执行，顺序稳定。
5. **Given** 一个未做任何修改的既有插件实现（安装入口无参、实现了拆卸入口），**When** 升级依赖后编译并运行，**Then** 编译通过，拆卸入口仍被调用，行为与升级前一致。
6. **Given** 图数据插件已迁移，**When** 完成一次连接与断开，**Then** 它注册的仓库配置在连接期间可查询、停机后不可查询。
7. **Given** 同名仓库已被后来者以不同配置覆盖注册，**When** 先注册者的作用域释放，**Then** 按配置对象身份守卫——不是自己那份就不撤销，后来者的注册保持有效。
8. **Given** 某插件的一个撤销动作抛错，**When** 停机继续，**Then** 同插件其余撤销照常执行，其他插件的释放不受影响，宿主对外的成败表现与本特性前一致。
9. **Given** 全部插件已迁移，**When** 审阅各插件源码，**Then** 原有的手工副作用清单（布尔标志、监听器数组、订阅表）已删除，而不是与作用域并存。
10. **Given** 插件契约的成员签名被故意改坏，**When** 运行类型契约测试，**Then** 测试失败——导出表面基线对这类变化不产生差异，因此不能作为契约未变的证据。

### User Story 3 - 插件声明依赖，由宿主决定装卸时机（Priority: P2）

插件声明「我需要什么才能工作」，宿主在依赖就绪后才安装它、在依赖消失时释放它、在依赖重新出现时重装它。
插件不再需要自己写「等依赖 → 判断有没有被中途拆掉 → 记录失败态以便重试」的状态机，也不会因为
等一个由连接流程自己提供的依赖而把连接流程等死。

**Why this priority**: 价值真实但可延后——前两个故事交付后泄漏已经修完，本故事解决的是**复杂度**与
一处今天完全没有信号的场景（多个连接共存时只断开其中一个）。它必须排在后面：依赖消失时的「释放」
以插件副作用已全部收进作用域为前提，否则只能释放掉一半。

**Independent Test**: 可独立验证——构造一个声明依赖的插件，分别在依赖缺席、就绪、消失、再现四种时序下
断言其作用域的存在与身份；并断言声明了不会出现的依赖时连接流程照常完成。

**Acceptance Scenarios**:

1. **Given** 某插件声明依赖某个尚未连接的资源，**When** 完成初始化，**Then** 该插件不安装、不产生作用域、不报错；未声明依赖的插件照常立即安装。
2. **Given** 承接上一条，**When** 该资源连接就绪，**Then** 该插件自动安装并获得新作用域，安装完成早于连接流程结束。
3. **Given** 某插件依赖一个本次不会连接的资源，**When** 连接另一个资源，**Then** 连接流程正常完成、不挂起——宿主只等待已经开始的安装。
4. **Given** 两个资源都已连接、某插件只依赖其中之一，**When** 断开它依赖的那个（另一个仍连着，不触发整体停机），**Then** 该插件的作用域被释放，其余插件不受影响，插件注册本身保留。
5. **Given** 承接上一条，**When** 该资源重新连接，**Then** 该插件以全新作用域重新安装，不出现双份注册或重复监听。
6. **Given** 依赖的提供者被替换成另一个实例但名称不变，**When** 宿主判定依赖是否仍是同一个，**Then** 按提供者身份判定为已变化并触发释放与重装，不因名称相同而漏判。
7. **Given** 插件 B 依赖插件 A，**When** 安装与释放，**Then** 安装顺序为 A → B，释放顺序为 B → A；逆拓扑序优先于逆注册序。
8. **Given** 两个插件互相依赖，**When** 规划安装，**Then** 以包含完整环路径的错误终止，不进入半安装状态。
9. **Given** 某插件依赖一个永远不会出现的名字，**When** 完成连接，**Then** 连接正常完成，并有一次明确列出缺失项的诊断提示，不静默。
10. **Given** 存在两个同名的依赖候选，**When** 有插件按该名字声明依赖，**Then** 抛出列出全部候选的歧义错误；**Given** 同名但无人依赖，**Then** 保持既有行为（仅告警）。
11. **Given** 一次延迟安装抛错，**When** 观察后续行为，**Then** 该插件被标记失败并释放其作用域，同一依赖代次内不自动重试；依赖代次变化后重新尝试。

### Edge Cases

- 撤销动作内部又在**同一个**作用域上登记新副作用会怎样？——按 FR-010 拒绝（释放中状态下登记即抛错），不产生「释放永不收敛」的循环。
- 异步登记的 setup 抛错、且此时作用域已被释放会怎样？——登记视为失败，无撤销动作可执行；错误按 FR-008 的口径合并进释放结果或抛给登记方，两条路径都不得静默。
- 插件在安装入口之外（例如后台续做的异步安装）还要登记副作用怎么办？——作用域按参数继续向下传递；任何把作用域存进实例字段的写法都会在下一次重装时拿到已释放的旧作用域。
- 停机与一次尚未结算的安装同时发生会怎样？——作用域释放对已登记项立即生效，对未结算的异步登记按 FR-006 生效；不依赖插件自己在每个 `await` 之后重新检查「我是不是已经被拆了」。
- 依赖在一次安装尚未完成时就消失了会怎样？——该次安装的作用域按 FR-031 释放，安装结果丢弃；依赖再次出现时是一次全新的安装，而不是续做。
- 同一个插件被注册两次会怎样？——沿用既有行为（告警并忽略后者），本特性不改变它。
- 既有插件既实现了新的作用域登记又保留了废弃的拆卸入口会怎样？——两者都执行（FR-017），顺序固定；文档必须说明这是过渡期写法而非推荐写法。
- 宿主对外的断开操作在插件拆卸失败时是否会失败？——不会，与本特性前保持一致（FR-022）。改变它是独立的破坏性变更，不在本特性内。

## Requirements _(mandatory)_

### Functional Requirements

#### A. 作用域原语

- **FR-001**: 作用域 MUST 允许在登记一项副作用的同一处登记它的撤销方式，并返回一个可单独调用的撤销句柄。
- **FR-002**: 作用域释放 MUST 按登记的**逆序**执行全部撤销。
- **FR-003**: 释放 MUST 幂等：重复释放作用域、或重复调用同一撤销句柄，MUST NOT 重复执行撤销动作，也 MUST NOT 抛错。
- **FR-004**: 某个撤销句柄被提前单独调用后，作用域整体释放时 MUST NOT 再次执行它。
- **FR-005**: 撤销动作返回未结算结果时，释放 MUST 串行等待其结算后再执行下一个；释放本身 MUST 可被等待。
- **FR-006**: 作用域 MUST 支持异步登记；若 setup 结算时作用域已被释放，其返回的撤销动作 MUST 被立即执行，MUST NOT 留下悬挂副作用。
- **FR-007**: 某个撤销动作抛错时，其余撤销动作 MUST 照常执行（不短路）。
- **FR-008**: 全部撤销执行完毕后，恰好一个错误时 MUST 原样抛出该错误；多于一个时 MUST 以聚合错误抛出并保留原始顺序。
- **FR-009**: 作用域 MUST 可嵌套；子作用域 MUST 随父作用域释放而释放，并在父作用域的登记序列中按其创建位置参与逆序。
- **FR-010**: 在已释放或正在释放的作用域上登记副作用 MUST 抛出专用的、可判别的错误；MUST NOT 静默丢弃，也 MUST NOT 先执行再撤销。
- **FR-011**: 作用域与每次登记 MUST 支持可选标签，标签 MUST 出现在释放期错误的诊断信息中。
- **FR-012**: 作用域 MUST 暴露只读的状态（活跃 / 释放中 / 已释放），且该状态 MUST 与 FR-010 的判定一致。

#### B. 插件作用域契约

- **FR-013**: 插件安装入口 MUST 接收一个作用域；插件在安装期产生的全部副作用 MUST 通过它登记。
- **FR-014**: 宿主 MUST 为每个插件的**每一次**安装创建独立的子作用域；同一插件跨断连重连的两次安装 MUST NOT 共享作用域。
- **FR-015**: 契约 MUST NOT 要求插件保存作用域引用；作用域只经安装入口传递。
- **FR-016**: 停机时宿主 MUST 按插件注册的逆序、**串行**释放各插件作用域。
- **FR-017**: 既有的拆卸入口 MUST 变为可选并标注废弃；废弃周期内 MUST 仍被调用，且 MUST 在该插件作用域释放**之后**调用。
- **FR-018**: 契约变更 MUST NOT 破坏既有插件的编译与行为：既有的无参安装实现与既有的拆卸实现都 MUST 继续通过类型检查并按原语义运行。
- **FR-019**: 宿主 MUST 提供与仓库注册对称的反注册入口，并 MUST 按配置对象身份守卫——只撤销调用方自己登记的那一份。
- **FR-020**: 仓库注册入口的既有签名与链式返回值 MUST NOT 改变。
- **FR-021**: 停机后，插件在安装期对宿主所做的每一项登记 MUST 回到安装前状态，至少覆盖：实例属性注入、实体注册、事件监听、订阅与仓库注册。
- **FR-022**: 单个撤销动作抛错 MUST NOT 阻止同插件其余撤销与其他插件的释放；错误在宿主边界的处置方式（吞掉或传播）MUST 与本特性前保持一致。
- **FR-023**: 在宿主初始化之后注册的插件 MUST 同样获得独立作用域并参与后续释放。
- **FR-024**: 仓库内全部插件包 MUST 迁移到新契约；迁移后其手工副作用清单字段 MUST 被删除，MUST NOT 与作用域并存。
- **FR-025**: 迁移 MUST NOT 改变各插件的对外行为、公开签名与错误类型。
- **FR-026**: 图数据插件注册的仓库配置 MUST 在停机后不可查询——这是本特性修复的既有泄漏，MUST 有直接断言。

#### C. 依赖声明与按需装卸

- **FR-027**: 插件 MUST 能声明一组依赖；取值 MUST 是封闭集合（内置资源名与已安装插件名），MUST NOT 接受任意字符串键。
- **FR-028**: 依赖未全部就绪的插件 MUST NOT 被安装且 MUST NOT 产生作用域；该状态本身 MUST NOT 被视为错误。
- **FR-029**: 依赖全部就绪时，宿主 MUST 自动安装该插件并为其创建新作用域。
- **FR-030**: 连接流程 MUST 只等待已经开始的安装；依赖未满足的插件 MUST NOT 使连接流程挂起。
- **FR-031**: 任一依赖消失时，宿主 MUST 释放该插件的作用域，同时 MUST 保留插件注册本身。
- **FR-032**: 依赖重新就绪时 MUST 以全新作用域重新安装，且 MUST NOT 产生重复注册或重复监听。
- **FR-033**: 「依赖是否仍是同一个」MUST 按提供者的身份判定，MUST NOT 仅按名称或布尔就绪位判定。
- **FR-034**: 安装顺序 MUST 满足依赖拓扑序；释放顺序 MUST 为逆拓扑序，同层内再按 FR-016 的逆注册序。
- **FR-035**: 依赖成环 MUST 在安装规划阶段被检测，并以包含完整环路径的错误终止；MUST NOT 进入半安装状态。
- **FR-036**: 依赖永不满足时 MUST 产生一次列出缺失项的诊断提示，MUST NOT 静默跳过。
- **FR-037**: 按名字解析依赖时遇到多个同名候选 MUST 抛出列出全部候选的歧义错误；仅存在同名而无人依赖时 MUST 保持既有行为。
- **FR-038**: 延迟安装失败时 MUST 标记该插件失败并释放其作用域；同一依赖代次内 MUST NOT 自动重试，依赖代次变化后 MUST 重新尝试。

#### D. 横切约束

- **FR-039**: 全部新增公开导出 MUST 补齐 TSDoc 并登记进 API 基线。
- **FR-040**: 插件契约的成员签名变化 MUST 由编译期类型契约测试守护；导出表面基线只记录名称与种类，成员签名变化不产生差异，因此基线通过 MUST NOT 被当作契约未变的证据。
- **FR-041**: 该类型契约测试 MUST 能在签名被改坏时失败，并 MUST 在交付前以一次故意改坏的红测试证明。
- **FR-042**: 废弃成员 MUST 走仓库既定的废弃周期：至少保留一个次版本，移除时在迁移文档记录。
- **FR-043**: 公开文档 MUST 说明新契约写法、废弃成员的过渡期、依赖声明的语义，以及「不要在安装入口里自己等依赖」的指引。
- **FR-044**: 覆盖率 MUST 满足仓库既有的分层门槛（宿主核心包 90%，其余包 80%），本特性 MUST NOT 下调任何门槛。
- **FR-045**: 宿主对外生命周期方法的签名与可见语义 MUST NOT 改变。

### Key Entities

- **EffectScope（作用域）** — 一段代码的存活期。持有按登记顺序排列的撤销序列与零或多个子作用域，暴露只读状态（活跃 / 释放中 / 已释放）与可选标签。释放一次且仅一次生效。
- **Effect registration（副作用登记）** — 一次「做了某事 + 如何撤销」的成对记录：可选标签、撤销动作、是否已被撤销。登记既可同步也可异步产生。
- **EffectDisposer（撤销句柄）** — 撤销单次登记的入口；可提前单独调用，调用后该项从作用域的释放序列中出局。
- **PluginInstallation（插件安装实例）** — 一次安装的全部上下文：插件实例、本次的子作用域、依赖代次快照、失败标记。跨断连重连不复用，每次安装是一个新的实例。
- **PluginDependency（依赖项）** — 插件声明的封闭取值之一：内置资源名或已安装插件名。
- **DependencyEpoch（依赖代次）** — 依赖提供者的身份标识；用于判定「依赖是否换了一个」，不使用名称或布尔就绪位。
- **Plugin name index（插件名字索引）** — 名字到插件实例的映射；一个名字可对应多个候选，歧义只在该名字被依赖时才成为错误。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 原语的五类语义（逆序、幂等、异步、错误隔离、嵌套）各自有独立用例冻结，通过率 **100%**；重复释放导致撤销动作重复执行的次数为 **0**。
- **SC-002**: 在已释放或释放中的作用域上登记副作用时，抛出可判别错误的比例为 **100%**，静默丢弃次数为 **0**。
- **SC-003**: 连接 → 断开往返 **10** 次后，插件登记的事件监听器、订阅、实例属性与仓库注册的净增量均为 **0**。
- **SC-004**: 停机后图数据插件注册的仓库配置可查询次数为 **0**（本特性前为 1，即当前的既有泄漏）。
- **SC-005**: 四个插件包中残留的手工副作用清单字段（布尔标志、监听器数组、订阅表）数量为 **0**。
- **SC-006**: 未修改的既有插件实现在升级后的编译错误数为 **0**，可观察行为差异为 **0**。
- **SC-007**: 插件拆卸期单个撤销动作抛错时，同作用域内其余撤销动作的执行率为 **100%**，其他插件释放的完成率为 **100%**，宿主对外成败表现与本特性前的差异为 **0**。
- **SC-008**: 声明了本次不会就绪的依赖时，连接流程的挂起次数为 **0**；连接耗时相对本特性前的回归为 **0**。
- **SC-009**: 「两个资源均连接 → 只断开其中之一」场景中，依赖被断开资源的插件作用域释放率为 **100%**（本特性前为 0%），其余插件受影响数为 **0**。
- **SC-010**: 依赖成环场景在安装前被拒绝的比例为 **100%**，遗留半安装状态数为 **0**。
- **SC-011**: 故意破坏插件契约成员签名时，类型契约测试失败率为 **100%**；仅凭导出表面基线判定该变更「无差异」的情形被显式记录在文档中。
- **SC-012**: 全部受影响包的覆盖率达到既有分层门槛，零 ESLint 警告，`pnpm test-all` 通过。

## 范围边界

### 明确不做（非目标）

- 依赖注入容器与动态服务注册表；依赖取值扩大到任意字符串键
- 用代理追踪「谁在调用我」来推断作用域归属（归属一律靠显式传参）
- 长异步栈追踪（把释放期错误指回登记点的调用位置）
- 词法多实例隔离（作用域的**可见性**问题，与**存活期**正交）
- 宿主自身停机复位路径的收敛（本特性只改插件侧契约与内部记账）
- 三框架绑定挂接到同一原语
- 开发者工具中的作用域树可视化
- 改变插件拆卸错误在宿主边界的出口（吞掉 / 传播）
- 立即移除废弃的拆卸入口（本特性只让它变可选并进入废弃周期）
- 延迟安装失败后的定时退避重试

### 交付顺序（依赖约束）

固定顺序为 **US1 → US2 → US3**，不可交换：US2 的安装入口签名需要 US1 冻结的作用域类型；
US3 的「依赖消失时释放」以 US2 已把插件副作用全部收进作用域为前提，否则「释放」只能释放掉一半。
本特性不依赖任何未排期工作，也不阻塞既有 Epic。

## Assumptions

- **「用户」是使用本库的应用开发者与插件作者**，不含最终用户；本特性没有界面，也不改变任何面向最终用户的行为。
- **原语落在通用工具包**：它不依赖宿主的任何类型，而该包已经承载了带生命周期的工具（异步队列、领导者选举、广播通道池）。具体包内路径与文件布局在计划阶段冻结。
- **作用域是进程内概念**：不持久化、不跨实例、不跨标签页；它与既有的跨实例协调机制正交。
- **插件安装的并发模型不变**：本特性改变的是释放的顺序与串行性，不改变安装期的并发行为。
- **依赖的封闭取值当前只有内置资源名与已安装插件名**；扩大取值范围必须另起故事并说明理由。
- **按名字声明依赖需要先补名字索引**：插件名今天只出现在诊断文本中，从未被当作索引使用，因此索引与重名裁决是本特性的一部分而非既有能力。
- **类名之外的内部字段命名、文件布局与错误码文本在计划阶段冻结**，本规格只约束语义与不变量。
- **既有插件的兼容性结论必须由真实编译用例证明**，不能靠「给函数加形参、把必选成员改为可选对实现方无影响」这一推断代替（FR-018）。
- 覆盖率、TDD 红→绿顺序、零 ESLint 警告、TSDoc 齐全与跨框架对称等仓库级铁律默认适用，本规格不重述。
