## User Scenarios & Testing _(mandatory)_

### User Story 1 — 录制一段会话并可靠落库 (Priority: P1)

使用 `@aiao/rxdb` 的应用开发者在自己的应用里挂上录制插件，按需开始录制；用户操作界面期间，界面变化作为事件流写进一个独立的
录制库；开发者停止录制时，还在缓冲里的事件全部落库；之后可以按会话导出完整事件流。录制不碰被录应用自己的库，被录应用启用了
工作树时也不多出任何未提交条目。

**Why this priority**: 没有可靠落库的事件流，回放、commit 关联与上限都无从谈起；这是阶段 C 的最小可用切片。

**Independent Test**: 在测试库上挂插件 → 开始录制 → 制造一批界面变化 → 停止 → 导出，比对导出的事件条数、顺序与制造的变化一致；
再看被录应用库的工作树摘要，未提交条目数不变。

**Acceptance Scenarios**:

1. **Given** 插件已挂在应用库上并完成连接，**When** 开始录制、产生界面变化、停止录制，**Then** 停止返回之前缓冲里的事件全部
   落库，导出得到的事件按序号连续、与产生顺序一致（AC#10）。
2. **Given** 应用库断开连接（插件随连接纪元拆卸），**When** 拆卸完成，**Then** 录制已停止、缓冲已排空、录制库连接已释放，
   不留后台写入（AC#10）。
3. **Given** 录制中有高频交互（拖拽、连续输入），**When** 中途刷新页面，**Then** 同一标签页刷新后自动续录同一会话，按会话 + 时间
   范围查询得到的事件序号单调递增、没有缺号，刷新前已产生的事件都在（AC#11）。
4. **Given** 高频交互，**When** 观察写入方式，**Then** 事件按批写入，每批一个事务，不逐条写（AC#11）。
5. **Given** 被录应用库启用了工作树，**When** 录一段会话，**Then** 被录库的未提交条目数不因录制增长（AC#12）。

### User Story 2 — 回放一段会话并跳到任意时刻 (Priority: P1)

开发者打开回放组件，选中一段已入库的会话，可以播放、暂停、拖动时间轴跳到时刻 T；回放显示的是 T 时刻界面应有的样子。同一组件在
Angular / React / Vue 三个框架里同名、同输入、同事件、同行为。

**Why this priority**: 回放是把事件流变成「案发现场」的唯一出口；三框架 parity 是仓库铁律，单端缺失即未完成。

**Independent Test**: 用一段已知事件流（含时刻 T 才出现的节点与文本）喂给三个框架的回放组件，各自跳到 T，断言该节点与文本出现在
回放画面里，跳到 T 之前则不出现。

**Acceptance Scenarios**:

1. **Given** 某会话已入库，**When** 回放组件跳到时刻 T，**Then** T 时刻应在的节点与文本出现在回放画面中（AC#13；具体的 T 与断言
   节点由用例冻结）。
2. **Given** 会话 id 不存在或会话没有可回放的事件，**When** 打开回放组件，**Then** 组件显示空态说明，不报错、不白屏。
3. **Given** 读事件失败，**When** 打开回放组件，**Then** 组件显示错误态（可被读屏器播报），并给出原因。
4. **Given** 三个框架的宿主，**When** 以同样的输入使用回放组件，**Then** 输入、输出事件、状态与可访问性行为一致（AC#17）。

### User Story 3 — 回放时间轴上的 commit 与数据恢复 (Priority: P2)

被录应用启用了工作树，录制期间每次提交都在事件流里留一个带 commit 标识的标记；回放时间轴上能看到这些标记，选中一个就把应用数据
恢复到那个 commit 的内容（作为未提交变更写回工作树）；恢复被拒时给出可操作的提示。

**Why this priority**: 这是「看回放定位 → 恢复数据 → 活应用调试」闭环的数据侧；依赖 US1 的事件流与 US2 的时间轴。

**Independent Test**: 录制期间做两次提交，导出事件流，检查两条 commit 标记的 commit 标识与提交顺序一致；在时间轴选第一条恢复，
数据与该 commit 一致；分别制造四种拒绝，检查各自的提示。

**Acceptance Scenarios**:

1. **Given** 录制期间工作树产生多次提交，**When** 检查事件流，**Then** 每次提交恰好一条带该提交 commit 标识的标记事件，顺序与
   提交一致；标记来自真实的提交完成通知，不按时间戳事后反查（AC#14）。
2. **Given** 时间轴上选中某个 commit 标记、工作树是干净的，**When** 执行恢复，**Then** 恢复成功，应用数据与该 commit 一致（AC#14）。
3. **Given** 恢复被拒（`conflict` / `dirty_working_tree` / `incompatible_schema` / `unreachable_target`），**When** 执行恢复，
   **Then** 每种拒绝各给一条可操作的提示（例如「先提交或丢弃未提交改动」），不吞掉拒绝原因（AC#14）。
4. **Given** 提交在事务里回滚或 CAS 落败，**When** 检查事件流，**Then** 不出现对应的标记。

### User Story 4 — 体积上限与显式报告 (Priority: P2)

录制数据有上限：单个会话与整个录制库各有一个上限，按序列化后的事件字节计、都可配置。超限不静默丢事件、不无限增长，而是停下并
明确告诉开发者原因；空间只能由开发者显式删除会话来释放。

**Why this priority**: 没有上限的录制会把用户的浏览器存储吃满；AC#15 要求冻结数值与策略。

**Independent Test**: 把上限配成很小的值，注入超限事件量：单会话超限时会话被截断并留下终止标记；总量超限时开始新会话被拒；删除
一个会话后可以再开始。

**Acceptance Scenarios**:

1. **Given** 单会话上限（默认 16 MiB），**When** 一个会话的已落库事件字节加上下一批会超过它，**Then** 该会话停止录制，事件流末尾
   写一条终止标记事件，会话状态为 `truncated`、原因码 `session_limit`；开发者能从录制状态与会话信息里读到这个原因（AC#15）。
2. **Given** 总量上限（默认 128 MiB），**When** 录制库里全部会话的事件字节已达上限时开始新会话，**Then** 开始被拒，原因码
   `store_limit`，不建会话（AC#15）。
3. **Given** 录制中的会话，**When** 下一批写入会让全库总量超过总量上限，**Then** 该会话同样截断，终止标记与会话状态的原因码为
   `store_limit`。
4. **Given** 已达总量上限，**When** 开发者删除一个会话，**Then** 该会话的事件与字节计数一并移除，之后可以开始新会话。
5. **Given** 任何时候，**When** 上限触发，**Then** 系统从不自动删除任何会话或事件。

### User Story 5 — 敏感信息不进事件流 (Priority: P2)

开发者配置脱敏选项（遮盖全部输入、屏蔽指定区域等），录制含敏感输入的表单时，敏感值不出现在事件流里。

**Why this priority**: 录制会把用户输入写进本地存储，脱敏是隐私底线（AC#16）。

**Independent Test**: 打开「遮盖全部输入」并屏蔽一个区域，在输入框里键入已知字符串、在屏蔽区域里放已知文本，导出事件流后全文
搜索这两个字符串，都搜不到。

**Acceptance Scenarios**:

1. **Given** 配置了遮盖全部输入，**When** 录制期间在输入框键入已知值，**Then** 导出的事件流里不含该值（AC#16）。
2. **Given** 配置了屏蔽选择器，**When** 录制期间屏蔽区域里出现已知文本，**Then** 导出的事件流里不含该文本（AC#16）。
3. **Given** 录制选项里其他脱敏项，**When** 配置它们，**Then** 原样透传给录制器，插件不改写语义。

---

### User Story 6 — demo 的 opt-in 录制闭环 (Priority: P3)

`dev-rxdb-angular` 演示应用里有一个录制入口，默认关闭；打开后操作应用、停止，在回放页选中这段会话回放，并能在时间轴上的 commit
标记处恢复数据。

**Why this priority**: 演示是用户发现这个能力的地方（宪法 III），也是 AC#17 的闭环验收；依赖 US1～3。

**Independent Test**: 在 demo 里打开录制 → 新建并提交一条数据 → 停止 → 回放页选中会话 → 跳到提交之后 → 看到那条数据；不打开录制
时，录制库里不出现任何会话。

**Acceptance Scenarios**:

1. **Given** demo 刚启动，**When** 什么都不做，**Then** 不录制、不建录制库连接（opt-in，AC#17）。
2. **Given** 开发者在 demo 里打开录制，**When** 操作应用后停止并到回放页，**Then** 能选中这段会话并回放（AC#17）。
3. **Given** 回放页上的会话含 commit 标记，**When** 选中标记恢复，**Then** 结果按 US3 的规则显示成功或提示。

### Edge Cases

- 停止录制时录制库写入失败：停止以错误结束并报告原因，会话状态不伪装成「已停止」；已落库的事件保留。
- 刷新时缓冲里还有未落库事件：刷新前同步暂存到标签页级存储，刷新后续录前先落库，保证无缺号（US1 场景 3）；暂存本身失败时，
  续录后的第一个事件带「之前有缺口」的标记事件而不是假装连续。
- 关闭标签页而没有停止：会话保持 `recording` 状态留在库里，导出照常可用；不自动改成别的状态，也不自动删除。
- 同一个应用库在两个标签页里各开一段录制：两段会话互相独立、各自计数；总量上限对两者同时生效。
- 被录应用没有挂工作树插件：录制照常，事件流里没有 commit 标记，回放时间轴没有 commit 标记；恢复入口不出现。
- 提交通知的订阅者抛错：不影响提交本身的结果，也不影响其他订阅者。
- 回放组件在会话仍在录制时打开：回放截至打开那一刻已落库的事件。
- 上限配置非法（非正数、单会话上限大于总量上限）：创建插件时立刻报错，不按默认值继续。
- 录制在浏览器以外的运行时（无 DOM）启用：开始录制报明确错误，不静默空录。

## Requirements _(mandatory)_

### Functional Requirements

**录制与生命周期**

- **FR-001**: 插件 MUST 按应用库的连接纪元管理生命周期：连接后可用，断开时停止录制、排空缓冲、释放录制库连接；依赖就绪由宿主
  调度，插件自己不等待依赖。
- **FR-002**: 插件 MUST 提供开始录制、停止录制、查询录制状态（含当前会话与截断原因）、列出会话、按会话 + 时间范围读事件、导出
  会话、删除会话的入口。
- **FR-003**: 停止录制 MUST 在返回前把缓冲里的事件全部落库；落库失败 MUST 以错误结束并带原因。
- **FR-004**: 录制状态 MUST 可被订阅，状态变化（开始、停止、截断、出错）都有通知。

**存储**

- **FR-005**: 事件流 MUST 存在独立的录制库里，录制库由插件选项注入的工厂创建；被录应用库里不写任何录制数据。
- **FR-006**: 每个事件 MUST 是一条记录，带会话标识、会话内序号、事件类型、时间戳、事件内容；MUST 能按会话 + 时间戳范围高效
  查询（复合索引）。
- **FR-007**: 事件 MUST 按批落库，每批一个事务，不逐条写；批的触发条件（时间间隔与条数）由 plan 冻结。
- **FR-008**: 会话内序号 MUST 从 0 起连续递增；同一标签页刷新后自动续录同一会话，序号接着刷新前的最大值继续，不缺号、不重号。
- **FR-009**: 录制 MUST NOT 在被录应用库里产生任何工作树条目。

**体积上限**

- **FR-010**: 插件 MUST 支持单会话上限与总量上限两个可配置值，默认 16 MiB 与 128 MiB，按每个事件序列化后的字节数累计。
- **FR-011**: 写入一批会让会话超过单会话上限时，MUST 停止该会话录制、写一条终止标记事件、会话状态置为 `truncated`、原因码
  `session_limit`。
- **FR-012**: 全库已用字节达到总量上限时，开始新会话 MUST 被拒，原因码 `store_limit`；录制中的会话下一批写入会让总量超过上限时，
  MUST 按 FR-011 截断，原因码 `store_limit`。
- **FR-013**: 删除会话 MUST 移除该会话全部事件并从已用字节里扣除；系统 MUST NOT 自动删除任何会话或事件。
- **FR-014**: 上限配置非法时 MUST 在创建插件时报错。

**commit 关联**

- **FR-015**: 工作树门面 MUST 提供一个只读的「提交完成」通知，在提交事务成功提交之后发出 `{commitId, branchId}`；回滚、CAS 落败
  不发。通知的订阅者出错 MUST NOT 影响提交结果。
- **FR-016**: 录制中且被录应用挂了工作树插件时，插件 MUST 在每次提交完成通知到达时写一条带 `commitId` 与 `branchId` 的自定义标记
  事件，顺序与通知一致。
- **FR-017**: 插件 MUST 提供「恢复到某个 commit」的入口：取一次新鲜的工作树凭据后调用恢复；成功如实返回，四种拒绝各映射为一条
  可操作提示，原始拒绝原因一并返回。

**回放组件**

- **FR-018**: Angular / React / Vue 三个框架 MUST 各提供一个回放组件，输入（录制库来源、会话标识、初始时刻）、输出事件（时刻变化、
  选中 commit 标记）、命令（播放、暂停、跳到时刻）同名同语义。
- **FR-019**: 回放组件 MUST 定义加载、空、错误三态；控件（播放 / 暂停、时间轴、commit 标记）MUST 可键盘操作、有可读名称，错误态
  可被读屏器播报（WCAG 2.1 AA）。
- **FR-020**: 时间轴 MUST 显示会话里的 commit 标记；选中标记 MUST 触发 FR-017 的恢复并显示结果或提示。

**脱敏**

- **FR-021**: 插件 MUST 把录制器的脱敏选项（遮盖全部输入、遮盖文本选择器、屏蔽选择器等）原样透传；遮盖全部输入默认开启。

**demo**

- **FR-022**: `dev-rxdb-angular` MUST 提供默认关闭的录制开关与回放页；开关关闭时不建录制库连接、不加载录制代码。

**依赖与公开面**

- **FR-023**: 录制与回放依赖 MUST 钉精确版本，过仓库的依赖审计门禁，不新增 high 漏洞。
- **FR-024**: 新增的公开导出 MUST 带 TSDoc 并进 API 基线；工作树门面的新成员同样进基线。

### Key Entities

- **录制会话（Session）**：一次从开始到停止 / 截断的录制。属性：会话标识、开始时间、最后事件时间、状态（`recording` /
  `stopped` / `truncated`）、截断原因码（`session_limit` / `store_limit`，仅 `truncated` 时有）、事件数、已用字节、下一个序号。
- **录制事件（Event）**：事件流里的一条。属性：会话标识、序号、类型、时间戳、内容、序列化字节数。按会话 + 时间戳索引。
- **标记事件**：自定义类型的事件，两种：commit 标记（带 `commitId`、`branchId`）与终止标记（带原因码与触发时的上限）。
- **提交完成通知**：工作树门面发出的 `{commitId, branchId}`，只在事务提交之后发。
- **恢复结果**：成功（带 commit 标识）或拒绝（原始原因 + 可操作提示）。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 停止录制后，导出的事件数等于录制期间产生的事件数（缺失 0 条）；含一次刷新的录制序号缺号 0、重号 0。
- **SC-002**: 录制一段会话前后，被录应用库的未提交条目数差为 0。
- **SC-003**: 回放跳到时刻 T 后，用例冻结的断言节点与文本 100% 出现；三个框架的组件测试与 parity 用例全部通过、无单端缺失。
- **SC-004**: N 次提交在事件流里恰好对应 N 条 commit 标记，顺序一致；四种恢复拒绝各有一条不同的提示。
- **SC-005**: 注入超限事件量后，录制库总字节不超过总量上限加一批的大小；截断与拒绝都带原因码，0 次自动删除。
- **SC-006**: 脱敏用例里键入的已知值与屏蔽区域里的已知文本在导出事件流里命中 0 次。
- **SC-007**: 录制开启时，单批写入耗时中位数 < 100 ms（宪法默认的数据库操作预算）；录制关闭时 demo 首屏不加载录制代码。
- **SC-008**: 新包自身（不含钉版本的录制 / 回放依赖）构建产物 < 50 KB gz；AC#1～3 继续通过。

## Assumptions

- 录制库与被录应用库是两个独立的数据库实例；录制库的存储后端由应用通过工厂决定，demo 用主线程 IndexedDB、与应用库不同的库名。
- 「同一标签页刷新后续录」用标签页级存储记住活动会话与刷新瞬间未落库的缓冲；关闭标签页或新开标签页不续录。
- 总量上限对录制中会话的截断（FR-012 后半句）是对 owner「总量超限拒绝新会话」的补充：不加它，多个标签页同时录制时总量可以
  越过上限，与「不无限增长」矛盾。
- 恢复入口沿用工作树既有的恢复语义：恢复成未提交变更，HEAD 不动；跨分支的 commit 需要先切分支，属于 `unreachable_target`。
- 回放是录制界面的重新渲染，不重执行应用代码；非确定性问题不承诺复现。
- 事件流云端上报、多端同步、压缩采样与保留治理不在范围内（故事 Out of Scope）。
- 阶段 B（PR #82）先于本阶段合并；本阶段不改阶段 A / B 的交付物。
