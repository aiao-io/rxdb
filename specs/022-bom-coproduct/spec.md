# BOM 联产品与确定性联合成本分配

## 授权与交付边界

用户本轮要求“完成所有任务”，范围覆盖此前价值待证的 US-513 阶段 B。本切片将其补成可以实施和验收的合同；原来的待证记录不再作为重复请求用户授权的理由。

主会话采用显式固定份额的默认方案，不做按市场价格或净实现价值自动分配。字段、结果、来源映射与迁移边界已复核，核心、集成与共享种子已按真实红绿证据实施，完整演示24/24已通过；故事整体已随最终完整门禁通过关闭为Done。既有单主产物、副产品、废料、`consume`判环、默认API调用与三框架行为保持兼容。

## 已有模型如何扩展

头父件仍是第一主产物，BOM 头和父修订仍是生产过程及基准批量的锚点，不新增与现有头并行的“流程对象”。行发生项新增 `flowDirection = 'produce'` 表示第二及后续联产品。

| 数据                              | 合同                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| 头的 `jointCostShare`             | 可空规范十进制串；联合生产时显式表示第一主产物的固定成本份额；旧头默认 NULL            |
| produce 发生项的 `jointCostShare` | 该联产品的显式固定成本份额；其他方向恒为 NULL                                          |
| produce 的输出身份                | `childItemId` 与必填 `childRevisionId`，修订必须属于该物料且为已发布可用修订           |
| produce 的数量                    | 现有 `qty` / `uom`，`qty > 0`；一个基准批量下的合格联产品产出量                        |
| 联产来源选择                      | `CostRollupContext` 新增可选 `jointCostSources`：按已解析输出修订 ID 显式选择生产头 ID |

`jointCostShare` 取 `[0, 1]`，最多 9 位小数，保存和回读保持规范字符串，聚合使用十亿分之一的整数。主产物与所有当时有效的 produce 输出的份额合计必须精确为 `1`，不自动归一化。显式零份额允许，零输出量不允许。

同一头、同一时间切片、同一输出修订最多有一个 produce 输出；不改变 consume 行允许多重边的既有合同。produce 子件不得是头父件，同一主产物不能同时用隐式头父件与 produce 表达。

## 最小用量合同

令 `L` 为本次请求的合格第一主产物数量，单位为头 `baseUom`；`B = baseQty`。联产品行在一个基准批量下的产出为 `q`，则该批实际产出为 `q × L / B`，单位为行的 `uom`。

联产品按 **L** 缩放。装配、组件、工序损耗仍由现有数量 kernel 决定投入需求和加工量，不额外制造合格联产品。现有 by_product 继续按既有 `P'` 规则缩放，不能借本次改动反转旧语义。

首个交付只支持比例产出。produce 行不接受公式、固定批量、阶梯、组件损耗、工序分摊、phantom、位号管理、替代组成员或配置/序列/批次选择条件；日期有效期与 ECN 仍受支持。字段违约在保存时拒绝并点名字段，不静默忽略。需要其他联产用量语义时另补合同。

## 联合成本与稳定舍入

先用现有 kernel 核算整个生产批的净联合成本：材料 + 加工 + 制费 − 副产品抵减。废料不计不抵，联产品不是抵减项，联产品物料的 `creditPrice` 不参与计算。

设净联合成本为 `C`、输出份额为 `sᵢ`。先按第一主产物、再按 `lineNo / lineId / occurrenceId` 的完整稳定顺序排列输出；按 C 的数量级确定整批共同的34位十进制量子。除尾差接收者外，各正份额输出的 `C × sᵢ` 在该共同量子上 half-even 一次；稳定排序中最后一个正份额输出获得 `C − 其他输出已分配成本合计`。零份额输出始终为0且保留结果，不承接尾差。这样各输出金额最多34位有效数字且逐字精确相加为 C；C=0时全部为0。净成本若为负，沿用现有负成本语义，不另做截断。

共同量子保证整批金额一致，但小份额的相对精度可能低于逐输出独立保留34位。具体反例、量子定义及人工golden见 [research](research.md)，不允许以最后一项越过34位换取合计一致。

输出单位成本 = 该输出的分配批成本 / 该批输出量，34 位有效数字 half-even。单位成本乘回数量可以有规定的舍入误差，不能代替“分配批成本合计等于 C”的验收。

现有 `rollupCost` 根仍是选定生产头的第一主产物。联合生产时，`root.batchCost` 和 `root.unitCost` 分别表示第一主产物分配到的批成本与单位成本；新增可选 `root.jointCost` 明示完整过程净成本和全部输出分配明细。材料、加工、制费和抵减明细仍是过程原始明细，不能误标成已经按份额缩减的明细。

没有有效 produce 行的旧单主产物数据不进入分配模型；旧结果不凭空增加字段，原批成本、单位成本、明细与错误行为逐字保持。只声明 NULL 的新列也不会改变旧数据的计算。

## 下游显式取成本

联合生产输出不回写物料主数据的 `unitPrice`，也不生成第二份可变单价真相源。

下游消耗一个已解析联产品修订时，若存在有效 produce 来源，必须通过 `jointCostSources[outputRevisionId] = producerHeaderId` 显式选择。即使只有一个候选也不自动选择；缺少选择、多候选未裁决、选定头不产出该修订、选定头在当前日期/类型/组织不适用，均明确报成本未解析。原始外购物料与普通 BOM 的默认成本路径不变。

所选来源需要在同一成本读取快照中解析，使用该输出分配后的单位成本，并先把需求单位换算到输出计价单位。选择映射按修订区分，不能把 precise D 版和 imprecise E 版混为同一个成本来源。结果 manifest 记录所选头、输出逻辑行/发生项、修订、份额、产出量与单位。

本轮不新增“以联产品修订直接替代生产头作为 rollupCost 根”的重载。调用方从生产头卷算结果读取该联产品的输出明细；下游 consume 可以按显式选择消费该单位成本。

`produce` 不进入原有 consume 存储并集判环和 `bom_reach`。成本递归另以生产头身份检测派生依赖环：P 消耗 Q，Q 又消耗 P 的联产品时，成本计算明确拒绝，不能死锁、返回部分值或复用主数据价格逃避环。缓存身份包含联产来源选择，单次卷算对同一来源头复用过程计算，不重复计费。

## 草稿、发布与 ECN

单行字段、修订归属和数值域立即校验；草稿只允许份额合计、输出覆盖等跨行聚合暂不合法。发布头时按生效期切片校验，ECN 发布/改期/取消在转换后的运行投影上做同一组校验，不能借未发布 ECN 补齐份额。

已发布头的 `jointCostShare` 仍遵守现有头字段不可改协议。ECN 可以调整 produce 行，但每个运行切片必须与该固定主产物份额一起精确合计 1；改变第一主产物份额、将既有单产头改成联产头，需要新建父修订与头，不能增加 ECN 对已发布头字段的写入特权。联合生产头不可出现没有有效联产品且份额合计缺失的空切片。

## v2导出与已发布依赖

默认 `EXPORT_CONTRACT_VERSION` 仍为 `1`，旧单产导出的版本、列序、行宽和字段不变。含produce或显式联产份额的数据使用版本 `2`：头和发生项的位置数组在v1列尾追加 `jointCostShare`，其他表列保持。v1不得承载produce，避免份额静默丢失；未知版本明确拒绝。

v2将produce精确引用的输出主数据放入独立 `dependencies.items` / `dependencies.revisions`，列序分别沿用v1物料/修订列；它们不重复放进待新建的items/revisions。目标库必须已经存在自然键一致、修订属于该物料、已发布且单位身份一致的依赖。检查 `stockUom`、`uomDecimals`、`uomConversion` 及发布修订的有效日/defaultPhantom，不把来源库的历史批次号当作目标库必须拥有的审计记录。

`importBomDraft` 不自动发布任何主数据，不为v2调用历史装载旁路，不放宽C05。输出依赖缺失、未发布或不匹配时逐条给出依赖诊断，整批失败且不新增/修改依赖或草稿。空库不能直接接收完整联产v2；调用方先经正常API明确创建并发布合法输出依赖，再导入草稿并由用户明确发布生产修订与头。过去生效的输出依赖需要调用方在本契约之外走已有可信装载流程，不能借导入隐式追溯发布。

这个取舍保留即时存储不变量和“导入只建草稿”的边界，代价是v2联产载荷不是空库的一步发布包。原v1导入语义保持，所有既有重复键拒绝仍然生效，不为依赖做静默upsert。

## 既有库与保存回填

应用负责给头与发生项增加可空字符串列 `jointCostShare`，旧行保持NULL，并迁移发生项的enum CHECK使其允许produce。SQLite需通过保留全量数据/外键/索引/其他约束的表重建更改旧CHECK；PGlite更新对应CHECK。插件不自动替应用迁移表。表结构迁移后，连接时替换既有SQLite发生项/ECN触发器与PG函数；持久守卫升级测试只证明这个前置下的协议更新，不代表自动表迁移。

仓储对捕获的十进制patch规范化时，仅在实体字段仍等于捕获值时同步规范串。数据库更新结果推进origin，更新期间的新编辑、撤回原值/null及reset均保留为下一次保存的patch；不能仅用相对旧origin的空patch判定未编辑，不能用旧提交结果覆盖新输入或把新输入误标为已保存。更新尝试成功或失败后释放本轮句柄，同一patch对象重试须捕获新起点；普通查询不取得保存回填语义。
