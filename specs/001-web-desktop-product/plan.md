# Implementation Plan: 双交互模式 Web 桌面产品

**Branch**: `012-web-desktop-product` | **Date**: 2026-11-07 | **Spec**: [spec.md](spec.md)

## Summary

实现全部 42 条当前范围故事；用户 2026-11-07 的 `/goal` 授权进入完整实施。使用 React 桌面外壳、仓内 Orbit iframe 内核和独立内置 Web 应用；沿用原有三框架绑定与文档站入口。原子 AC 唯一来源为 `apps/web-desktop/requirements/stories/`。不把历史需求文档中的“本轮仅编写需求”理解为对当前实施授权的限制。

## Technical Context

- Language/Version: TypeScript 6 strict，Node 26，pnpm 12，Nx 24（沿用当前锁文件）。
- Primary Dependencies: React 19、Vite 8、`@aiao/orbit`；不新增运行时沙箱依赖。
- Storage: IndexedDB 数据库版本 1，物理 storageVersion=1 将 v5 元数据与每文件字节拆成独立记录，支持真实 200 MiB 批次；含 v1/v2/v3/v4 业务迁移、旧单条布局原子拆分及应用资源指纹，文件字节与元数据在同一事务提交；Web Locks 协调单一可写宿主，BroadcastChannel 协商接管。能力缺失时明确阻止启动，不伪造持久成功。
- Testing: Vitest 单元测试、Playwright 正式产物浏览器测试；Nx 统一执行。
- Target Platform: 桌面 Chrome / Edge（macOS、Windows）及 Safari（macOS）；实机与读屏证据单独记录，自动化引擎测试不能代替。
- Project Type: HTTPS 静态多页面应用，支持配置部署基址。
- Scale/Scope: 42 stories / 256 AC / 8 epics；本地单人，无账号、公开市场或云服务。
- Performance: SC-004/005 冷启动 p95 ≤3s、热打开 ≤1s、20 个真实实例下 100 次交互 p95 ≤100ms；首绘 <1.5s，文件事务 <100ms，纯查询 <16ms；Orbit gzip <50KB。标准采样与正式基准设备以验收台账为准。

## Complexity Tracking

无需架构豁免。IndexedDB + Web Locks + BroadcastChannel 分别承担原子存储、排他拥有权和可取消接管协商，职责不互相替代。React 只用于外壳和独立应用 UI，Orbit 内核不引入 React。

## 预取与后台资源实施

US-307 使用独立调度、引用和挂起状态机，不在窗口状态中混入后台状态。宿主空闲 500ms 后只预取静态包，Worker 协议 2 统一限制并发 2、去重与前台抢占。资源清理串行，并保留持久安装 / 回退、实例、临时持有、任务和活 iframe 引用；文件数据库不参与清理。协作挂起先检查脏状态，再由声明协议的应用确认；恢复保留同实例内存与路由。自动化结果按逐 AC 台账登记，完整环境和发布验收不由单一 Chromium 结果替代。

## 实例导航实施

US-305 / US-501 在桌面 SDK 层维护每实例逻辑路由与内存历史，沿用 Orbit RPC 和 v3 会话 route 字段，不修改公共 Orbit API。完整 path/query/hash 在实例快照保存，顶层 URL 保持独立；凭据字段和跨来源位置明确拒绝。AppSession 统一处理宿主导航及位置同步，具体视图登记路由处理器并恢复目录、页面、文档与行号。导航期间阻止挂起，错误不推进历史，失败窗口重试保留完整布局。自动化旅程直接检查 IndexedDB 中的路由快照，再刷新验证真实恢复。

会话 v5 保存稳定窗口 ID、最小化前状态和最大化前的贴靠状态；所有刷新、重试与版本切换采用同一 SavedWindow 结构，恢复时按新视口重建几何。v1/v2/v3/v4 升级在原有单次写事务中完成，损坏输入回滚并保留原始字节。

受损数据启动失败与一般启动失败分开：只有读取校验错误开放两次确认的显式重置，原始记录保留到最终提交，写入期间丢失拥有权则回滚。重开会话说明未保存内容的恢复边界；布局保存异常说明影响范围，原有文件字节保持其独立事务承诺。

未安装应用在同步启动时失败，独立记录为恢复待办。稳定窗口 ID 区分内容完全相同的快照，刷新与显式重试保留该 ID；布局持久化在事务内合并仍待恢复的快照，避免其他窗口保存和工作区迁移丢项。用户可从应用目录确认安装后重试，或只移除对应快照。

备份恢复和全量重置使用同一会话替换流程：关闭协商提交前保存旧快照，替换期间暂停布局写入，原子事务完成后重新加载桌面，避免旧调用实例污染新会话。失败重新读取持久状态并显示结果；选择损坏文件立即清空此前待恢复的备份。只重置配置仍保留原实例。

US-601 / US-401 的文件授权提示使用 `permission-labels.ts` 显示中文能力名称、文件/目录种类及完整虚拟路径，明确本次运行和持久授权的有效期；权限记录和 RPC 继续使用不透明文件 ID、批准来源及实例绑定。提示生成信任已验证目录树，缺失记录直接报错。拒绝后的新实例不读取正文，原已授权实例保持可用。

设置的权限页复用授权说明模块，使用按需派生的 `GrantView` 显示应用、中文能力与文件范围。显示层保留对回收或永久删除范围的撤销入口，不把无效目标当成新授权的合法范围；原判权仍使用批准来源、appId、instanceId 与不透明 scope。

## 三框架同任务样例

桌面目录增加可选安装的 `sample-angular`、`sample-react`、`sample-vue`，共用同一版本化发布与授权入口，默认不安装。三端分别由 Angular、React、Vue 实际渲染，业务共用 `src/samples/document.ts` 的文档控制器、已有 `EditorDocument` 和 `AppSession`，不复制三份持久化、路由或关闭逻辑。

同任务为中文文本编辑、撤销重做、保存到“我的文件”、浏览器下载及文档位置导航。全部桌面能力走已有服务入口；可选剪贴板拒绝不能阻断编辑和文件保存。未保存内容、关闭保存/放弃、窗口命令和协作挂起共用当前文档状态。独立打开时仍可编辑与下载，明确显示桌面文件、剪贴板和窗口能力不可用。

入口在框架完成真实首次渲染后才报告 ready。销毁统一移除文档级事件、导航和服务处理器，随后卸载框架；启动中的晚到挂载结果立即卸载。三端通过正式资源包固定到 appId/version，继续校验 HTML 发布标记，不引入外部运行时或 CDN。

Angular 样例先保留 JIT 与按需加载，正式构建定义生产模式以裁剪开发检查；编译器按独立块输出。当前编译器单块仍略高于默认 500 kB 提示，明确登记体积，不提高阈值或据此声称性能预算达标。
