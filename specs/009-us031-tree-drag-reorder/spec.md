## User Scenarios & Testing _(mandatory)_

### User Story 1 — 菜单拖放的结果确定、刷新不变、三端一致 (Priority: P1)

在三端树菜单（全量、虚拟滚动、懒加载各一页）里拖动一个节点：放到两个兄弟之间就落在它们之间；放到组首或组尾就成为组首或组尾；
拖到另一个父节点的两个子节点之间就改挂过去并落在那两个子节点之间；拖进一个节点就成为它的最后一个子节点——不论这个节点是否展开、
它的子节点是否已经加载。刷新页面后顺序与拖放后一致，同一串操作在三端得到同一个顺序。

**Why this priority**: 拖放是树页面上最频繁的排序操作；「拖进未展开的懒加载节点与首个子节点撞键」已复现（故事缺陷三），
Angular 与 Vue 的四个懒加载页都有；三端的拖放算法各自一份、行为已经分叉（故事「三端已经分叉」）。

**Independent Test**: 在任一端菜单懒加载页，折叠一个已有子节点 c1、c2 的节点 P，把另一个节点 X 拖进 P，展开 P 后顺序为 c1、c2、X，
刷新后不变。

**Acceptance Scenarios**:

1. **Given** 同父下依次有 A、B、C、D，**When** 把 D 拖到 A 与 B 之间、刷新页面，**Then** 顺序为 A、D、B、C（AC#5）。
2. **Given** 同上，**When** 把 C 拖到组首（A 之前）或把 A 拖到组尾（D 之后），**Then** C 成为组首 / A 成为组尾，其余兄弟相对顺序不变（AC#5）。
3. **Given** P 下有 p1、p2，Q 下有 q1、q2，**When** 把 p1 拖到 q1 与 q2 之间，**Then** p1 的父节点变为 Q、位于 q1 与 q2 之间，P 下只剩 p2，
   改挂与定位在一次提交内完成（AC#5）。
4. **Given** 节点 P 已展开、有子节点，**When** 把 X 拖进 P，**Then** X 成为 P 的最后一个子节点（AC#5）。
5. **Given** 懒加载页节点 P 折叠、子节点未加载，**When** 把 X 拖进 P 后展开 P，**Then** X 排在 P 既有子节点之后，与它们互不同键（AC#5，缺陷三回归）。
6. **Given** 任一节点，**When** 拖到它自己或它的后代上（前、后、内部都算），**Then** 拖放被拒，库里零写入，界面不变（AC#5）。
7. **Given** 任一节点，**When** 原位放下（放回它当前位置的前后，或拖进它当前的父节点且它已是最后一个子节点），**Then** 库里零写入（AC#5）。
8. **Given** 完成了一次拖放，**When** 点一次撤销，**Then** 恢复拖放前的父节点与顺序（AC#5）。
9. **Given** 同一串操作，**When** 分别在 Angular、React、Vue 上执行，**Then** 三端结果一致（AC#5）。

### User Story 2 — 文件管理器在两种排序模式下的拖放规则一致 (Priority: P1)

文件管理器有「手动排序」与按名称 / 类型 / 扩展名 / 大小排序的非手动模式。手动模式下拖放与菜单相同，只是文件不能作为拖入目标。
非手动模式下页面显示的不是手动顺序，前后放置没有意义，只保留「换父节点」：拖进文件夹追加到它的末尾；把子级节点拖到某个根级节点的上方或下方，
等于把它移到根级、追加到根组末尾；同级节点之间的上方 / 下方放置被拒绝。三端规则相同。

**Why this priority**: Angular 的非手动模式规则在执行时没有生效（执行拖放时没传排序模式，根级分支走不到）；React / Vue 完全不区分模式，
非手动模式下前后放置会改写手动顺序但界面看不出变化。

**Independent Test**: 把文件管理器切到「按名称」排序，把文件夹 F 下的文件 x 拖到某个根级节点下方，切回手动排序，x 位于根级最后。

**Acceptance Scenarios**:

1. **Given** 手动排序模式，**When** 做 User Story 1 的全部拖放（文件不作为拖入目标），**Then** 结果同 User Story 1（AC#6）。
2. **Given** 手动排序模式，**When** 把节点拖到一个文件上、选择「拖入」，**Then** 拖放被拒、零写（AC#6）。
3. **Given** 非手动模式，**When** 把节点拖进文件夹 F，**Then** 节点成为 F 在手动顺序里的最后一个子节点（AC#6）。
4. **Given** 非手动模式、节点 x 在某文件夹下，**When** 把 x 拖到某个根级节点上方或下方，**Then** x 移到根级、在手动顺序里位于根组末尾（AC#6）。
5. **Given** 非手动模式，**When** 在同一父节点下的两个节点之间做上方 / 下方放置，**Then** 拖放被拒、零写（AC#6）。
6. **Given** 非手动模式下改过父节点，**When** 切回手动模式，**Then** 看到的手动顺序就是库里的顺序（AC#6、AC#8）。

### User Story 3 — 拖放失败时看得见、界面停在库里的真实顺序 (Priority: P1)

拖放被拒或提交失败时（例如邻居已被别处删掉、目标已被移走、被拖节点已不存在），库里零写入，页面在页内展示一条错误，
界面显示库里最新已提交的顺序，下一次拖放照常可用。三端用同一处提示、同一组文案。

**Why this priority**: 现在 Angular / React 用阻塞式弹窗、Vue 用浮层通知，Vue 的部分失败被静默吞掉、拖放状态不复位；
阶段 A 已把拖放以外的写入失败统一到页内提示，拖放是最后一处（阶段 A FR-008 明确留给阶段 B）。

**Independent Test**: 在两个标签页打开同一个菜单页，一个标签页删掉节点 B，另一个标签页把 X 拖到 A 与 B 之间：页内出现错误提示，
库里无变化，再把 X 拖到别处成功。

**Acceptance Scenarios**:

1. **Given** 拖放目标在拖动期间已失效（邻居被删或已不相邻、被拖节点已删除），**When** 放下，**Then** 零写，页内出现错误提示，
   界面停在库里的顺序（AC#7）。
2. **Given** 出现过一次拖放错误，**When** 再做一次合法拖放，**Then** 成功，错误提示可关闭或被下一次结果替换（AC#7）。
3. **Given** 拖放失败，**When** 检查页面，**Then** 没有阻塞式弹窗、没有未处理的失败，拖拽中的高亮与状态已复位（AC#7）。
4. **Given** 同一失败，**When** 分别在三端触发，**Then** 三端提示位置、结构与文案一致（AC#7）。

### User Story 4 — 手动顺序只有一个来源 (Priority: P2)

六个树页面在手动排序模式下显示的兄弟顺序就是库里的顺序：页面不再自己按排序键排序，也不再为显示额外指定排序键排序；
拖放之后与刷新之后读到的顺序相同。React 文件管理器手动模式现在会把文件夹排在文件前面，改为与另两端相同的纯手动顺序。
demo 里再也没有自己算排序键、比较排序键、整组重编号的代码。

**Why this priority**: 键的比较器副本散在 15 个文件里（故事「病灶在结构上」），任何一份与引擎的排序规则不一致，界面顺序就会与库里不同；
但只要拖放与创建都已交给引擎，现有副本的比较结果与库里一致，所以这是收尾，排在 P2。

**Independent Test**: 跑故事 AC#9 的两条检索都无输出；React 文件管理器手动模式下根级依次新建文件夹 A、文件 X、文件夹 B，显示为 A、X、B。

**Acceptance Scenarios**:

1. **Given** 三端六页手动排序模式，**When** 浏览全量、虚拟滚动与懒加载树，拖放后与刷新后各读一次顺序，**Then** 两次一致，且与库里的顺序一致（AC#8）。
2. **Given** React 文件管理器手动模式、根级有交替新建的文件夹与文件，**When** 查看根级，**Then** 按手动顺序显示，不再文件夹优先（AC#8）。
3. **Given** 三端 demo 源码，**When** 跑故事 AC#9 的两条检索，**Then** 都无输出；被删代码的单元测试随之删改（AC#9）。

### Edge Cases

- **拖进当前父节点**：节点已在 P 下、但不是最后一个子节点时，拖进 P 会把它移到 P 的末尾（「拖进一律追加到末尾」）；已是最后一个时零写。
  这改变了 React 现在「拖进当前父节点一律不动」的行为。
- **组首 / 组尾**：放到组首时只有后邻居、放到组尾时只有前邻居；组里只剩被拖节点自己时（例如拖到唯一兄弟的前面）属于原位放下。
- **根组**：根节点（无父节点）是一组；拖到某个根节点上方 / 下方即在根组内定位。没有「空白处」放置区，不新增。
- **虚拟滚动与搜索过滤**：被拖节点或邻居不在可视窗口内、或被搜索过滤隐藏时，邻居仍取自该组的完整序列（FR-002）；
  搜索中把 X 放到可见的 A 之后，X 落在 A 与它在完整序列里的下一个兄弟之间。
- **懒加载页的邻居**：目标可见即它所在的组已整组加载（展开时按父节点取全部子节点，不分页），邻居取自这一组；拖进折叠节点不读它的子节点。
- **并发移动下的环**：环检测在提交之前、按页面已知的祖先链判断；拖动期间另一处把目标移进被拖节点的子树，可能放过环（故事技术笔记，推断未复现），
  写入期的环检测不在本故事。
- **撤销粒度**：一次拖放（含跨父改挂）是一次提交，撤销一次恢复一次拖放；被拒的拖放不产生历史项。Angular 现在算键失败后的整组重编号会产生 N 条历史，随之消失。
- **非手动模式的显示**：非手动模式下按名称 / 类型 / 扩展名 / 大小排序的比较器保留，不在本阶段（故事 Out of Scope）。
- **数据已脏**：排序键损坏的锚点会被引擎拒绝；新实体只经引擎写入，正常不会出现，出现时按 User Story 3 展示错误。
- **实体模型页**：新实体在 demo 通用实体浏览页里的手动排序由 US-028 阶段 B 的界面负责，本阶段不另加验收。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 三端六页的拖放 MUST 把「目标位置」交给引擎的重排写入，由引擎在一次提交内读邻居、定位并写入；页面 MUST NOT 自己算排序键，
  MUST NOT 自己写排序键或分组字段来完成拖放。
- **FR-002**: 拖到某节点上方 / 下方时，页面交给引擎的邻居 MUST 取自目标所在组的**完整**手动序列（含被搜索过滤隐藏、不在虚拟滚动窗口内的兄弟）
  去掉被拖节点之后、目标两侧的兄弟；落点在组首 / 组尾时缺的一侧为空。只取页面上可见的兄弟会把被隐藏的兄弟夹在两个邻居之间，被引擎判为不相邻而拒绝。
- **FR-003**: 拖进某节点时，页面 MUST 以「追加到该节点子节点组的末尾」交给引擎，MUST NOT 读取或依赖该节点已加载的子节点；
  React 为此补的兄弟读取 MUST 删除。
- **FR-004**: 拖到自己或后代上的拖放 MUST 在提交前被拒绝、零写；三端 MUST 对前、后、内部三种落点都做这一判断。
- **FR-005**: 原位放下 MUST 零写、不产生历史项；判断以「落点就是节点当前位置」为准，三端一致。
- **FR-006**: 文件管理器 MUST 按当前排序模式决定可用的落点：手动模式同 FR-001～FR-005，文件不作为拖入目标；非手动模式只允许
  「拖进文件夹（追加到末尾）」与「把非根级节点拖到根级节点上方 / 下方（追加到根组末尾）」，同父节点之间的上方 / 下方放置 MUST 被拒、零写。
  三端 MUST 使用同一组规则；拖动中的落点高亮 MUST 与放下后的结果一致（被拒的落点高亮为无效）。
- **FR-007**: 拖放被拒或提交失败时 MUST 零写，页面 MUST 在阶段 A 已有的页内错误提示里展示错误、复位拖拽状态、保持库里最新已提交的顺序，
  下一次拖放可用；MUST NOT 使用阻塞式弹窗或浮层通知代替，MUST NOT 吞掉失败；三端 MUST 使用同一组提示文案。
- **FR-008**: 三端六页在手动排序模式下的兄弟顺序 MUST 取自查询的默认排序；页面查询 MUST NOT 再显式按排序键排序，页面 MUST NOT 再按排序键排序节点；
  React 与 Vue 懒加载文件管理器的「文件夹优先」预排序 MUST NOT 参与手动模式的显示顺序。
- **FR-009**: demo 源码中 MUST NOT 再有自算排序键、排序键比较器、整组重编号与「算键失败」路径；故事 AC#9 的两条检索 MUST 无输出，
  被删代码的单元测试 MUST 随之删除或改写。
- **FR-010**: 一次拖放 MUST 是一次提交，撤销一次 MUST 恢复拖放前的父节点与顺序。
- **FR-011**: 三端 MUST 以 Playwright 真实拖拽（鼠标按下、移动、松开）覆盖 User Story 1～3 的验收场景：操作后刷新页面读回顺序；
  缺陷三 MUST 有一条三端都跑、不修即红的回归用例；三端同一场景的用例同名。
- **FR-012**: 三端单元测试 MUST 断言页面交给引擎的重排目标（邻居或追加到组尾），以及环、原位、非手动模式被拒时不调用引擎写入。

### Accessibility

本阶段不新增交互控件，拖放沿用现有的拖拽手柄与落点高亮。拖放失败复用阶段 A 的页内错误提示（`role="alert"`、可关闭、键盘可用），
三端同一结构；不破坏现有树页面的键盘操作，三端 a11y 现状不得退化。拖放的键盘替代操作不在本故事范围。

### Key Entities

- **排序域**：同一父节点下的全部子节点构成一条序列，根节点是一组；拖放只改被拖节点的父节点与它在新组里的位置。
- **重排目标**：二选一——「落在前邻居与后邻居之间」（一侧可以为空，不能两侧都空），或「追加到某组末尾」（组由父节点确定，根组的父节点为空）。
- **排序模式**（文件管理器）：手动，或按名称 / 类型 / 扩展名 / 大小的升降序；只有手动模式显示库里的顺序。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 缺陷三（拖进未展开的懒加载节点撞键）的回归用例在三端的菜单与文件管理器懒加载页全部通过，回滚修复后会失败。
- **SC-002**: 三端六页的同父重排、组首 / 组尾、跨父定位、拖进节点四类拖放，拖放后与刷新后的顺序 100% 一致，三端对同一操作序列给出相同顺序。
- **SC-003**: 环、原位、非手动模式同级前后放置三类被拒操作，库里零写入、不产生历史项，三端一致。
- **SC-004**: 一次拖放从松开鼠标到界面显示新顺序在 1 秒内完成（demo 最大档位 10,000 节点的虚拟滚动页同样适用）。
- **SC-005**: 故事 AC#9 的两条检索在三端 demo 源码中无输出。
- **SC-006**: 三端拖放失败均不出现阻塞式弹窗，100% 的失败都在页内提示中可见。

## Assumptions

- US-028 阶段 A + D 已交付的重排写入（邻居之间、追加到组尾、跨组移动、原位零写、邻居失效与目标失效的拒绝）可直接使用；它们的语义正确性由
  US-028 的跨适配器契约套件保证，本阶段只验收 demo 交给引擎的目标是否正确。
- 阶段 A 的四个可排序树实体、页内错误提示组件与三端 e2e 夹具已就位（`specs/008-us031-sortable-tree-entities/`）。
- 文件管理器非手动模式的规则沿用 Angular 现状（故事 AC#6），React / Vue 向它对齐；非手动模式的显示比较器不动。
- 环检测沿用 demo 的祖先链判断（故事技术笔记），写入期环检测不在本故事。
- 阶段 B 与阶段 A 同一分支、同一 PR（owner 2026-10-08 定），故事「一阶段一 PR」一句随本阶段更新。
