# Contract: 三端 demo 树页面的创建类写入

范围：Angular / React / Vue 三个 demo 的树菜单（simple / virtual / lazy）与文件管理器（simple / virtual / lazy）六页。
拖放不在本契约（阶段 B）。三端 MUST 逐条满足，行为差异即缺陷。

## 页面与实体

| 页面         | 实体                 | 接线方式（沿用现状）                                          |
| ------------ | -------------------- | ------------------------------------------------------------- |
| 菜单 simple  | `SortableMenuSimple` | Angular 页面直接传类；React / Vue store 直接导入              |
| 菜单 virtual | `SortableMenuLarge`  | 同上                                                          |
| 菜单 lazy    | `SortableMenuLarge`  | Angular 经 `ENTITY_CLASS` 注入令牌；React / Vue 直接导入      |
| 文件 simple  | `SortableFileNode`   | 同菜单 simple                                                 |
| 文件 virtual | `SortableFileNode`   | 同上                                                          |
| 文件 lazy    | `SortableFileLarge`  | Angular 经 `FILE_ENTITY_CLASS` 注入令牌；React / Vue 直接导入 |

查询沿用现有的显式 `orderBy: [{ field: 'sortOrder', sort: 'asc' }]`（显示顺序改造属阶段 B）。

## 写入形状

| 操作              | 页面写入                                                                                                                                                      | 禁止                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 新建根 / 子节点   | 新实例只赋业务字段与 `parentId`（或 `parent$.set()`），一次保存                                                                                               | 赋 `sortOrder`；读兄弟取尾键；`catch` 后改用首键                      |
| 新建文件 / 文件夹 | 同上；文件与文件夹同属父节点下一组                                                                                                                            | 只在文件夹里取锚点                                                    |
| 批量添加          | 生成器不写 `sortOrder`（不写空串、不写 null 以外的值）；整批一次 `entityManager.saveMany`                                                                     | 逐条 `save()`（React 懒加载菜单现状）；以页面已加载的根节点作锚点     |
| 删除并提升子节点  | 从库里按父节点取直接子节点，只改 `parentId`；一次 `entityManager.mutations(getEntityMutations({ needSaveEntities: 子节点, needRemoveEntities: [被删节点] }))` | 只取已加载的子节点；逐条或 `Promise.all` 保存；给子节点赋 `sortOrder` |
| 是否弹删除对话框  | 以库里的直接子节点为准（按 `parentId` 查询），不看页面已加载的节点                                                                                            | 懒加载页按已加载节点判断                                              |

## 失败

除拖放外的写入（新建、重命名、批量添加、删除、级联删除、删除并提升子节点）失败时：

- 页内提示：`div.alert.alert-error`，`role="alert"`，`data-testid="tree-write-error"`，带可键盘操作的关闭按钮；
  文案「<操作>失败：<错误消息>」，操作名固定为「新建」「重命名」「批量添加」「删除」「级联删除」「删除并提升子节点」。
- 不吞错、不只打 console、不用 `window.alert`、不留未处理的拒绝；失败后页面状态即库里已提交的状态，下一次操作可用。
- 批量添加期间的「加载中 / 按钮禁用」沿用现有行为（三端 e2e 已有断言）。

## 验收

| 层级                                       | 用例                                                                                                                                                                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 单测（三端，各 store / hook / composable） | 新建、批量写入里没有 `sortOrder`；批量是一次 `saveMany`；删除提升是一次 `mutations`，子节点取自库；懒加载页折叠节点删除时弹对话框；写入失败时错误状态被设置、无未处理拒绝                                                                         |
| 回归                                       | 缺陷一（根级文件夹 / 文件交替新建）与缺陷二（删除提升）各一条，不修即红                                                                                                                                                                           |
| e2e（三端）                                | 根级依次新建文件夹 A、文件 X、文件夹 B，刷新后顺序为 A、X、B；在折叠、子节点未加载的节点下新建子节点，展开后在末尾；批量添加 100 条后刷新，原有节点在前、新节点按生成顺序在后；删除提升后刷新，子节点在祖父组末尾；懒加载页删除折叠节点弹出对话框 |

失败分支只在单测里验：本地库写入无法从 Playwright 拦截，页面的路径冲突预检又挡在唯一索引之前，e2e 没有确定性的失败注入点。页内提示的结构（`role="alert"`、关闭按钮、`data-testid`）由三端的组件或页面单测断言。
