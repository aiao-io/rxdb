## User Scenarios & Testing

### US0 路线停用后的明确拒绝（Priority: P0）

工艺工程师按明确评估日查看工序归属。已停用路线不能继续参与数量或成本计算，也不能被当作没有工序而静默忽略。

**Independent Test**: 同一发生项挂路线 R 的工序 20；在停用日前、停用日当天与之后执行真实解析消费。停用前正确归属工序 20；当天与之后报未覆盖，错误点名路线与发生项。SQLite/PGlite 使用相同断言。

**Acceptance Scenarios**:

1. 路线在评估日有效时，已挂接的工序和分摊按既有数量语义计算。
2. 路线有效域为 `validFrom <= asOfDate`，且 `disabledAt` 为空或 `asOfDate < disabledAt`；停用日当天起不再有效。
3. 指定工序或分摊引用失效路线时，数量、成本与导出明确拒绝，保留可定位的未覆盖原因；不把该行当作无工序计算。

### US1 结果随数据与上下文更新（Priority: P1）

应用开发者订阅一份 BOM 视图。新数据从不可见变为可见、评估日改变或被引用的物料信息变化后，视图自动反映当前输入对应的结构。

**Independent Test**: 先验证依赖注册通道，再在同一 fixture 上测试 ECN 发布、日期推进、imprecise 新修订、phantom 默认值与换算率变化。每个变化均须使三个框架得到相同的新结果（US-522 AC#6～#9）。

**Acceptance Scenarios**:

1. 原结果不包含的新行挂在 draft ECN 下时不可见；发布该 ECN 后自动出现，不能依赖新行曾进入旧结果。
2. 只推进显式评估日，也会使新生效行出现，不读取系统时钟决定结果。
3. imprecise 子件发布新修订后，自动更新到新修订对应的结构。
4. 发布 phantom 默认值不同的新修订，或修改物料换算率后，结构与数量同步更新。
5. 更换输入后，旧请求的迟到结果不覆盖新输入；离开页面或销毁绑定后停止订阅，重新进入可恢复正确结果。

### US2 按路径浏览与未解析展示（Priority: P1）

用户在树中查看层级、需求量、重复物料与共享子装配。每条路径独立展开；预算限制和未解析候选始终可见。

**Independent Test**: 三端用相同 fixture 渲染三重边、共享子装配、截断与三类未解析候选；发布改量 ECN 前保存节点的真实 DOM 引用，之后验证不受影响的路径仍复用原元素（US-522 AC#2/#4/#5/#10/#12）。

**Acceptance Scenarios**:

1. 同一物料三行独立展示与定位；同一子装配两条路径的展开状态互不影响。
2. 节点身份是发生项 ID 序列构成的完整路径。ECN 用新发生项替换旧发生项后，受影响路径及其数量变化；其余已渲染路径的 DOM 元素引用保持相同。
3. 首次展开某路径时才呈现其后代；折叠支路不预先挂载全部后代 DOM。允许共享计算层保守重算，不要求先实现最小重算集合。
4. 深度或数量预算触顶时，显示截断原因，不把部分结果当作完整结果。
5. 备选未定、manual 替代未选、序列/批次候选未定均保留候选与未解析标记。浏览可以继续，数量、成本及导出必须拒绝该未解析输入。
6. 后台刷新时保留既有树节点，显示刷新状态，不因切换加载态销毁整棵树。

### US3 在合法写入边界内编辑（Priority: P1）

用户编辑用量、组件损耗、工序和生效期，得到与领域内核相同的校验结果。已发布发生项不会被界面原地改写。

**Independent Test**: 三端对同一草稿发生项分别保存四种编辑；插入成环行时比较同一错误的 `code`、`payload`、`message`。另验证已发布既有发生项只读，draft ECN 新发生项可在既有协议内编辑（US-522 AC#3/#11）。

**Acceptance Scenarios**:

1. 草稿头的发生项可以直接编辑，四类字段保存后按对应 kernel 语义生效；草稿头仍不进入已发布结构解析。
2. draft ECN 下新发生项按 US-515 协议编辑；已发布既有发生项只读。界面不自动创建、发布、取消 ECN，也不自动把原地修改转换成新发生项。
3. 三端从同一个 kernel 接收相同错误合同，框架层不重新拼装业务消息。
4. 前置能力未交付的编辑字段不出现在任一框架；本轮工序编辑在 US0 的前置缺口修复后验收。

### US4 可复用的三端交付（Priority: P1）

Angular、React、Vue 应用使用同名绑定和组件，获得相同功能、状态与视觉语义，不必复制领域逻辑。

**Independent Test**: 三端以显式数据库和相同视图输入调用 `useBomView`，消费 `BomTree` / `BomLineEditor`。完整 AC#2～#12 每条三端各跑一次，同一共享 fixture 与同一断言；单端缺失不关闭 US-522（AC#1）。

**Acceptance Scenarios**:

1. 三端函数名称、参数和 `state/commands` 的业务字段及行为相同；仅框架容器形式允许 signal/ref/plain 的惯用差异。
2. 初始加载、空结果、数据与错误四种状态都有明确呈现；加载/保存时有禁用和进度，刷新有可感知状态。
3. 三端视觉规则一致，表单有标签，树支持键盘展开/折叠与焦点管理，截断、未解析和错误可被辅助技术读取，满足 WCAG 2.1 AA。
4. 示例、README 与公共 API 文档覆盖三端等价用法和写入边界，原有 BOM 演示与公开行为保持可用。

## Edge Cases

- 多重边与共享子树不得按物料 ID 合并，也不得共享某一处的折叠状态。
- ECN 发布可让原结果从未引用过的行出现；依赖不能只取旧发生项 ID 集合。
- 输入中的组织、BOM 类型、日期、备选、配置、序列、批次、计划量、预算或公式参数变化均不能复用错误的结果。
- 只改变安装事实的 US-523 记录不改变本轮主数据视图语义；实例图保持独立。
- 未解析与空结果不同；数量不可得不能被显示为零。未解析候选与截断可以同时出现，均须展示。
- 初始加载与后台刷新不同；刷新期间保留路径节点，失败时明确标识错误，不能把旧结果宣称为新输入的成功结果。
- 同一数据库多份视图、不同数据库同名物料、卸载后重挂以及连续上下文切换必须相互隔离。
- `disabledAt` 当天即失效；不允许用系统当前日期代替调用方评估日。

## Requirements

### Functional Requirements

- **FR-001**: 先以双后端真实失败回归补齐路线有效域与未覆盖拒绝，关闭 US-520 AC#11 / US-524 AC#7 的消费方缺口。
- **FR-002**: 三框架共用一套 BOM 派生视图与错误语义；三端同名 `useBomView`，显式传数据库及包含上下文、目标、计划量、预算和公式参数的输入。
- **FR-003**: 订阅依赖覆盖查询谓词作用域和结果引用实体，完整验证 US-522 AC#6～#9，不以旧结果参与集代替依赖。
- **FR-004**: 树节点按发生项完整路径识别，支持按路径惰性呈现、独立折叠、数量与层级；刷新复用未受影响的真实 DOM 元素。
- **FR-005**: 统一展示截断及三类未解析候选，并保持数量、成本与导出遇未解析即拒绝。
- **FR-006**: 行编辑遵循草稿直接写、draft ECN 新发生项写及已发布既有发生项只读的边界；数量全程使用十进制字符串。
- **FR-007**: 初始加载、空、数据、错误、后台刷新与保存进度在三端可见且可访问；表单和树满足键盘与辅助技术要求。
- **FR-008**: 所有 US-522 AC 在三端使用同一 fixture、同一行为断言与真实 DOM 引用验证；补对外文档、示例及 API 对称门禁。

### Key Entities

- **视图输入**：数据库明确归属、解析上下文、根目标、计划量、预算及公式参数。
- **派生视图快照**：按路径标识的行、数量、候选、截断与错误；不是新的持久化 BOM 真相源。
- **视图交互状态**：初始/刷新状态、已展开路径与独立编辑目标；生命周期结束后释放订阅。
- **行编辑目标**：实际发生项与可编辑字段，保留所在草稿头或 draft ECN 的合法写入边界。

## Success Criteria

- **SC-001**: US-522 全部 12 条 AC 三端通过，路线停用前置两条 AC 在 SQLite/PGlite 通过；原有领域与演示回归不缩减。
- **SC-002**: 改量 ECN 发布后，所有路径不含旧/新发生项的已渲染节点，真实 DOM 元素引用 100% 保持；三重边及共享子装配的独立性通过。
- **SC-003**: 在预热后的 100 节点 fixture 上，派生查询 p95 <16ms、单次保存 p95 <100ms、保存/输入变化完成到可见结果更新 p95 <100ms；三端首屏均 <1.5s。
- **SC-004**: 本轮新增或修改的非核心包四项覆盖率均 ≥80%；若确有必要修改核心 `rxdb` 或三框架基础绑定，则对应四项均 ≥90%。strict、零 ESLint 警告、公共 TSDoc、API 对称及全分支门禁通过。
- **SC-005**: 各包入口及静态依赖 gzip <50KB，保持按需加载；另报完整可达动态分块体积。同 viewport、字体与 fixture 下三端布局、尺寸、间距和状态呈现视觉一致，并通过 WCAG 2.1 AA 检查。

## Assumptions & Scope Boundaries

- 当前分支继续实施，不创建新分支；规格、计划、任务完成后才进入实现。
- 优先复用已有派生查询依赖注册通道；主会话先以 AC#6～#9 spike 收敛快照与生命周期细项，未证明缺口前不预设新引擎 API。
- 本轮包括共享 kernel、薄三端绑定与可复用 `BomTree` / `BomLineEditor`；框架惯用容器不同不改变业务 API。
- 配置产品界面、成本报表、拖放重排、ECN 管理界面、实例 UI 的三框架扩展均不在本轮。
- 本切片初始不包含US-510阶段B、US-513阶段B、US-519 AC#3/#7及US-509 AC#13；2026-10-18完整BOM授权已将这些范围分别纳入spec021～024实施与独立验收，不再作为未授权待办，也不由本切片部分通过自动关闭。
- 其他故事仅有状态漂移时，由独立审计提供证据后再回写，不随本步范围自动置 Done。
