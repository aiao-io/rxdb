本页回答「接下来做什么、什么必须排在什么前面」。故事状态与关闭条件见[状态概览](status-overview.md)，范围决策与外部条件见[决策](decisions.md)，证据见[验收记录](verification-report.md)。决策确定、计划完成、代码实现和真实环境验收分别记录。

## 图片主路径

**选模板或写提示词 → 登录平台账号 → 积分校验 → 单模型生成 1 张 PNG/JPEG → 预览 → RxDB 本机保存 → 下载 → 反馈。** 模型与凭据由平台统一托管（D-19）；未登录保留本机草稿、灵感浏览与本机作品，生成与跨设备同步需要登录。

## 后续产品方向

[未来功能需求与目录规划](future-requirements.md) 汇总当前方向：Web 持续优化、Tauri 本地安装程序、Cloudflare 业务后端与管理页面（安全代理）及统一的平台账号同步；同时给出产品目标目录。平台生图按 [D-19](decisions.md#d-19登录用户经平台积分生图移除用户自配供应商) 改为登录+积分，模型由平台托管；充值计费仍按 [D-17](decisions.md) 暂缓。首阶段代码与待验边界见[产品交付计划](plans/product-completion-20261030.md)。原自有项目接入按 D-16 撤销并移除；MEDIA-US-305 已部分接线，但真实 Storage 与跨设备尚未验收。

建议先保持 Web 与现有数据兼容、整理服务端/部署职责，按 MEDIA-US-206 → 109 → 108 的顺序完成积分生图改版，再继续完善平台任务与同步。Tauri 和平台同步按各自前置并行推进，不依赖收费生图；独立充值计费不在当前排期。详细依赖、验收目标和待定项见该文档；当前发布范围及故事状态继续按上文和 YAML 记录。

统一平台同步的目标流程为：**注册/登录平台账号 → 确认工作区与同步范围 → 元数据复制 → 确认历史/以后原图范围 → 上传 → 另一设备按需取回**。平台配置由部署方维护；元数据复制、原图远端保存与本机恢复各自验收，真实 Storage 与 Web/Tauri 通过后才交付完整流程。
