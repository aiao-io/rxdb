# 用户故事：图片原文件同步到平台 Supabase

## 作为/我想要/以便

**作为** 希望在多台设备查看和继续使用自己图片的创作者

**我想要** 注册或登录平台账号并确认范围后，自动把原图同步到平台 Supabase，并在其他设备按需取回

**以便** 换设备也能预览、下载原图，并明确知道哪些图片只在本机、哪些已经完成远端保存

## 当前问题

平台原图入口与传输能力正在接线；正式云 Web 侧原图上传、第二设备草稿恢复与显式下载已验（字节/SHA-256 一致，见[验收记录](../../verification-report.md#正式环境证据)），Tauri 跨设备、大图续传与删除冲突尚未验收。另一设备只有作品信息时仍显示“本机无原图”；作品信息同步成功不能证明远端存在可恢复图片。按 [D-16](../../decisions.md#d-16统一使用平台-supabase) 统一使用平台项目，终端用户不再配置自己的项目。现有边界见 [MEDIA-US-302](MEDIA-US-302-draft-sync.md)、[MEDIA-US-303](MEDIA-US-303-sync-targets.md) 与[作品界面](../../../apps/web/src/app/local-image-mvp.html)。

## 范围边界

### In Scope

- Web 与当前承诺的 macOS Tauri 支持 PNG/JPEG 原始字节的显式上传、已授权后的自动上传、跨设备按需下载和本机恢复；单张继续沿用现有 16 MiB 上限、格式/尺寸/解码与 SHA-256 校验。
- 首次单独选择“仅同步以后保存的图片”或“同步已有及以后保存的图片”，默认不选择。已有范围预览作品数、总字节数、不可读/超限作品和平台工作区；以后保存仅指确认后在当前工作区完成本机保存的新作品，重新连接不自动扩大到历史图片。
- 每个工作区只使用统一平台目标；按平台账号、工作区和稳定作品/文件版本标识隔离。图片与必要元数据从客户端直达平台 Supabase 的私有 Storage 与数据库，使用受限用户会话；不经过生图任务的临时 R2 存储。表、bucket 与访问策略由部署方维护，用户无需执行管理操作。
- 本地持久传输队列维护每张图的选择范围、源摘要、目标、进度、失败和已确认回执；图片先在本机保存，上传失败不影响原图预览、下载或继续创作，不调用生成模型。
- 文件上传、远端完整性检查、作品与文件版本关联分别确认；刷新、超时、响应丢失和多设备上传同一版本可核对恢复，不覆盖其他字节、不产生重复关联或把半成品标为已同步。
- 有界并发与分块传输，断网、刷新和应用重开可继续；通过平台 Storage 恢复可续传分片进度。续传会话过期时重新核对同一不可变文件身份，再重传当前文件；不清空整个传输队列。
- 原图和缩略图都保持私有。新设备先显示“远端可取回”，进入视口才读取受权预览，显式下载/保存才恢复原图；没有本机文件时不能显示“已保存到本机”，已有本机原图可离线使用。
- 展示已选图片数、已传字节、待传、失败、最近成功时间、可确认的存储/文件限制和费用承担方。未知配额显示未知；额度不足暂停传输并保留队列，不自动扩大上传范围或升级套餐。
- 停止/断开、退出和切账号/工作区使旧传输失效；本机已保存文件和远端已确认对象保留。三种删除范围分别操作：仅删本机副本、从同步图库移除、删除远端原图副本；远端对象回收须遵守下面的删除契约。

### Out of Scope

- 用户自有 Supabase、管理 OAuth 接入、同时把同一工作区转存多个目标、团队共享、公开 bucket 或永久公开分享 URL。
- API Key、管理 OAuth token、项目私钥、账号会话、本机路径、句柄和本地 blob URL 的业务同步。
- 自动删除本机文件以腾空间、对已确认原图进行压缩/重编码、自动购买容量、生成新图片以补回缺失文件。
- 按 TTL 自动 GC、重置远端修订/检查点，以及不提示删除影响就永久清除所有历史版本或账号。

## 用户流程

1. 用户注册或登录平台账号，按 [MEDIA-US-303](MEDIA-US-303-sync-targets.md) 确认同步工作区后打开“图片同步”；无需提供项目 URL、Key、SQL 或另行授权项目管理。
2. 查看平台账号、工作区、数据范围、图片数量与大小、Storage 限制和费用说明，明确选择历史图片是否加入。
3. 点击“确认并启用图片同步”。应用先保留本机副本，再在后台上传选择范围内的图片，逐张显示状态。
4. 另一设备登录同一平台账号并确认同一工作区，看到远端作品并按需预览；点击“保存到本机”后校验并落盘，完成后可离线查看和精确下载。
5. 用户可暂停、重试失败、停止自动上传或分别管理本机/远端副本；切换账号或工作区必须重新确认。

## 删除与冲突契约

| 操作             | 本机影响                                                           | 远端及其他设备影响                                                                                                                                          |
| ---------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仅删本机副本     | 显式确认后清理此设备文件与本机文件关联，保留远端作品记录           | 远端原图与作品信息保留；此设备不因后台扫描自动重新下载，用户可主动取回                                                                                      |
| 从同步图库移除   | 发起设备的本机原图保留，界面单列为仅本机；其他设备已下载文件也保留 | 写作品删除标记并传播，旧传输/离线编辑不能静默复活；已上传对象保留，后续物理回收另行确认                                                                     |
| 删除远端原图副本 | 本机已下载文件保留                                                 | 展示对象与保留版本影响后单独确认；先提交当前文件删除标记并使旧任务失效，再走鉴权 Storage 删除与可恢复回执；其他设备显示远端不可取回，离线冲突保留并等待选择 |

删除远端原图前检查当前关联、保留版本、冲突和待核对传输的引用。事务内解除本次明确确认删除的当前文件关联后，如仍有其他保留引用，拒绝物理删除并说明原因；拒绝时保留原图与可恢复记录。首版不跨作品物理去重，避免删除一张作品影响其他作品。D-06 的 tombstone、冲突版本和日志继续保留；旧删除/上传回执不得清理新版本，删除后重新上传需要新的明确操作与版本。无引用对象也只能经上述显式操作回收，不新增自动 GC。

## 技术笔记

- 图片同步控制器、私有 Storage 迁移和平台 UI 入口已接线；隔离本地真实 Auth/数据库的双设备接线已补验（Storage 字节为 fixture）。2026-11-06 正式云已完成真实原图上传、第二设备草稿恢复与显式下载，字节/SHA-256 一致；Tauri 跨设备、大图续传与删除冲突仍待验。证据见[平台统一同步验证](../../verification-report.md#2026-11-06-平台统一同步验证)与[正式环境证据](../../verification-report.md#正式环境证据)。现有 [product-sync-store.ts](../../../apps/web/src/local-data/product-sync-store.ts) 仅复制元数据，[browser-media.ts](../../../apps/web/src/local-data/browser-media.ts) 维护本机原图；[平台 R2 交付](../../../apps/api/src/platform-coordinator.ts) 不属于本故事的平台 Supabase 文件同步。
- 根据 Supabase Storage 官方文档，私有 bucket 的上传和下载均须授权；实现需同时限定 bucket、平台账号与工作区，并拒绝路径替换、公开 URL 和越权签名。临时预览/签名 URL 不作为持久图片身份，不进入同步 DTO。
- 对象路径包含平台用户、工作区、作品 ID 与不可变文件版本/摘要；不同版本不 upsert 覆盖，文件与记录采用可恢复提交。重试只允许可核对、可幂等的传输，不复用生图重试规则重新调用模型。
- 传输现状：文件记录先 INSERT 建 `pending`，对象写入后按修订 UPDATE 为 `uploaded`（`BEFORE INSERT` 触发器先于冲突判定执行，用 upsert 推进会被拒）；下载按作品记录的摘要精确取版本；切换目标、账号或工作区即中止在途传输，迟到结果不提交记录、不写入本机。单文件 TUS 会话地址与 offset 已持久保存于设备 SQLite；重开后显式继续上传先 HEAD 核对服务端进度，仅补传剩余字节，过期仅重建当前文件，见[本地续传验证](../../plans/image-sync-resume-20261114.md)。多文件范围持久队列、重开自动调度、限次退避与授权/容量暂停已接线并有本地测试；真实 Storage、大图跨端和删除冲突仍待正式联验，不能以本地通过关闭 AC#5/#6。
- 支持续传的 Storage 使用官方 TUS 能力，分片大小等接口参数按实施时官方文档配置；受限/不兼容的平台存储须明确提示，不能悄悄退化并宣称已续传。大文件测试覆盖超过 6 MiB，单张上限沿用 16 MiB。
- 现有协议的 `metadataOnly` 判定和所有“原图只在本机”说明需按新能力显式版本化，保持仅 metadata 连接可用。旧客户端遇到新协议/文件版本须保留数据并安全拒绝，不通过清除兼容守卫上线。
- 验证分层：单元/契约覆盖授权范围、队列、提交和删除状态；真实本地或专用云 Storage 验 RLS/回执/续传；真实 Web/Tauri 验证原图字节、原生落盘、离线与切账号/工作区；平台注册与同步接线同 MEDIA-US-303 联验。文档门禁不证明任何运行行为。
