# 后台配置同步与提交工作流交付记录

日期：2026-11-16。范围：Spec Kit 特性 `001-supabase-rxdb-backend` 余下的 T035、T036、T041、T044、T046、T051、T052，对应 [MEDIA-US-307](../stories/local-first/MEDIA-US-307-admin-rxdb-model.md) 与 [MEDIA-US-308](../stories/local-first/MEDIA-US-308-config-branch-commit-sync.md)。证据均来自本地真实 Supabase（Docker）、真实 RxDB 与真实浏览器；生产部署、双区域与正式账号不在本轮范围内。

## 交付内容

### 配置实体与提交投影接入 RxDB 同步（T051）

- 配置实体（模板、供应商策略、平台模型）改到 `public` 命名空间，对应远端 `media_prompt_templates`、`media_provider_policies`、`media_platform_models`。它们按工作区经变更日志双向同步，编辑受工作树版本控制。
- 领域层 `createMediaConfigSyncOptions` 生成同步计划：配置实体用 `Filter`（只拉本工作区），提交投影用 `QueryCache`（远端权威，不进工作树）。白名单之外的实体与 RxDB 内部系统实体（含工作树提交图）都会被拒绝。
- 迁移 `023-config-rxdb-sync.sql`（22 → 23）内容如下：
  - 三张配置表，带管理员加工作区 RLS、身份字段不可改、同步触发器。
  - `rxdb_change` 的配置日志只对本工作区管理员可读，按行快照里的工作区判定，删除日志同样适用。
  - RxDB 形状的投影表 `media_config_projection_commits` / `_changes`。客户端只能写 `prepared`，变更到齐后才能标记 `synced`；其余状态只由应用或回滚 RPC 推进。
  - 旧投影表的数据迁入新表，旧表停止接收客户端写入。
  - 应用与回滚 RPC 改读新表，版本冲突改用 `PT409`。
  - 作者与应用记录的外键改为随账号级联删除。
- 后台节点 `openBackendConfigRxdb` 使用同一份计划。`BackendConfigCommitCache` 经查询缓存读取完整投影并复核指纹；状态为 `prepared` 或变更未到齐时不加载，等待补偿。
- Supabase 适配器不提供查询缓存的远端写，所以投影写入走 PostgREST，由触发器与 RLS 把关；读取走 RxDB 查询缓存。

### 后台配置页（T041、T052）

- 每个账号使用独立的本地库（`aiao-media-admin-v2-<账号摘要>`）。同步游标、工作树与未提交修改都不跨账号共用。退出登录时关闭配置库，并重新加载页面。
- 先打开本地库，已有内容立即可看可改；之后连接远端并同步。旧版草稿表只补本机与工作区都没有的标识，不再覆盖本机修改（G11）。
- 页面显示本机未提交修改数，并提供提交说明与“提交修改”入口（G06）。提交后经 `commits$` 与补偿扫描生成投影；提交详情显示状态、操作者、全部父提交、应用与发布时间、拒绝原因，以及“应用提交”和带页内确认的“执行安全回滚”。
- 应用或回滚成功后，本机写回服务端 revision。这类只改 revision 的簿记不计入未提交修改，也不进入投影。
- 加载、空列表、读取失败、离线、冲突与无权限各有明确状态。权限未确认或已撤权时，不渲染列表、提交入口或任何特权按钮（G12）。新建时工作区、分支、修订号、删除时间由系统固定，且只读（G05 的系统字段部分）；模板等的必填字段在提交前校验。

### 本轮发现并修复的缺陷

| 缺陷                               | 后果                                                                                                    | 修复                                                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 父提交原样取工作树父节点           | 第一次配置提交的父节点是系统基线，服务端永远找不到它，应用必然失败                                      | 跳过 `baseline` / `branch_baseline`，指向最近的可投影祖先；父提交不在历史中时拒绝投影，不猜测               |
| 提交指纹包含 `status`              | 服务端推进状态后，后台复核指纹必然不一致                                                                | 指纹只覆盖不可变内容                                                                                        |
| UUID 校验只认 v1–v5                | RxDB 与工作树生成的是 v7 标识：提交标识被改写，完整度查询与远端记录对不上，已同步提交的重放写入会被拒绝 | 接受 RFC 9562 的 v1–v8                                                                                      |
| 更新的 CAS 预期值优先取逆向快照    | 每次应用后再编辑都会被判为版本冲突                                                                      | 更新以提交时的当前 revision 为准，删除才取逆向快照                                                          |
| 投影实体与配置实体同样受版本控制   | 投影写入进入工作树，下一次提交带上投影实体后投影失败                                                    | 投影改为查询缓存，不进工作树                                                                                |
| 冲突以 `40001` 抛出                | PostgREST 把它当作序列化失败自动重试，数秒后以 500 返回，界面显示成“服务不可用”                         | 023 改用 `PT409`；后台客户端把 `40001` / `23505` / `23514` / `PT409` 统一报告为版本冲突，与 Worker 同一口径 |
| 作者、应用记录外键为 NO ACTION     | 删除已应用过配置的管理员账号失败                                                                        | 改为随账号级联删除                                                                                          |
| 后台首屏打包了配置库的适配器与插件 | 首屏初始包超出 2 MB 告警线                                                                              | 配置库按需加载，初始包由 2.18 MB 降到 1.65 MB                                                               |

## 2026-11-21 分支管理补充

- 配置页从 RxDB 分支表展示本地分支，支持创建、切换和 `previewMerge` 合并预览；工作树未提交、恢复中或冲突时阻止切换与合并，有冲突时阻止合并。只有 `main` 分支允许 commit projection，feature 分支提交只保留本机。
- `admin-config-branches.spec.ts`、`admin-config-projection.spec.ts`、`product-client.spec.ts` 覆盖分支标识、冲突计数、分支过滤和 projection 边界。

## 边界与后续

- 远端分支仍只开放 `main`。服务端以 revision CAS 拒绝冲突应用，双方原始提交保留在各自历史中。MEDIA-US-308 AC7 的本地路径已通过，公共目录发布链路仍待接通。
- 发布链路仍缺：应用结果写入 `media_config_records`，尚未接到普通用户读取的公共目录（G07，后台差距评估 C 阶段）。
- 公共包缺口：`rxdb-model-angular` 表单的输入框没有关联字段标签（只有字段组有名称），加载动画没有可读名称，读取失败显示成空列表。这些要在公共包里按三框架对称修复，本轮由宿主页面承担错误态。
- 本地开发库 `aiao-media-admin-config` 不迁移；生产尚未部署配置编辑器，没有用户数据受影响。
