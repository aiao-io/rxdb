# 原图大文件续传本地验证（2026-11-14）

关联 [MEDIA-US-305](../stories/local-first/MEDIA-US-305-supabase-image-sync.md) 的 AC1–13。本记录持续补齐单文件 TUS 会话、多文件队列、分片进度、三种独立删除范围、引用/回执、显式新版本及远端可见预览的本地接线与验证。真实 Storage/Web/Tauri 联验仍未完成，故事和 AC 状态不因此关闭。

## 修复

此前大图上传每次都创建新会话，分片成功响应没有核对 `Upload-Offset`。发生应答丢失或重开时无法利用已有分片，还可能在错误进度回执后继续确认文件关联。

- [续传模块](../../apps/web/src/local-data/resumable-image-upload.ts) 用既有 SQLite `LocalPreference` 保存版本化会话、不可变文件路径、大小、类型与进度。键按平台 Storage 地址与文件身份摘要隔离；沿用修订冲突保护，不新增数据库表或修改既有文件标识。
- 会话创建回执先落盘，再发送 6 MiB 分片。每个成功分片必须返回精确的下一 offset；失败与未知回执保留原会话，不自动重传。
- 再次上传同一版本先对原会话发送 HEAD，核对文件总长度与服务端 offset，从已接受位置续传。最后应答丢失而服务端已接收完整文件时，不再传字节。
- 仅明确 404/410 过期会话重新创建当前文件的传输；授权失败、限流、服务故障与无效进度均停止，不循环重建。原图、其他文件与任务不被删除，也不调用生成模型。
- 新建及持久会话地址均限定在已授权 Storage 的 TUS 路径下；未知日志版本、身份变化、外站或带账号的地址保留记录并拒绝继续。账号会话和 Key 不写入续传日志。
- [图片同步控制器](../../apps/web/src/local-data/image-sync.ts) 共用此模块；Web 与 Tauri 沿用既有数据层。设备会话不进入原图备份或元数据同步。

## 多文件持久队列补齐

- [设备队列](../../apps/web/src/local-data/image-upload-queue.ts) 每张原图单独使用 `LocalPreference` 持久化，按平台、账号、远端工作区和本机副本摘要隔离。记录保存用户已选的 existing/future 来源、不可变源 SHA-256/字节数、状态、尝试次数、退避时间及确认回执；不保存 Key、用户会话或本机文件路径。
- 已有图片先逐张入队，再执行网络调度；新图片完成本机保存后入队。重开、重新聚焦或联网只恢复已入队文件，不重新扫描历史图库。不同文件互不覆盖，重复选择同一版本不会清除失败或重传成功文件。
- 使用 Web Locks 按同一设备授权范围互斥，网络传输并发为一；键游标分页每批最多 100 项，不把整库设置装入单个 JSON。队列写入沿用现有事务和修订保护，磁盘写入失败时停止网络派发。
- 网络、截止超时、HTTP 408/429/5xx 最多自动尝试三次，失败后分别等待 1 秒和 2 秒；已失败任务保留并可明确重试。401/403、413/507 暂停整个范围，重开不能隐式解除，处理授权或容量后手动重试。
- 停止、退出或切换作用域取消旧请求和计时器，迟到成功不确认到新空间。恢复中断任务仍核对原摘要，源文件变化时保留失败记录，不能静默上传新字节。
- 页面显示已选数量、总字节、已确认字节、成功/待传/失败和最近成功时间，并提供“重试图片队列”。只在持久完成回执确认后增加已确认字节，部分分片不能视为整图成功。

验证：应用回归先在旧循环下复现“第一张失败后第二张未执行”（实际调用 1 次，期望 2 次），修复后通过。完整 `aiao-media:coverage --args='--maxWorkers=2'` 为 53 文件、878/878；整体语句/分支/函数/行覆盖率 88.97%/82.76%/92.32%/92.89%，队列模块 99%/98.42%/100%/100%。Web lint/typecheck 均通过。新增真实 Chromium SQLite/OPFS 双文件队列关闭重开测试通过：只恢复未确认且已选择的任务，第三张历史原图不入队；原有大图 TUS 恢复测试继续通过。网络与 Storage 回执仍由 fixture 提供，不扩大正式验收结论。

## 显式图库移除与并发保护

- [应用操作](../../apps/web/src/app/local-image-mvp.html) 将“仅删本机”与“从同步图库移除”分开；后者独立确认各设备原图和云端对象均保留。本机作品和仅远端元数据均有入口；移除后保留本机作品并显示“仅本机”，历史上传范围不再包含已移除项。
- [工作区控制器](../../apps/web/src/app/product-workspace.ts) 先检查点、在设备复制库持久写入作品 tombstone 并投影，再请求远端同步。离线时保留意图并明确显示“远端尚未确认”；重开继续同步。待处理作品冲突先拒绝移除，账号或工作区改变时迟到回复不能修改新作用域。
- [设备队列](../../apps/web/src/local-data/image-upload-queue.ts) 读取已有 v1，后续写入 v2；`removed` 与作用域内的来源移除标记一次事务落盘。先停止旧范围传输再移除，迟到回执不覆盖删标；重开、重试和旧确认名单均不能重新入队。成功回执保留，移除项不计入选中/待传总量；原图和设备日志都不删除，日志继续排除在备份与同步外。
- [迁移 014](../../infra/supabase/migrations/014-image-lifecycle.sql) 让同一作品与文件版本的 tombstone 不可逆，固定路径、SHA-256、字节数、尺寸与 MIME；新增文件必须使用账号/工作区/来源/摘要/格式完全对应的路径。图库删除、文件提交和 Storage 写入复用工作区事务锁，移除后新旧上传都不能重新确认。已移除图库对象仍允许原账号读取；已确认 `uploaded` 对象不能被写入覆盖。

## 远端原图删除与引用保护

- [迁移 015](../../infra/supabase/migrations/015-image-delete.sql) 独立维护保留历史/冲突引用与每文件唯一的删除回执。预览列出当前文件和作品修订、其他版本、保留/冲突引用、待核对传输和未知历史；引用未释放、修订变化或历史不完整均拒绝新删除。迁移会回填历史摘要，无法验证的历史不会被当成无引用。
- 删除先按预览修订提交不可逆文件 tombstone 与 `pending` 回执，再由 Storage API 清理精确对象路径。Storage DELETE 的 RLS 重查引用并与作品/上传操作共用工作区事务锁；删除准备后新增引用也能阻止清理。只有确切对象目录已不存在，完成 RPC 才推进回执为 `complete`；HTTP 200 本身不表示删除完成，重复请求与旧回执不能清理其他对象。
- [设备控制器](../../apps/web/src/local-data/image-delete.ts) 先持久写入版本化请求日志，再发送删标；日志按项目地址、账号、工作区与文件身份隔离，不含会话或 Key。写盘失败不提交删标，迟到/中止响应不触发对象删除，未知日志保留并拒绝继续。应答丢失后复用原请求并先核对远端；已有完成回执仍封存设备旧队列，不重复删除。
- [同步副本](../../apps/web/src/local-data/product-sync-store.ts) 协商 `imageReferences: 1`；只支持元数据的旧服务继续同步。作品冲突先在本机保留双方与最新远端，再登记去重的摘要引用；登记失败后每轮重试，即使远端修订没有改变。显式解决并核对推送结果后才按准确作品修订释放引用，失败以持久 `resolved-*` 状态恢复，成功后标为已释放。
- [应用确认](../../apps/web/src/app/local-image-mvp.html) 展示文件大小、格式、SHA-256、精确路径、其他版本和引用数量。“仅删本机”“从同步图库移除”“删除远端原图”独立操作；只有远端删标成功后才停止旧来源队列。取消确认不写删标，不删本机；切账号/工作区后的迟到结果不覆盖新状态或调度新队列。
