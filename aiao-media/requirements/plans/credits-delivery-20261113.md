# 平台积分账本与后台交付

本轮对应 [MEDIA-US-206](../stories/account/MEDIA-US-206-credit-admin.md) 的 A/B 阶段，也是 [MEDIA-US-108](../stories/generation/MEDIA-US-108-platform-generation.md) 接入生成的前置。海外与国内正式部署尚未验收，不能关闭 MEDIA-US-206 AC5。

## 已实现

- `012-credits.sql` 提供账户、不可变流水和任务预占。后台调整与未来生成消费使用同一账户、同一流水表；管理员只能经 RPC 写入，service role 也没有直接修改或删除流水的权限。
- 调整原子更新余额、流水与后台审计，必须填写原因；相同请求标识重试只生效一次，参数变更返回冲突。账户锁防双花，回收不能侵占任务已预占的余额。
- 预占绑定用户、任务、额度、请求指纹与令牌摘要。成功结算扣减一次，失败释放；与已结算状态矛盾的请求被拒绝。任务机制接入由 MEDIA-US-109/108 继续完成，目前不能据此宣称平台生图已交付。
- 后台用户页支持邮箱/账号搜索、余额与流水查询、带原因的正负调整与流水翻页。请求未确认时保留原请求标识，供重复提交核对；身份切换丢弃迟到响应。
- 用户「我的账号」提供本人余额、预占、可用积分与流水，支持刷新、翻页；账号切换不会显示前一账号结果。
- `GET /api/credits`、`GET/POST /api/admin/users/:userId/credits` 已注册公开接口文档；用户标识来自有效会话，管理权限在每次请求时重新确认。
- 新项目 SQL 包包含积分迁移；现有项目升级文件随管理产物提供为 `/admin/upgrade-credits.sql`。管理后台 typecheck 已由输出提示恢复成真实的应用与测试 TS 检查。
