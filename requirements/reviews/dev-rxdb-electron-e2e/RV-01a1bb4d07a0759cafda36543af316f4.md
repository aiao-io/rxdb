# RV-01a1bb4d07a0759cafda36543af316f4：只读文件写入负对照在首次不存在时立即通过，漏掉迟到写入

## 问题与影响

只读用例触发新建目录与上传后，异步请求尚未落盘时两个目标路径本来就不存在。负向断言立即通过，不会观察稍后到达的错误写入；若写入授权回归但落盘稍慢，整条“一个字节都不落盘”的用例仍可能报绿。测试随后关闭应用，还可能中断未完成写入，进一步掩盖回归。P2：这是明确的测试假通过窗口，未声称当前生产授权已经失效。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/dev-rxdb-electron-e2e/src/devtools-native-files-mutation.spec.ts:278` 的 waitForPath 同时用于等出现和等消失；:281 第一次 existsSync(path) 与 shouldExist 相等就 return true。用例 :413 的目标是证明“始终没有写入”，但 :429 与 :430 调用 shouldExist=false 时，目标最初不存在即可满足，完全没有等待注释承诺的 30000ms 观察预算。:160 的 createDirectory 与 :180 的 uploadThroughPanel 只派发 UI 事件，返回不代表请求已经被拒绝或落盘。

确定触发顺序为：派发写入 → write 尚在 IPC/异步文件操作中 → 两次 existsSync 都为 false → 测试断言成功 → 之后才写入或被 finally 中的 app.close 中断。该结论直接来自返回条件与调用链，不依赖机器快慢的固定实验结果。

## 修复方向

负对照先等待这两次操作的可判别授权拒绝，再比较磁盘快照；若保留时间窗口判据，应让“始终不存在”在整个窗口内持续成立后才成功。补一条延迟落盘的反例，确保授权错误不会因首次取样过早而报绿。
