# RV-01a1bb5b41337f2783ce3875cd1a4cdc：未推送数据的 Pull 负对照在同步完成前即可通过，漏掉迟到失败

## 问题与影响

第二个全新浏览器上下文最初没有目标 Todo，也没有同步错误。用例点 Pull 后立刻断言这两个“不存在”，可在网络请求尚未结束时全部通过并关闭上下文。即使 Pull 最终失败，或完成后错误地带回目标行，该负对照仍可报绿，不能证明声明的远端隔离行为。P2，测试缺口；不声称当前同步引擎已经泄漏数据。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/dev-rxdb-supabase-e2e/src/remote-sync.spec.ts:207` 的负向用例，在 :233 点击 Pull，:235/:236 只等目标行和 .alert-error 的 count 为 0；两项在点击前已经成立，没有任何一次成功 Pull 的结算条件。

真实页面 `apps/dev-rxdb-supabase/src/app/todo/todo.page.ts:334` 的异步同步包装在等待 operation 时保持 pending，失败后才设置错误；点击事件返回不等于该 Promise 已完成。同文件其余正向用例等待新行出现/完成状态变化，因此不会被相同的“初态为空”掩盖。

## 修复方向
