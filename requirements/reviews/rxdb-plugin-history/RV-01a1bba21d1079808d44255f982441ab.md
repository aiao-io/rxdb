# RV-01a1bba21d1079808d44255f982441ab：history 快速示例切到源分支后合并自身，正常顺序执行必然报错

## 问题与影响

使用者照 README 的使用示例顺序执行分支部分，在新建 feature-a 并成功切过去后，下一句 mergeBranch('feature-a') 会把源和目标设成同一分支，必然被正常的自身合并守卫拒绝。快速示例无法完成它展示的分支合并流程；这是文档消费路径的 P2 错误，库的拒绝行为本身正确。

## 证据与根因

冻结源码 SHA：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-plugin-history/README.md:39` 创建 feature-a；`:40` await 切到 feature-a；`:41` 紧接着把 feature-a 传给 mergeBranch，没有先回目标分支。
- `packages/rxdb-plugin-history/src/VersionManager.ts:441` 的 mergeBranch 现取当前分支，`:445` 将其 id 用作 targetBranchId。前一句切换已经成功时，这个值就是 feature-a。
- `packages/rxdb-plugin-history/src/merge-branch.ts:147` 在 sourceBranchId 与 currentBranchId 相等时立即抛 merge_into_itself_error；`:26` 的错误工厂给出不能合并进自身的 RxDBError。

因此在没有其他调用方插入切分支的正常顺序执行中，只要示例前两步成功，最后一步一定进入该守卫。结论来自参数相等和 await 顺序，不依赖后端时序或动态试验。

## 修复方向

合并示例在从 feature-a 合回去之前，显式切回原来的目标分支；或者把三种独立动作拆成互不暗示顺序执行的片段。保留库的自身合并守卫。文档消费测试应核对示例的当前分支与合并源不同。
