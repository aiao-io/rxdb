# RV-01a1bb2d6152721bacc1bd61696a7629：Todo 页的撤销重做使用数据库作用域，会回滚页面外实体

## 问题与影响

Angular Todo 页的历史列表、撤销/重做计数来自 Task 仓库，但按钮实际调用无参 history()，选择整个数据库的最新历史。先在 Todo 写一条任务，再到菜单/文件页修改数据，返回 Todo 点「Undo」，会撤销菜单/文件操作，Todo 列表和历史却没有相应变化；重做也会操作页面外实体。React、Vue 的同功能按钮使用页面已有的 Task 作用域 API。常见跨页面操作即可触发且会意外修改其他数据，同时破坏三端行为对称，定 P1。

## 证据与根因

冻结源码快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `modules/angular-todo/todo-page/todo.page.ts:70` 创建 history(Task)；`modules/angular-todo/todo-page/todo.page.html:1`、`modules/angular-todo/todo-page/todo.page.html:2` 由它驱动按钮计数与禁用条件，侧栏也是这个 history。
- `modules/angular-todo/todo-page/todo.page.ts:369` 的 undo 和 `modules/angular-todo/todo-page/todo.page.ts:373` 的 redo 却重新调用无参 versionManager.history()。`packages/rxdb-plugin-history/src/history-scope-api.ts:78` 明确把无参解析成 database，类参数解析成 repository；`packages/rxdb-plugin-history/src/history-scope-api.ts:249` 按这个 scope 选整条事务。`packages/rxdb-plugin-history/src/scope-selection.ts:35` 对 database 作用域接受所有实体。
- 对照 `apps/dev-rxdb-react/src/app/pages/todo.tsx:356` 与 `apps/dev-rxdb-vue/src/pages/TodoPage.vue:322`：均调用页面已有的 history.undo()/redo()，与其 Task 计数一致。
- `apps/dev-rxdb-angular/src/app/rxdb/setup_rxdb_wa-sqlite.ts:33` 为多实体 demo 复用同一 RxDB；它是实际可达的跨页面历史序列，不需要构造跨数据库场景。
- 现有组件测试 `modules/angular-todo/todo-page/todo.page.spec.ts:101` 无论入参是什么都返回同一 mock，`modules/angular-todo/todo-page/todo.page.spec.ts:268` 只断言按钮触发了 mock，没有验证作用域；现有 Todo e2e `apps/dev-rxdb-angular-e2e/src/todo.spec.ts:129` 只检查按钮可见。

有界复现：`node /Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-todo-history-scope.mjs`。从冻结源码提取页面实际 undo/redo 方法与插件实际 selectScopedHistories，给定最新 MenuNode、较早 Task 两条历史。实际两次调用 scope 都为 database，选中 MenuNode。该复现验证入口与选择逻辑，未执行真实数据库写入或浏览器交互。

## 修复方向

两个按钮复用页面持有的 Task 作用域 history。测试提供按入参区分的 database / Task mock，加入「页面外更新后返回 Todo 撤销/重做」场景；核对共享组件的 Angular、Electron、Tauri、Supabase 宿主，保持 React/Vue 同行为。
