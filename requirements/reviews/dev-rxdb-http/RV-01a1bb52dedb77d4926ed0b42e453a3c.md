# RV-01a1bb52dedb77d4926ed0b42e453a3c：SSE 连接失败后仍显示已接通，将启用意图误当真实状态

## 问题与影响

默认开启变更通知时，把 api 指向未监听的合法回环端口，或在已连通后断开后端，SSE 会进入失败/退避重连；顶栏却持续显示“已接通”。用户无法据此区分没有新写入和通知链路已断，演示台给出错误的网络诊断。定为 P2；本问题不声称重连或数据同步引擎失效。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/dev-rxdb-http/src/app/app.html:30` 只按 $changeFeedOn 输出已接通/已断开；`apps/dev-rxdb-http/src/app/app.ts:311` 的初值来自 URL 开关，:445 与 :680 只从 adapter.changeFeedEnabled 回读。这个属性是调用方的启用意图，连接失败时会保持 true，README 的“运行时启停”明确说明了该语义。

`apps/dev-rxdb-http/src/app/setup_rxdb_http.ts:108` 已把真实故障交给 recordChangeFeedUnavailable；`apps/dev-rxdb-http/src/app/change-feed-diagnostics.ts:72` 也保留 unavailable 和 lastUnavailableMessage。完整模板却既不消费这两项，也不据此更新连接显示，所以已经收到故障报告仍不能改变“已接通”。浏览器 e2e 的 openDemo 只等待这个文案，:30 的意图位还会把它提前当成连接就绪信号。

## 修复方向

分别表达启用意图和实际连接状态。开关继续使用 changeFeedEnabled，连接标签通过宿主的连接/故障事实显示连接中、已接通或重连中，并展示现有故障说明；不要仅将故障计数大于零永久判为断开。补首次连接失败和已接通后掉线再恢复的可见状态断言。
