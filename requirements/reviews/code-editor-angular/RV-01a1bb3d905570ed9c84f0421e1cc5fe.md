# RV-01a1bb3d905570ed9c84f0421e1cc5fe：Angular 编辑器外部写入的光标与撤销回归绕过组件入口，只验证测试 helper

## 问题与影响

现有测试声称保证宿主外部写入保留光标/选区、只替换差量且不进入 undo 历史，四组关键断言却直接调用测试文件自写的 dispatchValue()。helper 自行计算正确差量并显式附加 addToHistory(false)，不会调用组件的 ngOnChanges() 或 writeValue()。若组件外部同步退化为全文替换或遗漏禁止入历史注解，这些断言仍会通过，已声明的用户体验回归没有被测试锁住。当前生产实现正确，本条是可定位的测试缺口，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/code-editor-angular/src/__tests__/code-editor.spec.ts:104` 的 dispatchValue() 在测试内计算差量，直接调用 EditorView.dispatch；external 参数只让 helper 自己写 Transaction.addToHistory(false)。
- 第 126–154 行的光标、范围选区、不入 undo 三个用例，第 165–180 行的最小替换用例，均通过这个 helper 完成所谓外部写入，没有触发组件输入或 CVA。
- 真正被承诺的组件入口在 `packages/code-editor-angular/src/code-editor.ts:351` 的 value 变更分支，以及第 427 行 writeValue()。测试 helper 不依赖这两处的实现；将其中差量替换改成全文替换，或删去 addToHistory 注解，不改变上述四个用例的执行路径和结果。
- 同目录其余测试已完整核对：实际 value/CVA 用例验证文本、事件或表单优先级；所有 selection/undoDepth 断言都集中在上述 helper 路径及用户直接编辑，没有另一组经真实入口覆盖该契约。
- React 的 `packages/code-editor-react/src/__tests__/CodeEditor.spec.tsx:116` 与 Vue 的 `packages/code-editor-vue/src/__tests__/CodeEditor.document-sync.spec.ts:36` 则通过 rerender/setProps 写入，再断言真实选区与历史，属于对应端有效的回归入口。

## 修复方向

把 Angular 四个契约用例改为通过 componentRef.setInput('value', ...) + detectChanges() 驱动；另覆盖初始化后的 writeValue() 或真实 FormControl.setValue()。断言光标、范围选区、实际 change span、undoDepth 和不反向上报事件。测试辅助函数只保留用于模拟用户编辑，不要在被验证的路径内自行实现同步算法和历史注解。
