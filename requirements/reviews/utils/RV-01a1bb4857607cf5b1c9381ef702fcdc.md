# RV-01a1bb4857607cf5b1c9381ef702fcdc：小数步长取整会把已经对齐的数值多抬高一整步

## 问题与影响

给 numberStep 传入合法的正有限小数步长，数值按十进制已对齐时，二进制除法误差可能让商略大于整数，Math.ceil 因而多进一整步。例如 numberStep(0.28, 0.01) 得到 0.29，而不是保持 0.28。用于表单固定步长等已声明场景时会改变用户值；小数边界触发，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/utils/src/number/numberStep.ts:23` 直接计算 Math.ceil(value / step) * step，没有对步长商的浮点误差作规范化。当前校验只限制 step 正且有限，并未把 API 限定成整数步长；已有测试也明确接受 2.5 步长。

对冻结源码经仓库 TypeScript 转成等价 JS 后隔离执行：

- value=0.07、step=0.01，商为 7.000000000000001，结果 0.08；
- value=0.14、step=0.01，结果 0.15；
- value=0.28、step=0.01，商为 28.000000000000004，结果 0.29；
- value=0.56、step=0.01，结果 0.5700000000000001。

这不是仅有尾部精度误差，而是多进一个完整步长。`packages/utils/src/__tests__/number/numberStep.spec.ts` 只覆盖整数和可精确二进制表示的 2.5，无法检出百分位步长。公开 barrel `packages/utils/src/number/index.ts` 与主入口导出它；`numberStepScreenSize` 也直接复用同一计算。

## 修复方向

按明确的小数步长精度规则进行整数域运算或商值误差规范化，保留负数的向上取整语义。补已对齐百分位、稍高于边界、负数和普通非对齐输入的回归，防止容差把真实跨步吞掉。
