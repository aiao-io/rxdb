# RV-01a1bbb13a4871648c4b48e970813a31：日期可转换谓词遇到 bigint 或 Symbol 会抛错

## 问题与影响

公开函数接受 unknown 并承诺返回是否可转换为有效日期，但对 bigint/Symbol 直接进入 Date 构造器，抛出 TypeError，调用方无法把它当作普通验证谓词使用。例：对混合未知输入逐项过滤 canBeDate，遇到1n即终止整个过滤。无效对象/空值已有false语义与测试，这两种不可转换值却走异常路径。属于输入校验边界，定为 P2。

## 证据与根因

冻结 SHA `0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/utils/src/date/canBeDate.ts:7` 参数为 unknown，`:8` 至 `:9` 仅排除部分非日期类型，`:11` 的类型断言不改变运行时值，new Date(1n)/new Date(Symbol())均抛TypeError，未能返回`:12`的布尔结果。原测试`packages/utils/src/__tests__/date/canBeDate.spec.ts`验证了{}、null、NaN、Infinity返回false，未覆盖这两类输入。

对原始TS仅做类型擦除后执行导出，实测1n→TypeError(Cannot convert a BigInt value to a number)、Symbol→TypeError(Cannot convert a Symbol value to a number)。证据在本组 `repro-utils-predicates-reentry-003.json`；未改源码或原测试。

## 修复方向

按已声明的Date/string/number输入域先做类型判定，不可转换类型返回false；增加bigint、Symbol及不可转换对象的谓词回归。不要只靠类型断言把unknown交给Date。
