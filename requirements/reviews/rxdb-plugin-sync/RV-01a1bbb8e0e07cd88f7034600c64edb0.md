# RV-01a1bbb8e0e07cd88f7034600c64edb0：bulkSync 的仅 pull 示例传 push:false，类型不接受且运行时仍会推送

## 问题与影响

消费者照 SyncManager.bulkSync 的公开 TSDoc 示例执行“并发模式仅 pull”时，传入 push:false。BulkSyncOptions.push 只接受 PushRepositoryOptions，TypeScript 消费者无法按例编译；JavaScript 消费者则没有这个类型检查，operation 仍为 undefined，在具备 Full/Filter 推送能力的仓库上会同时执行 push，可能把用户原本只想留在本地的待推变更发送出去。这是示例与已实现公开 API 契约的 P2 不一致，不需要并发复现才能判断。

## 证据与根因

冻结源码 SHA：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-plugin-sync/src/SyncManager.ts:618` 写“并发模式仅 pull”，`:619`–`:623` 只传 concurrent、concurrency 与 push:false，没有 operation。
- `packages/rxdb-plugin-sync/src/bulk-sync.ts:47` 的 push 声明是 PushRepositoryOptions，不是 boolean；`:31` 的 operation 才是 pull/push/sync 三态选择。
- `packages/rxdb-plugin-sync/src/bulk-sync.ts:306`–`:309` 把 options.operation 赋给 direction，把 options.push 当作推送选项转发，没有按 false 禁用方向。
- `packages/rxdb-plugin-sync/src/sync-repository.ts:285`–`:289` 在 direction 缺省且仓库具备 push 能力时进入推送分支；push:false 不参与 shouldPush 判定。
- 现有 `packages/rxdb-plugin-sync/src/__tests__/contracts/sync-manager-api.spec.ts:143` 起的类型断言也将 push 固定为 PushRepositoryOptions | undefined，未把这个文档片段编入断言。

上述结论直接来自参数与条件分支，未执行示例、被评审代码、测试、网络请求或探针。

## 修复方向

把该示例改成 operation:'pull'，与 BulkSyncOptions 的公开契约一致。保留 push 作为推送选项对象的含义。核对公开 TSDoc 示例的参数可编译且方向与文字一致，无需扩张运行时 API。
