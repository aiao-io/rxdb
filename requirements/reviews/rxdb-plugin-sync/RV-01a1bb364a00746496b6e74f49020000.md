# RV-01a1bb364a00746496b6e74f49020000：推送回执本地提交失败会抹掉已在远端生效的进度

## 问题与影响

远端已经 applied 一批变更，随后本地保存 remoteId/水位线因磁盘满、事务提交失败或分支校验拒绝而失败时，`pushRepository()` 抛出裸原始错误，丢掉已在远端生效的条数。`syncRepository` 和批量聚合无法辨认这次是部分完成，会显示零推送进度；调用方也无法按约定通过 `RxDBPartialSyncError.result` 得知远端已变更。水位线确实应回滚，但远端写不会随本地事务回滚。边界失败的结果契约错误，定为 P2；本次没有证明远端重复执行或永久丢数据。

## 证据与根因

完整冻结 SHA：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-plugin-sync/src/push-repository.ts:1024` 在远端回执确认后累加 `plan.pushed`。
- `packages/rxdb-plugin-sync/src/push-repository.ts:1114` 在 `persistPushReceipts` 失败时给所有 ready 计划强行传入 `pushed=0`。这只应撤回本地回执与被拒标记，却连远端已 applied 的事实一起删掉。
- `packages/rxdb-plugin-sync/src/push-repository.ts:142` 的 `throwPushFailure` 对 `pushed===0` 直接抛原错，正数才包装 `RxDBPartialSyncError`；因此这里不会附带进度。
- `packages/rxdb-plugin-sync/src/sync-repository.ts:147` 通过 `partialPushProgressOf` 读取进度，裸错误读不到，替换为 `emptyPushResult`；push-only 场景连 `persistedProgress` 也为 false。
- `packages/rxdb-plugin-sync/src/push-repository.ts:127` 已明确声明 pushed 的含义为「已经落在远端且不会回滚」。这与本地提交是否成功是两个事实。
- 现有 `packages/rxdb-plugin-sync/src/__tests__/push-repository.spec.ts:1454` 的本地提交失败用例只断言抛错、标记回滚、水位线不动，没有断言远端进度与 partial error。

本轮 `repro-push-receipt-progress.cjs` 在内存中转译真实 `push-repository.ts` 及现有测试接缝，只导出并调用既有 harness，不改测试文件。通过公共 `pushRepository(..., {includeRelated:false})` 发一条 INSERT；远端替身返回真实契约的 applied/remoteId，随后 saveMany 固定抛 `disk full`。断言远端调用一次、源变更一条；最终抛的就是原 Error，`partialPushProgressOf(error)===undefined`，本地 remoteId 与水位线均回滚。输出：`remoteApplied=1, localReceiptRolledBack=true, partialProgress=null, isPartialSyncError=false`。

## 修复方向

分别保留远端已 applied 的事实与本地提交失败的事实：本地回执/水位线照常整体回滚，抛错仍携带实际 `plan.pushed`。同步调整 `pushRepositoryResult` 的失败判定，不能只把 0 换成 pushed 后让 `failed===0` 将提交失败伪装成 success。补单仓、级联及 push-only 聚合的回归，断言错误根因、真实远端进度和未推进的本地水位线。
