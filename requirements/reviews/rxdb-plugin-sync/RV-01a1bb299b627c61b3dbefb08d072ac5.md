# RV-01a1bb299b627c61b3dbefb08d072ac5：QueryCache 的 public 裸标识在跨 namespace 同名实体下无法解析

## 问题与影响

同一 RxDB 配置同时注册 `public:Todo` 与 `tenant:Todo`，对 public 实体使用 QueryCache + Supabase 远端（或 PGlite 本地缓存）时，普通 `find/count` 在网络请求或缓存读写前就抛出实体名歧义错误。离线出站重放同样使用这个标识，恢复联网也无法推出 public 实体积压。tenant 实体正确传递 `tenant:Todo`，同一配置下可以解析。

这是允许跨命名空间同名配置时的边界故障，按 P2 记录；没有证据证明发生跨租户误写或数据损坏。

## 证据与根因

完整冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb/src/schema/SchemaManager.ts:99` 以 namespace + name 注册实体，只拒绝同一 namespace 内重名，允许上述配置。
- `packages/rxdb-plugin-sync/src/query-cache-entity-identifier.ts:28` 把 public namespace 有意删成裸 `Todo`，丢失原本已知的作用域。此 helper 是在线读写与离线重放共用的根因。
- `packages/rxdb-plugin-querycache/src/query-cache-primary.ts:454` 的 `createQueryCachePrimary` 直接消费 helper；`packages/rxdb-plugin-querycache/src/query-cache-primary.ts:409` 把结果交给 `fetchMetadata`。
- `packages/rxdb-plugin-sync/src/query-cache-outbox.ts:335` 的 flush 也交同一裸名给 probe / replay / repair。
- `packages/rxdb-adapter-supabase/src/entity_scope.ts:37` 对裸标识按所有 namespace 匹配，`packages/rxdb-adapter-supabase/src/entity_scope.ts:54` 在多匹配时抛 `SupabaseConfigError`。
- `packages/rxdb-adapter-pglite/src/query-cache/query_cache_target.ts:54` 对裸名也搜索全部 namespace，`packages/rxdb-adapter-pglite/src/query-cache/query_cache_target.ts:71` 在多匹配时拒绝。显式 `public:Todo` 可以唯一解析。
- 已完整核对 `packages/rxdb-plugin-querycache/src/__tests__/query-cache-primary.namespace.spec.ts`：仅覆盖非 public 的单个实体；未覆盖 public 与其他 namespace 同名的组合。

隔离复现位于本轮 plugins 目录的 `repro-querycache-public-namespace.cjs`。它转译并加载冻结工作区中的真实 helper、`createQueryCachePrimary`、Supabase/PGlite 作用域解析函数；只替换元数据来源和存储接缝，没有连接网络。实际断言：public 主仓储 `count` 抛 `multiple namespaces`；tenant 主仓储 `count` 返回 0；`public:Todo` 可由真实 Supabase 解析器唯一解析；PGlite 拒绝裸 `Todo`。这证实的是 public 同名组合，不能据此把所有非 public QueryCache 路由判为错误。

## 修复方向

在生产调用方保留已经确定的 public namespace，统一在线读写和离线重放的实体标识契约，并核对 HTTP resources 等现有裸名映射的兼容性。另一可行方向是适配器对裸名统一明确为 public，但需要同步三种后端契约；不要只改一个适配器掩盖差异。补 public + tenant 同名配置下的读、计数、在线写与离线重放回归。
