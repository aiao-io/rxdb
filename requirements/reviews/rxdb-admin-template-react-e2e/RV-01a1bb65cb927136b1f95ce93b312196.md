# RV-01a1bb65cb927136b1f95ce93b312196：列表有数据断言仅检查空态不存在，加载中或失败也可通过

## 问题与影响

实体页面尚未挂载、列表还在初始化，或页面已进入加载失败状态时，entity-empty-state 都可能不在 DOM。共享 helper 会把这些状态立即判成“列表有数据”。尤其已有数据恢复被拒后的保留性回归，以此作为最后的断言，不能证明原记录仍然读得出来。P2，明确测试缺口；不据此断言当前业务数据已经丢失。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/rxdb-admin-template-react-e2e/src/e2e-utils.ts:137` 的 expectListHasRows 仅在 :138 判断空态组件 count=0，没有等待实体壳/表格就绪，也不读取 canvas 的 records 或已知记录值。因此即便页面停在首页、加载指示器或失败态，该 helper 的唯一条件仍然满足。

`apps/rxdb-admin-template-react-e2e/src/backup-restore.spec.ts:211` 在恢复被拒后导航到实体页，紧接着调用此 helper 并结束测试，没有后续记录值或实际行数断言。三端 e2e 都配置使用同一 src 目录，缺口一并适用。正向的 expectActionIcon 已经能从真实 VTable 实例读取行数据，现有工具具备更强判据。

## 修复方向

先等实体列表及表格完成加载，确认没有错误，再从 VTable records/rowCount 或已知记录读取正向证据。数据保留性用例应检查原记录的身份和值，不能只检查“没有空态”。补加载中和失败态都不能满足有数据 helper 的反例。
