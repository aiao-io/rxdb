# RV-01a1bb9aac657e74801b00d8d21351fd：React Headless 旧弹窗取消后的迟到保存会关闭新弹窗

## 问题与影响

在 Headless 详情保存尚未完成时点击取消，随后打开另一篇文章或新建弹窗；旧保存完成后，新弹窗被关闭并显示 saved，尚未提交的草稿消失。取消按钮在保存期间仍可用，因此这是实际可达的异步会话交错，定 P2。

## 证据与根因

冻结源码：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `apps/dev-rxdb-react/src/app/pages/headless/detail-dialog.tsx:62` 等待 controller.save 后，只要结果 valid 就无条件 onClose(saved)，未核对组件或会话是否仍有效。第69行允许随时取消，第130行的取消按钮没有 saving 禁用条件。
- `apps/dev-rxdb-react/src/app/pages/headless/headless.page.tsx:45` 的 close 将该结果直接交给页面长期持有的 dialog.resolve；第69行按 open 状态挂卸载子弹窗，因此后续新弹窗仍复用同一个页面 dialog 控制器。
- `packages/rxdb-model/src/entity-detail/headless.ts:111` 在控制器已销毁时仍将有效提交结果返回原调用者，取消了控制器内部发布；这不会阻止消费方原 Promise 回调继续执行。`packages/rxdb-model/src/entity-dialog/headless.ts:61` 的 resolve 会关闭当前弹窗，没有旧会话身份可核对。

有界诊断 `/Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-react-headless-late-save.mjs` 转译冻结 React 的原 save/cancel 回调并直接加载冻结的真实 headless 控制器源码。将持久化延迟，按 save→cancel→dispose→open(new draft)→旧写入完成执行；新弹窗最终 open=false、result=saved。未使用已构建产物，未运行真实浏览器；原页面关闭回调按源码接线。

## 修复方向

为异步保存结果绑定具体的弹窗会话或组件有效期，旧弹窗卸载/取消后不得再关闭页面上的新会话。补充保存中取消、重新打开、旧结果晚到的交错用例；同时核对 Angular/Vue 事件绑定是否具有等价保护。
