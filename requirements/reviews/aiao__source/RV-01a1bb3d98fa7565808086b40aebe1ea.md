# RV-01a1bb3d98fa7565808086b40aebe1ea：删除整段大故事清单会让需求一致性门禁静默通过

## 问题与影响

requirements/README.md 的大故事索引整段丢失或引导格式被改掉时，即使仓库仍有 43 条分阶段故事，一致性门禁也返回无错误。读者失去受机器维护的索引，而 CI 仍声称派生视图一致。这是整段遗漏时的 fail-open，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/audit/requirements-consistency.mjs:683` 从故事正文算 actual，但在第 692 行只有 count 正则匹配时才核对数量，第 694 行只有 listed 非空时才比较集合。整段清单缺失会同时使两道条件为假。

读取冻结工作区全部故事元数据，actual 有 43 条；原 requirements/README.md 调用 checkBigStoryList 返回 []。仅在内存文本中移除“现有 43 条：...”这一行，再用同一 actual 调用，仍返回 []。未修改真实 README 或故事。

既有 requirements-consistency.spec.mjs 只验证清单存在但数字/成员不符；“run() 按 requirements/README.md 核对”回归也未覆盖整段缺失，源码注释所述“根 README 没有匹配、检查恒绿”的同类根因仍可触发。

## 修复方向

存在分阶段故事时，缺少清单数量或索引本身必须报错；即使 listed 为空，也要与 actual 比较。补整个清单移除、空清单、格式损坏和实际无大故事的边界回归。
