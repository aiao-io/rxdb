# RV-01a1bba86d8f7e7db7a84b5896178955：Code Scanning 同步只取首屏会误删仍开放的本地告警

## 问题与影响

当 CodeQL 告警清单超过100条（含已关闭历史条目）时，文档命令只拉取第一页，随后把「本地存在但清单没有」的编号直接删除。仍开放但位于后续页的告警因此从本地工作集消失，也不会按关闭流程保留处置结论。根文档和应用模板包含相同规则；这是告警较多时的同步边界，定为 P2。

## 证据与根因

冻结 SHA `0ffa3c419fcc59dc3e13d695ca4658116134bfa0` 中，`requirements/code-scanning/README.md:29` 请求 `per_page=100`，没有 `--paginate` 或 page 循环；`:43` 把未出现在结果中的本地编号当成应删除的记录。`requirements/app-template/code-scanning/README.md:23` 的同样单页命令和 `:32` 的缺席即删除规则会把缺陷复制到应用目录。

本机 `gh api --help` 明确说明 `--paginate` 才追加请求后续页。固定输入推演：远端101条告警均open，首页1..100，本地已有101；按文档执行结果删除101，但该告警远端仍open。本组 `repro-code-scanning-pagination-003.json` 保存完整输入和计算结果。没有查询真实GitHub清单、没有删除任何真实告警文件。

## 修复方向

完整收集全部页后再做缺席判定；分页失败时禁止把部分结果用于删除本地工作集。根文档和应用模板同步修正，可补101条及中途失败的流程示例。
