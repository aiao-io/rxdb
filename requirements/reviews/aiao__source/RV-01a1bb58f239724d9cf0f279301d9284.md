# RV-01a1bb58f239724d9cf0f279301d9284：Docker 快速开始依赖未入库的环境变量模板，干净检出无法启动

## 问题与影响

干净 clone 或新 worktree 按 Docker README 初始化本地测试环境时，第一步复制 .env.example 就报文件不存在，无法获得 Compose 所需的数据库、网关与鉴权配置。仓库的 postinstall 也不会生成这份缺失模板。老检出可能残留未跟踪文件而掩盖问题，新的贡献者必现，定为 P1。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`docker/README.md:16` 指示在 docker 目录执行 cp .env.example .env，但冻结 Git 树既没有 docker/.env.example，也没有根 .env.example。工作区同样缺少二者；对 docker 模板执行普通文件复制得到 ENOENT。

`.gitignore:15` 的 .env* 会忽略同名示例文件，现有树又未以例外或强制跟踪形式保留任何模板。`scripts/check-workspace.mjs:38` 虽列出根与 Docker 的示例路径，第 52 行仅在 examplePath 存在时复制，缺模板时直接跳过，因此 pnpm install 无法修复快速开始所需的输入。

这是独立于 Compose 项目名冲突的问题：即使修复关联 RV 的初始化目标，新检出仍无法执行 README 的模板复制步骤；反之，仅恢复模板仍会遇到关联 RV 的 init 项目冲突。

## 修复方向

恢复并跟踪只含示例/占位值的 Docker 环境模板，确保 ignore 规则允许它入库；或把文档改成有确定生成源、可在干净检出成功执行的初始化命令。补针对冻结/干净工作树的快速开始输入完整性检查，不依赖开发机未跟踪文件。
