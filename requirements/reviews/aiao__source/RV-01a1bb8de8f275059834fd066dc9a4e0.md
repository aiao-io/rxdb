# RV-01a1bb8de8f275059834fd066dc9a4e0：漂移门禁允许给 executor 的声明借用于 adapter 写入

## 问题与影响

同一具名函数中先给 executor 声明意图，再错误地改为 adapter.mergeChanges，静态门禁仍通过；两者是不同作用域对象时，真实 adapter 上没有该声明。重构写宿主的漂移因此不能在既定门禁中被发现。运行期通道按对象登记，问题属于一致性漏检，定为 P2，不描述为权限防御边界被攻破。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/audit/working-tree-callsite-drift.mjs:717` 至第722行只按所属函数找声明，再判断声明键是否在登记表；没有把 declaration.scope 与 call.receiver 关联。前面的声明校验只检查 scope 是否属于 adapter/executor 词表，两个名字都合法，错误关联便被放过。

隔离样本在 merge_branch(adapter: Host, executor: Host, actions: unknown[]) 中调用 declareTrustedWrite(executor, 合法登记键)，下一行调用 adapter.mergeChanges(actions)。真实 auditSource 返回 []。对同一有完整类型声明的样本做 TypeScript strict/noEmit 校验，诊断也为 []，因此不是编译器已经能抓到的错误。

`packages/rxdb/src/trusted-write/trusted-write-scope.ts:106` 实际把声明写入以 scope 对象为键的 WeakMap；takeDeclaredWrite 必须使用同一对象。给 executor 的声明不会出现在另一个 adapter 对象上。既有 spec 只检查 repo 这类不在词表的宿主，没有两个合法宿主互换的回归。

## 修复方向

为每处写入匹配同一作用域宿主上的有效声明，保留对真实函数归属、登记键和时序的校验；补两个合法但不同的对象、正确同宿主及别名约束回归。
