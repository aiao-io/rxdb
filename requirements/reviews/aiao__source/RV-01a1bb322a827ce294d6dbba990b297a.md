# RV-01a1bb322a827ce294d6dbba990b297a：API 门禁漏掉纯值导出改为 type-only 导出的破坏性变化

## 问题与影响

将公开常量或函数的 export 改成 export type 后，TypeScript 发射会完全移除对应运行时导出；但 API 表面工具仍把它记为 value，与旧基线完全一致。门禁因此漏掉消费者运行时 import 会失败的破坏性变化。触发限于纯值符号的 type-only 重导出，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/audit/api-surface.mjs` 的 extractExports 先按声明 flags 求 isType，再以 isTypeOnlyExport 屏蔽 isValue；然而当原符号为纯值时，两者同时为 false，kind 三元表达式的最后分支仍返回 value。

隔离源码 models.ts 导出 VERSION 常量和 runTask 函数；before.ts 通过 export { VERSION, runTask } 转出，after.ts 改成 export type { VERSION, runTask }。对两份入口执行真实 extractExports，前后都得到 runTask/value、VERSION/value。对 after.ts 用当前仓库 TypeScript 发射，实际输出只有 export {};，没有任何运行时导出。

既有 api-surface.spec.mjs 的 type-only 回归只有 class（声明本身有 Type flag），纯值对照 VERSION 仍是正常值导出，不能检出两 flag 同时为 false 的分支。

## 修复方向

显式根据导出语法区分 type-only，不能在 isType/isValue 均为 false 时退回 value。补常量、函数、逐 specifier type-only 和声明级 type-only 的前后基线差异回归，并核对发射后的运行时导出。
