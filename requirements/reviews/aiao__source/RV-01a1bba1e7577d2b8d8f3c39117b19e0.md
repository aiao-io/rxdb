# RV-01a1bba1e7577d2b8d8f3c39117b19e0：显式声明的 preset 模板文件缺失时静默丢弃贡献层

## 问题与影响

启用的 preset 在有效 manifest 中声明 plan-template 的 append/prepend/wrap 或 replace 文件，但该文件丢失时，解析器不报错，直接跳过这个层并使用低优先级/core 模板。计划可继续生成，看起来成功，却遗漏 preset 要求的内容和约束。使用扩展模板的路径才触发，定为 P2。

## 证据与根因

冻结 SHA `0ffa3c419fcc59dc3e13d695ca4658116134bfa0` 的 `.specify/scripts/bash/common.sh:780` 已识别显式声明；`:792` 至 `:795` 对不存在文件只留下空 candidate，`:804` 至 `:811` 跳过该层，随后继续 core。`.specify/scripts/bash/setup-plan.sh:48` 把返回0视为成功并在 `:54` 写入 plan.md。`.agents/skills/speckit-constitution/SKILL.md:82` 的解析契约要求模板栈成功、不得只保留部分贡献层。

本组临时 fixture：启用 priority1 的 guard preset，其有效 `preset.yml` 声明 plan-template → `templates/missing-guard.md`、strategy append；core 内容为 CORE-ONLY。source 实际 common.sh 后调用 resolve_template_content，返回0、stdout=`CORE-ONLY\n`、stderr空。使用本机 specify-cli 自带 Python/PyYAML，见 `repro-template-missing-layer-pyyaml-003.json`。首次系统 Python 缺 PyYAML 的失败输出另保留，未将该失败当作此缺陷证据。

## 修复方向

当 manifest 已明确声明模板时，无法读取或不合法的文件路径应使整个解析失败；保留没有声明该模板时跳过 preset 的现有行为。为缺文件的组合层和 replace 层补回归。
