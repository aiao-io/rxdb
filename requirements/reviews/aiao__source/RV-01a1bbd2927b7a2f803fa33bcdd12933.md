# RV-01a1bbd2927b7a2f803fa33bcdd12933：Supabase Docker 测试库未建立 MenuLarge 的同级唯一约束

## 问题与影响

发布的 `MenuLarge` 实体声明 `(parentId, title)` 的 normalized unique sibling index，树唯一性套件也把重复根/同级菜单作为契约；但 Docker/Supabase 初始化的 `public.menu_large` 只建了 parentId 与 sortOrder 普通索引，没有 `parent_title` 唯一索引或等价约束。使用这套初始化数据库的 Supabase 适配器可以写入重复同级菜单，行为与实体元数据及其他适配器不一致，定为 P1。

## 证据与根因

冻结 SHA `0ffa3c419fcc59dc3e13d695ca4658116134bfa0`：`packages/rxdb-test/entities/MenuLarge.ts` 声明 `parent_title`，`packages/rxdb-test/src/__tests__/entity-model-contract.spec.ts` 明确要求该索引 `unique=true, normalized=true`，`packages/rxdb-test/src/tree-unique/sibling-unique.suite.ts` 覆盖重复同级菜单应拒绝。对应 `docker/sql/03-business-tables.sql:54-68` 只创建 `menu_large` 表、`idx_menu_large_parent_id` 和 `idx_menu_large_sort_order`；全文没有 `parent_title`、`lower` 或 `COALESCE` 的唯一索引。

固定输入证据写入本组 `repro-docker-menu-unique-004.json`：同一 parentId/title 的实体 metadata 约束为拒绝，Docker SQL 的约束集合为空。未连接真实 Supabase；该结论由已读源模型、契约测试和初始化 SQL 的完整交叉核对得出。

## 修复方向

在 Docker/Supabase 初始化 SQL 中补充与 normalized metadata 同语义的唯一索引（对 NULL parentId 与大小写归一化），并让远端 tree-unique 套件使用这份初始化库验证重复根/同级写入和并发写入。
