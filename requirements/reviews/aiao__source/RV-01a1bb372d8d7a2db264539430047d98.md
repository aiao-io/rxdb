# RV-01a1bb372d8d7a2db264539430047d98：惰性后端门禁把不可达的孤立 chunk 当作可加载的后端分支

## 问题与影响

产物目录仍有包含后端标记的孤立 JS，但应用的任何入口都无法加载它；只要首屏图另有一个不相关的动态路由 import，惰性后端门禁就会全绿。后端分支已失去可达性或动态导入已被改错时，这条宣称验证两条按需加载分支的门禁漏报。属于产物图边界，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/audit/desktop-lazy-backend.mjs:175` 只检查标记在某个非首屏文件中，未验证该文件可从入口动态可达。`scripts/audit/desktop-lazy-backend.mjs:204` 至 `scripts/audit/desktop-lazy-backend.mjs:210` 虽收集 dynamicTargets，最终只断言集合非空，既不读取这些目标的传递图，也不把后端标记与目标关联。

隔离产物为 index.html → main.js → framework.js 的静态图，main.js 另有动态 import(route.js)，route.js 只有 unrelatedRoute。orphan-backend.js 包含全部 9 个 LAZY_MARKERS，但没有任何 import 指向它。真实 auditDemo 返回“✓ 首屏 2 个 chunk，惰性 2 个；9 个标记全部只出现在惰性 chunk 里”。后端实际上完全不可达。

既有 desktop-lazy-backend.spec.mjs 的孤立 chunk 用例只覆盖首屏完全没有动态 import 的情况；添加一个无关路由动态 import 就绕过了那条检查。

## 修复方向

从首屏种子沿静态与动态边构造实际可达图，验证每类后端标记由可达的惰性分支承载，并检查目标存在。补“无关动态路由 + 后端标记孤岛”的负例。
