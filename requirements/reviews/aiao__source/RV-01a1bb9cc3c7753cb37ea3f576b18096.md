# RV-01a1bb9cc3c7753cb37ea3f576b18096：覆盖率首页刷新在报告目录并发重建时终结服务

## 问题与影响

运行 `pnpm coverage:serve` 并同时重跑覆盖率时，Vitest 清理/重建输出目录；首页请求扫描到的某个包目录可能在 `readdirSync` 后、`statSync` 前消失。`listReports` 的异常逃出 HTTP 请求回调，客户端得到连接重置，整个本地服务退出。文件读取分支已有竞态处理，但首页仍存在这条失败路径。属于本地并发刷新边界，定为 P2。

## 证据与根因

`scripts/coverage-serve.mjs:236` 对 group 先 exists 后 stat；`:239` 先列目录，`:241` 对每项直接 stat，没有捕获 ENOENT。`:723` 在每次首页请求中直接调用 `renderIndex(listReports())`，异常未被请求处理器拦截。以上均对应冻结 SHA `0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

复制该 SHA 相同的脚本到本组辅助目录，建立一个有效报告；只在服务器成功启动后的首次首页扫描注入一次 statSync ENOENT。真实 HTTP 请求得到 `ECONNRESET`，子进程退出码 1，栈为 `listReports:241` → 请求回调 `:723`。复现脚本 `repro-coverage-list-race-003.mjs` 和输出 `repro-coverage-list-race-003.json` 在本组目录。注入模拟目录并发消失，不声称运行了 Vitest。

## 修复方向

目录枚举和 stat/read 统一处理输出目录刷新时的 ENOENT/ENOTDIR；允许本次报告项消失或返回可恢复响应，避免异常终结监听进程。补首页并发目录刷新回归。
