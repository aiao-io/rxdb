# RV-01a1bb9cc4247851ab37c7e9f32a6189：任务转 issue 按局部任务编号去重会吞掉其他 feature 的任务

## 问题与影响

同一仓库先后为两个 feature 生成 tasks.md 并执行 taskstoissues 时，每个 feature 都从 T001 编号。已有 feature A 的 `T001: Create auth model` 会使 feature B 的 `T001 Create search model` 被标成已有 issue 并跳过；若编号全部重叠，第二个 feature 一个 issue 都不会创建。去重未包含 feature 身份或任务文件路径。影响多 feature 的任务跟踪边界，定为 P2。

## 证据与根因

冻结 SHA `0ffa3c419fcc59dc3e13d695ca4658116134bfa0` 中，`.agents/skills/speckit-tasks/SKILL.md:155` 规定从 T001 顺序编号，`.specify/templates/tasks-template.md:52` 也从 T001 开始；`.agents/skills/speckit-specify/SKILL.md:83` 为 feature 创建独立目录。`.agents/skills/speckit-taskstoissues/SKILL.md:77` 列全仓 issue 后只用 `\bT\d{3,}\b` 匹配局部 ID，`:79` 据此跳过任务。Claude 的对应逻辑在 `:80`，Copilot 在 `:71`，均未限定 feature。

固定输入：feature A 已有 T001/T002 的 auth issue，feature B 的 search tasks 也是 T001/T002；执行指令规定的正则和匹配规则，实际 skipped=2、created=0，正确的新任务数应为 2。完整输入/输出在本组 `repro-task-issue-feature-collision-003.json`。这是指令算法的确定性推演，没有访问或创建真实 GitHub issue。

## 修复方向

把 feature 的稳定身份与任务 ID 一起写入 issue 并共同匹配；保持同一 feature 重跑幂等，同时避免不同 feature 共用 T001 时碰撞。三份平台指令保持一致。
