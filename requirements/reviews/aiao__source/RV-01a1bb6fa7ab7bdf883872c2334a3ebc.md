# RV-01a1bb6fa7ab7bdf883872c2334a3ebc：日志版全量检查遇到新文件时漏掉已修改源码

## 问题与影响

工作区同时有已修改的受跟踪源码和任意新文件时，pnpm test-all:log 默认只把 --untracked 传给 Nx。Nx 因此只评估新文件，已修改的产品源码及其依赖者不进入 affected 集合，脚本仍可能汇报全量检查通过。新增测试或需求文件同时修改实现是常见流程，定为 P1。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/test-all-log.mjs:127` 至 `scripts/test-all-log.mjs:137` 根据 git status 二选一：只要有 ?? 行就返回 --untracked；分支中的已修改文件完全被覆盖。buildNxArgs 在第 155 行原样使用该结果。

当前锁定的 Nx 24.0.5 的 parseFiles 对 untracked 分支只返回 getUntrackedFiles()；--base 分支才合并提交差异、未提交修改和未跟踪文件。该行为已用工作区安装的实际解析器验证，未凭 CLI 名称猜测。

在本组用只响应只读查询的 Git 替身提供状态：一条 M packages/rxdb/src/review-case.ts 和一条 ?? scripts/review-new.mjs。真实脚本 --dry-run 输出只含 --untracked。把该选择交实际 Nx parseFiles，结果只有 scripts/review-new.mjs；--base=main 对照则包含两条路径。没有修改源码、没有运行 Nx 任务或 Git 提交。

既有 test-all-log.spec.mjs 校验目标集合、日志解析和参数透传，没有混合已修改/未跟踪文件的范围选择回归。

## 修复方向

默认以基线分支收齐所有应检查文件，或显式合并各类改动后传给 Nx；不能用一种状态替代另一种状态。补已提交分支变更、已修改文件、新文件混合存在的范围回归，并断言产品源码不会遗漏。
