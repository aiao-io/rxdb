# RV-01a1ba456acb7b83a1e877e0aedfe967：整个项目被删除时分支评审遗漏全部删除单元

## 问题与影响

功能分支删除一个完整 Nx 项目（包括 `project.json`），`affected` 正确返回原项目名，但后续 `status --project <原名> --range branch` 报未知项目；改用 `--project all` 又把该项目的全部删除文件滤掉，甚至返回 `required=0 / complete=true`。删除公开包或应用时无法登记删除侧审查，可能在未核对消费者的情况下误报已完成。定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/ai-review/ai-review.mjs:372` 至 `scripts/ai-review/ai-review.mjs:373` 只从 head 树构造可选项目集合。虽然 `branchChanges()` 对删除文件使用 base 侧项目归属，但其结果随后用这个仅来自 head 的 `selected` 集合过滤，因此已消失的项目永远不会被选中。

在独立临时 Git 仓库建立根项目与 `core` 项目，提交后从 `main` 建功能分支，删除 `packages/core/`（含项目配置与源码）并提交。使用导出 API 在该分支快照执行：

- `affectedProjects(...).projects` 得到 `["core"]`；
- `requiredUnits(..., projects: ["core"], range: "branch", base: "main")` 抛 `未知项目 core；候选：无`；
- `coverageStatus(..., projects: "all", range: "branch", base: "main")` 返回 `required: 0, outstanding: 0, complete: true`。

现有 `affectedProjects` 测试恰好包含删除整个 `core-angular` 的场景，但没有把该结果继续传给 `requiredUnits` / `coverageStatus`。

## 修复方向

仅在 `range=branch` 下合并 merge base 与 head 的项目元数据，用于项目名校验、all 选择和删除侧归属；项目改名同样保留原名删除单元。补从 affected 到 status、cover 的完整删除项目回归。
