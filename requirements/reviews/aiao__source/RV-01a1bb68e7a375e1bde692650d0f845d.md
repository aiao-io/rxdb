# RV-01a1bb68e7a375e1bde692650d0f845d：静态服务在文件检查与 stat 之间发生删除时会崩溃

## 问题与影响

构建进程在静态服务已确认文件存在之后删除或替换该文件，statSync 抛 ENOENT 时，请求处理器没有捕获，整个 Playwright webServer 进程退出。后续 e2e 用例因此全部连接失败。该脚本已针对同类 readFileSync 竞态承诺返回 500 并存活，但 stat 路径仍遗漏，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/e2e-static-server.mjs:200`、`scripts/e2e-static-server.mjs:205` 都在 try/catch 之外执行 existsSync → statSync。后面的异常保护仅包住 readFileSync，覆盖不到 stat 的失败。

在本组临时静态根建立真实 asset.txt，以单独 Node 子进程启动真实 startStaticServer；通过 syncBuiltinESMExports 对 fs.statSync 做故障注入，仅在请求该文件、且 existsSync 已成功后抛出 ENOENT，模拟另一构建进程删除文件的时序。一次 GET 即使子进程 exit 1，栈明确落在原脚本第 200 行。既有 spec 只注入文件读权限错误并验证 500，没有覆盖存在性检查后的 stat 失败。

## 修复方向

把请求中的文件定位、目录/文件判定及读取纳入一致的异常处理，或用一次可捕获的查找流程避免检查后再使用的竞态；补 stat 阶段失败后服务仍可处理下一请求的回归。
