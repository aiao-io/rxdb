# RV-01a201324fef7a3081ab7f05da54c1cf：更新已有 agent 上下文时会跳过 Recent Changes 区块

## 问题与影响

已有上下文文件同时包含 `## Active Technologies` 和后续的 `## Recent Changes` 时，运行 `update-agent-context.sh` 更新项目上下文，不会把本次 feature 写入 Recent Changes，也不会执行只保留最近两条旧记录的逻辑。脚本仍会成功退出，调用方会得到看似成功但历史区块没有更新的 agent 上下文。该路径是更新已有 Claude、Copilot、Cursor 等上下文文件的正常流程，属于边界内容更新错误，定为 P2。

## 证据与根因

证据快照：`084a80d0f64ef6af2b1944f7b82116416004c230`。

`.specify/scripts/bash/update-agent-context.sh:460-468` 在 `in_tech_section` 为真时把任意二级标题当作 Active Technologies 的结束，并执行 `continue`。因此紧随其后的 `## Recent Changes` 永远不会到达 `.specify/scripts/bash/update-agent-context.sh:479-488` 的 Recent Changes 分支，`in_changes_section` 不会置为真，`new_change_entry` 也不会写入。

在临时 Spec Kit 项目中创建 `specs/001-demo/plan.md`，已有 `CLAUDE.md` 内容为 Active Technologies、Recent Changes 及三条旧记录，再运行：

```text
SPECIFY_INIT_DIR=<临时项目> SPECIFY_FEATURE_DIRECTORY=specs/001-demo SPECIFY_FEATURE=001-demo \
  bash .specify/scripts/bash/update-agent-context.sh claude
```

命令返回 0，Active Technologies 新增了本次技术栈，但 Recent Changes 仍保留原三条记录且没有新增 `001-demo`，与函数注释和“最近 3 个 feature”模板契约不符。

## 修复方向

让 Active Technologies 的结束分支在写入标题后继续处理标题，或单独识别并初始化 Recent Changes 区块。补充已有上下文文件中 Active Technologies 紧邻 Recent Changes、已有 0/1/2/3 条记录以及缺少任一区块的回归测试。
