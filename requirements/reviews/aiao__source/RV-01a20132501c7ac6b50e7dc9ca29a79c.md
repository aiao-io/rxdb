# RV-01a20132501c7ac6b50e7dc9ca29a79c：Python auto-commit 忽略 conventional commit 配置并错误提交固定消息

## 问题与影响

用户把 `.specify/extensions/git/git-config.yml` 的 `commit_style` 设为 `conventional`，并启用某个事件的自动提交后，通过随扩展提供的 Python `auto_commit.py` 执行该事件，脚本不会要求 agent 提供生成的 Conventional Commit 消息，也不会读取 `--message-file`。它会直接提交配置中的固定消息或默认消息，导致提交策略被绕过，并且 Python、Bash、PowerShell 三个实现的行为不一致。该路径会产生错误的提交历史，定为 P2。

## 证据与根因

证据快照：`084a80d0f64ef6af2b1944f7b82116416004c230`。

扩展命令契约在 `.specify/extensions/git/commands/speckit.git.commit.md` 要求 `conventional` 模式必须使用 agent 生成的单行消息，缺少消息时失败。Bash 实现的 `.specify/extensions/git/scripts/bash/auto-commit.sh:90-101`、`:188-193` 和 PowerShell 实现的 `.specify/extensions/git/scripts/powershell/auto-commit.ps1:193-201` 都执行了该判定。

`.specify/extensions/git/scripts/python/auto_commit.py:148-177` 只解析 enabled 和 message，随后无条件在 `:176-177` 回退到 `[Spec Kit] Auto-commit ...`，没有读取 `commit_style`、没有解析消息文件，也没有在 conventional 模式缺少消息时失败。

在临时 Git 项目中设置：

```yaml
commit_style: conventional
auto_commit:
  after_specify:
    enabled: true
    message: fixed configured
```

修改一个已跟踪文件后运行 `python3 .specify/extensions/git/scripts/python/auto_commit.py after_specify`，命令返回 0，提交标题为 `fixed configured`。按命令契约该调用应拒绝提交并报告缺少生成消息。

## 修复方向

让 Python 端与 Bash、PowerShell 使用相同的参数契约，支持 `--message-file` 或等价的安全文件输入，读取并校验 `commit_style`，在 `conventional` 模式缺少生成消息时返回失败，并忽略配置中的 fixed message。补充 fixed、conventional 有无消息及消息含特殊字符的跨实现回归测试。
