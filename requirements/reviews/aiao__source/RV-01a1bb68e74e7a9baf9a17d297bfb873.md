# RV-01a1bb68e74e7a9baf9a17d297bfb873：通配分支配置使本地提交与推送文案校验全部被跳过

## 问题与影响

根 workspace 配置把 NEED_CHECK_COMMIT_BRANCH_NAMES 设为 ['_']，表示所有分支都要校验，但检查函数只判断数组是否包含完整分支名。因此 main、codex/_ 等实际分支均返回 false，本地 commit-msg / pre-push 对不合规标题静默 exit 0。默认配置下普遍触发，定为 P1。CI 的 --message 模式先于分支判断，仍会校验 PR 标题。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/commit-lint.mjs:115` 至 `scripts/commit-lint.mjs:116` 没有识别配置约定的 '*'；第 297 行据此提前返回。配置源是 scripts/workspace.mjs 的 NEED_CHECK_COMMIT_BRANCH_NAMES，调用者为 .husky/commit-msg / .husky/pre-push。

隔离调用实际导出函数，得到 configuredBranches=['*']、shouldCheckCurrentBranch('main')=false、shouldCheckCurrentBranch('codex/example')=false。同一条非法文案直接交 validateCommitMessage 得到 ok=false，但把它写入本组消息文件再执行真实 commit-lint CLI，退出码为 0、只有启动横幅，没有校验结果。没有执行 git commit 或 git push。

## 修复方向

显式实现约定的全部分支标识，同时保留 detached HEAD 的既定处理；补默认配置下 main/特性分支及直接消息、消息文件模式的回归。
