# RV-01a1bb79f54b77beb3fde42360957fcf：renderer 产物内建依赖门禁漏掉裸 Node 模块名

## 问题与影响

桌面适配器 renderer 产物若引入 fs、path 等不带 node: 前缀的 Node 内建模块，消费者审计不会记录它们，无法兑现“renderer 依赖图不得出现 Node 内建”的发布门禁。Node 中执行探针又能正常加载这些模块，因而不能补上这一判断缺口。属于特定导入写法的漏检，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`scripts/audit/desktop-adapter-consumer.mjs:307` 只以 startsWith('node:') 识别内建。裸 fs 经 createRequire.resolve 得到的仍是字符串 fs，随后既不含 node_modules/@aiao，也不在 renderer 目录前缀下，因此被当成外部依赖跳过。

从冻结脚本的 runtime 模板抽取原样 collectGraph 与正则，只还原模板中的反斜杠转义，用同一逻辑检查两个真实小模块。import fs from 'fs' 的结果是 files=1、builtins=[]；把同一导入改成 node:fs 后，builtins 正确记录 node:fs。后续断言只检查 builtins.size，所以裸名能绕过这一项门禁。没有运行耗时的 pack/install/tsc 全链路。

## 修复方向

用 Node 提供的内建模块判定统一识别裸名和 node: 名，保留对外部非本仓库依赖的既定范围。补 bare/prefixed、静态和动态导入的产物图回归。
