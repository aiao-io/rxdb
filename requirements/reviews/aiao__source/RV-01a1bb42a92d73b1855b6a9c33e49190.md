# RV-01a1bb42a92d73b1855b6a9c33e49190：隔离回归在没有默认容器的干净机器上误判并失败

## 问题与影响

机器上本来没有 supabase-db 或 supabase-kong 时，隔离回归脚本把 Docker inspect 的失败输出与 absent 拼成带前导换行的字符串，后面误认为默认容器原本存在。即使新起的两套隔离环境完全正常，脚本仍在检查不存在的默认容器时退出 1，无法证明干净机器的隔离行为。定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`docker/supabase-ci-isolation-regression.sh:36`、`:37` 使用 $(docker inspect ... || echo absent)。当前 Docker CLI 对不存在对象会在 stdout 先输出一个换行，然后以非零码退出；echo absent 拼接后得到换行 + absent。命令替换只删结尾换行，不删前导换行。

第 87 行和第 91 行用字符串与 absent 比较，得到“不相等”，随后第 88/92 行再次无保护 inspect 不存在的默认容器；set -e 使整条回归失败。

真实只读执行 docker inspect -f Id root-review-deliberately-missing-01a1bb，返回 code=1、stdout 为单个换行。运行与脚本完全相同的赋值和判断后，实际进入 branch=preexisting；字节为 0a 61 62 73 65 6e 74（前导换行加 absent）。没有创建或删除容器。

## 修复方向

在命令失败分支直接赋值为明确 sentinel，或先单独判断成功与否后再使用输出，避免把失败时 stdout 与 echo 拼接。补默认环境缺席、只有一个默认容器和默认环境已存在的分支测试。
