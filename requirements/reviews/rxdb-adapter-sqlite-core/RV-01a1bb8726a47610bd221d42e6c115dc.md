# RV-01a1bb8726a47610bd221d42e6c115dc：查询 SQL 压缩空白改写字符串字面量，等值筛选命中另一行

## 问题与影响

普通 string 字段等值筛选的值含连续空格、换行或 tab 时，查询编译器把 SQL 字面量里的空白一起压成单个空格。例如查询 `a  b` 会变成查询 `a b`，漏掉目标行并命中另一行。核心 JS 增量匹配仍按原值比较，首屏 SQL 与后续实时匹配不一致。普通用户文本就能触发，定 P1；未声称本次会改写数据库里的值。

## 证据与根因

源码快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-sqlite-core/src/query/query_sql.utils.ts:636` 的 build_rule 在末尾对已拼好字段、操作符和字面量的完整 SQL 执行 `/\s+/g` 替换。此时 get_rule_value / get_sql_value 已把值放进单引号字符串，替换没有识别 SQL 词法边界，改变字面量内容；被引用的标识符里的连续空白同样会受影响。

入口 `packages/rxdb-adapter-sqlite-core/src/query/query_sql.ts:114` 在 buildRuleGroup 内调用 build_rule，find/count 的正常条件都经此处。bigint/binary 参数化值与提前返回的子串分支不属于这次已证的普通等值路径，不能一概扩报。

新有界诊断转译冻结查询编译器和依赖，使用真实 SQLite 建两行 wanted=`a  b`、other=`a b`。同一个 RuleGroup 的编译结果实际为 `_."value" = 'a b'`，SQL 返回 other；真实核心 isEntityMatchWhere 对原规则返回 wanted。没有 mock 编译、数据库或 JS 匹配。

## 修复方向

停止对完整 SQL 做无差别空白替换，直接按生成阶段的片段拼接。若需要格式规范化，只能处理明确的 SQL token 边界。补连续空格、换行、tab 的等值/不等值/IN/区间对照与 JS 匹配一致性；不要把合法业务文本预先 trim 或压缩来迁就 SQL。
