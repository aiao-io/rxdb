# RV-01a1bb5da749776ebe2e03b3b16448ad：加密列的静态 default 被明文写入 SQLite schema 与物理文件

## 问题与影响

实体属性同时声明 `encrypted: true` 与非函数、非 binary 的静态 `default` 时，元数据被接受，但生成器直接把缺省值写进 `CREATE TABLE ... DEFAULT ...`。不需要创建任何业务行或解锁，默认明文就已进入 `sqlite_master.sql` 和物理库文件。声明加密的值因此不满足本地静态零明文保证。定 P1：触发依赖该受支持的 schema 组合；不声称所有加密列都泄漏，也未证明任意运行时用户输入都会写入 schema。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-sqlite-core/src/table/create_table_sql.ts:87` 的 hasDbDefault 只排除 UUID 主键已有缺省值；`packages/rxdb-adapter-sqlite-core/src/table/create_table_sql.ts:88` 的分支只检查 default 存在、非函数、非 binary，未排除 `property.encrypted`。第 98 行用普通 SQLite 类型转换处理缺省值，第 108 行将其作为明文 SQL 字面量拼进 DDL。加密仅改变列类型并在其他分支禁用类型 CHECK，不保护 DEFAULT 文本。

实际建表入口 `packages/rxdb-adapter-sqlite-core/src/RxDBAdapterSqliteBase.ts:994` 调用 `create_tables_sql()`；`packages/rxdb-adapter-sqlite-core/src/table/create_tables_sql.ts:31` 逐实体调用该 DDL 生成器。元数据层并未拒绝此组合：core 的 transitionMetadata 仅收集加密属性，adapter 的加密校验也未禁止 default。

新建有界 Node 诊断直接转译冻结的 create_table_sql、exclusion_trigger_sql、table-name-resolver、sqlite-core.utils 源文件；用真实 transitionMetadata 与加密元数据校验生成 schema，再用 Node 内置真实 SQLite 创建文件：

1. 属性 secret 为 string、encrypted=true、default=`DEFAULT_SECRET_storage_review_20261108`。
2. 元数据验证通过，实际生成 `"secret" TEXT DEFAULT 'DEFAULT_SECRET_storage_review_20261108' NOT NULL`。
3. 查询真实 `sqlite_master`，该字符串原样存在。
4. 关闭连接后读取 12,288 字节物理文件，原始字节也含相同明文。

没有 mock DDL、元数据校验、SQLite 或物理文件读取；未运行浏览器后端全套，也未重复旧的五个诊断。

## 修复方向

加密列的缺省值应在写入前按属性元数据补齐并封成信封，不应出现在数据库 DDL 的 DEFAULT 中。同步核对单条 INSERT、批量 INSERT、初始数据播种与迁移；若暂不支持 encrypted+default，需在 schema 校验时明确拒绝。补 sqlite_master/物理文件哨兵扫描及单条、批量缺省值往返测试。存量库 schema 已含明文的清理需要单独处理，单改新建 DDL 不会抹去旧 schema 与空闲页。
