# RV-01a1bb30d8a87b148e1d76491dc76226：OO1 部分纯读查询返回上一条写入的 rowsAffected

## 问题与影响

在同一连接上成功写入一行后，执行包含分号文本字面量、文本 `returning` 或 CTE 的纯读查询，返回 `rowsAffected: 1`；数据库实际没有修改。普通 SELECT 返回 0，两者行为分歧。公共客户端调用者若以此字段统计写入或判定读写结果，会得到上一笔写入的计数。查询数据本身仍正确，属于边界 SQL 形态的结果契约错误，定 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-sqlite-core/src/execute_oo1_helper.ts:93` 只在 prepared 分支用 `isReadOnlyStatement()` 把纯读计数置零。`packages/rxdb-adapter-sqlite-core/src/execute_oo1_helper.ts:109` 的 exec 分支无条件返回 `db.changes()`，SQLite 对 SELECT 保留上一条 DML 的变更数。

`packages/rxdb-adapter-sqlite-core/src/execute-sql.utils.ts:34` 用 `includes(';')` 判断多语句，字符串里的分号也使单条 SELECT 进入 exec 分支；同文件 `packages/rxdb-adapter-sqlite-core/src/execute-sql.utils.ts:48` 的 `isReadOnlyStatement()` 用全文 RETURNING 正则排除纯读，字符串 `returning` 也使真实 SELECT 走错误计数逻辑。`WITH ... SELECT` 不以 SELECT/EXPLAIN 开头，亦走 exec 分支。

`packages/rxdb-adapter-sqlite-core/src/Oo1ClientBase.ts:264` 直接返回助手结果；官方 SQLite 和 sqliteai 客户端均继承该基类。现有测试 `packages/rxdb-adapter-sqlite-core/src/__tests__/execute_oo1_helper.spec.ts:113` 固定了普通 SELECT 应返回 0，却未覆盖上述 SQL 形态。

使用安装的真实 `@sqlite.org/sqlite-wasm`（引擎输出 3.54.1），加载原助手去类型模块及原错误类，先 `CREATE TABLE t; INSERT INTO t VALUES (1)`，再依次查询：

- `SELECT id FROM t`：rowsAffected=0（正确对照）。
- `SELECT 'a;b' AS value FROM t`：rowsAffected=1，返回 a;b。
- `SELECT 'returning' AS value FROM t`：rowsAffected=1，返回 returning。
- `WITH data AS (SELECT id FROM t) SELECT * FROM data`：rowsAffected=1，返回 1。

末尾核对物理表仍仅一行。没有 mock SQLite、SQL 解析或计数逻辑。

## 修复方向

统一 prepared 与 exec 路径的变更计数语义，使用引擎能区分语句读写的能力或可证明的执行计数差值；避免全文正则把字符串/注释当 RETURNING。补含分号/returning 的 SELECT、CTE SELECT 与 CTE DML RETURNING 对照，确保多语句写入计数按既定契约处理。
