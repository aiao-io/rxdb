# RV-01a1bb8cb3107cff9c2d81b1f2d6b56a：嵌套 EXISTS 固定引用顶层别名，内层关系关联到错误实体

## 问题与影响

查询作者「存在文章，且该文章存在 body=hit 的评论」时，内层评论被关联到作者 id，而不是当前文章 id。正常数据 author=a1、post=p1、comment.post_id=p1，查询错误返回空；若另一条评论碰巧 post_id=a1，还可能错误命中。嵌套 where 是被类型与校验器接受的规则结构，生成器不报不支持而是交出错误结果，定 P1。本次实际验证了漏结果，未虚报误命中实测。

## 证据与根因

源码快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-sqlite-core/src/query/query_sql.utils.ts:686` 的 EXISTS 生成器固定将当前关联根写成 MAIN_TABLE_ALIAS（`_`），并固定将每一级子查询根命名为 `child`。`packages/rxdb-adapter-sqlite-core/src/query/query_sql.utils.ts:546` 的 buildWhere 虽按关系目标实体递归编译 where，却没有把「本层外表别名」传给下一层 handle_exists；嵌套生成器继续引用顶层 `_`。

真实公开 find_sql → buildRuleGroup 路径接受该规则。冻结源编译出来的核心片段为：外层 `posts child WHERE child.author_id = _.id`，内层 `comments child WHERE child.post_id = _.id AND child.body = 'hit'`。内层应关联当前 post，而不是顶层 author；同名 child 又遮蔽了外层 child，单把 `_` 改成 child 也不够。

有界诊断使用真实 RxDB 实体/SchemaManager，按 Author.posts → Post.comments 两级存在关系编译 find_sql；真实 SQLite 放入 a1/p1/c1 三行，生成查询 actual=[]，显式正确 JOIN 对照 expected=[a1]。未 mock 元数据关系、查询编译或数据库。现有 1262 行条件测试覆盖单层 EXISTS 和子查询内的 JOIN，没有嵌套 EXISTS 的结果集断言。

## 修复方向

给规则编译显式传递当前查询根别名及子查询作用域，内层使用本层外表关联列，每级分配唯一的 child/junction 别名；保持公开调用的默认顶层别名兼容。覆盖所有关系种类的 exists/notExists、两级/三级嵌套、别名冲突及树 CTE 根别名对照，不能只替换一处 `_`。
