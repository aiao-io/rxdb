# RV-01a1bb651a5d78539163e452df53992a：SQLite 漂移检查把建表注释中的伪 CHECK 当成真实约束

## 问题与影响

既有表的合法 CREATE TABLE 注释里包含 `CONSTRAINT "ck_..." CHECK (...)`（例如迁移说明或注释掉的旧约束）时，数据库实际上没有该约束，但连接期漂移检查把它列为多余 CHECK，抛 RxDBConstraintDriftError，阻止打开本来可用的库。触发依赖手写建表/迁移注释，定 P2。

## 证据与根因

源码快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-sqlite-core/src/table/check-entity-constraints.ts:46` 的 stripSqlStringLiterals 只剥离单引号字符串，没有剥离行/块注释。`packages/rxdb-adapter-sqlite-core/src/table/check-entity-constraints.ts:85` 的 actualCheckNames 随后对整个剩余文本应用命名 CHECK 正则，注释中的片段也会入集合。文件注释关于 sqlite_master 不会出现此类文本的假设不成立：SQLite 保存的建表 SQL 保留列定义里的块注释。

真实入口 `packages/rxdb-adapter-sqlite-core/src/RxDBAdapterSqliteBase.ts:799` 在 bootstrapTransaction 内执行该检查。现有 407 行测试覆盖了字符串字面量伪片段、大小写及外键前缀，没有覆盖注释。

有界 Node 诊断加载冻结的实际检查器，真实 Entity 元数据没有声明任何 CHECK；真实 SQLite 执行 `CREATE TABLE "probe$comment_drift" (id TEXT PRIMARY KEY, value TEXT /* CONSTRAINT "ck_Comment_fake_12345678" CHECK (1) */)`。读取真实 sqlite_master 确认注释仍在，再让原检查器经真实 SELECT 查询该目录，实际抛 RxDBConstraintDriftError，extra=[ck_Comment_fake_12345678]、missing=[]。没有 mock SQL 目录内容或检查结果。

## 修复方向

对建表 SQL 做明确的词法扫描，跳过单引号字符串和两类注释，再识别约束；保留正确的标识符转义处理。补真实 SQLite 的块/行注释、注释里的单引号，以及真正 CHECK 的对照用例，不要直接关闭漂移检查。
