# RV-01a1bba58cf57124a7f48db112b2a898：默认事务在 BEGIN 前采样分支，并发切换后把新写入记进旧分支

## 问题与影响

两个独立连接打开同一 SQLite 文件。连接 A 开始默认记录日志的事务，在实际 BEGIN 前读出当前 main；此时连接 B 完整切到 feature 并提交；A 随后取得写锁、重建触发器并写入。活动分支已是 feature，业务表也处于切换后的投影，但 A 的变更仍被永久记入 main，收尾还把 main 触发器提交回去。历史、撤销和按分支同步会消费错误归属的变更。不是同时占用同一连接：即使两连接都使用 BEGIN IMMEDIATE 也能触发，定 P1。

## 证据与根因

冻结源码：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-sqlite-core/src/RxDBAdapterSqliteBase.ts:2059` 在 autocommit 下调用 read_current_branch_id，同一结果用于生成 log_begin/log_commit；`packages/rxdb-adapter-sqlite-core/src/RxDBAdapterSqliteBase.ts:2066` 才执行 BEGIN，之后未重新采样。读与使用之间没有覆盖两连接的事务边界。`packages/rxdb-adapter-sqlite-core/src/version/read_current_branch_id.ts:91` 的契约也明确要求读点落在使用它的事务内部，当前消费者违反该条件。普通 per-adapter 队列只能串行各自实例，sharedClientLockName 缺省不持有跨实例锁。

真实多连接消费者：`packages/rxdb-adapter-electron/src/electron-sqlite-host.ts:179` 明确每个 open 使用独立 DatabaseSync、并发交给 SQLite 文件锁；同文件 `packages/rxdb-adapter-electron/src/electron-sqlite-host.ts:252` 向客户端交付 BEGIN IMMEDIATE。文件锁取在 BEGIN，所以无法保护它之前的采样。此处仅按消费者读相关入口，未宣称整个 Electron 单元完成。

有界诊断转译真实 Base 及本包依赖，使用真实 RxDB 元数据、原始触发器生成器、原始 switchBranch 与同一文件的两个 node:sqlite 连接：A 完成分支 SELECT 后暂缓返回；B 经另一个真实 Base 实例 switchBranch(feature) 并完整提交；A 继续默认 transaction 并 INSERT。查询得到 active=feature、RxDBChange.branchId=main，wrongBranch=true，两连接均 BEGIN IMMEDIATE。只替换 client 传输门面以控制时序；未模拟分支查询答案或手写触发器，未启动 Electron 宿主。

现有 Base spec 使用固定 main 应答，并将 BEGIN 前分支查询从 transactionSqls 中滤掉；它验证了单实例顺序，没有覆盖两个独立连接交错的时序。

## 修复方向

先成功 BEGIN，再经当前 executor 读取分支并生成/安装日志触发器；读失败仍由既有回滚流程处理。核对多连接后端的 BEGIN IMMEDIATE 与事务读写锁契约。补两连接交错切换回归，断言业务投影、当前分支与变更归属一致，并确认提交后的普通裸写使用同一正确分支。
