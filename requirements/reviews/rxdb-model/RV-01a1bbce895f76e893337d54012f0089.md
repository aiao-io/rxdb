# RV-01a1bbce895f76e893337d54012f0089：表格编辑器把合法 null 单元值误当成未提供而回退过期 ctx.value

## 问题与影响

VTable 单元格真实值为 null、但编辑上下文仍保留旧值时，颜色/日期/JSON 编辑器会展示并提交旧值，用户无法把单元格编辑为空值，可能覆盖已清空的数据。相同模式影响本批已读的多个编辑器，记 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

三个 `onStart` 都用 `(ctx.table as TableLike)?.getCellOriginValue(...) ?? ctx.value`。`null` 是合法单元值而非“没有 origin”；`??` 将它吞掉。真实 happy-dom 复现给 table.getCellOriginValue 返回 null、ctx.value 给旧颜色/日期/对象：ColorEditor 得到 `#abcdef`，DateEditor 得到旧日期，JsonEditor textarea 仍为旧对象。

## 修复方向

区分“table 不支持 getCellOriginValue”和“该单元值为 null”：只有前者回退 ctx.value。补颜色、日期、JSON 及其余 editor 的 null origin 回归，确认清空后提交仍为空。
