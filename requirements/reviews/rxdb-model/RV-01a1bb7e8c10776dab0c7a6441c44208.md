# RV-01a1bb7e8c10776dab0c7a6441c44208：README 查询构建器示例仍按旧签名调用 addRule，直接接入会失败

## 问题与影响

消费者照 README 查询构建器示例调用 qb.addRule({field,operator,value})，当前公开 API 的第一个参数实际是父组 ID。TypeScript 编译时报参数类型不匹配；绕过类型检查时把规则对象当成组 ID 查找，无法把规则加入根组。影响推荐入门示例，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-model/README.md:42` 使用 `qb.addRule({ field: 'title', operator: 'contains', value: 'a' })`。
- `packages/rxdb-model/src/query-builder/services/query-builder.service.ts:245` 公开签名为 `addRule(parentGroupId: string | null = null, rule?: Partial<Omit<UIRule,'id'>>) : string`。
- 第 254–257 行直接用首参数作为 targetId，找不到目标组就抛错；文档给出的规则对象不可能等于字符串组 ID。
- 已读 headless-contracts、headless-i18n-refresh 与三端 headless 绑定均按 `addRule(null, rule)` 使用，没有支持该旧文档写法的重载。

## 修复方向

更新 README 为当前双参数签名，如 qb.addRule(null, {...})；同时核对示例的 schema 字段确为查询字段配置。通过现有文档示例门禁编译最小消费者，避免公开签名变化后只更新测试调用而遗留 README。
