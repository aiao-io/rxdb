# RV-01a1bba2f8707de0a30a89ef0a12a9f1：同轮 Esc 后重开对话框时，模态同步不会重跑且迟到 close 吞掉请求

## 问题与影响

已打开的命令面板或偏好抽屉先收到原生 cancel，模型关闭并在同一 React 批处理中重新打开；由于 open 最终仍为 true，原生已关闭的 dialog 不会再次 showModal，迟到 close 又把模型改回 false。用户重开请求丢失。仅在关闭与重开没有渲染间隙时触发，记 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-admin-react/src/use-dialog.ts:16` 同步 effect 仅依赖 open；`:30` cancel 立即回写关闭，但没有触发一次原生状态重新对账；`:31` close 只检查 dialog.open，无法区分旧 cancel 的尾声。真实 React hook 复现 cancel→移除原生 open→同轮 setOpen(true)：model=true/native=false；再派发尾随 close 后 model=false/native=false。Angular 对应指令有 #native 修订和 cancel 尾声标记，且 palette-lock/preferences 测试覆盖此序列。Vue 实际 watch 会重新对账，复现 model/native 均 true，故不将此问题泛化到 Vue。

## 修复方向

原生 cancel/close 触发独立对账，区分 cancel 尾随 close 与独立原生关闭；补无渲染间隙关闭重开的 React 回归，保持锁屏禁止 Esc 的行为。
