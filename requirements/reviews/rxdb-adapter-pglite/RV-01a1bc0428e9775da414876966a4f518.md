# RV-01a1bc0428e9775da414876966a4f518：PGlite 版本切换对自定义主键列名仍硬编码 id

## 问题与影响

实体公开支持把属性 `id` 映射到自定义物理列名，例如 `pk_id`。PGlite 的 undo/redo、切分支工作树播种等路径复用 `convertSwitchResultToSql` 时，删除语句与 INSERT 冲突目标仍写死 `id`。因此这类实体的版本切换在首个 delete 上报 `column "id" does not exist`，或在 insert/upsert 上报没有匹配 `id` 唯一约束；目标状态无法应用，整笔切换回滚。普通仓储写入的合法自定义主键不受此缺陷影响，但历史/工作树路径不能使用同一实体，属于有效适配器配置下的核心功能阻断，定 P1。

## 证据与根因

冻结源码：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-pglite/src/version/switch-result.utils.ts:223-228` 按 `idType` 选择数组类型，却固定生成 `WHERE id = ANY(...)`；`packages/rxdb-adapter-pglite/src/version/switch-result.utils.ts:407-417` 的 `generateOnConflictClause` 也固定生成 `ON CONFLICT (id)`。两处都应使用 `metadata.propertyMap.get('id')?.columnName` 并引用物理列。

调用链是 `RxDBAdapterPGlite.mergeChanges` / `switch_branch` / `createSeededTableSet` → `convertSwitchResultToSql` → 上述 delete 或 insert SQL。实体建表和普通批量 upsert 已明确保留物理主键列：`packages/rxdb-adapter-pglite/src/entity/insert_sql.ts:46-64` 从转换后的物理列生成 INSERT，`packages/rxdb-adapter-pglite/src/entity/inserts_sql.ts:68-81` 已用 `metadata.propertyMap.get('id')?.columnName` 生成冲突目标；PGlite 查询/建表测试也使用 `id` 属性映射到 `parent_key`、`pk_id` 等列。故这不是假设列名可变，而是同一适配器已有的公开元数据契约与版本实现不一致。

未执行运行实验，按用户要求只完成静态证据核对；冻结代码中 SQL 文本已足以证明目标表没有名为 `id` 的自定义主键时会失败。

## 修复方向

抽取并复用按 metadata 解析、按 PostgreSQL 标识符引用的主键列名，同时更新 ANY 删除和 ON CONFLICT 目标；补自定义主键列名实体的 merge/undo/redo 与工作树播种回归，覆盖 string、integer/bigint 绑定类型及加密列。
