# RV-01a1bb2992b87bdab0c6621a195a68cc：启动清扫未隔离新写入，删除活跃临时文件导致提交失败

## 问题与影响

文件树启动清扫尚未进入某个子目录时，renderer 已可通过文件桥在该目录开始写入。清扫随后会删掉本轮活跃写入的临时文件，正常文件名的 writeCommit 返回 file_not_found，目标文件不会生成。目录树较大或磁盘较慢时存在实际竞争窗口，定为 P2；本次复现表现为显式提交失败，未声称已经提交成功的数据因此丢失。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/dev-rxdb-electron/src-electron/desktop-file-bridge.ts:152` 在后台发起递归 sweepTemporaryFiles，:159 的 handle 未等待 whenSwept，也未将当前 host 的活跃 writeId 排除。sweepTemporaryFiles 在 :134 递归后，:135 仅按后缀删除。`packages/rxdb-adapter-electron/src/electron-file-host.ts:585` 在目标目录创建本轮 .UUID.rxdb-tmp，提交在同文件 :646 依赖该路径 rename。

诊断用真实 createDesktopFileBridge 与 createElectronFileHost、真实文件系统，仅将 fs.promises.readdir 在既有 late 子目录的那次调用暂停，固定一次合法 I/O 调度：开始清扫并停在 late → file.open → file.writeBegin(late/normal.txt) → file.writeChunk 成功 → 放行清扫 → 等 whenSwept → file.writeCommit。输出显示写入期间目录含一个 .UUID.rxdb-tmp，清扫后提交返回 {kind:"error",code:"file_not_found",message:"ENOENT on late/normal.txt"}，目标不存在。所有等待设置 2 秒上限，无无界调度。

## 修复方向

在允许文件请求前完成启动清扫，或令清扫只处理本轮 host 建立前已经确定的遗留文件集合，并与本轮活跃写入隔离；补一个受控 I/O 时序回归。仅缩窄临时名匹配不能修复此竞争。
