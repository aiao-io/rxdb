# RV-01a1bb27849e78ed858f01a3ee3911b9：启动临时文件清扫按后缀误删已经提交的用户文件

## 问题与影响

通过原生文件桥成功写入并提交名为 report.rxdb-tmp 的普通文件后，重启应用会永久删除该文件。路径协议允许此文件名，提交已经返回成功；启动清扫却将任意同后缀文件视为未提交产物。属于已提交数据丢失，因需特定文件名定为 P1，合并前修复。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/dev-rxdb-electron/src-electron/desktop-file-bridge.ts:135` 仅用 entry.name.endsWith(TEMPORARY_SUFFIX) 判定并 rm。实际临时名在 `packages/rxdb-adapter-electron/src/electron-file-host.ts:585` 是前导点 + UUID + 后缀；公共协议已有更窄的临时名判据，见 `packages/rxdb-adapter-sqlite-core/src/desktop/desktop-host-protocol.ts:89`。该协议的路径校验（同文件 :638）并不禁止普通 report.rxdb-tmp。应用每次首次构建 host 都执行该清扫，见 desktop-file-bridge.ts:152 及 `apps/dev-rxdb-electron/src-electron/main.ts:39`。

轻量 Node 诊断加载共享工作区原始 TypeScript，经内存转译执行实际 createDesktopFileBridge 与 createElectronFileHost；未替换文件 host、未修改源码。file.open → file.writeBegin(report.rxdb-tmp) → file.writeChunk → file.writeCommit 全部成功，盘上读到 committed user content；closeAll 后在同一根重建 bridge 并等待 whenSwept，文件 exists=false。现有 `apps/dev-rxdb-electron/src-electron/desktop-file-bridge.spec.ts:161` 只保护 keep.txt，未保护合法的同后缀内容。

## 修复方向

用协议已有的完整临时文件名判据识别遗留产物，避免把所有同后缀文件视为垃圾；补实际写入、提交、重建 host 的回归，并保护普通同后缀文件。清扫与新写入的时序另见相关记录。
