# RV-01a1bb3603d7799ea7142b4afee64071：token 分页的时间水位线无法固定快照，并发更新导致现存行遗漏

## 问题与影响

客户端开始一次多页 metadata 拉取后，另一请求更新尚未读取的行。该行 updatedAt 被推进到首页水位线之后，后续页将其过滤掉，整轮分页正常结束却缺少数据库中仍然存在的行。参考服务因此违反协议的同快照、完整无漏保证，可能向 QueryCache 提供不完整的远端集合。并发编辑是正常条件，定为 P1；本次验证到服务端分页遗漏，未运行客户端孤儿清理，也未声称物理远端行被删除。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/dev-rxdb-http-server/src/recipes-repository.ts:199` 仅在首页读取最大 (updatedAt,id)；:204 至 :211 的每页查询都读取当前 live repository，并以旧水位线作为 updatedAt 上界。`updateRecipe` 在同文件 :300 更新实体，后端审计时间会推进。token 中没有固定结果集或可复读快照，旧行一经更新便移到水位线外。末页 :216 又以无行正常终止，未报告快照失效。

契约证据为 `website/docs/adapters/http-protocol.md:128` 至 :130（同一查询拼接完整无重无漏，多页基于同一快照）。现有 `apps/dev-rxdb-http-server/src/__tests__/server.spec.ts:124` 只在页间插入新行，未更新旧行。

轻量 Node 诊断执行实际 listMetadataByToken、page-token 编解码及共享 toRecipeMetadataRow，数据提供端为按实际查询条件/排序求值的内存仓储（未启动 HTTP/PGlite）。三行 a/b/c、limit=1：无并发对照收齐 a/b/c；读完 a 后把 c.updatedAt 推进到旧水位线之外，后续只收到 b，第三页为空并结束，物理数据集仍有 a/b/c。每轮最多 5 页，确定性终止。

## 修复方向

让 token 引用真正稳定的读取快照或固定的 metadata 结果集；若无法继续该快照，应明确让客户端重启整轮，不能以正常末页返回残缺集合。补页间更新未读行、更新水位线行、删除与重放同 token 的契约回归。
