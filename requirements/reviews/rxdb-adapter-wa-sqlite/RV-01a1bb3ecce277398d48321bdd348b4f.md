# RV-01a1bb3ecce277398d48321bdd348b4f：wa-sqlite 接受会归一到同一物理文件的不同数据库名

## 问题与影响

配置不同逻辑库名，例如 `tenant alice` 与 `tenant%20alice`，两者都通过 wa-sqlite 的名字校验，却被 VFS 映射到同一个物理文件路径。持久 VFS 的不同实例共享其底层文件命名空间，因此第二个逻辑库会读取、改写首个库，`dropStorage()` 也会删除同一批文件。数据库隔离与删除归属失效，定 P1；影响依赖这些特殊但目前合法的库名，未把全部普通库名判为不可用。

## 证据与根因

本仓库源码证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-adapter-wa-sqlite/src/SqliteClient.ts:29` 的 `assertWaSqliteDatabaseName()` 只限制 UTF-8 字节数（最多 49），未拒绝/编码 URL 路径会折叠的名字。`packages/rxdb-adapter-wa-sqlite/src/create_sqlite_client.ts:54` 调用该校验后，`packages/rxdb-adapter-wa-sqlite/src/WaSqliteClientBase.ts:351` 原样把 `${dbName}.sqlite` 传给 `open_v2()`。

上游 VFS 把文件名当 URL：冻结快照 `packages/rxdb-adapter-wa-sqlite/package.json:68` 固定的 wa-sqlite commit 为 `2bf1c59d89eb6497535a4217bc62fec68a0bb994`。该版本 `src/examples/IDBBatchAtomicVFS.js` 的 `jOpen()` 以 `new URL(zName, 'file://').pathname` 为 IndexedDB metadata 键；MemoryVFS 也用同样的 pathname 做文件键。空间字符被编码成 `%20`，调用方原本传入的字面 `%20` 被保留，两个名字确定性碰撞。`#`、`?`、点路径等也会被 URL 重新解释，需要统一审视，而非只拦这一个示例。

本仓库删除端 `packages/rxdb-adapter-wa-sqlite/src/RxDBAdapterSqlite.ts:97` 同样用 URL pathname 推导路径。`packages/rxdb-adapter-wa-sqlite/src/drop-storage.utils.ts:47` 按该路径删除持久 VFS 共用库的记录，所以两个逻辑名字不会在删除端重新分开。根 `RxDB` 仅在 `packages/rxdb/src/RxDB.ts:646` 追加同一固定后缀，不消除该碰撞。

隔离复现使用真实 wa-sqlite 同步 WASM 与真实 MemoryVFS，同一 VFS 上开两个通过原公开校验函数的连接，分别叫 `tenant alice@0.0.1` 与 `tenant%20alice@0.0.1`：首个连接建 secrets 表并写入 alice-only，第二个连接直接读到该行；VFS 文件键仅有 `/tenant%20alice@0.0.1.sqlite`。原校验函数只去类型，错误类在该无异常路径用 Error 代替；SQL、SQLite 引擎、URL 处理和 VFS 均未 mock。

这是 VFS 文件命名的隔离证明，未运行浏览器 IndexedDB 完整 RxDB 路径。默认持久 VFS 的影响另以相同 pinned 版本的 `jOpen()` 路径键实现静态核对；不声称已实测浏览器删除或加密数据跨库解密。

## 修复方向

在适配器边界定义唯一、无碰撞的库名到文件名映射；鉴于存量物理路径的兼容性，可先拒绝会折叠的输入并明确诊断，不能悄悄换一套编码让原数据不可寻址。打开、跨标签锁、访问句柄探测与删除应使用同一已验证物理身份。补空格与 `%20` 两种库名、URL 查询/片段、点路径和普通/Unicode 名字的隔离与删除回归。
