# RV-01a1bb54b35b79d491932d4436e84437：Vue headless 表单与详情移除 mode 后无法恢复默认编辑态，与另两端不对称

## 问题与影响

宿主使用响应式 options 或 props，将 headless 表单/详情从 mode='view' 切换为 mode=undefined（恢复未传入的默认模式）时，Vue 绑定仍保留 view，字段输入和 submit 继续被只读约束拒绝。相同输入在 Angular 与 React 绑定中会恢复默认 edit。问题限于显式模式移除的路径，定为 P2；不将其他容器形态的合理差异算作不对称。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- 共享控制器 `packages/rxdb-model/src/entity-form/headless.ts:136` 将未提供的 mode 归一为 edit，setMode(view) 会使 setField/submit 保持只读约束。
- Vue 表单 `packages/rxdb-model-vue/src/entity-form/headless.ts:31` 的 mode watcher 只在真值时调用 setMode；详情 `packages/rxdb-model-vue/src/headless.ts:126` 使用相同条件。undefined 变化被忽略，旧 view 粘住。
- Angular `packages/rxdb-model-angular/src/headless/bindings.ts:85` 与第 150 行在两条绑定中使用 current.mode ?? 'edit'；React `packages/rxdb-model-react/src/entity-form/headless.ts:39` 与 `packages/rxdb-model-react/src/headless.ts:99` 同样归一默认模式。
- 已有三端 headless-bindings 测试只覆盖明确 edit/view 值，没有覆盖撤下可选 mode 的场景。

本组 `repro-vue-headless-mode-default.mjs` 使用真实 Vue 自定义 renderer 与共享控制器源码。由于 model 尚无现成 dist，Node 进程内以项目 TypeScript 转译器剥离源码类型并解析相对 .js→.ts；不输出项目构建产物、不修改源码、不模拟控制器。对照先断言未传 mode 的共享控制器初值为 edit；两条 Vue 绑定以 view 挂载后将 mode 设为 undefined，再 setField('title','B')，实际输出：

```json
{ "detailMode": "view", "detailValue": "A", "formMode": "view", "formValue": "A" }
```

字段仍未从 A 改成 B。动态验证只运行 Vue；另两端由明确的默认值归一源码对照，不声称运行其完整测试。

## 修复方向

两处 watcher 统一使用 mode ?? 'edit'，与共享控制器、Angular 和 React 的默认值一致；补 view→undefined、create→undefined 及同一草稿保留的回归，同时验证恢复后 setField/submit 可用。保持组件卸载的订阅与 dispose 行为。
