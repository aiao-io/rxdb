# RV-01a1bb5ca8507ce89159ab95e8dd7ad7：实体 glob 判定遗漏 extglob，将合法分组模式当作不存在的字面文件

## 问题与影响

entities 配置使用 glob 库支持的 `@(A|B).ts` 或 `+(A|B).ts` 选择实体文件时，目录中确有 A.ts/B.ts，生成器却将整个模式作为一个字面路径返回。后续分析尝试读取不存在的分组文件名，生成失败；allowEmpty=true 也无法按 glob 语义处理该模式。Vite watch 根使用同一判定，亦无法把这种模式归到其真实父目录。星号/问号/字符类/花括号模式不受影响，按部分合法输入失效定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-client-generator/src/cli/find-files.ts:22` 的 GLOB_MAGIC 只识别 `* ? [ ] { }`，不识别 `@(...)`、`+(...)`、`!(...)` 的 extglob 分组起点。
- 第 34 行将未命中正则的字符串直接 normalize/resolve 后加入结果，完全绕过实际 glob 库。
- `packages/rxdb-client-generator/src/plugins/vite.ts:18` 复用该正则；没有命中就把完整模式当作字面 watch 根。
- `packages/rxdb-client-generator/src/cli/build-client-lib.ts` 把 findFiles 返回值直接交给 createAnalysisProject/analyzeFile，不会再次展开这个遗漏的模式。
- `packages/rxdb-client-generator/src/__tests__/cli/find-files-glob-magic.spec.ts` 声称覆盖完整 glob 语法，但只对星号/问号/字符类/花括号作断言，没有 extglob。

本组 `repro-client-generator-extglob.mjs` 在本组目录创建仅含 A.ts/B.ts 的有界夹具，直接调用真实 findFiles 源码，并用该包所装的 glob 库作同参对照。输出：

```json
[
  { "pattern": "@(A|B).ts", "glob": ["A.ts", "B.ts"], "generator": ["@(A|B).ts"], "allGeneratorPathsExist": false },
  { "pattern": "+(A|B).ts", "glob": ["A.ts", "B.ts"], "generator": ["+(A|B).ts"], "allGeneratorPathsExist": false }
]
```

此复现已证实文件发现错误；未声称运行完整 CLI/Vite 构建。

## 修复方向

采用与实际 glob/minimatch 解析器一致的 magic 判定，并让文件发现和 watch 字面前缀计算共用这一语义。补 `@(...)`、`+(...)`、`!(...)`、含目录分组、零匹配/allowEmpty 和实际字面路径对照，避免只扩展一个仍不完整的字符表。
