# RV-01a1bbb23fef7a81875b1c88d00f80bd：保留实体 getter 时丢失其模块绑定，生成成功后访问抛 ReferenceError

## 问题与影响

手写 getter 引用同模块 helper 或导入函数时，生成器只搬 getter 本身，既没有携带自由绑定也未拒绝该输入。构建成功，客户端读取 getter 才抛 ReferenceError；即便 helper 为纯函数也会失败。影响带模块依赖 getter 的路径，记 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-client-generator/src/cli/analyze-file.ts:565` 仅提取 getAccessors，`:568` 把单个 getter 送进临时 class 转译。`packages/rxdb-client-generator/src/core/RxDBClientGenerator.ts:507` / `:551` 把 runtime 文本拼进实体类；运行时 imports 只由元数据生成，源文件 helper/import 未进入输出。真实源码 const double=(value:number)=>value*2；get doubled(){return double(this.value)} 经 analyzeFile→addEntity→exec 成功，运行生成类的 getter（value=2）得到 double is not defined。现有 build-client-lib.spec.ts 的 getter 用例只引用 this.name，未覆盖模块绑定。

## 修复方向

生成前识别 getter 的自由符号并保留受支持的依赖/导入；暂不支持的绑定应明确 fail-fast。补同模块 helper、外部导入与相应返回类型依赖的消费方回归。
