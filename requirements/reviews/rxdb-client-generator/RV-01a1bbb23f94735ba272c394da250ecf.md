# RV-01a1bbb23f94735ba272c394da250ecf：静态枚举求值只按名字匹配，把同名局部对象替换成核心枚举值

## 问题与影响

实体源码声明 const PropertyType={integer: string值} 并在内联 metadata 使用 PropertyType.integer 时，分析器既没有按文档拒绝局部动态值，也没有保留源码含义，而是静默使用核心的 integer。生成字段类型与源码定义不同，按边界合法/误用输入导致错误元数据记 P2；不声称执行了输入代码。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb-client-generator/src/cli/analyze-file.ts:181` 用 owner.getText() 直接索引 SAFE_CONSTANTS，未校验 owner 符号所属模块。真实 ts-morph 内存源码只从核心导入 Entity、本地声明 PropertyType={integer:'string'} as const；analyzeFile 产出 properties[0].type=integer，而源成员值为 string。实体装饰器已通过来源校验，枚举成员缺少相同校验。

## 修复方向

按绑定符号核验核心枚举的来源；对同名局部对象按静态表达式契约拒绝，并核对合法枚举别名与 namespace 导入的处理。补不能静默替换源码含义的回归。
