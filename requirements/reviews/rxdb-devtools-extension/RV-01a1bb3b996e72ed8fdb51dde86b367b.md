# RV-01a1bb3b996e72ed8fdb51dde86b367b：同源导航的旧权限查询可覆盖刚成功的授权，面板重新要求授权

## 问题与影响

用户授权当前站点的请求尚未完成时，被检查页发生同源导航并发起一次 permissions.contains。若该查询基于授权前状态得到 false、结果晚于 request(true) 返回，已经成功的授权会被覆盖为 required。端口已激活，但面板重新显示“允许访问当前站点”并遮住内容。属于异步结果陈旧导致的可见状态错误，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`apps/rxdb-devtools-extension/src/devtools/services/inspected-page-access.service.ts:78` 等待授权；:82 仅比较当前 pattern，因此同源导航之后允许结果生效，:83 写入 granted、:88 activate。与此同时，refresh 在 :124 等待的 contains 使用的是同一次导航 revision；requestAccess 成功没有推进该 revision。旧 contains(false) 回来仍通过 :125，:126 把状态倒退成 required。

`modules/rxdb-devtools-panel/src/components/connection-guard.component.ts:13` 的 required 分支优先于 connected，状态倒退会直接挡住已连接内容。现有同源导航回归 `apps/rxdb-devtools-extension/src/devtools/services/inspected-page-access.service.spec.ts:305` 附近使用立即返回 false 的 contains，仅覆盖 contains 先结束、request 后成功的顺序。

轻量 Node 诊断加载实际服务类，最小 Angular 信号/注入及 Chrome 权限 API 替身控制 Promise 时序：首次查询 false → request 挂起 → 同源导航启动第二次 contains 并挂起其 false → request 返回 true（state=granted，activations=1）→ 第二次 contains 返回 false（state=required，activations=1）。未启动真实 Chrome，也未替换待审类的方法；诊断只证明服务的异步结果覆盖及面板状态消费路径。

## 修复方向

把成功授权纳入权限状态结果的版本管理，使之前开始的 contains 不能覆盖它；保留同源授权结果仍可应用、跨源/销毁结果必须作废的现有语义。补 contains 晚于 request 成功返回的同源导航回归。
