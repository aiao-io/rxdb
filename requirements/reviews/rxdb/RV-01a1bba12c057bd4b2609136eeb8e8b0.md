# RV-01a1bba12c057bd4b2609136eeb8e8b0：字段描述解析器接受稀疏 fields 数组，返回值无法遍历或 JSON 往返

## 问题与影响

向公开接受 unknown 的 parseEntityFieldsDescriptor 传入 {dtoVersion:1,entity:'Test',namespace:'public',fields:new Array(1)} 时，解析器成功返回 EntityFieldsDescriptor，实际 fields[0] 却是 undefined。普通 for...of 读取 field.field 抛 TypeError；JSON 序列化把空洞变成 null，同一解析器随后拒绝自己的序列化结果。违反严格 JSON-safe、字段元素经过校验及 DTO 往返契约。需要 JavaScript 构造的稀疏数组（标准 JSON 输入无法直接表达空洞），故为边界缺陷 P2。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb/src/entity/entity-field.utils.ts:650` 的 assertJsonSafe 用 Array.forEach 检查数组元素，跳过空洞；`packages/rxdb/src/entity/entity-field.utils.ts:980` 用 Array.map 调用 parseFieldDescriptor，又跳过同一空洞。字段顺序检查也基于 map/findIndex，未拒绝空洞。返回类型却承诺每个索引是 EntityFieldDescriptor。

完整核对 `packages/rxdb/src/__tests__/entity/entity-field.utils.descriptor.spec.ts`：包含非对象字段、非 JSON-safe 值、循环引用与往返用例，没有稀疏数组反例。

有界 Node 隔离复现：用本地 esbuild 将冻结内容一致的实体字段模块打包到内存后调用实际导出，输出 parsedLength=1、ownsIndex0=false、wire 的 fields=[null]；for...of 抛 Cannot read properties of undefined (reading 'field')；JSON 往返再解析抛 RxDBError，指出 $.fields[0] 必须是对象。未修改源码或原测试。

## 修复方向

按数组长度逐项验证并明确拒绝空洞，保证字段解析确实处理每个索引；对 enum、format.schemes 等数组采用一致的严格策略。补空洞与显式 undefined/null 的回归，保留合法空数组。
