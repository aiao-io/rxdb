# RV-01a1bbbd842e7ef48fa0682bc76f9ec9：__decorateClass 的返回类型在属性描述符和 undefined 分支失实

## 问题与影响

公开导出的 __decorateClass 接受数字 kind，却对所有分支声明返回输入 target 的 TTarget。kind=2 且装饰器为空或返回 undefined 时实际返回 undefined；kind=1 则返回 PropertyDescriptor 或 undefined。因此严格 TypeScript 下 __decorateClass([], {value:1}, 'value', 2).value 可按公开签名通过类型检查，运行时读取 value 却抛 TypeError。需要属性分支这一边界，定 P2；当前客户端生成器只用类分支，未发现生成实体主流程受影响。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb/src/rxdb-utils.ts:139` 附近 __decorateClass 的泛型只绑定 target；初始化分支 kind > 1 得到 undefined，kind=1 取 Object.getOwnPropertyDescriptor，:156 又直接把 result 断言回 TTarget。`packages/rxdb/src/index.ts:207` 将该工具公开导出，没有收窄 kind 的入口。

完整核对 `packages/rxdb/src/__tests__/rxdb-utils.spec.ts:217` 附近现有用例：kind>1 的装饰器可返回字符串 modified；随后明确断言装饰器返回 undefined 时 result 为 undefined。kind=1 的用例也明确检查描述符的 value。这些现有确定反例已经证明返回形状不同，本次不重复运行实验。测试只做运行时断言，没有返回类型的正反例，因而当前无条件 TTarget 签名仍被保留。

`packages/rxdb-client-generator/src/core/RxDBClientGenerator.ts:510` 与 :554 的生成模板只提供 decorators 与类 target（默认 kind=0），故其正常类替换路径不需要更改。

## 修复方向

按 kind 对返回类型与装饰器签名做分支或重载，准确表达类、描述符及可能缺失的返回；如果只承诺类装饰器，则收窄公开 kind 参数而非继续接受不可满足 TTarget 的分支。保留生成器类路径兼容性，补严格类型断言，并保留现有运行时反例。
