# RV-01a1ba7549407bf48eb698893c5e4596：旧插件释放任务跨越重置后反复拆装新纪元插件

## 问题与影响

provider 的依赖断开时，释放流程正在等待 consumer 的旧异步 install；此时调用 disconnectAll() 完成停机，再重新连接并成功安装新一轮插件。旧 install 随后结算，旧释放循环会把新纪元 consumer 当成待拆对象；但新 provider 已 active，consumer 拆完又立即被重装，循环持续占用微任务队列。公开 RxDB 生命周期调用已经复现，不限于直接调用内部 reset。实例无法正常继续处理事件，定为 P1；需要特定并发重连时序，因此不是所有启动路径都受影响。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb/src/plugin/dependency-scheduler.ts:365` 在等待依赖方后没有核对连接纪元；`#releaseDependents()` 在 398–408 行反复读取同一张可变 activation 表。`reset()` 就地复用记录和插件实例，新连接仍引用同一个 provider 对象；旧循环因此命中新连接 consumer。`#startTransition` 末尾的任务身份守卫只保护收尾，挡不住 work 内部的旧循环和状态写回。

公开入口复现步骤：

1. 配置本地、远程两个适配器并连接；注册 provider（inject adapter:local）和 consumer（inject plugin:provider）。consumer 首次 install 返回手动结算的 Promise，以后返回成功。
2. consumer 首次 install 挂起时启动 disconnect(local)，让 provider 进入释放等待；不等待此调用，再 await disconnectAll()。
3. await connect(local) 与 connect(remote)，两插件累计各安装两次，证明新连接已成功。
4. 结算旧 consumer 的 install Promise。没有新的依赖变化，consumer 却不断重装；带次数上限的隔离复现输出 providerInstalls=2、consumerInstalls=8，以退出码 33 主动终止。

内部调度器独立复现得到相同结果；对照路径不 reset 时只安装一次并正常结束。首次未加次数上限的隔离进程因持续重装、累积诊断对象发生 OOM，已退出；后续复现限制 128 MiB、4 秒及 8 次安装，防止影响宿主。

## 修复方向

为释放流程和反向依赖扫描携带连接纪元或 activation 身份，所有 await 返回与每轮扫描都拒绝过期任务；不能只在 finally 类收尾处守卫。保留同一纪元的逆拓扑释放顺序，并补真实 RxDB 的并发 disconnect / disconnectAll / reconnect 与旧 install 迟到结算回归。
