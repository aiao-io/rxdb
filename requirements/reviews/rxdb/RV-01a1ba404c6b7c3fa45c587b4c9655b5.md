# RV-01a1ba404c6b7c3fa45c587b4c9655b5：备份结构指纹未包含实体级 CHECK 与区间排他约束

## 问题与影响

源库与恢复目标的实体列、索引等声明相同，只有实体级 `checks` 或 `exclusions` 不同，`computeRxDBSchemaFingerprint()` 仍返回相同值。恢复入口据此把旧结构判为兼容并开始写入目标，恢复完成后连接目标才因约束漂移报错。恢复 API 已经改变持久化目标，违反不兼容归档应在写目标前拒绝的契约。触发需要两份配置恰好只在这些约束上不同，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb/src/backup/schema-fingerprint-encoding.ts:24` 的 `FINGERPRINT_KEYS` 没有 `checks`、`exclusions`，而这两项是 `EntityMetadataType` 的独立实体级字段。
- `packages/rxdb/src/backup/schema-fingerprint.ts:14` 只从该白名单取值；新增实体级 CHECK 不会改变 `properties` 数组，因而从整个编码输入中消失。
- `packages/rxdb-adapter-pglite/src/backup/restore-pglite-database.ts:352` 与 `packages/rxdb-adapter-sqlite-core/src/backup/restore-sqlite-database.ts:297` 在开始恢复前以这个指纹判兼容。PGlite 恢复后的 `verifyPGliteRestored()` 只检查引擎兼容键、系统结构版本和编码版本，没有核对实体约束；下一次 `RxDB.connect()` 才执行约束漂移检查。
- `packages/rxdb/src/system/bootstrap-fingerprint.ts:25` 和 `packages/rxdb/src/system/worktree-table-set.ts:58` 已单独补入这两项，但备份格式没有对应补充机制。

在仓库根使用 Nx 构建后的公共入口执行：

```javascript
import {
  Entity,
  EntityBase,
  PropertyType,
  getEntityMetadata,
  computeRxDBSchemaFingerprint
} from './packages/rxdb/dist/index.js';
const entity = (checks = []) =>
  Entity({
    name: 'FingerprintReview',
    namespace: 'review',
    properties: [{ name: 'amount', type: PropertyType.number }],
    checks
  })(class extends EntityBase {});
const a = entity();
const b = entity([
  { name: 'positive', rule: { combinator: 'and', rules: [{ field: 'amount', operator: '>=', value: 0 }] } }
]);
console.log(
  getEntityMetadata(a).checks.length,
  getEntityMetadata(b).checks.length,
  computeRxDBSchemaFingerprint([a]) === computeRxDBSchemaFingerprint([b])
);
```

实际输出 `0 1 true`。该结论验证了指纹碰撞与兼容闸门缺口；本次没有执行完整数据库恢复端到端复现，恢复后约束漂移的影响依据上述调用链。

## 修复方向

为备份兼容性增加版本化的约束结构信息，并在开始写目标前核对。现有白名单注释明确担心改键后旧备份全部失配，所以不能直接改键破坏已有归档；需声明格式升级与旧格式的明确兼容条件，并补两后端仅 CHECK 或排他约束不同的拒绝恢复回归。
