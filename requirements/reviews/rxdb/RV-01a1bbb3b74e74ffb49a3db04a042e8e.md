# RV-01a1bbb3b74e74ffb49a3db04a042e8e：bigint 排他闭区间的合法最大上端点在 PGlite 抛溢出

## 问题与影响

bigint 的公开值域包含 9223372036854775807，排他区间又公开支持两端闭合 []。合法行取 from=0n、to=9223372036854775807n、bounds=[] 时，元数据生成的 PG 区间表达式在没有任何竞争行的情况下就抛 22003 bigint out of range，导致 PGlite 写入失败，而非排他冲突。上界为最大值这一少见边界，定 P2。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb/src/entity/property-types.interface.ts:332` 附近 BigIntProperty 明确支持有符号 64 位完整值域。`packages/rxdb/src/entity/exclusion-constraint.ts:202` 将 bigint 映射为离散 int8range；:219 至 :224 的 exclusionRangeExpressionPG 对 [] 直接生成 int8range(from,to,'[]')。离散闭上界规范化需要将上端点加一，最大值在此溢出；仅判断 from > to 的 CASE 不覆盖该情况。

`packages/rxdb-adapter-pglite/src/table/create_table_sql.ts:356` 将该核心表达式直接放入 EXCLUDE 元素。完整核对 `packages/rxdb/src/__tests__/entity/exclusion-constraint.spec.ts` 全 231 行，矩阵只有 date / integer 区间，没有 bigint 极值。

有界实际 SQL 验证（本地 @electric-sql/pglite，单连接内存库，20 秒硬超时，finally close）：先用实际 exclusionRangeExpressionPG 导出生成表达式，再从 VALUES (0::bigint,9223372036854775807::bigint) 求值。bounds=[) 正常返回 [0,9223372036854775807)；bounds=[] 返回 code=22003、message=bigint out of range。进程退出 0，连接已关闭。未建立完整 EXCLUDE 表或重复全套构建，但实际建表方逐字使用该表达式，因此不能绕过求值错误。

## 修复方向

使 bigint 离散闭区间在完整公开值域内可表示，并保持 SQLite/PGlite 在最大值及 NULL 无界端点上的相交语义一致；不要把溢出误包装成排他违约。补最大值闭区间、最大值单点、相邻区间及多维组合的实际 SQL 回归。
