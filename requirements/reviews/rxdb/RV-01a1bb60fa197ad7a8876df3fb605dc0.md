# RV-01a1bb60fa197ad7a8876df3fb605dc0：物理列名 **proto** 被归一化字典吞掉，创建丢值且更新报空补丁

## 问题与影响

实体使用普通 JS 字段 label，并通过合法 columnName 映射到 SQL 的 **proto** 列。元数据校验通过，但创建时该字段被静默漏出 INSERT，nullable 列最终存为 NULL；仅修改它时归一化补丁为空，SQL 生成器抛 Empty patch。这会影响有该遗留物理列名的库，按命名边界定 P2；没有证明全局原型污染或远程攻击。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb/src/entity/entity.utils.ts:363` 附近的 normalizeCreateEntity 和 `packages/rxdb/src/entity/entity.utils.ts:301` 附近的 normalizeUpdateEntity 都用普通 {} 建结果，再以 result[property.columnName] = value 写键。**proto** 命中 Object.prototype 的继承 setter；字符串值被忽略，不会产生自有可枚举数据键。

`packages/rxdb-adapter-sqlite-core/src/entity/insert_sql.ts:41` 调用前一函数，随后按归一化对象的键列举 INSERT 列；`packages/rxdb-adapter-sqlite-core/src/entity/update_sql.ts:21` 调用后一函数并把空结果拒绝为 Empty patch。

有界复现使用公开 transitionMetadata / validateEntityMetadata / normalizeCreateEntity / normalizeUpdateEntity 和实际 SQLite SQL 生成器，存储为 Node 内置 SQLite 内存库：

1. id:string 主键，label:string、columnName=**proto**、nullable=true；validateEntityMetadata 返回 []。
2. 对 {id:row,label:written} 归一化，只剩 id；生成 INSERT 也只包含 id。
3. 用该实际 SQL 写物理表后读回，label=NULL，没有保存 written。
4. 仅更新 label=next，归一化结果无键，实际 update_sql 抛 Empty patch。

这次验证到 SQLite 物理行；没有运行 PGlite 或其他后端。它与 namespace/**proto** 的既有问题是不同写字典和不同根因入口。

## 修复方向

把物理列名作为自有数据键安全构建，避免触发继承 setter；同步处理创建、更新和外键列映射，核对返回对象形状兼容性。补普通列、**proto**、constructor、toString 的映射与真实写回回归，不应静默丢键。
