# RV-01a2019db2be7bd490322f8c0126f27f：RxDB.init 在配置校验失败后仍保持已初始化状态

## 问题与影响

当 JavaScript 调用方、旧配置反序列化或绕过 TypeScript 类型检查的调用缺少库级 `sync` 时，`RxDB.init()` 会抛出配置错误，但实例仍把初始化标志保留为 `true`。后续调用 `init()` 会命中幂等早退，无法重新执行初始化，实例停留在半初始化状态。调用方只能丢弃该实例，属于可恢复配置错误被转换为不可恢复生命周期故障，定为 P2。

## 证据与根因

证据快照：`6f7358614362378a47fb005af83c380da980517d`。

`packages/rxdb/src/RxDB.ts:707-708` 先把 `#rxdb_initialized` 设为 `true`，而 `packages/rxdb/src/RxDB.ts:719-721` 才校验 `#config.sync`。这段校验位于后续管理器初始化的 `try/catch` 之外，抛错时不会执行 `packages/rxdb/src/RxDB.ts:743` 的回滚。

最小触发路径如下：

```ts
const db = new RxDB({ dbName: 'missing-sync', entities: [], sync: undefined } as never);
expect(() => db.init()).toThrow(/缺少库级 sync/);
expect(db.initialized).toBe(true);
expect(() => db.init()).not.toThrow();
```

当前仓库的 `rxdb-review.md` 也记录了同一触发路径与影响，当前实现的初始化顺序仍未改变。

## 修复方向

把库级配置校验移到设置 `#rxdb_initialized` 之前，或纳入统一的初始化回滚路径。补充缺少 `sync` 时初始化失败后 `initialized === false`，以及修正配置后第二次 `init()` 能正常完成的回归测试。
