# RV-01a1bbf30321706fae1aa80ee723f776：SyncScenarioFixture.createConflict 生成不同实体 ID，冲突场景会被误当成两条实体

## 问题与影响

调用 `SyncScenarioFixture.createConflict()` 期望得到同一实体的 local / remote 两个版本，用于验证冲突解决或同步冲突展示。但该工厂分别调用 `uuid()` 生成 `local.entityId` 和 `remote.entityId`，两个变更实际指向不同实体。依赖此 fixture 后按 `namespace + entity + entityId` 配对冲突的测试会走不到冲突分支，可能在错误的无冲突输入上通过；测试基础设施因此不能证明冲突路径有效。问题影响测试覆盖与回归可信度，定为 P2。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb/src/__tests__/fixtures/test-fixtures.ts:135` 至 `154` 的 `createConflict()` 在 `local` 对象中写入 `entityId: uuid()`，又在 `remote` 对象中写入另一处独立的 `entityId: uuid()`。两者没有共享一个实体 ID；而 `local` / `remote` 的其他字段却明确构成同一字段的两个版本。按实体键配对的消费者会把它们视为两个实体，不能触发冲突。

## 修复方向

在工厂入口先生成一次 `entityId`，local 与 remote 共用该值；补一个断言确认两侧 ID 相同，并由实际冲突配对路径消费该 fixture，避免只检查返回对象形状。
