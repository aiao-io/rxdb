# RV-01a1bba6ab29728087a86f29e433b88e：数字布尔值 1 被实体值解析器静默解码为 false

## 问题与影响

parseEntityFieldValue("boolean", 1) 返回 false，而同一个值用字符串 "1" 表示却返回 true。parseEntityRecordValues 的远端整行解码复用该分支，因此 REST 以数字 0/1 返回布尔列时，已保存的真值被反转为 false。需要数字表示这一边界，定 P2。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

`packages/rxdb/src/entity/entity-value.utils.ts:118` 只比较 true、"true"、"1"，漏了数字 1，且把所有其余非空值归为 false。`packages/rxdb/src/__tests__/entity/entity-value.utils.spec.ts:218` 附近明确描述远端布尔可能为 0/1，但实际布尔用例只传原生 true/false 与字符串。`packages/rxdb-plugin-querycache/src/query-cache-primary.ts:279` 的 #decodeRemote 使用这条整行解码路径，随后可 Object.assign 回实体。

实际导出复现：原生 true → true，数字 1 → false，字符串 "1" → true；propertyMap 中 done 的 type=boolean，parseEntityRecordValues(metadata,{done:1}) 得到 {done:false}。

## 修复方向

明确接受原生布尔及已支持的 0/1 线格式，至少正确处理数字 1；补标量解析与整行解码的 0/1 成对回归，核对 QueryCache 写响应回填。
