# RV-01a2019db2e8711aa667e2b7b3bbc926：RxDB.disconnectAll 并发执行时会重复拆卸同一实例

## 问题与影响

两个 `disconnectAll()` 在第一轮拆卸完成前并发调用时，会各自创建并启动一轮 `#disconnect_all()`。同一批插件可能收到两次销毁调用，同一适配器可能收到两次 `disconnect()`，全局状态复位也会并发执行。插件的旧版 `destroy()` 没有统一的幂等保证，适配器实现也可能在第二次关闭时抛错，导致调用方观察到不一致的拆卸结果，定为 P2。

## 证据与根因

证据快照：`6f7358614362378a47fb005af83c380da980517d`。

`packages/rxdb/src/RxDB.ts:1424-1426` 每次调用 `disconnectAll()` 都直接执行 `this.#disconnect_all()`，然后才通过 `#track_teardown()` 登记适配器名。该登记只保存按适配器名索引的记录，没有全局 in-flight Promise 入口，因此第二次 `disconnectAll()` 不会复用第一轮正在执行的 `#disconnect_all()`。

`packages/rxdb/src/RxDB.ts:1719-1752` 的 `#disconnect_all()` 会独立执行 `#shutdown()` 和对所有已缓存适配器调用 `adapter.disconnect()`。两个并发调用会在 `#track_teardown()` 覆盖记录前后都进入这条路径，重复销毁插件、复位实体管理器和断开适配器。

最小触发路径如下：

```ts
const first = db.disconnectAll();
const second = db.disconnectAll();
await Promise.all([first, second]);
```

在适配器的第一次 `disconnect()` 阻塞期间观察第二次调用，会再次进入同一个适配器的断开路径。当前仓库的 `rxdb-review.md` 已记录同一竞态，当前 `disconnectAll()` 入口仍没有全局 Promise 复用。

## 修复方向

为全局拆卸增加单独的 in-flight Promise。已有全局拆卸时，后续 `disconnectAll()` 应直接复用同一个 Promise，并让所有调用方观察到一致的成功或失败结果。补充两次并发 `disconnectAll()`、单点 `disconnect()` 与 `disconnectAll()` 重叠时插件和适配器各只执行一次的回归测试。

- 结论：成立，范围比本记录写的大：重复的是两个底层操作，不只是 `disconnectAll()` 入口。单点 `disconnect()` 断掉最后一个已连接适配器时也走 `#shutdown()`，所以它卡在插件销毁或关连接上时进来的 `disconnectAll()` 同样会二次 `destroy()` 或二次 `adapter.disconnect()`（根目录 `rxdb-review.md` 的触发条件一）。只在 `disconnectAll()` 入口复用 Promise 盖不住这两种情形，因此修在底层：`#shutdown()` 单飞，进行中的那一轮记在 `#shutdown_running`，后到的共用；同一实例的 `adapter.disconnect()` 单飞，`#close_adapter()` 按实例用 WeakMap 记进行中的关闭，单点与全局拆卸都经它关连接。两次并发的 `disconnectAll()` 因此只跑一轮停机、每个实例只关一次，失败时所有调用方拿到同一个错误；底层单飞之后，入口再加一个全局 Promise 是冗余的第三套机制，未采纳。行为变化：单点停机卡在插件销毁上时，`disconnectAll()` 改为等这一轮结束，不再另起一轮。另起一轮会二次调用 legacy `destroy()`，而且先跑完的那一轮复位、实例重连之后，迟到的那一轮醒来会接着拆新纪元的插件作用域与连接作用域。保留既有契约：还有别的适配器连着、卡在插件释放（`scheduler.settle()`）上的单点 `disconnect()` 仍由 `disconnectAll()` 接管、不等它（`RxDB.disconnect-window.spec.ts` 原有用例照旧通过）。不在本修复范围：单点 `disconnect()` 已经关完之后，`disconnectAll()` 按开始时的快照再关同一个实例一次，这是先后调用而非重叠，属于 `IRxDBAdapter.disconnect()` 契约要求的幂等调用。`#disconnect_all()` 原先兜同步抛错的 `catch` 在 `#close_adapter()` 把同步抛错转成 reject 之后不可达，一并删去。
