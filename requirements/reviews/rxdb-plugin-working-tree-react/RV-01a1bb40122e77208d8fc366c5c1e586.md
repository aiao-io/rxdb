# RV-01a1bb40122e77208d8fc366c5c1e586：React 工作树文档把可变资源放进 effect 依赖导致循环查询

## 问题与影响

应用照 README 的 mounted 订阅示例编写组件，普通挂载就会反复执行 `status()`，即使数据库、挂载表集都没有变化。`status()` 每次产生新的状态对象，资源 `tree` 的引用跟着变化，effect 依赖它又立即发起下一次查询。结果是持续数据库事务、重复渲染与 loading 闪烁。问题发生在文档消费路径，属于 P2；hook 已提供稳定方法，可以通过正确依赖避开。

## 证据与根因

冻结 SHA：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-plugin-working-tree-react/README.md:70` 的示例为 `useEffect(() => void tree.status(), [tree, worktrees.mounted])`。
- `packages/rxdb-plugin-working-tree-react/src/use-working-tree.ts:110` 依赖 `slot.states` 重新构造返回的资源对象；资源引用有意随状态改变。
- `packages/rxdb-plugin-working-tree/src/working-tree/working-tree-commands.ts:223` 的 runStatus 进入状态跟踪；`packages/rxdb-plugin-working-tree/src/working-tree/async-state.ts:250` 起同步发 loading、再发 empty/success，每次都用新对象。
- 同一 React hook 的 TSDoc 已明确方法引用稳定、资源随状态变化，故依赖项应该选稳定的 `tree.status`。

有限反例 `repro-working-tree-react-readme-effect.cjs` 使用真实 ReactDOM/HappyDOM、源 hook 与真实共享命令，在单次挂载、mounted 从未变化的条件下运行同一 effect/deps。唯一增加的仪器守卫是在第 5 次读取后停止发起，防止无界微任务。实际达到 `statusReads=5, singleMount=true, mountedChanged=false, cap=5`；没有用户事件或换挂操作。未移除守卫运行无界循环。

## 修复方向

文档示例依赖稳定方法引用与 mounted；若解构 status，依赖 status 即可。对照 Angular/Vue 示例保持「只在挂载表集变化时重读」的目的。增加一个有限计数的文档消费回归，断言稳定挂载只读一次、真实换挂再读一次。
