# RV-01a1bb334b9b7516b7ed404cf0b6fc7d：React 与 Vue README 将未导出的四个 Tree hook 列为可用公开 API

## 问题与影响

消费者按 React 或 Vue 包 README 的查询 API 清单导入 useFindDescendants、useCountDescendants、useFindAncestors 或 useCountAncestors，公开入口中没有这些具名导出，编译或 ESM 模块加载失败，文档承诺的树查询示例无法接入。问题在文档与当前公开面不一致，不据此推断删除能力本身错误；定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-react/README.md:71` 至第 74 行把四个 Tree hook 列在查询 hooks 清单中；`packages/rxdb-vue/README.md:134` 同样显式声明这四个 Tree API。
- `packages/rxdb-react/src/index.ts:22` 与 `packages/rxdb-vue/src/index.ts:22` 从 hooks 模块再导出，而两端 hooks 的完整实现只包含基础与 Graph 查询，没有上述四个函数；入口其它再导出模块也不提供它们。
- `packages/rxdb-react/src/__tests__/hooks.spec.ts:479` 和 `packages/rxdb-vue/src/__tests__/hooks.spec.ts:420` 的公开查询转发用例同样只有实际存在的方法，未验证 README 清单。

本组 `repro-framework-doc-contracts.mjs` 读取现有已构建两端公共入口，四个名字在两端的 `name in api` 均为 false。源码与 dist 导出核对一致。

## 修复方向

按当前树查询能力的真实归属更新两端 README，移除或改写已不存在的导出及准确的接入入口；在既有文档/API 一致性门禁中核对具名导出。不要为迎合旧清单重新加入已经移除的 API。
