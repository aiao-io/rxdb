# RV-01a1ba4b4adf7ad8a00cf9436d4ef117：SSR 请求共用持久化状态单例，后续请求读到前一用户的值

## 问题与影响

React 与 Vue 的 `usePersistedState()` 将注册表建在服务端模块全局。一个长驻 SSR 进程连续处理两名用户的请求，应用按相同 namespace/name 传入各自请求的初值时，第二个请求会读取第一个请求保存的内存值，而不使用自己的初值。React 的第二次 HTML 已可直接包含第一名用户的数据；Vue 在服务端调用组合式函数得到同样结果。涉及用户数据时跨请求泄露，且无须请求并发，定为 P1。触发条件是 SSR 使用该明确声明支持的 API 并传入请求相关值，不影响仅浏览器使用的场景。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-react/src/use-persisted-state.ts:17` 与 `packages/rxdb-vue/src/use-persisted-state.ts:17` 的 `registry` 是模块级单例，没有请求或应用级归属。
- `packages/utils/src/@browser/persisted-state.ts:198` 的 `entry()` 将状态放入持久 Map；命中同键时只核对粗粒度类型标签，直接返回旧门面并忽略新初值。`IS_BROWSER` 只禁用读盘写盘，没有禁用这份进程内缓存。
- React 的 `getServerSnapshot` 也传 `entry.get`，因此服务端渲染实际读取这份跨请求缓存。Vue 的 `bindingOf()` 同样按 entry 复用绑定。
- 两端现有测试通过每例使用不同 namespace 隔离单例，未覆盖两个 SSR 请求使用同一业务键的场景。

在仓库根通过 Nx 构建两端后执行：

```javascript
import { createElement } from 'react';
import { renderToString } from 'react-dom/server';
import { usePersistedState } from './packages/rxdb-react/dist/index.js';
import { usePersistedState as useVueState } from './packages/rxdb-vue/dist/index.js';
function Profile({ secret }) {
  return createElement('span', null, usePersistedState('review-ssr-profile', 'secret', secret).value);
}
console.log(renderToString(createElement(Profile, { secret: 'alice-private' })));
console.log(renderToString(createElement(Profile, { secret: 'bob-private' })));
console.log(useVueState('review-ssr-profile', 'secret', 'alice-private').value.value);
console.log(useVueState('review-ssr-profile', 'secret', 'bob-private').value.value);
```

实际两个 React 输出均为 `<span>alice-private</span>`，两个 Vue 输出均为 `alice-private`。Vue 此处验证的是 Node 服务端组合式函数调用，未运行完整 Vue SSR 渲染器。

## 修复方向

保留浏览器内同键共享语义，为 SSR 提供请求或应用作用域的注册表，并使两端从当前作用域取表；Vue 的绑定缓存随对应注册表隔离。补连续两次请求以及并发请求的隔离用例，核对 hydration 初始快照与 Angular 侧注入器内状态的契约。不要要求调用者靠每请求发明随机 namespace 绕过隔离问题。
