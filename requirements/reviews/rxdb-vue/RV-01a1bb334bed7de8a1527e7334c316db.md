# RV-01a1bb334bed7de8a1527e7334c316db：Vue useEntityChange 的 SFC 示例把嵌套 Ref 当实体读取导致标题始终为空

## 问题与影响

消费者逐字使用公开 TSDoc 或 README 中 useEntityChange 的 Vue 单文件组件示例，live 是包含 value Ref 的普通对象，模板却写 live.value?.title，实际对 Ref 读取 title。即使初始实体有标题或 patch 已到达，示例界面仍为空。运行时桥接及直接解构成顶层 Ref 的用法可以正确工作，问题限于推荐示例，定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-vue/src/use-entity-change.ts:81` 与 `packages/rxdb-vue/README.md:222` 均使用 `<div>{{ live.value?.title }}</div>`。
- `packages/rxdb-vue/src/use-entity-change.ts:108` 创建 shallowRef，第 136 行将该 ref 放在返回对象的 value 字段；返回对象本身不是 reactive，也不是 ref。嵌套对象字段不会在属性访问中自动解包。
- 真实行为测试 `packages/rxdb-vue/src/__tests__/use-entity-change.spec.ts:49` 的渲染函数使用 `change.value.value`，没有编译文档中的 SFC 模板，故不会发现这一错层。

本组 `repro-framework-doc-contracts.mjs` 使用项目所装 Vue 编译器编译两个模板，并由真实 Vue 自定义 renderer 挂载，唯一差异是读取路径。实体标题 first→updated 后，文档模板输出为 `{before:"",after:""}`，显式读取 live.value.value 的对照为 `{before:"first",after:"updated"}`。

## 修复方向

同步修正 TSDoc 和 README 的模板路径，或在 setup 直接解构返回的 value Ref 为顶层绑定，再在模板使用该绑定；补一个由真实模板编译器执行的推荐用法用例，验证初值及 patch 后标题可见。
