# RV-01a1bb2cb3a07e52b8851d5bd202d97c：Vue 同步状态面板在 provider 切库后继续订阅并显示旧库状态

## 问题与影响

应用通过公开支持的 `provideRxDB(shallowRef(databaseA))` 提供数据库，子组件在 setup 调用 `useSyncState()`。组件保留挂载并将 ref 切为 databaseB 后，六个同步状态字段仍来自 A，新库 B 的离线、待推、错误和冲突状态均不会显示，A 的后续变更反而继续改变当前面板。切换工作区或账号后会展示错误数据库的同步情况，旧库订阅保留到组件卸载。单库正常用法不受影响，按切库边界路径定为 P2。

## 证据与根因

证据快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `packages/rxdb-vue/src/rxdb-vue.ts:117` 接受调用方持有的 Ref 并原样提供；`injectRxDBRef()`/`useRxDBRef()` 公开这一响应式数据库引用。
- `packages/rxdb-vue/src/use-sync-state.ts:66` 仅在 setup 通过 `useRxDB()` 解构一次 `syncState`；第 69–72 行把订阅固定在旧 hub，仅注册卸载退订，没有观察数据库 ref 或切换订阅。
- React 对应实现 `packages/rxdb-react/src/use-sync-state.ts:52` 在 provider 改变后重新读取 `syncState`，订阅回调以该 hub 为依赖；Vue 缺少对应切换行为。
- `packages/rxdb-vue/src/__tests__/use-sync-state.spec.ts:47` 的挂载帮助函数只接受固定 RxDB，每例均验证单库，没有 provider ref 更换的断言。

本组 `repro-vue-sync-switch.mjs` 使用现有已构建公共入口、Vue 真实自定义 renderer 与 RxJS BehaviorSubject；不启动浏览器、不连接存储。A 的 pendingCount 初值 1，B 初值 20。把 ref 从 A 切 B 后实际仍为 1；随后 A 更新为 7、B 更新为 21，面板实际显示 7。输出：

```json
{ "afterSwitch": 1, "afterUpdates": 7, "before": 1, "newObserved": false, "oldObserved": true }
```

卸载后 A 订阅才清理。源码证据与公共入口复现一致；未修改源码和原测试。

## 修复方向

在 setup 获取响应式数据库 ref，观察数据库身份变化并先释放旧 hub、再从新 hub 的权威快照初始化和订阅。保持缺少 provider、初次未就绪的严格报错契约；与 React 的切库语义对齐。补 provider ref A→B、旧 hub 后续发射不影响面板、新 hub 发射可见和最终卸载退订回归。
