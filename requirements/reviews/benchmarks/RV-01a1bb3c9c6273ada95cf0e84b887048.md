# RV-01a1bb3c9c6273ada95cf0e84b887048：基准工厂丢弃 caller-owned Worker 句柄，重复运行持续遗留线程

## 问题与影响

在支持 OPFS 的浏览器中运行默认 wa-sqlite 基准，每个场景创建一个新 dedicated Worker。场景结束只断开 RxDB，Worker 的默认所有权却属于 caller；工厂既不保存句柄，也没有 terminate。四个场景跑完会留下四个空闲但仍活着的 Worker，重复运行继续线性累积。sqlite-wasm 的 OPFS 分支以及 sqliteai / 官方 sqlite 的 dedicated Worker 分支同样未交还所有权。浏览器线程及加载过的 WASM 运行时继续占资源，污染之后的内存/性能测量；需要多轮运行才能明显放大，按 P2 资源生命周期缺陷记录。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `benchmarks/src/utils/rxdb-factory.ts:111`、`benchmarks/src/utils/rxdb-factory.ts:137`、`benchmarks/src/utils/rxdb-factory.ts:161`、`benchmarks/src/utils/rxdb-factory.ts:176` 内联 new Worker，options 中没有 workerOwnership，函数最后只返回 rxdb，外部无法再取得 Worker 句柄。
- `packages/rxdb-adapter-sqlite-core/src/create_sqlite_client.ts:168` 将省略的所有权设为 caller；`packages/rxdb-adapter-sqlite-core/src/create_sqlite_client.ts:240` 只有 endpoint.root.ownership === 'client' 时才 disposeTransportRoot，`packages/rxdb-adapter-sqlite-core/src/create_sqlite_client.ts:217` 的 root.worker?.terminate() 因而不会运行。该 API 明确保留 caller Worker 供其复用，责任在创建它的工厂。
- `benchmarks/src/hooks/useBenchmark.ts:51` 每个 suite 都调用 createRxDB 建新实例，`benchmarks/src/hooks/useBenchmark.ts:109` 遍历四个 suite；`benchmarks/src/hooks/useBenchmark.ts:34` 断开时把 rxdbRef 置 null 后只 await disconnectAll，工厂创建的 Worker 无其他回收者。
- 即使改用 RxDB.destroy()，caller-owned transport 的契约仍不会替调用方 terminate；需同时处理所有权。

有界复现：`node /Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-benchmark-worker-ownership.mjs`。从冻结源读实际 factory 与 wrapWithComlinkEndpoint / releaseComlinkProxy，替换数据库、Worker 与 Comlink 的外部执行面，逐个实例化四个 dedicated Worker 分支并断开。实际 terminated 全为 false；相同回收代码对显式 workerOwnership='client' 的对照实例 terminated=true。脚本不启动浏览器、WASM 或真实性能数据量。

## 修复方向

工厂为自行创建、从不对外复用的 Worker 声明 client 所有权，或保存并在最终 teardown 中显式 terminate/关闭根端口。覆盖正常四场景结束、适配器创建失败和重复运行；共享 Worker 分支也应核对根端口所有权，避免关闭其他连接。验证多轮之后活 Worker 数量不随轮次增长。
