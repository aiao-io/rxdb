# RV-01a1bb66415f728cbb2c0cbff1f96483：OPFS 与 storage 路由重复解码，合法百分号名称抛错或改变目标路径

## 问题与影响

打开或导航到包含字面百分号的目录，例如 /opfs/100%25（真实目录名100%）时，Angular已将URL片段解成100%，matcher再decodeURIComponent便抛URIError，页面无法进入。名为literal%2Fname的合法单个目录则被再次解成literal/name两个层级，浏览目标改变。storage matcher使用相同处理。限定含百分号名称的路径，按P2记录。

## 证据与根因

冻结源码快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `apps/dev-rxdb-angular/src/app/app.routes.ts:28` 和 `apps/dev-rxdb-angular/src/app/app.routes.ts:43` 对每个 UrlSegment.path 再执行 decodeURIComponent。
- 实际 Angular DefaultUrlSerializer 已把 /opfs/100%25 的第二段解析为100%；/opfs/literal%252Fname解析为literal%2Fname。第二次解码分别抛URIError与改变名称为literal/name。
- 拼接后的值在 `apps/dev-rxdb-angular/src/app/app.routes.ts:34`、`apps/dev-rxdb-angular/src/app/app.routes.ts:49` 直接作为 opfsPath/storagePath 传入页面。错误发生在路由匹配期，无须数据库或OPFS权限即可触发。

复现：`node /Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-angular-path-decoding.mjs`。读取冻结matcher实际实现，调用当前安装的Angular DefaultUrlSerializer。四个断言通过：两个%路径抛URIError，两个字面%2F路径被改成两个层级。未启动Angular构建/浏览器。

## 修复方向

使用路由解析器已经解码的段值，保留文件名中的字面百分号；对%以及字面%2F补matcher回归，覆盖OPFS与storage，核对正常空格/中文路径。
