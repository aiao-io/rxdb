# RV-01a1bb8181557c9fb496ca848d463fc5：Angular 与 Vue 分支切换被拒绝后，选择器继续显示未切入的分支

## 问题与影响

当前处于main，用户在侧栏选择feature；若switchBranch因分支被其它检出位持有或其它前置检查而拒绝、当前分支数据未变化，Angular/Vue的下拉仍显示feature，但读写实际还在main。用户依据选择器继续编辑就会操作错误分支。React已有受控value及失败提示/回滚测试。此处限定切换失败边界，定P2。

## 证据与根因

冻结源码：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `apps/dev-rxdb-angular/src/app/components/branch-manager.ts:40` 与 `apps/dev-rxdb-vue/src/app/components/AppBranchManager.vue:76` 把当前分支绑定在各option的selected布尔值上，select本身没有受控value。浏览器change已经先改了真实选择值。
- Angular在 `apps/dev-rxdb-angular/src/app/components/branch-manager.ts:191` 仅打console，Vue在 `apps/dev-rxdb-vue/src/app/components/AppBranchManager.vue:50` 仅打toast；finally只取消pending，没有恢复select值。失败时activeBranch数据未改，option布尔绑定新旧相同，框架不会重写被浏览器改变的selected状态。
- 对照 `apps/dev-rxdb-react/src/app/components/AppBranchManager.tsx:73` 的受控value，以及 `apps/dev-rxdb-react/src/app/components/AppBranchManager.spec.tsx:74` 的失败回滚用例。Angular/Vue现有单测只检查外部挂载检出位改变时的选择值，没有检查失败后DOM与模型的一致性。

有界验证（均未启动完整Angular构建或浏览器）：

- `/Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-angular-branch-selection.mjs`：抽取冻结的select模板及原switchBranch方法，固定当前分支数据为main，用实际Angular TestBed和Happy DOM渲染；模拟选择feature，拒绝写请求后继续变更检测，实际仍选feature。
- `/Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-vue-branch-selection.mjs`：编译冻结的完整Vue SFC，使用实际Vue DOM渲染，替换外部数据库/工作树/通知依赖。拒绝switch后toast收到错误，但选择值仍feature。

## 修复方向

使选择器受当前分支快照控制，切换失败或尚未确认成功时显示真实分支；保留明确失败反馈。两端补与React等价的「当前main→选择feature→Promise拒绝→仍显示main」用例，再核对成功后的异步分支数据回传。
