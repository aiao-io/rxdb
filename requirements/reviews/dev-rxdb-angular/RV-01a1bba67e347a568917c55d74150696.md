# RV-01a1bba67e347a568917c55d74150696：三端远程缓存页在卸载后继续创建预览 URL，导航反复累积 Blob 资源

## 问题与影响

已缓存文件存在时进入远程缓存页，在异步 list 或 createObjectUrl 返回前快速离开；清理先扫空 URL Map，随后迟到初始化又分配 Blob URL 并保存到已离页的 Map。这些 URL 不再有页面清理机会，保留到长期存活的数据库服务销毁或整个文档关闭；反复导航、大文件缓存会持续占用内存。三端都有同一生命周期缺口，定 P2。

## 证据与根因

冻结源码：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `apps/dev-rxdb-angular/src/app/pages/remote-cache/remote-cache.page.ts:183` 的 refresh 在两个 await 后不检查页面有效期，第198行创建 URL 并重新写入 Map；第98行 ngOnDestroy 只调用一次 releaseObjectUrls。
- `apps/dev-rxdb-react/src/app/pages/remote-cache.tsx:77` 的 loadCachedItems 有相同序列，第112行 effect 启动后第114行清理无法阻止其后续分配。
- `apps/dev-rxdb-vue/src/pages/RemoteCachePage.vue:85` 的 refresh 在第100行分配，第181行 onUnmounted 仅清空现有 Map。
- `packages/rxdb-plugin-storage/src/storage.service.ts:348` 的 createObjectUrl 由服务登记资源，调用方应 revoke；服务仅在自身 destroy 时兜底回收。页面导航不会销毁应用数据库，服务层 active 校验不能代替页面的取消。

诊断 `/Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-remote-cache-late-url.mjs` 转译冻结的完整 Vue script，捕获原 mounted/unmounted 入口，替换存储 IO 并用真实 Blob URL 分配；按 mounted→unmounted→list返回一项执行，结果 createdAfterUnmount=1、revoked=0、liveUrls=1。Angular/React 以各自原刷新与清理控制流核实同根因；未宣称三端浏览器集成测试。

## 修复方向

给页面刷新设置生命周期和请求纪元；等待后若失效，不再分配 URL，已分配的迟到结果立即 revoke。串行或去重同一文件的并发预览创建，并覆盖在途初始化晚于卸载、重入刷新两种时序。
