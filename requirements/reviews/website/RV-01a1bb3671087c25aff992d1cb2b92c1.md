# RV-01a1bb3671087c25aff992d1cb2b92c1：架构页的客户端生成命令指向不存在的 Nx target

## 问题与影响

读者按照架构页「关键代码路径 → 2. 生成稳定接口」复制命令 `nx run rxdb-client-generator:generate`，无法完成客户端生成：仓库没有给该项目声明 generate target，包也没有同名 script，已配置的 Nx 插件未把 generate 作为推断 target。安装全局 Nx 或补 pnpm 前缀都不能修复这个不存在的目标。该页面把命令作为定义模型后的实际生成步骤，导致读者无法继续到后面的 Todo.find 示例，按 P2 文档功能缺陷记录。

## 证据与根因

冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `website/src/pages/architecture.tsx:488` 的 bash 代码字符串是上述命令，紧接着承诺输出实体类型、CRUD、框架封装与关系支持。
- `packages/rxdb-client-generator/project.json:5` 的显式 targets 仅 typecheck；`packages/rxdb-client-generator/package.json:28` 提供 bin rxdb-client-generator，没有 generate script；`nx.json:53` 起的插件只配置 build/typecheck/dev/serve/lint/test/e2e 等目标，没有为本包生成 generate。
- 真实入口 `packages/rxdb-client-generator/src/cli/cli.ts:97` 的 main 以第一个参数作为配置文件路径，无参数会输出 Usage 并退出。`website/docs/client-generator.md:20` 起已给出配置文件 + 包 CLI 的可行接入方式，架构页未与它保持一致。
- 示例位于 TSX 字符串中，既有 TypeScript/ESLint 与 Markdown 文档检查不能发现不存在的命令目标。

## 修复方向

让架构页引用客户端生成文档已给出的真实 CLI / 配置文件用法，或改为链接到接入说明。若保留可复制命令，明确配置文件输入，使用仓库包管理器前缀，并用轻量检查验证命令对应项目目标或包 bin 存在。
