# RV-01a1bb297e76773182c8142a5baa5a2e：深链挂载后的首次快速导航被路由闸门丢弃，宿主 URL 停留旧页

## 问题与影响

从文档站深链（如 /demos/vue/todo）打开 demo，或宿主把已加载的 demo 导航到 /todo，子应用完成该导航后 600ms 内再点击 /search：子页面已经进入 /search，宿主地址仍停留 /demos/vue/todo。闸门超时仅发生在下一条回传到来时，不会补回被丢弃的 /search，因此等待也不会自行一致。复制 URL 或刷新会回到错误页面。三端共用此协议，均受影响。需要窗口内快速操作或宿主连续导航，按 P2 边界时序问题记录。

## 证据与根因

证据冻结快照：`0ffa3c419fcc59dc3e13d695ca4658116134bfa0`。

- `website/src/components/DemoMicroAppClient.tsx:93` 的 expectRoute 对非根路径设置 pending；`website/src/components/DemoMicroAppClient.tsx:98` 的 armRouteSync 在 afterMount / activated（`website/src/components/DemoMicroAppClient.tsx:178`、`website/src/components/DemoMicroAppClient.tsx:179`）重新上闸，宿主后续路径变化也在 `website/src/components/DemoMicroAppClient.tsx:143` 上闸。
- `modules/wujie/src/host-route.ts:249` 在接到宿主路径时先将 current 设为该路径，再驱动框架导航；实际导航完成的回调在 `modules/wujie/src/host-route.ts:258` 因 next === current 直接返回，故不会把宿主等待的确认回传回来。
- `modules/wujie/src/host-route.ts:228` 只接受精确命中 pending 的路径；首次用户导航到不同路径时返回 false。宿主在 `website/src/components/DemoMicroAppClient.tsx:158` 直接丢弃该回传，没有缓存或超时重放。
- 原测试分别验证「宿主导航不回传」与「pending 不匹配则拒绝」，没有验证二者接在一起后的快速用户导航。

有界复现：`node /Users/jimmy/Documents/aiao/rxdb/.git/ai-review/v1/runs/full-main-20261108/parallel-001/web/repro-route-sync.mjs`。脚本从上述 SHA 读取实际协议实现，使用同步假 bus 与可控时钟：expect('/todo') → bindWujieRoute(props.route='/todo') → 导航完成 onChange('/todo') → t=100ms 用户 onChange('/search')。实际 hostPath=/todo、subPath=/search、accept=false；t=601ms 后 hostPath 仍为 /todo。

## 修复方向

统一宿主闸门与子应用导航确认的契约：宿主期望路由完成后明确解除 pending，或者在等待期区分初始化回弹与真实用户导航。核对首次深链、宿主前进后退、alive 再激活及快速连续点击。给 website / wujie 增加组合时序回归，确保用户已经完成的导航不会被永久丢弃。
