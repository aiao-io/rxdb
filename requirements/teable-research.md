## 第一项：保存业务视图

### 入场条件与最小范围

用户反复对同一实体重做相同筛选、排序或列配置，刷新或重新进入后需要再次设置。
先用现有资产工作台验证这种重复劳动。

建议首版交付：

- 一个实体可以创建、重命名、切换和删除多个命名视图。
- 保存筛选、排序、列顺序与显隐；列宽、冻结列和分组可分别评估，避免扩大首版。
- 刷新或重开后恢复视图；空结果、配置损坏、字段失效均给出明确结果。
- 视图只引用既有实体与字段；运行时建表、多用户共享和权限隔离单独评估。

### 后续需要拍板

| 决策        | 建议                                           | 需要核对的问题                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------- |
| 持久化归属  | 优先评估工作台自己的配置实体，形成可备份的数据 | 配置是否需要随数据备份、跨设备移动、与业务写入分开管理？ |
| 配置边界    | 用一个框架无关配置描述筛选、排序与列信息       | 既有查询状态哪些可以稳定序列化，哪些是运行时对象？       |
| schema 变化 | 显式报告失效字段，让用户修复                   | 重命名能否可靠映射？不能映射时如何保留配置和当前编辑？   |
| 默认视图    | 始终保留可用的基础入口                         | 删除当前视图后回到哪个明确入口？默认排序如何保持稳定？   |

### 验收与边界

用“在用资产”“购入价高于指定金额”“按分类查看”三个视图验证切换、重命名、删除、刷新与关闭重开。
筛选结果和列配置应按视图独立保存。检查非法配置、失效字段、无匹配记录及配置保存失败时的反馈。
筛选与列显隐仅影响呈现，权限隔离另按权限模型实现。

## 第二项：CSV 导入导出

### 入场条件与最小范围

有一份使用者会持续维护的真实清单，需要从现有表格搬进工作台，或把筛选结果交给其他工具。
先确认文件、字段和预期记录数，再估算首版容量。

建议首版交付：

- 向既有实体导入 CSV：读取表头、选择字段映射、预览解析结果与逐行校验错误。
- 第一版优先追加新记录；更新现有记录、按业务键合并、Excel 文件与运行时推导 schema 分别评估。
- 导出整实体或当前筛选结果，明确列顺序、排序、编码与关系字段表示。
- 数据库备份继续承担恢复职责；CSV 的范围是业务数据交换。

### 后续需要拍板

| 决策           | 建议                                       | 需要核对的问题                                                 |
| -------------- | ------------------------------------------ | -------------------------------------------------------------- |
| 写入与失败语义 | 首版容量内优先校验通过后整批事务提交       | 目标适配器支持什么事务边界？超出容量是否明确拒绝？             |
| 重复记录       | 不自动覆盖；首版显式拒绝唯一约束冲突       | 主键、业务唯一键、空值与同批重复如何报告？                     |
| 类型转换       | 复用字段语义与校验，解析失败保留原值供修正 | 空字符串与 null、金额精度、日期时区、布尔值采用何种约定？      |
| 关系字段       | 单独确定支持范围，无法唯一匹配时拒绝       | 按 ID 还是业务键关联？同名、缺失和引用尚未导入的记录如何处理？ |
| 当前视图导出   | 导出全部命中记录                           | 如何跨分页查询，并保证导出范围与稳定排序一致？                 |
| 往返兼容       | 声明可无损往返的类型集合                   | JSON、数组、长整数、附件和关联如何编码？                       |

### 验收与边界

导入一份真实资产 CSV，核对条数、字段值和关联结果；导出筛选结果后，验证声明支持的字段可重新导入。
覆盖 UTF-8 BOM、引号、逗号与换行、重复表头、缺失必填、类型错误、唯一约束冲突、不可写字段及事务失败。
还需明确导出到电子表格时公式样式内容的处理策略，避免转义规则破坏承诺的往返语义。
整批或分批提交的语义必须能通过故障注入验证，不能出现成功提示下的未知部分写入。

## 第三项：关联引用与汇总

### 入场条件与最小范围

已有界面重复拼装关联名称或聚合值，使用者需要在当前列表直接查看这些结果。
现有 [资产分类、资产与维护记录](../apps/dev-rxdb-admin/src/app/entities/asset-entities.ts) 可作验证载体，
但示例本身仍需实际使用证明需求。

建议首版交付：

- Lookup：沿已有关系读取关联记录的指定字段，例如资产显示分类名称。
- Rollup：沿一对多关系计算维护记录数量与费用合计；先验证 count / sum，再评估其他聚合。
- 来源新增、修改、删除、关系重绑后，结果响应式更新。
- 派生结果以只读形式在表格、表单和详情保持一致；底层关系选择体验另按现有组件补齐。

### 后续需要拍板

| 决策             | 建议                                         | 需要核对的问题                                                 |
| ---------------- | -------------------------------------------- | -------------------------------------------------------------- |
| 派生值的生命周期 | 优先验证查询时派生，物化在性能证据出现后评估 | 是否进入同步、历史和备份？离线重开后如何重建？                 |
| 执行位置         | 先限定已验证的本地适配器组合                 | SQLite / PGlite 等后端是否具有相同聚合、精度和响应式失效语义？ |
| 结果形状         | 首版优先标量引用与标量聚合                   | 多值 Lookup 的顺序、去重、空集合与 null 如何定义？             |
| 类型与金额       | 沿用字段类型和聚合结果契约                   | 空记录的 count / sum 返回什么？数值精度是否满足维护费用？      |
| 查询能力         | 显示先行，筛选排序单独明确                   | 派生字段能否参与筛选排序，在哪些适配器上成立？                 |
| 依赖约束         | 明确限制路径与检测循环                       | 多跳关系、多对多重复记录、循环依赖如何处理？                   |

### 验收与边界

给一台资产新增两条维护记录，核对维护次数与费用；修改费用、删除维护记录、重绑所属资产后，列表和详情应更新。
补验空关系、零条记录、来源字段空值、被引用记录删除、非数值聚合与依赖失效。
跨适配器结果、不可编辑的派生字段，以及失败时不保留看似有效的旧值都应纳入验收。

| 附件字段            | 用户确实需要给业务记录绑定文件           | 元数据与文件体的删除、备份恢复、对象 URL 回收；缩略图与跨设备文件体同步另估          |
| 看板 / 日历 / 画廊  | 有状态流、排期或图片浏览任务             | 拖拽能否写回字段、日期边界、手动排序与筛选一致性；区分通用视图与任务看板领域模型     |
| 收集表单            | 专用录入或外部收集需求出现               | 内部表单可复用现有组件；公开链接需远端接收、访问控制、附件与滥用限制                 |
| Query Library / MCP | 具名脚本或 AI 消费方反复调用查询         | 查询 ID 与版本、参数契约、返回类型、授权和字段暴露；不能把连接工具视为已完成权限控制 |
| 自动化              | 明确的重复动作值得自动执行               | 浏览器关闭后的执行责任、离线补跑、幂等、触发循环、失败重试与外部动作凭据             |
| 权限                | 团队明确要求按人、角色或字段隔离         | 读取与写入、权威端校验、选择性同步、已下载数据的生命周期；只隐藏 UI 不能证明隔离     |
| AI 字段             | 有一份可评价结果质量的数据整理任务       | 预览、覆盖范围、来源变化、过期结果、失败重跑、成本与数据发送范围                     |

公开收集、多人协作、任意运行时 schema 编辑、完整 AI 应用构建器分别需要独立的用户与范围证据。
当前结论先服务固定 schema 的单人本地工作台。
