# 候选领域：稍后读与批注（Pocket / Instapaper 重构）

> 本文是候选领域分析，不是用户故事，不参与状态统计。状态与维护规则见
> [本目录 README](README.md)。

**一句话结论**：正文搜索、批注实体与进度持久化可复用；内容导入、正文提取、批注锚点与失败恢复仍需实现。
先用真实阅读任务验证个人工具闭环，不以竞品已有功能推断商业上限。

**对标产品**：Pocket（品类鼻祖）；Instapaper；Readwise（高亮批注标杆）；Wallabag（开源自托管）。

## 引擎缺口

无。正文抓取 / 可读性提取不是引擎缺口——那是外部服务。

## 引擎外成本

- **正文抓取与可读性提取**：URL → 干净正文的服务（自建或第三方），演示版可手动导入正文绕开
- 服务端账号体系（可选）

## 立项前置

无硬前置（演示版手动导入正文）。

## 入场条件（什么信号才值得立项）

- 出现具名用户「多设备阅读进度不同步 / 收藏夹搜不到内容」的具体症状
- 或 owner 决定做「实体关系 + FTS + 进度同步」的轻量演示
