# 候选领域：密码管理器（Bitwarden / 1Password 重构）

> 本文是候选领域分析，不是用户故事，不参与状态统计。状态与维护规则见
> [本目录 README](README.md)。

**一句话结论**：本地字段加密、条目表单与数据库备份可复用，但本地静态加密不等于零知识同步。
单机保险库可作为验证切片；E2EE、跨设备密钥与恢复协议需要独立设计和安全验证。
加密字段不能进入现有搜索索引，解锁后应用层过滤的范围与暴露面也须明确。

**对标产品**：Bitwarden（开源 E2EE 标杆）；1Password（体验标杆）；KeePass（纯本地路线）。

## 引擎缺口

US-803 只承诺本地持久化前加密、读取时解密，明确排除跨端密钥同步和远端密钥管理。
不能据此保证 Supabase 只接收密文；E2EE 的载荷、密钥、历史日志与备份边界均需验证。
搜索先限定为解锁后的应用层过滤，容量、自动锁定和明文清理须纳入原型验收。

## 引擎外成本

- **密钥与恢复协议**：主密码 KDF、跨设备密钥分发、共享与撤销、恢复和换钥；可复用密码学库，
  仍需验证协议及其与同步、历史和备份的组合
- **浏览器自动填充扩展**：平台插件开发，与引擎无关
- 2FA / WebAuthn 集成

## 立项前置

先验证本地单机保险库的解锁、自动锁定与可恢复备份。多端版本须先定义 E2EE 和密钥生命周期，
证明同步载荷、远端行及日志均不包含秘密明文，不能把通用 Supabase 同步视为已交付的密文协议。

## 入场条件（什么信号才值得立项）

- 出现具名用户「跨设备密码不同步 / 丢失保险库」的具体症状
- 或 owner 批准有明确安全边界的本地加密演示；同步需另验 E2EE 前提
