# 候选领域：密码管理器（Bitwarden / 1Password 重构）

> 本文是候选领域分析，不是用户故事，不参与状态统计。状态与维护规则见
> [本目录 README](README.md)。

**一句话结论**：加密是品类的生死线，而加密 keyring 是引擎**内建**能力——离线解锁、
条目表单、多端同步、备份恢复全部现成。与微信客户端候选的关键差异：密码管理器必须走
零知识（E2EE）模型，因此「加密与搜索互斥」在这里**成立**，搜索走解密后应用层过滤。

**对标产品**：Bitwarden（开源 E2EE 标杆）；1Password（体验标杆）；KeePass（纯本地路线）。

## 引擎缺口

无硬缺口。搜索与加密的互斥在本候选成立（零知识模型要求密文不进索引，
[vision](../vision.md) 阶段 6），但保险库条目量级（千级）用解密后应用层过滤完全够，
不需要 FTS。

## 引擎外成本

- **密钥派生与共享协议**：主密码 KDF、家庭共享 / 组织密钥交换（Bitwarden 的核心难点）——
  纯引擎外，可用现成密码学库
- **浏览器自动填充扩展**：平台插件开发，与引擎无关
- 2FA / WebAuthn 集成

## 立项前置

无硬前置（可先做本地单机保险库 + Supabase 密文同步，共享协议后置）。

## 入场条件（什么信号才值得立项）

- 出现具名用户「跨设备密码不同步 / 丢失保险库」的具体症状
- 或 owner 决定做「加密 + 同步」的旗舰演示——本地加密是引擎与竞品差异化的第一卖点
