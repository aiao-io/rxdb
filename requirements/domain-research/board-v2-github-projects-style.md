**一句话结论**：把 GitHub Projects v2 里对本地单人版可移植的能力分成三层补进看板——A 层
细节密度（列头统计、卡片 chip 化、hover 操作、点击即筛选、快捷键面板）零 schema 变更、
感知最大；B 层视图系统（结构化筛选条、保存视图、表格视图、可选字段体系）是「跟 GitHub
没法比」的结构性差距；C 层本地工作流（列 → 完成 / 归档、陈旧卡归档）与洞察图表后置。

## 对标拆解：GitHub 强在哪（三层）

GitHub Projects 的看板不是「功能清单」堆出来的，而是三层结构：

### 层一：条目生态（卡片是实体的投影）

- 条目有三种类型：**issue / PR / draft**。draft 是项目本地条目——无仓库负担、无通知、
  快速捕获，需要时才「转换为 issue」选仓库落地。
- 每个条目有自己的主页：描述（含任务清单 checkbox，逐条可转成独立 issue）、活动时间线、
  子 issue、引用关系。卡片只是它的一个投影；Board / Table / Roadmap 是同一实体的三种投影。
- assignee / 提及 → 通知，构成协作回路。

**对本地版的启示**：我们不需要 issue 生态，但「实体 + 多投影」的架构可以学——同一个
Task 实体在板视图与表格视图下是同一份数据；「快速捕获（draft 式轻量任务）→ 补充字段」
的两段式录入也是纯本地可做的。

### 层二：视图系统（这才是「没法比」的主体）

- 项目主页顶部是**多个保存视图的 tabs**（如「当前迭代」「Backlog」「我的工作」），加
  「洞察」与「设置」页；项目还有标题、短描述与 README。
- 每个视图 = 布局（板/表/路线图）+ 筛选 + 排序 + 分组 + 切片 + 字段可见性 + 列上限，
  全部打包保存，改完有「保存 / 放弃修改」。
- 视图头部的**筛选条**：输入时自动补全字段与值，语法含 `label:bug,support`（同字段 OR）、
  `-status:done`（否定）、`has:/no:`、`@me`、相对日期 `@today..@today+7`、迭代 `@current`；
  已生效的筛选以可点击删除的条目呈现。
- **点击卡片上的数据即筛选**（board 布局）：点卡片上的某个标签，直接 toggle 该值的筛选——
  零学习成本的筛选入口。
- 表格视图是「数据区」：行即条目、单元格点击即编辑、批量勾选改字段、triage 用 `no:priority`
  切片——GitHub 的实际工作流是「表格里管数据、看板里看状态」。

### 层三：细节密度

- 列头 = 值名 + 条目数 + **字段求和**（数字字段合计）；列菜单（设上限 / 隐藏列 / 移动 / 排序）；
  列底 `+ 添加条目` 输入框（Enter 提交 / Esc 取消）。
- 卡片：标题、标签、assignee 头像、截止日 chip（逾期红色）、关联 PR 图标（带合并状态色）、
  milestone、编号；hover 出现快捷操作（归档 / 转换 / 复制链接）。
- 键盘体系：方向键在卡与列间移动、Enter 打开、`Ctrl+Shift+.` 侧栏、`?` 快捷键面板；
  批量选择（Shift 点击）整体移动。
- 右侧面板：所有字段 + 描述 + 活动时间线 + 子 issue；不离开板就能完成大部分编辑。

## 差距定位（对照 v1 demo）

| 层       | GitHub 有                                                       | 我们 v1                        | 差距性质             |
| -------- | --------------------------------------------------------------- | ------------------------------ | -------------------- |
| 条目生态 | 实体多投影、draft 快速捕获、任务清单转 issue                    | Task 单实体、详情面板          | 架构可学，生态不需要 |
| 视图系统 | 保存视图 tabs、筛选条自动补全、点击即筛选、表格视图、切片       | 无（仅板选择器 + 全文搜索）    | **结构性差距，最大** |
| 细节密度 | 列头计数+求和、卡片 chips/头像/图标、hover 操作、`?` 面板、批量 | 列头计数、标题+标签+截止日文本 | 感知差距，成本最低   |

## 引擎缺口

- **字段与列实体的关系要定**：v1 列是实体（[US-534](../stories/domain/US-534-board-column-task-skeleton.md)），
  v2 字段是 Task 上的属性，两者并存——字段不驱动列、列仍由 Column 实体驱动。与 GitHub
  「列 = 字段值」不同，是有意的模型差异，不应动摇 US-534 的地基。
- **保存视图、可选字段、本地工作流规则需要 schema 变更**：新实体 / 新字段各一次迁移；
  归档恢复到实体结构指纹一致版本的约束（US-537）随迁移版本推进。
- **表格视图需要与 rxdb-model 的能力对齐评估**（单元格编辑 / 批量编辑的命令面已有先例），
  避免在看板包内另造一套表格。
- 其余各项可用现有公开能力，无计划内引擎前置。

## 引擎外成本

全部本地能力、零后端；主要工作量是三端对称 UI 与 e2e。无账号、无同步（团队版仍归价值
待证的 US-541）；不采纳的部分：assignee / 提及通知 / 关联 PR / 组织级工作流配额 /
GraphQL API 自动化——这些的本地价值为零。

## 分项清单（按成本 × 感知排序）

### A 层：细节密度（零 schema 变更，逐项独立可交付）

| 项                                                 | schema | 依赖         | 备注                                                         |
| -------------------------------------------------- | ------ | ------------ | ------------------------------------------------------------ |
| 列头统计（任务数旁加「逾期 N」与标签分布小计）     | 无     | 无           | 数据现成，纯视图派生；感知最大的一行改动                     |
| 卡片截止日 chip 化（色块 + 图标，逾期红 / 今天黄） | 无     | 无           | 替代现在的纯文本；颜色只作辅助（US-539 约定不变）            |
| 卡片 hover 快捷操作（编辑 / 复制 / 移动入口）      | 无     | 无           | GitHub 同款 hover 工具条                                     |
| 点击卡片标签 → toggle 该标签筛选                   | 无     | A 层筛选状态 | board 布局的 click-to-filter；筛选状态即标签 id 集合         |
| `?` 快捷键面板 + 方向键卡片导航                    | 无     | 无           | GitHub 键盘体系；AC#6 已要求键盘等价，面板是 discoverability |
| 详情面板分区（字段 / 描述 / 标签分组，右栏不溢出） | 无     | 无           | 现状为平铺 label 列表，对照 GitHub 侧栏信息架构              |

### B 层：视图系统（结构性差距；结构化筛选与多视图需按决策 5 复核解锁）

| 项                                                        | schema | 依赖            | 备注                                                           |
| --------------------------------------------------------- | ------ | --------------- | -------------------------------------------------------------- |
| 结构化筛选条（标签多选、截止日范围、有 / 无；chips 可删） | 无     | US-538          | 只做 UI 筛选器 + chips，不必实现 GitHub 全文语法；自动补全可选 |
| 搜索结果就地呈现（未命中淡化、命中高亮）                  | 无     | 结构化筛选      | 纯视图改法，替代独立结果列表                                   |
| 分组泳道（按标签）                                        | 无     | US-028          | 升级路径与草稿区「按字段分组的视图」一致                       |
| 可选字段体系（优先级单选项、规模数字）                    | 有     | 无              | 地基项：解锁字段求和、列上限、按优先级分组                     |
| 列头统计扩展（字段求和 + WIP 上限）                       | 有     | 可选字段        | 与 GitHub 同为提示性、不强制                                   |
| 保存视图（`BoardView` 实体 + 板上视图 tabs）              | 有     | 前五项          | 布局 + 筛选 + 分组打包，可切换；每个板多视图                   |
| 表格视图（同实体集）                                      | 有     | rxdb-model 对齐 | 与草稿区「多视图工作台」合并评估，避免另造表格                 |
