# 用户故事：重开恢复与备份导出

## 作为/我想要/以便

**作为** 单人看板用户
**我想要** 导出我的看板数据，关掉浏览器、甚至清掉站点数据后，还能导回来继续用
**以便** 攒了半年的任务清单不会因为清一次浏览器缓存就没了

## 范围边界

### In Scope

- **重开恢复**：刷新 / 重开浏览器后板、列、任务、标签与排序全部原样（持久化验收，与
  [US-526](US-526-board-column-task-skeleton.md) AC#3、[US-528](US-528-task-detail-editing.md) AC#1
  的重开断言同源，本故事把「重开」做成产品入口与验收闭环）
- **备份导出**：以 [US-217](../adapter/US-217-local-database-backup-restore.md) 已交付的备份 API
  生成归档文件，浏览器侧触发下载（归档可带走，与站点数据隔离）
- **备份恢复**：在普通连接之前，将同 adapter 的兼容归档恢复到新的空存储位置；完整校验、持久化
  与读回成功后再切换当前看板，失败或取消保留原库与原活动位置，不覆盖或合并非空库
- **启动入口**：无本地看板时先显示「新建看板 / 从备份恢复」，选择前不连接数据库、不建表、不装载
  种子；已有看板从工具菜单进入恢复，先通过 US-526 的应用可写上下文门禁，再确认「恢复成功后将打开备份中的看板」
- **UI 状态**：导出中 / 已下载 / 选择备份 / 恢复中 / 已恢复 / 失败或取消；三端交互由
  [US-531](US-531-board-tri-framework-ui.md) 接线，本故事冻结状态转换与失败后去向
- **首轮支持组合**：三端与 demo 默认使用 US-217 已支持的 **PGlite 主线程 + IndexedDB 持久化**，
  导出和恢复保持同 adapter、同兼容配置；必须实跑导出 → 清站点数据 → 启动恢复 → 重开闭环
- **额外连接形态**：OPFS 专用 Worker / IDB SharedWorker 等不在备份矩阵内的组合必须如实拒绝；
  此类拒绝仅验证能力边界，不能替代首轮支持组合的成功验收

### Out of Scope

- 跨端同步备份（→ [US-533](US-533-board-team-sync.md)）
- 云备份 / 自动定时备份
- 备份加密与 keyring 语义——US-217 已覆盖（加密字段保持密文、密钥不进入归档），本故事不扩展
- 损坏数据库的自动修复（US-217 边界：只允许拒绝，不得猜测性恢复）
- 覆盖或合并非空库、跨 adapter 迁移、自动把 Worker 连接降级成内存库
- 外置附件备份；首轮看板数据不包含附件，归档仅覆盖数据库

## 技术笔记

**这是 domain-research 产品形态结论的直接落地：浏览器清数据即丢库，备份 / 导出必须一等公民。**
零后端单机版（静态托管、无服务端）的命门是「清站点数据 = 丢库」，备份属于首轮切片。
US-217 已交付一致快照、空目标恢复、完整性检查与失败原子性；看板仍须补齐**应用启动、存储位置
选择、跨标签页协调与切换**，不能把引擎能力完成等同于产品闭环完成。本故事不修改引擎 API。

**支持配置先固定。** PGlite 主线程客户端的 `idb://` 已在 US-217 阶段 A 矩阵内，支持持久化
导出与恢复。三端和 US-532 首轮 demo 使用此组合；相同 `dbName`、schema、扩展与版本兼容配置
用于源和目标，物理 IndexedDB 位置可不同，加密认证域不得更名。US-909 实测的 OPFS 专用 Worker /
IDB SharedWorker 仍明确拒绝；不可用内存目标冒充「重开恢复」。

**恢复生命周期由应用服务编排，三端消费同一状态。**

| 状态              | 允许操作与转换                                                                               | 失败 / 取消后去向                                            |
| ----------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 启动选择          | 无活动库时选择新建或恢复；只有新建才连接并允许显式装载演示数据                               | 留在启动选择，不自动建库                                     |
| 选择备份          | 文件选择本身不写库；已有库恢复先确认，取消不启动恢复                                         | 回到原看板或启动选择                                         |
| 恢复中            | 协调所有已打开页面，暂停写入与重复提交；选新空位置并取得目标独占后调用恢复，不先 `connect()` | 原活动位置保持不变；清理本次目标，原看板可重新打开           |
| 切换中            | 完整验证并持久化后，先释放所有旧活动连接及其作用域，再连接目标读回；成功才持久保存新活动位置 | 关闭失败的目标连接，再按旧活动位置重连；不删除原库           |
| 已恢复            | 打开备份中的看板；其他页面重新读取活动位置后才能恢复写入                                     | 后续操作沿正常看板流程                                       |
| 恢复失败 / 未完成 | 按错误类别展示重试、关闭其他页面、释放空间或安全清理入口                                     | 未完成目标禁止普通连接；清理失败保留可判别状态，不伪装成空库 |

新的空目标必须没有任何引擎内容、系统表或元数据；目标独占从空状态检查持续到恢复成功或失败
处理结束，覆盖其他实例、标签页及重复恢复请求。应用层协调同时防止恢复过程中其他页面继续向
旧活动库写入；协调失败先拒绝本次恢复，不强行关闭别人的连接。应用保存的活动位置是启动选择
依据，切换提交前中断仍回到旧位置，提交后中断只能打开完整的恢复库。只有原库不存在时才回到
启动选择；检测到未完成恢复不得走普通空库初始化。种子仅由明确的新建演示 / 重置动作触发，
不能挂在页面加载或恢复目标连接钩子中。

源与目标保持相同逻辑 `dbName`，但物理位置不同；[`RxDBTabsGateway`](../../../packages/rxdb/src/gateway/RxDBTabsGateway.ts)
的广播与选主域按 `dbName` 区分。连接新目标前必须释放全部旧活动连接与页面作用域；旧页面不能
完成释放时拒绝切换，不能让不同物理库同时作为同一逻辑库活动。失败时关闭目标再重连原库，
验证源库可恢复时也必须先断开目标。

导出入口沿用 US-217 的流式有界处理、取消与输出完成语义；只有输出完成才能显示「已下载」。
切换提交前的取消保留原活动位置；切换提交后到达的取消不回退已完成结果。
恢复错误按稳定错误码映射为用户可执行的提示，技术详情放诊断信息，不要求用户理解 adapter、
Worker 或物理存储位置。与原看板断开、目标连接及活动位置切换失败都必须覆盖，不能只测试
归档损坏。

**关闭条件**：首轮支持组合在三端完成持久化导出 → 清站点数据 → 连接前恢复 → 重开闭环；
已有库恢复到新位置且切换失败保留原库；竞争页面、取消、中断与失败路径符合上述状态流；
不支持组合如实拒绝；恢复后继续编辑和导出正常。US-532 AC#6 复用连接前启动恢复路径。
