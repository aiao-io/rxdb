# 用户故事：三框架看板视图与交互

## 作为/我想要/以便

**作为** 三端 demo 的维护者与看板模型的接入者
**我想要** Angular / React / Vue 三端各有一份功能相同的看板视图——板 / 列 / 卡片、拖拽、详情
面板、搜索框、备份入口
**以便** 看板领域模型一次定义、三端一致消费，单端缺失不算完成

## 交付阶段

| 阶段  | 内容                                                                                         | 关闭判据           | 前置                              | 状态 |
| :---- | :------------------------------------------------------------------------------------------- | :----------------- | :-------------------------------- | :--- |
| **A** | 基础看板：空库创建、板切换、列与任务排序、本列排序、详情、标签、撤销重做、删除确认、备份恢复 | AC#1～14 三端全绿  | US-534 / US-535 / US-536 / US-537 | ⚠️   |
| **B** | 板内搜索与结果定位                                                                           | AC#15～16 三端全绿 | US-538、阶段 A                    | ⬜   |

阶段 A 可独立交付，不依赖搜索；搜索框只在阶段 B 接入后出现。三端对称按阶段验收，

## 范围边界

### In Scope

- **基础闭环**：空库建板、建列、建任务；多板切换；板 / 列 / 任务删除确认与取消；重开后数据一致。
  删除前列出受影响的列数 / 任务数 / 标签定义数 / 任务标签关联数，按实际级联范围展示；删除任务
  同时显示标题，删列不删除板级标签定义
- **看板视图**：列横向排列、任务卡片纵向堆叠，列序支持拖动与键盘移动；卡片显示标题、标签名与
  颜色、可选截止日。板选择器按板的创建时间升序、同时刻按 `id`；打开时进入上次打开的板（记在本地），
  没有则进第一块。三端同功能同领域 API，不要求 DOM 或像素完全相同
- **真实拖拽**：三端 Playwright 用真实拖拽验收（US-028 阶段 B 先例）；三端只采集 Pointer Events，
  落点换算调用 [US-535](US-535-cross-column-move-ordering.md) 核心包里的同一份换算表
- **本列排序**：列菜单「按截止日排序」「按标题排序」，执行中阻止重复提交，成功后整列一次可撤销；
  领域语义随 US-535
- **详情面板**：看板绑定自建详情面板，消费 [US-536](US-536-task-detail-editing.md) 的详情编辑服务
  （不使用 rxdb-model 的 `EntityDetail`，理由见 US-536）；卡片标题提供内联编辑，同样调用其校验与保存服务
- **板级标签与编辑历史**：创建 / 改名 / 改色 / 删除板级标签，任务可选多个标签；撤销 / 重做入口
  沿 US-302 处理本次会话内最近的变更事务，不过滤成「仅任务编辑」历史；未保存输入不建立独立历史
- **搜索框**：三端绑定消费 US-538 提供的同一 `SearchSourceLike` 领域源，复用其板内过滤、分页与
  请求失效语义；阶段 B 起接入，不让三端各自实现板内过滤
- **备份入口**：导出、启动页（新建空看板 / 装载演示数据 / 从备份恢复）、工具菜单恢复与重置为演示数据，
  及其状态反馈随 [US-537](US-537-board-backup-restore.md)
- **写入门禁**：实体入口取「非恢复中」与 `deriveEntityCapabilities()`（`@aiao/rxdb-model`）的交集；
  撤销 / 重做与恢复同样先过门禁。所有领域写入口复核同一门禁，不能只靠按钮禁用
- **无障碍**：三端 e2e 各带 axe 用例（rxdb-model 先例：三端 a11y e2e）

### Out of Scope

- 单端 demo 应用（→ [US-540](US-540-board-end-to-end-demo.md)：`apps/dev-rxdb-board` 单端即可，
  先例 US-214）
- 团队同步 UI 与只读宿主（→ [US-541](US-541-board-team-sync.md)）
- 通用可复用组件库——本故事交付**看板的**三端视图，不是第四个通用实体 UI 库

## 验收标准

每条 AC 都在 Angular / React / Vue 执行同一组领域操作并比较最终持久化数据与用户可见状态。
归一化快照用于辅助对拍，不能替代创建、交互与重开验收。

## 技术笔记

**三框架对称按阶段关闭。** 对称的判据是用户能完成同一任务、领域 API 契约相同、持久化结果
相同；框架的属性绑定形式、DOM 与像素允许不同。检查沿用仓库已有机器：跨框架对拍
（`modules/e2e-parity/entity-model-parity.mjs` 的归一化快照口径，T049 已落地；看板另写一份归一化与 golden）与
`tri-framework-check`（`.claude/skills/tri-framework-check`，按 `<prefix>-{angular,react,vue}` 识别三端组）。

**落点换算只有一份，而且是新建的。** 树页面没有可复用的实现：US-031 的 `resolveTreeDrop` / `treeDropPosition`
是三个 demo 应用各一份的同名拷贝，靠同名用例保持一致。看板从第一天就把换算表放进核心包
（[US-535](US-535-cross-column-move-ordering.md)），三端绑定只采集指针事件后调用同一函数，不各自算落点。

**保留的端差异要有设计理由。** React `*Props` 接口、Vue `defineExpose` 守卫、Angular input
别名这类框架适配允许不同；在三端对拍清单中声明等价关系，公开能力、事件结果与错误语义一致。

**交互约定。** GitHub Projects 是卡片内联编辑、列头菜单与键盘操作的交互参照；MVP 使用 US-534 的列实体，
拖卡改变列归属与排序。布局与状态以以下约定验收，不用参考产品名称替代设计：

| 区域 / 状态 | 约定                                                                                                                                                                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 页头        | 板选择器（按创建时间升序）、板标题、「新建列」、标签管理、撤销 / 重做与备份入口；阶段 B 加板内搜索。窄屏入口可收进菜单，保持键盘可达                                                                                                                   |
| 列头        | 列标题、任务数、拖动手柄、含改名 / 前移 / 后移 / 按截止日排序 / 按标题排序 / 删除的菜单；列尾有「添加任务」；列横向滚动，保留明显的横向溢出提示                                                                                                        |
| 卡片        | 标题最多两行且详情展示全文；独立「编辑标题」按钮或聚焦卡片后 F2 进入内联编辑，Enter 保存、Esc 取消，失焦保留草稿及保存 / 取消入口；标签按创建时间顺序同时显示名字与颜色；截止日用文字说明逾期 / 今天，颜色只作辅助；拖动手柄与打开详情有独立可访问名称 |

| 空态        | 无板时提供「新建板」；无列时提供「新建列」；空列保留建任务入口及可放置区域；搜索无匹配单独显示，不能冒充板为空                                                                                                                                         |

| 写入        | 创建 / 保存 / 移动 / 删除期间显示进行中并阻止重复提交；失败保留草稿或恢复原位置并提供重试；持久化成功前不宣称已保存                                                                                                                                    |

| 恢复中      | 保留浏览、切板与详情阅读；创建 / 编辑 / 删除 / 移动 / 本列排序 / 历史写入 / 再次恢复禁用并说明「恢复中」；领域入口复核门禁，不依靠隐藏按钮作为权限保证                                                                                                 |

**日期与历史边界。** `due_date` 与本地当天都按 `YYYY-MM-DD` 纯日期比较，不把日期解析成 UTC
时刻；本地跨午夜及页面重新获得焦点时更新派生状态。模型没有完成字段，列名即使叫 Done 也不能
自动免除逾期提示。一次详情保存的多字段变更同属一个事务，一次 undo 整体反转；分三次保存才
产生 US-536 AC#7 的三次撤销。历史入口沿 US-302 反转本次会话内最近的变更事务，不按实体或操作类型跳过
板 / 列删除、标签定义管理等后来操作；只剩一个页面时刷新，此前的事务不再可撤销。看板保存横跨 task 与
`task_label`，三端都用数据库级 history（仓储级范围会抛 `RxDBCrossScopeTransactionError`）；看板使用独立的
RxDB 实例，它的历史不包含宿主其他页面的写入。

**恢复入口不等于覆盖当前库。** 首轮持久化闭环使用 sqlite-wasm 主线程 `vfs: 'idb'`。首次打开在 `connect()`
与装载演示数据前选择恢复；已连接时，确认后断开、恢复到新库名、整页重载，读回成功才保存新的活动位置。
失败保留源库与当前视图，不将清库当作恢复前置操作（US-537 / US-217）。新旧库名不同，旧页面随活动位置变更
重载，不会与新库共用网关。

**三端宿主。** 现有 `dev-rxdb-{angular,react,vue}` 各加一个看板页与 e2e 用例。看板页使用独立的 RxDB 实例：
sqlite-wasm 主线程 `vfs: 'idb'`、独立库名、看板实体在 `board` 命名空间，进入看板页才创建（满足启动选择前不连接），
绑定经自己的注入入口拿到这个实例，不复用宿主的 `provideRxDB`。宿主主实例用的是 OPFS 专用 Worker / IDB SharedWorker
（备份返回 `unsupported_combination`），注册了 rxdb-test 的 `Task`，Todo 页还有数据库级撤销；独立实例让看板的存储、
实体与撤销历史都不与之相交。整页重载式切换会重载整个宿主应用。

**共享种子先于 demo 应用。** 三端对拍的数据定义放在 US-540 指定的公共测试文件，随本故事阶段 A
准备；US-540 消费同一文件，不因文档中数据集归属引入「US-539 等待 US-540 应用」的循环依赖。

**落点：`packages/rxdb-plugin-board-{angular,react,vue}`** 三个绑定包，与 search / tree / replay 同构，只依赖
各自框架与核心包 `rxdb-plugin-board`；视图、指针事件采集、详情面板、标签管理、历史与备份入口都在绑定包内，
领域逻辑全部在核心包。

**关闭条件**：阶段 A、B 分别完成三端全部 AC；空库创建到重开闭环可用；真实拖拽后 DB 重查一致，
键盘有等价路径；详情 / 标签 / 历史 / 备份 / 搜索行为一致；恢复中门禁与状态反馈一致；axe 通过。
