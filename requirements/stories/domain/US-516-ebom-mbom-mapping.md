# 用户故事：EBOM ↔ MBOM 映射与差异对比

## 作为/我想要/以便

**作为** 工艺工程师
**我想要** EBOM 与 MBOM 各自是独立的图，由 `bom_map` 关联
**以便** 制造侧能自由新增、拆分、合并与重新分层，而设计变更仍能追到对应的制造行

## 范围边界

### In Scope

- **变换范围** `bom_map_scope`：一对根级头 `(ebom_root_header_id, mbom_root_header_id)`，两侧 `org_id` 相同、父件是同一物料（修订可以不同）；
  每条映射属于一个变换范围
- `bom_map`：`source_line_id` ↔ `target_line_id`（逻辑行，[US-507](US-507-bom-graph-skeleton.md)），多对多，带 `relation`
- `relation` 六态：`one_to_one` / `split` / `merge` / `added` / `removed` / `resequenced`
- **NULL 规则**：`added` 只能 source 为 NULL、`removed` 只能 target 为 NULL，其余四态两侧必填；不允许双 NULL
- **两侧约束**：source 行所在头 `bom_type = 'EBOM'`、target 行所在头 `bom_type = 'MBOM'`，与变换范围同一 `org_id`；
  source 行必须属于从 **EBOM 根头**出发的头链，target 侧对 MBOM 根头同理（见技术笔记「范围成员资格」）：
  根层的行 `bom_header_id` 必须**等于**根头，不能只是「父件是根物料」；更深的行要有一条从根头出发、逐跳可证明的头链。
  物料级并集图只做剪枝，不作成员资格的证明。**不要求**每对映射行的即时父件相同——那正是重新分层要改变的东西（见技术笔记「变换范围」）
- **映射身份是行定义，路径可选**：默认一条映射作用于该逻辑行出现的所有展开路径；共享子装配只在某一条路径上被重构时，
  映射带 `source_line_path`（自 EBOM 根起的逻辑行 ID 序列）只作用于那条路径。覆盖率按路径计：一条源路径被覆盖，
  当且仅当有作用于它的路径级映射或行级映射。不用行 ID 冒充路径身份。路径须首元素是范围根头的行、逐级相邻、
  末元素等于 `source_line_id`，否则保存拒绝；跟进基线与缺口查询随映射的作用范围走（行级覆盖所有路径，路径级只覆盖那一条）。
  target 侧本期只按行定义，不带路径。「相邻」与范围成员资格用同一个「头链一跳」判据（技术笔记）：前一行存在某个 `consume` 发生项，
  后一行所在头是该发生项可选到的子件头——不按生效期。已存发生项只会经两条路径消失：草稿头下的删除（[US-507](US-507-bom-graph-skeleton.md) 发布边界，
  草稿头下的行与子表可自由编辑）与 ECN 撤回 / 取消的级联（[US-515](US-515-bom-change-management.md)，已发布头下只有这一条）；
  消失后，失去相邻性的路径级映射与失去成员资格的行级映射在覆盖率与缺口查询里标「路径失效」，不静默算作覆盖
- **跟进基线**：身份与版本是两层。`source_line_id` 与逻辑行路径是稳定身份；基线记的是版本——建映射 / 上次确认时的**源侧解析依据**，
  加 `target_occurrence_id`（目标侧确认跟进到的发生项）。解析依据是映射作用范围内、**到源行为止**的源路径所经过的**解析步骤的集合**，
  一步 = `(逻辑行, 该行在上下文下的有效发生项, 解析所得的子件修订)`，取自 [US-508](US-508-bom-view-resolution.md) 的 manifest
  （头随行走：`bom_line.bom_header_id` 创建后不可改，不另存）。源行以下的结构不在内，由其下各行自己的映射负责
  - 只存末端行的发生项不够：祖先用量变了，扁平化后的目标行需求跟着变，末端行却没有新发生项（AC#16）；
    imprecise 行解析到的修订变了，行发生项同样不动（AC#17）；precise 锁版不受新修订发布影响（AC#18）
  - 路径级映射比较那一条路径的步骤，行级映射比较该逻辑行全部展开路径的步骤并集（AC#21）。按**步骤集合**比，不枚举路径：
    路径数随菱形结构指数增长（[US-510](US-510-bom-multilevel-explosion.md) 技术笔记）
  - 基线存成可逐项比对的步骤，不存摘要：缺口要能指出哪一步由什么变成了什么
  - 只比结构依据：`as_of_date` 不入基线，评估日变而解析依据没变不是缺口（AC#20）；物料级换算率、`qty_formula` 参数与费率不在发生项里，
    按 US-508 的边界不进基线，它们变化不产生缺口——要看数字差异，比对 [US-511](US-511-bom-quantity-semantics.md) /
    [US-514](US-514-bom-cost-rollup.md) 追加到 manifest 的值
- 跟进缺口查询：按 `ResolutionContext`（US-508）自范围根头出发（根头由范围钉住，不随上下文重选）求源侧当前解析依据，与基线逐步比较——
  任一步的发生项或解析修订不同、出现或消失即为缺口；按映射列出，附目标行（`removed` 无目标行），并分别给出基线与当前的差异步骤。
  求解遇到 US-508 的 `unresolved` 或 US-510 的 `truncated`，该映射标「无法判定」，点名那一跳与原因，不算无缺口（AC#22）
- 目标侧「确认跟进」把基线**整体**推进到当前解析依据与当前目标发生项，不只改末端发生项（AC#7 / #19）
- 源头出新修订、换头时：映射**不自动迁移、不继承**。新头的逻辑行都是新行（`line_no` 只在一张头内是身份，不是跨头业务身份），
  新根头即新变换范围，其全部行报未覆盖（AC#6），由人工重新映射；旧映射留在旧头上，旧范围的覆盖率不变（AC#14）

### Out of Scope

- 自动生成 MBOM（转换规则引擎）——本故事只记录人工或外部工具产生的映射
- 工艺路线生成

## 技术笔记

**本故事的关闭条件是「明确不用视图实现」。**

「不同 BOM 类型只是同一张图的不同视图」这个假设在 EBOM→MBOM 上不成立：视图只能做**行的子集**，
而制造侧要做的是**结构重构**——新增 EBOM 里不存在的节点（包装、工装、工序件 WIP）、
把一个零件拆成多个制造步骤、把多个零件合成一次工序、以及按装配顺序整体重新分层（AC#5）。
这四种变换没有一种是子集。

因此 EBOM 与 MBOM 是两张独立的 `bom_header` + `bom_line`，`bom_map` 是它们之间的第三张表。
这张表是 PLM↔ERP 集成的核心资产，不是可选的便利设施——AC#4 的跟进缺口查询完全依赖它。

两张头各自挂自己的 `parent_revision_id`（[US-507](US-507-bom-graph-skeleton.md)）：制造侧的分层
与设计侧的修订不同步推进，共用一个修订会让 MBOM 的每次工艺调整都伪装成一次设计变更。
`bom_map` 连的是**行**而非头，两侧修订各走各的不影响映射。

**变换范围。** 约束不能写成「每对映射行所在头的父件相同」：重新分层恰恰改变即时父件，EBOM `整机 A → 功能模块 B → 螺钉 C`
扁平成 MBOM `整机 A → 螺钉 C` 时，C 的源行父件是 B、目标行父件是 A，合法重构会被约束拒掉（AC#11）。业务作用域不是「同一个父件」，
而是「同一次 EBOM → MBOM 变换」——由根级头的配对定义，两侧的行只需落在各自根件的结构里（AC#12），组织约束保留。

**范围成员资格：从根头出发的头链，不是物料可达。** 范围用的是具体根头 ID，成员判据若退回物料级，头版本身份就被降级成物料身份：
同一物料 A 另一修订的头 A_E，其根行仅凭「父件是 A」就混进 A_D 的范围；只在 A_E 上存在的 A→B 边，也会因物料级可达把 B 的行带进来（AC#15）。
[US-510](US-510-bom-multilevel-explosion.md) 已经说明物料级可达性对任何上下文都只是上界。所以成员资格是：

- 根层：行的 `bom_header_id` = 范围根头；
- 一跳 H → H′：H 上有一条已存的 `consume` 发生项（含挂在 `draft` ECN 上的候选发生项——为待发布变更预建映射是合法用法），
  H′ 的 `bom_type` / `org_id` 与范围相同、父修订属于该发生项的子件物料，且修订可被该发生项选到：precise 只认锁定的修订，imprecise 认该物料的任一修订；
- 更深的行要有一条 根头 → … → 本行所在头 的头链。

并集图（与 [US-509](US-509-bom-dag-cycle-detection.md) 判环同一张、不按生效期）只用来剪枝：物料级不可达即可直接拒绝（AC#12），可达还须找到头链。
不同时点会选到不同修订的跨期预建映射由 imprecise 一跳覆盖，不需要另记基线上下文。

**共享子装配与路径。** 一个子装配经两条路径出现时，「行」与「路径」不是一回事：只重构其中一处，行级映射会把两处一起标成已覆盖。
所以映射默认是行定义级，确有路径差异时显式带路径（AC#13）；路径用逻辑行 ID 序列而不是发生项 ID 序列——发生项随每次 ECN 更替，
拿它做路径身份，映射会在下一次改量时悄悄失效。

**换头不继承（AC#14）。** 逻辑行的身份是 `(bom_header_id, line_no)`，新修订就是新头，同号行也是新行。
「同号即同一行」会把换了子件的行 10 也继承过来；要继承就得定义显式的跨头 lineage 或迁移操作，有驱动场景再加。

**为什么光有 `source_line_id` ↔ `target_line_id` 答不了「需跟进」，只存末端行的发生项也不够。** 源行 ID 不变、qty 由 2 改 3，
MBOM 随后也改了——映射前后都是同一对 ID，引用本身不知道目标「跟进到了哪次源变更」。所以缺口判据不是
「源变了」而是「源当前解析依据 ≠ 映射基线」，目标确认把基线推进（AC#7），源再变又不等（AC#8）。
这依赖 US-507 的两层行身份：逻辑行给映射一个稳定锚点，发生项给变更一个可比较的版本；不需要内容指纹，也不是自动转换引擎。

比较的是**解析依据**而不是末端行的发生项，因为末端行的版本不是需求的全部依赖。两个反例都不改末端行：

- **祖先用量变（AC#16）**。无损耗、无换算、各头基准量均为 1：EBOM `A→B` 每 A 用 2 个 B、`B→C` 每 B 用 5 个 C，MBOM 扁平为 `A→C` 每 A 用 10 个 C。
  祖先 ECN 把 `A→B` 改为 3 后，设计需求是 `3 × 5 = 15`，而 C 的源行、目标行与逻辑行路径都没换 ID，`B→C` 的发生项也没变——
  只比末端发生项，这条映射不会被列出。`A→B` 自己若有 `removed` 映射，它的缺口只说明 B 这条结构关系变了，
  替代不了对 C 的判定：B 在制造侧被删掉可以继续成立，C 的制造用量仍须复核。
- **imprecise 解析到新修订（AC#17）**。EBOM 的 C 行 `child_revision_id = NULL`，确认时解析到修订 D，MBOM 对应行 precise 锁 D；
  修订 E 发布并进入评估日的选择范围后，EBOM 解析到 E、MBOM 仍锁 D，行发生项与目标发生项却没有任何改写。
  基线不记确认时实际选中的 D，就比较不出这一变化。

稳定身份与版本基线是两层合同，前者不能代替后者：路径身份刻意用逻辑行 ID，是为了下一次 ECN 不让映射失效，
所以「路径身份没变」不等于「工程依据没变」，须另存解析依据来检测变化。这不是历史重放引擎——只比结构依据，
不重算数量，也不替工程师判断 MBOM 该是多少；人工「确认跟进」仍是裁决点。

**为什么按步骤集合比。** 每一步带着它解析出的子件修订，下一跳的头由该修订决定，所以步骤集合与「到源行的路径集合及各路径上的取值」
互相决定：集合相等当且仅当路径集合与每条路径上的取值都相等。行级映射因此不必枚举路径，成本随步骤数而不是路径数增长。
（**推断**：独立探针在随机 DAG 上逐例对照过两种判定一致；探针未入库，实现时落成属性测试。）

视图过滤仍然适用于**同一 `bom_type` 内**的修订、生效期、组织差异，那部分在
[US-508](US-508-bom-view-resolution.md)。两者的分界就是本故事与 US-508 的分界。
