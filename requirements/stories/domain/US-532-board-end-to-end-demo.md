# 用户故事：看板端到端 demo：一份数据集走完全域

## 作为/我想要/以便

**作为** 要判断这套看板模型「设计对不对」的评审者与第一批接入者
**我想要** 一份真实感的看板数据集在一个能一键起起来的应用里跑完——建板、建列、建任务、跨列
拖动、改详情、撤销、重开、备份导出与恢复、搜索，**同一份数据，不换样例**
**以便** 组合错误（拖动落点与排序键、删除级联与重开、备份与既有库重开）当场显形，
而不是到一个真实用户手里才发现

## 交付阶段

| 阶段  | 内容                                                                   | 关闭判据                                                  | 状态 |
| :---- | :--------------------------------------------------------------------- | :-------------------------------------------------------- | :--- |
| **A** | 首轮切片闭环：建板 → 建列 → 建任务 → 跨列拖动 → 重开 → 备份导出 → 恢复 | AC#1～8 全绿；一条 `serve` 起来就能操作整块板             | ⬜   |
| **B** | 搜索接入                                                               | AC#9～12 全绿；前置 [US-530](US-530-board-task-search.md) | ⬜   |

**各阶段可用的页面**：阶段 A 只有看板页（列 + 卡片 + 拖拽 + 详情对话框 + 备份入口）；搜索框到
阶段 B 才出现，A 阶段不放空搜索框。阶段 A 有独立价值：它是[首轮可开工切片](../../epics/epic-010-task-board-domain-model.md#首轮可开工切片)
的**验收手段**，不依赖 B 就能被用来判断那五条故事是否真的交付了。**全部阶段关闭后才置 `Done`**
（[CONVENTIONS 大故事分阶段](../../CONVENTIONS.md#大故事分阶段不拆子故事文件硬规则)）。

## 范围边界

### In Scope

- **`apps/dev-rxdb-board`**：Angular demo，看板页（列 + 卡片 + 拖拽 + 详情对话框 + 备份入口）+
  搜索页（阶段 B）；端口 `127.0.0.1:4311`（BOM 的 US-525 用 4310，看板避让）
- **一份确定性种子数据集**：一块「rxdb 1.0 发布计划」板（4 列 × 12 任务，含标签与截止日），落
  `packages/rxdb-plugin-board/src/testing/release-board-dataset.ts`，**demo 与 vitest 用例共用
  同一份**；`id` 与审计时间戳由种子固定给出，**零随机、零 `Date.now()`**（US-525 AC#1 的同一条
  理由：否则 e2e 只能断言「大概有几条」）
- **分层种子**：同一块板按阶段分层装载，每层只**追加**该阶段已存在的实体（A：板 / 列 / 任务 /
  标签；B：无新实体，只开搜索入口），不改写下层的行
- **拖拽后 DB 重查**：每条拖拽 AC 都在操作后刷新读回并断言列归属与顺序（US-028 AC#18 先例）
- **备份导出循环**：导出归档 → 清库（或新环境）→ 恢复 → 数据一致（US-529 语义的贯穿验收）
- **既有库重开**：一条先以非看板实体建库、重开后再装看板插件并跑种子的用例——插件的新表在
  既有库上正常创建，既有数据不受影响（US-525 既有库重开先例；[US-526](US-526-board-column-task-skeleton.md) AC#8）
- **`apps/dev-rxdb-board-e2e`**：playwright，12 条 AC 各至少一条用例；拖拽用真实拖拽

### Out of Scope

- **可复用的三框架绑定**（→ [US-531](US-531-board-tri-framework-ui.md)）：本故事交付的是**一个
  应用**，不是**一套绑定**。单端即可，先例是 [US-525](US-525-bom-end-to-end-demo.md) 与
  [US-214](../adapter/US-214-http-browser-demo.md)（`status: Done`，只有 Angular 前端）。
  三端对称是 US-531 的关闭条件，不是本故事的
- **团队同步演示**（US-533 价值待证）与**评论 / @ 提醒**——不进演示
- **性能基准**：种子数据集按「覆盖全部硬用例」设计，不按「压出规模」设计
- **新领域能力**：本故事**不新增任何抽象**，全部行为都归属到已有的 7 条故事

## 技术笔记

**组合缺陷只在贯穿应用上显形，这是 CONVENTIONS 领域硬约束的验收侧。** 看板的典型缺陷不是
单点：拖动落点算对了但排序键写错、删除级联删对了但重开后孤儿复活、备份导出了但既有库重开
后触发器没建。各故事的 AC 是单点断言，本故事用一份贯穿数据集把它们串起来（AC#3 / #5 / #6 /
#7 各自对应一类组合）。

**确定性的归属。** 种子板（「rxdb 1.0 发布计划」）的 12 条任务编号、标签、截止日全部字面值
固定；`id` 由业务键确定性派生、审计时间戳取固定基准——与 US-525 AC#1 同一条理由：e2e 只能
断言确定的状态。

**单端即可，先例两条。** US-525（BOM demo，Angular）与 US-214（HTTP demo，Angular）都是
单端交付、三端对称另由绑定故事关闭的先例。本故事照抄这个边界：`apps/dev-rxdb-board` 是
Angular 应用，三端对称是 US-531 的事。

**备份循环是演示的「一等公民」证据。** 零后端单机版的命门是清数据即丢库（domain-research
产品形态坑 ①）。AC#6 把导出 → 清库 → 恢复做成页面可点的循环，评审者不用读 US-529 的 AC
就能看见这条命门被关掉。

**关闭条件**：一份种子数据走完阶段 A～B 全部 AC；每条 AC 至少一条 playwright 用例；
拖拽用真实拖拽且拖后 DB 重查；两遍 seed 逐字节相同。
