# 用户故事：三框架看板视图与交互

## 作为/我想要/以便

**作为** 三端 demo 的维护者与看板模型的接入者
**我想要** Angular / React / Vue 三端各有一份功能相同的看板视图——板 / 列 / 卡片、拖拽、详情
对话框、搜索框、备份入口
**以便** 看板领域模型一次定义、三端一致消费，单端缺失不算完成

## 交付阶段

| 阶段  | 内容                                                                                         | 关闭判据                      | 前置                              | 状态 |
| :---- | :------------------------------------------------------------------------------------------- | :---------------------------- | :-------------------------------- | :--- |
| **A** | 基础看板：空库创建、板切换、列与任务排序、批量改序、详情、标签、撤销重做、删除确认、备份恢复 | AC#1～4、#6～14、#16 三端全绿 | US-526 / US-527 / US-528 / US-529 | ⬜   |
| **B** | 板内搜索与结果定位                                                                           | AC#5、#15 三端全绿            | US-530、阶段 A                    | ⬜   |

阶段 A 可独立交付，不依赖搜索；搜索框只在阶段 B 接入后出现。三端对称按阶段验收，
阶段 A 单端完成不能算阶段 A 完成；两个阶段全部关闭后才置 `Done`
（[CONVENTIONS 大故事分阶段](../../CONVENTIONS.md#大故事分阶段不拆子故事文件硬规则)）。

## 范围边界

### In Scope

- **基础闭环**：空库建板、建列、建任务；多板切换；板 / 列 / 任务删除确认与取消；重开后数据一致。
  删除前列出受影响的列数 / 任务数 / 标签定义数 / 任务标签关联数，按实际级联范围展示；删除任务
  同时显示标题，删列不删除板级标签定义
- **看板视图**：列横向排列、任务卡片纵向堆叠，列序支持拖动与键盘移动；卡片显示标题、标签名与
  颜色、可选截止日。三端同功能同领域 API，不要求 DOM 或像素完全相同
- **真实拖拽**：三端 Playwright 用真实拖拽验收（US-028 阶段 B 先例），拖动落点判定三端共用
  同一张判定表（[US-527](US-527-cross-column-move-ordering.md) 技术笔记）
- **批量改序**：列菜单打开完整列排序面板；勾选多个任务时显示选中数量与「重排选中项」入口，
  仅改变选中项在原槽位的排列。预览中支持键盘上移 / 下移，显式应用或取消，领域语义随 US-527
- **详情对话框**：复用三端 rxdb-model `EntityDetail`，任务字段接线随
  [US-528](US-528-task-detail-editing.md)；卡片标题提供内联编辑，同样调用其校验与保存服务
- **板级标签与编辑历史**：创建 / 改名 / 改色 / 删除板级标签，任务可选多个标签；撤销 / 重做入口
  沿 US-302 处理最近的变更事务，不过滤成「仅任务编辑」历史；未保存输入不建立独立历史
- **搜索框**：三端绑定消费 US-530 提供的同一 `SearchSourceLike` 领域源，复用其板内过滤、分页与
  请求失效语义；阶段 B 起接入，不让三端各自实现板内过滤
- **备份入口**：导出、启动恢复、当前库恢复到新目标及其状态反馈随
  [US-529](US-529-board-backup-restore.md)
- **写入门禁**：实体入口取应用可写上下文与 `deriveEntityCapabilities()` 的交集；恢复与历史写入
  同样先检查应用可写上下文。所有领域写入口复核同一门禁，不能只靠按钮禁用；US-027 的静态实体
  能力不代替上下文只读或身份授权
- **无障碍**：三端 e2e 各带 axe 用例（rxdb-model 先例：三端 a11y e2e）

### Out of Scope

- 单端 demo 应用（→ [US-532](US-532-board-end-to-end-demo.md)：`apps/dev-rxdb-board` 单端即可，
  先例 US-525 / US-214）
- 团队同步 UI（→ [US-533](US-533-board-team-sync.md)）
- 通用可复用组件库——本故事交付**看板的**三端视图，不是第四个通用实体 UI 库

## 验收标准

每条 AC 都在 Angular / React / Vue 执行同一组领域操作并比较最终持久化数据与用户可见状态。
归一化快照用于辅助对拍，不能替代创建、交互与重开验收。

## 技术笔记

**三框架对称按阶段关闭。** 对称的判据是用户能完成同一任务、领域 API 契约相同、持久化结果
相同；框架的属性绑定形式、DOM 与像素允许不同。检查沿用仓库已有机器：跨框架对拍
（`modules/e2e-parity/entity-model-parity.mjs` 的归一化快照口径，T049 已落地）与
`tri-framework-check`（`.claude/skills/tri-framework-check`，T050 用它修复过 7 处不对称）。

**落点判定表三端同一张，是 US-031 教训的直接复用。** 三端 demo 曾在「懒加载拖进未展开节点
算出 a0 撞键」这类落点语义上分叉（US-031 症状），最终以「三端同一张落点判定表与三等分落点
区间」收口。看板从第一天就用同一张表（[US-527](US-527-cross-column-move-ordering.md) 已把落点
换算定为领域服务），三端 UI 不各自算落点。

**保留的端差异要有设计理由。** React `*Props` 接口、Vue `defineExpose` 守卫、Angular input
别名这类框架适配允许不同；在三端对拍清单中声明等价关系，公开能力、事件结果与错误语义一致。

**交互约定。** GitHub Projects 仅作视觉参照，MVP 使用 US-526 的列实体，拖卡改变列归属与排序。
布局与状态以以下约定验收，不用参考产品名称替代设计：

| 区域 / 状态 | 约定                                                                                                                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 页头        | 板选择器、板标题、「新建列」、标签管理、撤销 / 重做与备份入口；阶段 B 加板内搜索。窄屏入口可收进菜单，保持键盘可达                                                                                                                       |
| 列头        | 列标题、任务数、拖动手柄、含改名 / 前移 / 后移 / 批量改序 / 删除的菜单；列尾有「添加任务」；列横向滚动，保留明显的横向溢出提示                                                                                                           |
| 卡片        | 标题最多两行且详情展示全文；独立「编辑标题」按钮或聚焦卡片后 F2 进入内联编辑，Enter 保存、Esc 取消，失焦保留草稿及保存 / 取消入口；标签同时显示名字与颜色；截止日用文字说明逾期 / 今天，颜色只作辅助；拖动手柄与打开详情有独立可访问名称 |
| 批量改序    | 列菜单可重排完整列，卡片复选后可重排选中项；面板明确显示作用范围、当前排列与预览，键盘上下移动后显式应用 / 取消；同序不提交写入；过期或失败重查后重建预览，不自动重试                                                                    |
| 详情        | 展示标题、描述、标签与截止日的同一份草稿，显式保存 / 取消；未保存关闭或切板先确认放弃；保存成功才更新已保存状态，不把每次按键当一次业务编辑                                                                                              |
| 空态        | 无板时提供「新建板」；无列时提供「新建列」；空列保留建任务入口及可放置区域；搜索无匹配单独显示，不能冒充板为空                                                                                                                           |
| 读取        | 首次加载显示加载态，失败显示原因与重试；已有数据显示中的刷新失败保留现有内容并提示；读取失败不呈现可写的空板                                                                                                                             |
| 写入        | 创建 / 保存 / 移动 / 删除期间显示进行中并阻止重复提交；失败保留草稿或恢复原位置并提供重试；持久化成功前不宣称已保存                                                                                                                      |
| 备份 / 恢复 | 显示操作进度、成功、失败原因及不支持的连接形态；恢复期间暂停写入与重复恢复，多页不能取得独占协调时先拒绝；成功切换目标后其他页面重读活动位置（US-529）                                                                                   |
| 删除        | 任务显示标题；确认清单包含实际影响的列数 / 任务数 / 标签定义数 / 任务标签关联数，删列不删除板标签；取消不写库；若确认期间范围变化，更新清单并要求重新确认；取消后焦点回触发入口                                                          |
| 只读        | 保留浏览、切板与详情阅读；创建 / 编辑 / 删除 / 移动 / 批量改序 / 历史写入 / 恢复禁用并解释原因；领域入口检查应用可写上下文与实体能力交集，不依靠隐藏按钮作为权限保证                                                                     |

**日期与历史边界。** `due_date` 与本地当天都按 `YYYY-MM-DD` 纯日期比较，不把日期解析成 UTC
时刻；本地跨午夜及页面重新获得焦点时更新派生状态。模型没有完成字段，列名即使叫 Done 也不能
自动免除逾期提示。一次详情保存的多字段变更同属一个事务，一次 undo 整体反转；分三次保存才
产生 US-528 AC#7 的三次撤销。历史入口沿 US-302 反转最近的变更事务，不按实体或操作类型跳过
板 / 列删除、标签定义管理等后来操作；各领域操作保留其同一事务与历史，不另造过滤后的撤销栈。

**恢复入口不等于覆盖当前库。** 首轮持久化闭环使用 PGlite 主线程 `idb://` 连接。首次打开时可在
`connect()` / seed 前选择恢复；已连接时，恢复到新的未初始化空目标，校验、连接和读回成功后再
保存新的活动位置并切换。失败保留源库与当前视图，不将清库当作恢复前置操作
（US-529 / US-217）。

源库与目标保持相同 `dbName`、不同物理存储位置；连接新目标前先协调所有页面释放旧活动连接与
作用域，不让同名库的新旧目标同时活动。新目标连接或读回失败时重新连接旧库，保留原活动位置；
源库的独立重开验证在断开目标后执行（US-529）。

**共享种子先于 demo 应用。** 三端对拍的数据定义放在 US-532 指定的公共测试文件，随本故事阶段 A
准备；US-532 消费同一文件，不因文档中数据集归属引入「US-531 等待 US-532 应用」的循环依赖。

**落点：`packages/rxdb-plugin-board`** 的三框架绑定（BOM 先例：US-522 的绑定在
`packages/rxdb-plugin-bom`），三端 demo 各自消费。

**关闭条件**：阶段 A、B 分别完成三端全部 AC；空库创建到重开闭环可用；真实拖拽后 DB 重查一致，
键盘有等价路径；详情 / 标签 / 历史 / 备份 / 搜索行为一致；权限与状态反馈一致；axe 通过。
