# 用户故事：看板任务搜索：FTS 接线

## 作为/我想要/以便

**作为** 单人看板用户
**我想要** 在当前板内搜任务标题与描述，从结果直接定位卡片
**以便** 找到任务，同时保持当前板的工作上下文

## 范围边界

### In Scope

- **板内搜索**：复用 [US-702](../future/US-702-full-text-search.md) / [US-703](../future/US-703-pglite-full-text-search.md)
  的全文检索；应用层以 `task.columnId → column.boardId` 确定当前板，不给 task 增加第二份板归属
- **板级搜索源**：提供符合 `SearchSourceLike` 的领域搜索源，三端搜索绑定消费同一实现；
  `SearchOptions.collections` 只选 task 实体，不承担行级隔离
- **过滤与分页**：收齐 task 实体的本次关键词命中后，按当前板过滤，再分页；上游仍有页时不能
  显示「无匹配」或把上游的 `hasMore` 当成当前板的 `hasMore`
- **结果与定位**：每条结果显示标题、所在列与纯文本匹配片段；点结果滚动到卡片并短暂突出显示，
  不修改列序或卡片顺序；结果已删除时提示「任务已删除」并重查
- **数据更新**：任务创建、编辑、移动、删除及列删除触发当前查询重算；切板立即清空旧板结果，
  搜索词可保留，旧查询不能覆盖新板状态
- **能力边界**：搜索插件缺失或 adapter 不支持时禁用入口并说明原因；已配置插件但初始化失败时
  显示失败并允许重试，不伪装为无匹配，不另做无索引扫描

### Out of Scope

- 跨板全局搜索、标签 / 截止日筛选、附件与语义搜索
- 新分词器、卡片正文关键词着色、全文引擎的行级 scope API
- 后端分词、相关性排序与召回结果的完全一致；三框架对拍使用相同 adapter、同一数据集

## 技术笔记

**现有 scope 只到实体，不到行。** [`SearchOptions.collections`](../../../packages/rxdb-plugin-search/src/types.ts)
是实体名 / 表名 allowlist；[`RxDBPluginSearch.search()`](../../../packages/rxdb-plugin-search/src/plugin.ts)
在选定表上检索并分页。直接传 task 字段配置无法完成板内搜索，也不能先过滤第一页就判空。

**首版采用应用层收集、过滤、分页。** 领域搜索源对外沿用
[`SearchSourceLike` / `SearchHandle`](../../../packages/rxdb-plugin-search/src/types.ts)，状态机可复用公开的
[`createSearchHandle()`](../../../packages/rxdb-plugin-search/src/core/search-handle.ts)。一次查询按以下步骤执行：

1. 捕获当前 `boardId`、查询词与本次请求代次；以 task collection 创建上游搜索句柄，等待首个完成或失败状态；空输入或无可索引词元沿用上游 idle，结束收集并回到未搜索状态。
2. 上游 `hasMore$` 为真时逐次等待 `loadMore()`；读取累计结果，直到上游无后续页。读取期间保持板级加载态，
   任一步失败都进入错误态，不把部分结果当作完整结果。
3. 通过仓储批量读取命中任务及其列，按 `column.boardId` 过滤；删除的任务 / 列不进入结果。补出标题与列名，
   保留引擎返回的相对顺序，按任务 id 去重。不能依赖 `SearchResult` 自带板 / 列字段，它没有这些字段。
4. 对完整的板内结果分页，板级 `hasMore` 由剩余板内结果计算；只有本批次仍有效时才发布结果。
5. 任务 / 列的数据变更立即使收集批次与缓存失效，销毁上游句柄后重查；切板、换词、清空、恢复切库与关闭页面
   同样使旧批次失效并释放资源。数据变更后等待稳定再发布，不能拼接不同版本的分页。

数据事件沿用 [`RxDBPluginSearch.#bindEntityEvents()`](../../../packages/rxdb-plugin-search/src/plugin.ts)
使用的实体创建 / 更新 / 删除通知；领域层额外关注 column，避免只监听 searchable task 而漏掉列名和删除变化。
重新查询时可保留同板上次结果并标记「更新中」，此时禁止点击旧结果；切板必须直接清空。

该方案的收集成本随全部板的关键词命中数增长，不宣称索引内行级过滤或规模性能。第 0 步使用多板样本核对
可接受性；若真实使用需要大规模行级搜索，单独提取搜索底座增量评审，不能在领域分支偷加内部接口或截断结果。

**中文搜索沿用实际后端契约。** SQLite 搜索实现已有 CJK 单字 / 双字索引；PGlite 使用原生 tsvector
与其既有词元、前缀规则，见 [`compilePgQuery()`](../../../packages/rxdb-plugin-search/src/backend/pg/pg-query-compiler.ts)。
不承诺任意中文子串必命中，也不改变既有搜索引擎的召回预算；AC 的「回归」「修复」使用词元前缀样本。

**关闭条件**：板内隔离、完整分页、结果定位、变更重查与请求失效全部可复验；不支持与查询失败能被用户区分。
US-530 依赖 US-526 / US-528 的实体与字段，搜索 UI 由 US-531 阶段 B 消费；本故事不反向依赖 UI。
