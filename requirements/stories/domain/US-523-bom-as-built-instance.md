# 用户故事：as-built / as-maintained 实例 BOM

## 作为/我想要/以便

**作为** 售后与追溯工程师
**我想要** 已交付个体的实际装机结构独立于主数据 BOM 存在
**以便** 回答「这台设备装的是哪个批次的哪个件」，且主数据变更不改写历史

## 范围边界

### In Scope

- `bom_instance_node`：实例节点，**自带事实**——实际 `item_revision_id`、序列号 / 批次、安装 / 拆卸区间
  `[installed_at, removed_at)`、自己的父实例 `parent_instance_id`
- 序列化物料的实例节点**必须带序列号**：`item.serialized`（[US-507](US-507-bom-graph-skeleton.md) 阶段 A 预留给本故事的标记）取自实例节点 `item_revision_id` 所属的物料；
  非序列化物料不要求
- 实例节点引用其来源**行发生项**（US-507），只回答「本该装什么」；
  展示「实际装了什么」**只读实例自己的字段**，不经来源发生项解析
- 来源发生项被引用后**限制删除**，不论删除来自哪条路径：草稿头下的直接删除、ECN 撤回（`draft`）与取消（`released` 未生效）的级联删除一律拒绝——
  ECN 引入的发生项只要被实例引用，该 ECN 即不可撤回、不可取消（在 [US-515](US-515-bom-change-management.md) 的取消校验上追加，与其 AC#12 / #26 同族）。
  已发布发生项的直接改写本就被 US-507 AC#10 拒绝；主数据侧退役一个发生项只能经 ECN 截止它的生效期，不能抹掉实例的来源
- 实例图的不变量：单父、无环、同一实例节点在同一父下的安装区间不重叠、同一序列号的件同一时刻只装在一处
- 实例树的展开与反查（这个件装在哪台设备上），不进主数据的可达性表
- 主数据 BOM 变更**不影响**既有实例

### Out of Scope

- 维修工单与换件事务（属事务域）
- 实例与主数据的自动差异告警
- 质量追溯的召回范围计算

## 技术笔记

**本故事的关闭条件是「实例图与主数据图分离」。**

实例 BOM 与主数据 BOM 的基数差异是几个数量级：一张主数据 BOM 对应成千上万台实例，
每台实例一棵完整的树。塞进同一套 `bom_header` / `bom_line` 会让主数据查询被实例数据淹没，
而 AC#5 正是为此设的规模验收。

另一个不能合并的理由是**生命周期相反**：主数据 BOM 会改版、会失效、会被 ECN 重写；
实例 BOM 一旦记录就是历史事实，永不随主数据变化（AC#2）。同一张表上放两种可变性不同的数据，
迟早要靠「这行是不是实例」的分支判断来保护历史，而那种分支会被漏掉。

实例节点引用来源行发生项（回答「本该装什么」），但实例的父子关系是自己的边，
不进 [US-510](US-510-bom-multilevel-explosion.md) 的 `bom_reach`。

**实际修订必须存在实例上（AC#6）。** 来源发生项可以是 imprecise（只锁物料，修订随生效期浮动），
实际装的是 D 版，之后来源跟随到 E 版；若展示实际件仍经来源发生项解析，实例的父子关系没变，实际修订却被改写了。
所以实例节点记录装机当时的事实（修订、序列 / 批次、区间、父），来源引用只是追溯线索；来源不可删（AC#7），
主数据侧要退役一个发生项只能截止它的生效期，历史引用仍然可达。

**来源不可删覆盖 ECN 的撤回与取消（AC#7）。** [US-515](US-515-bom-change-management.md) 的撤回 / 取消级联会删掉该 ECN 引入的发生项；
被实例引用的来源因此让所属 ECN 不可撤回、不可取消，整次回滚——与 US-515 AC#12（引入的发生项被后续 ECN 截止过）、AC#26（被其他 ECN 引用）同族，
本故事把「被实例引用」追加进同一道校验。已生效的 ECN 本就不可取消（US-515 AC#7），所以受限的只是未生效的 `released` ECN 与 `draft` ECN。
来源引用只是追溯线索，本故事不要求来源在装机日有效（与主数据的自动差异告警在 Out of Scope），
试制或提前装机的实例就可能引用到尚未生效、甚至仍为 `draft` 的 ECN 引入的发生项——按本故事现有约束**推断**，这条路径可达，不能靠「来源一定已生效」绕开。
已发布头下对来源发生项的直接删除早在 US-507 AC#10 / US-515 矩阵处被拒，实例引用不是那里的判别因素；
所以 AC#7 取的是协议本身放行、只剩引用校验能拒绝的三条路径：草稿头下的直接删除、`draft` ECN 的撤回、未生效 `released` ECN 的取消。

**实例图的不变量（AC#8～#13）。** 主数据 BOM 是多重 DAG，一个子装配可以被多处共享；实例树是**物理事实**，
一个件同一时刻只在一处、只有一个父，也不可能装进自己的后代。换件是「旧安装区间截止 + 新安装区间开始」，
所以单父与不重叠都按半开区间判定（同一父下的重装同理，AC#13）。这些都是写入期约束，不是展示期过滤。
序列号是否必填由物料的 `serialized` 标记（US-507 阶段 A）定：序列化物料的件靠序列号区分个体，「同一序列号只装在一处」才有可比较的对象，
所以它的实例节点必须带序列号（AC#12）；非序列化的批量件只带批次，其实际数量与单位见下一段。

**这些写入期约束的落点。** 单父、同一父下安装区间不重叠与「同一序列件同一时刻只装一处」都是
「相等列 + 区间维」的排他形状（相等列 = 实例节点或序列号，区间维 = `[installed_at, removed_at)`），
走 [US-030](../core/US-030-declarative-storage-constraints.md) 阶段 C 的区间排他，与 US-508 AC#2 同机制；
实例图无环（AC#9）要读整张实例边表，走插件自有触发器（[US-509](US-509-bom-dag-cycle-detection.md) 的先例，自父 = 路径长度 0 的退化环）；
错误点名相交区间与引用实例数（AC#7 / #13）的动态消息依赖 SQLite ≥ 3.47（US-030 AC#7 的宿主版本门槛）。

**待驱动场景裁决，当前字段不覆盖。** 实例节点只有修订、序列 / 批次与装拆区间。两类追溯问题它答不了，不默认已覆盖：
非序列化批量件的实际数量与单位（「这台设备装了 3.2 m 这一批次的线缆」），以及同一实物多次拆装之间的稳定身份
（拆下维修后装到另一台设备上的还是「同一个件」吗）。二者都要真实售后 / 追溯场景给出形态再加字段与 AC。

AC#4 的「装机区间可查」意味着实例节点需要 `installed_at` / `removed_at`，
这是有效性的第四种形态——与 [US-508](US-508-bom-view-resolution.md) 的日期生效期形似但语义不同：
前者是既成事实的记录，后者是计划的适用范围。不共用实现。
