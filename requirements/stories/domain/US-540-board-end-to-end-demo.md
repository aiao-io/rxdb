# 用户故事：看板端到端 demo：一份数据集走完全域

## 作为/我想要/以便

**作为** 要判断这套看板模型「设计对不对」的评审者与第一批接入者
**我想要** 一份真实感的看板数据集在一个能一键起起来的应用里跑完——建板、建列、建任务、跨列
拖动、改详情、撤销、重开、备份导出与恢复、搜索，**同一份数据，不换样例**
**以便** 组合错误（拖动落点与排序键、删除级联与重开、备份与既有库重开）当场显形，
而不是到一个真实用户手里才发现

## 交付阶段

| 阶段  | 内容                                                                   | 关闭判据                                      | 前置                                             | 状态 |
| :---- | :--------------------------------------------------------------------- | :-------------------------------------------- | :----------------------------------------------- | :--- |
| **A** | 首轮切片闭环：建板 → 建列 → 建任务 → 跨列拖动 → 重开 → 备份导出 → 恢复 | AC#1～8 全绿；一条 `serve` 起来就能操作整块板 | US-534 / US-535 / US-536 / US-537、US-539 阶段 A | ⚠️   |
| **B** | 板内搜索、隔离与升级重开验收                                           | AC#9～13 全绿                                 | US-538、US-539 阶段 B、阶段 A                    | ⚠️   |

**各阶段可用的页面**：阶段 A 只有看板页（列 + 卡片 + 拖拽 + 详情面板 + 备份入口）；搜索框到
阶段 B 才出现，A 阶段不放空搜索框。阶段 A 有独立价值：它是[首轮可开工切片](../../epics/epic-011-task-board-domain-model.md#首轮可开工切片)
的**验收手段**，不依赖 B 就能被用来判断那五条故事是否真的交付了。**全部阶段关闭后才置 `Done`**
（[CONVENTIONS 大故事分阶段](../../CONVENTIONS.md#大故事分阶段不拆子故事文件硬规则)）。

## 范围边界

### In Scope

- **`apps/dev-rxdb-board`**：Angular demo，看板页（列 + 卡片 + 拖拽 + 详情面板 + 备份入口），
  阶段 B 在同页接入板内搜索与结果区；端口 `127.0.0.1:4312`（4310 / 4311 留给 BOM demo）。
  首轮闭环用 sqlite-wasm 主线程 `vfs: 'idb'` 持久化连接，刷新后重连同一库，不用内存库冒充重开恢复
- **一份确定性种子数据集**：主板「rxdb 1.0 发布计划」4 列**共 12 条任务**，分布为 5 / 4 / 3 / 0，
  含标签与截止日；同一数据集另含隔离板及文本同词任务，供切板、删除隔离与搜索分页验证。落
  `packages/rxdb-plugin-board/src/testing/release-board-dataset.ts`，**demo 与 vitest 用例共用
  同一份**；`id` 与审计时间戳由种子固定给出，**零随机、零 `Date.now()`**（否则 e2e 只能断言「大概有几条」）。
  种子只装进新库（启动页「装载演示数据」或工具菜单「重置为演示数据」，见 [US-537](US-537-board-backup-restore.md)）
- **种子使用约定**：A、B 及三端对拍共用这一数据集，隔离板在 A 已装载，B 只开搜索入口，不更换
  任务内容。各用例从全新浏览器上下文装载种子后执行自己的操作；空库创建与既有库重开用例明确从其指定初态
  开始。板级页大小与结果排序固定；隔离板含高排位同词命中且数量超过一页，主板命中过滤后超过一页，
  用于验证板内分页不被异板挤空
- **公共测试文件的交付顺序**：数据定义随 US-539 阶段 A 供三端对拍准备，本 demo 复用它；本故事
  负责贯穿验收与应用接线，不要求三端绑定反向依赖 demo 应用
- **拖拽后 DB 重查**：每条拖拽 AC 都在操作后刷新读回并断言列归属与顺序（US-028 AC#18 先例）
- **备份导出循环**：导出归档 → 工具菜单恢复到新库名 → 整页重载读回后切换 → 重开数据一致；
  同时验启动页恢复入口。恢复不依赖用户先清掉当前数据，失败保留源库（US-537）
- **既有库重开**：一条先以非看板实体建库、重开后再装看板插件并装载种子的用例——插件的新表在
  既有库上正常创建，既有数据不受影响（[US-534](US-534-board-column-task-skeleton.md) AC#8）
- **阶段 A → B 升级重开**：阶段 A 版本建的库在阶段 B 版本里重开，数据完整、旧任务可被搜到
  （schema 自阶段 A 定稿，见 epic 首轮切片）
- **`apps/dev-rxdb-board-e2e`**：playwright，AC#2～13 各至少一条用例；拖拽用真实拖拽

## 技术笔记

**组合缺陷只在贯穿应用上显形，这是 CONVENTIONS 领域硬约束的验收侧。** 看板的典型缺陷不是
单点：拖动落点算对了但排序键写错、删除级联删对了但重开后孤儿复活、备份导出了但既有库重开
后触发器没建。各故事的 AC 是单点断言，本故事用一份贯穿数据集把它们串起来
（AC#3 / #5 / #6 / #7 / #13 各自对应一类组合）。

**确定性的归属。** 主板 12 条任务与隔离板任务的编号、标签、截止日全部固定；`id` 由业务键
确定性派生、审计时间戳取固定基准，零随机、零 `Date.now()`。确定性在 vitest 层验收：demo 的库在浏览器
IndexedDB 里，Node 侧的 Nx target 写不进去，所以不设 `reset` / `seed` target；页面上的「装载演示数据」
调用同一个种子函数，e2e 用全新浏览器上下文得到干净初态。逐字节对比只针对五张业务表；系统历史验证同一保存的
事务关联与无部分提交，不要求随机事务标识相同。日期展示测试固定本地当天日期，按 US-539 的纯日期规则断言，
不让种子到期状态随执行日期漂移。

**单端即可。** US-214（HTTP demo，Angular，已 Done）是单端交付、三端对称另由绑定故事关闭的先例，
BOM 的 US-525 同样按单端规划。本故事照此划界：`apps/dev-rxdb-board` 是 Angular 应用，三端对称是 US-539 的事。

**恢复必须有独立启动路径。** 初次进入可在 `connect()` 与装载演示数据前选择新建、装载演示数据或恢复；
已连接库的恢复先断开，再恢复到新库名并整页重载，读回成功才保存新的活动位置，失败回到旧库，不覆盖源数据。
AC#6 验两条成功路径，AC#8 验失败后保留源库并继续写入；清站点数据只用于模拟丢库后的启动恢复；
内存库不能代替持久化验收。

**关闭条件**：一份种子数据走完阶段 A～B 全部 AC；AC#1 由 vitest 关闭，其余每条 AC 至少一条 playwright 用例；
拖拽用真实拖拽且拖后 DB 重查；两次装载的五张业务表逐字节相同，系统历史事务一致；阶段 A 建的库在阶段 B 正常打开。
