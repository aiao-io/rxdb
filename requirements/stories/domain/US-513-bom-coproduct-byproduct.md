# 用户故事：联产品与副产品：多输出物料流

## 作为/我想要/以便

**作为** 流程行业工艺员
**我想要** 一次反应产出主产品与副产品，且副产品可作为另一工艺的投入
**以便** 回流料与联产不被 DAG 约束误判成环

## 交付阶段

| 阶段 | 内容                                                                                                    | 状态 |
| ---- | ------------------------------------------------------------------------------------------------------- | ---- |
| A    | `flow_direction` 三值 `consume` / `by_product` / `scrap_out`；主产物 = 头父件；副产量的基准、单位与缩放 | ✅   |
| B    | 联产品（第二及后续主产物，`produce`）、固定份额联合成本、显式下游来源、ECN与v2依赖导入导出              | ✅   |

原数字AC归阶段A，C01～C14归阶段B。阶段B于2026-10-18随用户“完成所有任务”的范围授权启动，固定份额合同已由主会话复核；核心、集成、种子与24条demo均已有通过证据，阶段B功能验收完成，最终完整分支门禁已通过，本故事已Done。

## 范围边界

### In Scope

- 行发生项的 `flow_direction`：`consume` / `by_product` / `scrap_out` / `produce`
- **主产物就是头的父件**：头的 `base_qty` / `base_uom` 就是一个基准批次的主产量，不另写产出行；
  [US-514](US-514-bom-cost-rollup.md) 卷算的头成本即第一主产物成本，联合生产时为分配后成本
- **联产品的合同**：`produce` 精确引用已发布、非phantom的输出修订，数量为每个头基准批量的合格产出，按 `q × L / base_qty` 缩放；头与produce行显式声明固定成本份额，每个运行日期切片精确合计1
- 下游以输出修订ID显式选择生产头取得联产品单位成本；来源校验、过程成本与来源manifest共享读取快照，不自动选唯一候选、不回退物料单价、不回写物料价格
- **副产量的合同**：`by_product` 行的 `qty` 是**每个头基准批量**的产出量，单位为行 UoM；随装配损耗后的 `P'` 线性缩放
  （`q × P' / base_qty`），`is_fixed_qty` 时按批不缩放；不过组件损耗与工序损耗。`by_product` 的子件不得是头父件本身
- 只有 `consume` 边进入可达性表与环检测
- 展开与卷算时 `by_product` / `scrap_out` 作为反向物料流处理
- 四个方向**各自**的下游消费方明确，没有一个是只声明不消费的枚举值
- **允许的回流范围**：回流只能经 `by_product` 边表达；任何 `consume` 边仍受 US-509 并集无环约束，
  「回流」不是绕开环检测的通道

### Out of Scope

- 副产品定价与成本分配方法学（→ US-514 只消费 `credit_price`）
- 按市场价/净实现价值自动分配联合成本；当前只支持显式固定份额
- produce的公式、固定量、阶梯、损耗、工序分摊、phantom、位号、替代成员与配置/序列/批次条件；首个合同只支持正比例产出与日期/ECN
- 以联产品修订直接替代生产头作为成本卷算根；调用方读取生产头的输出明细
- 工艺配方的批次放大规则（副产量只按上面的线性 / 按批两种规则缩放）
- 回流料的净需求抵扣（产出的 S 抵掉投入的 S）——属 MRP / 库存域，展开只给毛需求与产出量

## 技术笔记

纯 DAG 表达不了流程行业的真实物料流：钢厂废钢回炉、化工 recycle stream、联产品互为投入。
解法不是放弃 DAG，而是**把 DAG 约束的作用域缩到 `consume` 子图**——
结构层级与拓扑排序仍在 DAG 上进行（US-514 的卷算依赖这一点），反向流走另一类边。

这条与 [US-509](US-509-bom-dag-cycle-detection.md) AC#4 互为对偶：US-509 负责「非 consume 边不参与检测」，
本故事负责「这些边有明确语义并被展开与卷算正确消费」。

**AC#1 的前置取一对反向边，因为它能区分两种实现。** `by_product` 若被误计入判环（边方向与 `consume` 相同，`parent_item_id → child_item_id`），
X→Y 加 Y→X 恰成环；不计入则只有 X→Y，无环。前置的边集必须在计入时成环，「`by_product` 不入检测」这条合同才钉得住。

**每个方向必须各自有消费方**，否则枚举里会留下只能写进去、没人读出来的值：

| `flow_direction` | 进环检测与闭包 | 数量语义                                            | 成本语义                                      |
| ---------------- | -------------- | --------------------------------------------------- | --------------------------------------------- |
| `consume`        | 是（US-509）   | [US-511](US-511-bom-quantity-semantics.md) 七步公式 | 材料项（[US-514](US-514-bom-cost-rollup.md)） |
| `by_product`     | 否             | 副产量，本故事 AC#2 / #10                           | 按 `credit_price` 抵减（US-514 AC#5 / #17）   |
| `scrap_out`      | 否             | 废料量，本故事 AC#6                                 | 不计不抵（本故事 AC#7）                       |
| `produce`        | 否             | 合格主产量L的比例产出，`q × L / base_qty`           | 固定份额联合分配；下游显式来源，见C01～C14    |

第一主产物不在表里：它就是头父件，主产量就是L，联合生产时成本是其分配所得。US-511的七步公式只作用于consume，其余方向使用各自明确的产出与成本规则。
AC#2 / #7 钉的是上表两格的归属（`by_product` 抵减、`scrap_out` 不计不抵），数值 oracle 由 US-514 AC#5 / #17 承接——两条随 US-514 同批关闭，避免同一断言在两处各自演化。

**为什么阶段 A 不支持联产品。** 只有方向、没有合同的 `produce` 回答不了这些问题：一批投入 110 kg、产主品 100 kg 与副品 10 kg 时，L 是一个工艺批、100 kg 主品，
还是父件基准量？L 翻倍或带装配损耗时副品怎么变？同一头两条 `produce` 时成本归谁？头父件是工艺 P、产物是 M 时，下游 consume M 从哪取成本？
`credit_price` 只回答副品单位抵减价，回答不了这些。所以阶段 A 收窄到能闭合的最小模型：主产物固定为头父件、基准批量就是头的 `base_qty`，
副产量相对这个基准给系数与单位、按 `P'` 缩放（AC#10）；「无主产物」不可能（头总有父件），「多主产物」与「产物不是头父件」都在保存时拒绝（AC#11）。
阶段B已用固定份额、L比例产出和显式修订来源补齐这些合同，详见C01～C14；阶段A曾拒绝produce的限制由阶段B合同取代，不能继续作为当前四值枚举的验收预期。

AC#8 / AC#9 划的是回流的边界：自回流（同一头既副产又投入 S）只需要 `by_product` 边，不碰 `consume` 子图；
而「S 的 BOM 消耗 P、P 又消耗 S」是投入关系本身成环，卷算的拓扑序无从建立，不能因为旁边有一条 `by_product` 边就放行。

AC#5 的理由：允许 `consume` 边带负用量等于给同一件事留了两种表达，
两种表达的系统最终会两种都出现在数据里。
