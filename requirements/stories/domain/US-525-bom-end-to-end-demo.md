# 用户故事：BOM 端到端 demo：一份数据集走完全域

## 作为/我想要/以便

**作为** 要判断这套 BOM 模型「设计对不对」的评审者与第一批接入者
**我想要** 一台电动滑板车的完整数据集在一个能一键起起来的应用里跑完——多重边、虚拟件、替代组、
副产与废料、工序分摊、ECN 生效期、EBOM↔MBOM 重构、成本卷算，**同一份数据，不换样例**
**以便** 每个展开量旁边并排显示它的七步手算式，算错的时候当场看见差在第几步，
而不是拿到一个看起来正常、要到 MRP 下单才发现不对的数字

第 5 步显示「工序损耗未交付」，**不显示为「按 0 计算」**。阶段 A 的种子里根本没有工艺路线与工序损耗——那些实体的 schema
在 A 阶段还不存在，谈不上拒绝或忽略；它们随阶段 B 的种子层加入（见 In Scope「分层种子」）。阶段 B 起第 5 步可用。
成本页到阶段 D 才出现，B / C 阶段不放空成本页。

阶段 A 有独立价值：它是[首轮可开工切片](../../epics/epic-009-bom-domain-model.md#首轮可开工切片)的**验收手段**，
不依赖 B~F 就能被用来判断那五条故事是否真的交付了。后续各阶段各自等对应故事落地，
**全部阶段关闭后才置 `Done`**（[CONVENTIONS 大故事分阶段](../../CONVENTIONS.md#大故事分阶段不拆子故事文件硬规则)）。

## 范围边界

### In Scope

- **`apps/dev-rxdb-bom`**：Angular demo，展开树 + **算式面板** + 评估日切换 + EBOM/MBOM 双图对比
- **一份确定性种子数据集**：一台电动滑板车 `SC-100`，落
  `packages/rxdb-plugin-bom/src/testing/scooter-dataset.ts`，**demo 与 vitest 用例共用同一份**；
  `id` 与审计时间戳由种子固定给出，`loadHistory` 的批次号可复现（见技术笔记「确定性的归属」）
- **分层种子**：同一台车按阶段分层装载，每层只**追加**该阶段 schema 已存在的实体（A：物料 / 修订 / 头 / 行与位号；
  B：替代组、`flow_direction`、工艺路线与工序损耗；C：ECN；D：映射与成本输入；E：`attr_def` / `ext`、序列与批次有效性、
  配置模型、导出与导入演示数据；F：实例树与换件记录），不改写下层的行；
  种子经 [US-508](US-508-bom-view-resolution.md) 的历史装载通道写入，带过去日期的修订、头与 ECN 不被禁止追溯生效拦下
- **分阶段 golden**：golden 每条路径按阶段给值；不受新层影响的路径各阶段的值**逐位相同**（这本身是一条断言：
  加层不扰动旧结构），受影响的路径（如阶段 B 加入工序损耗后的投料）在新阶段给出新值
- **算式面板**：选中任一展开行，按 [US-511](US-511-bom-quantity-semantics.md) 七步公式
  逐步列出中间值与单位（`P` / `P'` / `G` / `G'` / `G''` / 换算 `D` / 穿透），每步标出取自哪个字段；各阶段可用步骤见上表
- **手工 golden 表**：`packages/rxdb-plugin-bom/src/testing/scooter-golden.ts`，每条路径发生项、每个阶段的单位、七步中间值、最终数量，
  以及材料 / 加工 / 制费 / 抵减与总额，**全部手写**，不调用被测 kernel 生成
- **评估日（as-of date）显式入参**：页面顶部输入，驱动 [US-508](US-508-bom-view-resolution.md)
  的生效期过滤；**不读系统时钟**。阶段 E 起同排加序列号（`unit`）输入，不填 = 不带 unit 解析
  （[US-518](US-518-bom-unit-lot-effectivity.md) AC#6 的候选集展示）
- **直连写入入口**：绕过应用层校验直接写库的按钮，用来证 [US-509](US-509-bom-dag-cycle-detection.md)
  AC#5 的约束真的在存储层
- **`apps/dev-rxdb-bom-e2e`**：playwright，16 条 AC 各至少一条用例
- **既有库重开**：e2e 里有一条先以非 BOM 实体建库、重开后再装 BOM 插件并跑种子的用例——插件的新表与触发器在既有库上正常创建；
  安装期 DDL（US-509 可达性触发器、US-511 格式触发器）只在全新库上跑，会漏掉既有库执行时的失败形态

### Out of Scope

- **可复用的三框架绑定**（→ [US-522](US-522-bom-tri-framework-ui.md)）：本故事交付的是**一个应用**，
  不是**一套绑定**。单端即可，先例是 [US-214](../adapter/US-214-http-browser-demo.md)（`status: Done`，
  只有 Angular 前端）。三端对称是 US-522 的关闭条件，不是本故事的
- **配置求解器**（[US-517](US-517-configurable-sales-bom.md) 只定模型与求解契约，求解可外挂）、
  **联产品**（US-513 阶段 B）与**热字段提升的索引加速演示**（US-519 AC#3 / #7，等 US-030 阶段 D）——
  三者不进演示。其余全域能力（含配置选择、序列 / 批次、实例 BOM）在阶段 E / F 内，见对应 AC；
  「一份数据集走完全域」的「全域」以 US-525 阶段 A～F 的 AC 为界
- **性能基准**：本故事的数据集按「覆盖全部硬用例」设计，不按「压出规模」设计
- **新领域能力**：本故事**不新增任何抽象**，全部行为都归属到已有的 18 条故事

## 技术笔记

**一份数据集，不是十八份样例。** 这是本故事唯一不可让步的形态要求。
epic-009 的 18 条故事各有自己的 AC，但每条都是**单点断言**：替代组加权对、损耗乘序对、
可达性剪枝与生效期二次过滤对。BOM 的实际缺陷出在这些东西**同时发生**的地方——
一只带替代组的电阻，挂在有工序损耗的 SMT 工序上，父件是虚拟线束，整机又在 ECN 生效日前后各展开一次。
每条 AC 配一个干净的孤立样例，这类组合缺陷永远照不出来。
所以种子是一台完整的滑板车 `SC-100`：位号、替代、虚拟件、多输出、工序、双图重构、
扩展属性、序列换件、配置、导出与实例各自落在这台车的**不同真实部位**上（阶段 E / F 的种子层随各自 schema 落地追加），
而不是十八个互不相干的迷你 BOM。

**每个数字并排一条手算式。** BOM 算错不会崩——它给出一个看起来完全正常的数字，
要到 MRP 多下了 400 颗螺钉才有人发现。算式面板把 [US-511](US-511-bom-quantity-semantics.md)
七步公式的每步中间值摊开，并标出每步取自哪个字段（`h.assembly_scrap` / `l.component_scrap` /
`op.scrap` / `r.default_phantom`）。这和 [US-214](../adapter/US-214-http-browser-demo.md)
的「协议流量面板」是同一招：把**本来不可见的中间态**摆到页面上，让错误在发生处显形而不是在下游。

**评估日必须是显式入参，这是 demo 逼出来的 API 约束。** AC#10 要求把机器时钟调开一天、
展开结果不变。做不到就说明展开实现内部读了 `Date.now()`——那样的实现对过去日期的解析会漂，e2e 也只能在一天之内绿。
这条约束已落成 [US-508](US-508-bom-view-resolution.md) 的 AC#7（`as_of_date` 必填）与 AC#8（改系统时钟结果不变），
AC#10 是它在页面上的复现。

**AC#5 的两条路径必须得到同一个错误码。** US-509 AC#5 要证的是约束**在存储层成立**，直连写入入口证的是「绕过应用层也被拒」；
表单那一条证的是反面——应用层**没有**重复一份环校验。若表单走自己的校验器报自己的错，存储层的触发器在正常路径上
就成了从不触发的死代码，两份逻辑迟早分叉，而且没有任何用例会发现。所以两条路径必须报同一个存储层错误码；
vitest 另有一条反证：卸掉触发器后，表单写入成环边**成功**。US-509 AC#9 的 `union_only` 标记是插件对存储层错误的补充，
不是第二道校验。没有直连入口，AC#5 在 demo 里是演不出来的——这也是为什么它是 In Scope 的一项，而不是调试便利设施。

**与 [US-522](US-522-bom-tri-framework-ui.md) 的分工**：US-522 交付**可复用绑定**，
关闭条件是三端同 API、单端缺失即未完成；本故事交付**一个应用**，关闭条件是一份数据集
把上述断言当场演出来。两条的前置也不同——US-522 要等三框架绑定，本故事阶段 A 只等首轮切片。
demo 单端即可，先例是 US-214（`status: Done`，只有 Angular 前端）：
本仓铁律「三框架 API 必须对称」约束的是**包的导出面**，不是 demo app 的数量。

**种子落插件而非 app**：`packages/rxdb-plugin-bom/src/testing/scooter-dataset.ts`。
理由是 vitest 用例与 demo 共用同一份数据后，demo 就是那批单测的**可视化视图**——
单测断言的数字和页面上显示的数字来自同一组输入，两边对不上时先怀疑的是实现而不是样例。
放进 app 则两边各自演化，很快就不再是同一台滑板车。

**确定性的归属：种子与固定输入，不是通用 ID 策略。** AC#1 的逐字节相同由 `scooter-dataset.ts` 兑现：
`id` 由业务键派生，`createdAt` / `updatedAt` 取固定基准，日期是字面值，全部显式传入。
引擎只给**未赋值**的属性套默认值，构造期传入的 `id` / `createdAt` 会覆盖默认的 `uuid()` 与当前时刻
（[`fillInitValue`](../../../packages/rxdb/src/entity/entity.utils.ts) 的说明：`readonly` 是「创建后不可改」，不是「构造时不可传入」），
先例是 [`seedRxdbStore`](../../../apps/dev-rxdb-http-server/src/rxdb-store.ts) 经 `entityManager.instantiate` 传入 `id` / `createdAt` / `updatedAt`；
所以 [US-507](US-507-bom-graph-skeleton.md) 的实体不必声明确定性 ID 策略。插件侧只有一个前提：[US-508](US-508-bom-view-resolution.md)
`loadHistory` 写出的批次号可复现、不含随机成分——这条合同归属 US-508 的历史装载通道，本故事只消费它；种子的装载顺序固定（A→F 层依次追加）。

**共享输入，不共享预期。** 若算式面板、预期数字与生产结果都由同一个 kernel 重算，同一个乘序或单位错误会三边一起绿。
所以 `scooter-golden.ts` 是手写的独立 oracle：数量单测、存储 conformance、三框架合同与 playwright 都只拿它**比较**，
没有一处从被测 kernel 生成 expected。缺成本报错（AC#15）证明不了卷算正确，AC#14 是正向成本 oracle。
16 条 UI 用例也不替代数据库与数学层的组合测试，它们在各自故事里另测。
