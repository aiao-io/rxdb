# 用户故事：多级展开与 where-used 反查

## 作为/我想要/以便

**作为** 计划员
**我想要** 从任意节点向下多级展开、向上反查被哪些整机使用
**以便** 评估某零件停产会影响哪些产品

## 交付阶段

| 阶段 | 内容                                                                                       | 状态 |
| ---- | ------------------------------------------------------------------------------------------ | ---- |
| A    | 递归 CTE 实现下钻与反查；展开预算（深度、展开数、返回路径数、取消）与 `truncated` 截断标记 | ⬜   |
| B    | `bom_reach` 物料级可达性物化（键含 `bom_type, org_id`，不存路径、不带生效期）+ 增量维护    | ⬜   |

## 范围边界

### In Scope

- 下钻：给定节点与 `ResolutionContext`（[US-508](US-508-bom-view-resolution.md)），返回各级子件、层级与路径；
  路径由**行发生项 ID 序列**标识，同一子装配经两条路径出现即两个结果节点
- 反查（where-used）：给定子件，返回所有使用它的父件与路径
- **预算**：深度上限、展开节点数上限（同 graph 插件 `GRAPH_MAX_PATH_EXPANSIONS` 的先例）、返回路径数上限、调用方可取消；
  任一触顶即停止并标 `truncated`，附触顶的是哪一项
- **截断结果不是完整结果**：UI 浏览可以展示 `truncated` 结果；[US-511](US-511-bom-quantity-semantics.md) 数量、
  [US-514](US-514-bom-cost-rollup.md) 成本与 [US-521](US-521-bom-erp-mrp-integration.md) 导出遇到 `truncated` 一律拒绝
- 可达性表**只回答「能不能到」**：物料级、不带生效期，与 [US-509](US-509-bom-dag-cycle-detection.md) 判环用的是同一张表；
  它对任何解析上下文都是上界，查询用它剪枝，路径与生效期仍由 CTE 按上下文求
- 可达性表的维护入口：行发生项的插入、删除（含 ECN 撤回 / 取消的级联删除），以及 `child_item_id` / `flow_direction` 更新（`flow_direction` 由 [US-513](US-513-bom-coproduct-byproduct.md) 阶段 A 引入，列落地前没有这一入口，口径同 [US-509](US-509-bom-dag-cycle-detection.md)）；
  生效期变化与发布**不是**入口（见技术笔记）。决定作用域与父端点的结构归属列创建后不可改（[US-507](US-507-bom-graph-skeleton.md) AC#13），
  所以也不是入口

### Out of Scope

- 累计用量与损耗（→ US-511；可达性表**不存**用量）
- 成本（→ US-514）
- 按路径物化全部祖先—后代路径（`line_path` 闭包）——路径数随菱形结构指数增长，见技术笔记；需要时以实测热路径另立阶段

## 技术笔记

**AC#3 是本故事最重要的一条，它决定物化表的列。** 结构变更频率低、用量变更频率高；
若物化表存累计用量，改一个 `qty` 就要重算整棵子树。所以拆成两件事：

- 可达性表回答**能不能到**（写入稀疏）；
- 路径与用量卷算是**按上下文现算的递归**（读时或作业时计算，不落进可达性表）。

物化表的键**必须**含 `(bom_type, org_id)`——同一对 `(parent, child)` 在不同类型与组织下结构完全不同。

**为什么只物化可达性，不物化路径。** 路径数随结构指数增长：20 个串联菱形只有 61 个节点、80 条边、深度 40，
根到末端就有 2^20 = 1,048,576 条路径（Python 拓扑 DP 计数探针），全祖先—后代路径还更多；多重边会再放大。
可达对最多是节点数的平方，且与路径数无关。判环（US-509）只需要可达性；展示需要的路径按需递归、受预算约束（AC#10）。
二者不强制同一表形态。深度上限挡不住这种膨胀——深度 40 的结构在多数业务里不算深——所以预算必须同时管展开数与返回路径数。
AC#10 的三个预算值是测试输入，让「返回路径数」先于另两项触顶，不是产品默认值：深度 50 大于结构深度 40，展开数取 `GRAPH_MAX_PATH_EXPANSIONS` 的 100,000
（递归 CTE 每行即一个结果，返回 10,000 条时展开行数仍远低于它）。

**AC#7 定的是可达性与生效期的分工，它和 AC#3 是同一条原则的两半。** 可达性若把生效期算进去，
每天零点整张表的语义都会变，维护成本等同于按日期物化。所以它存的是「**曾经或现在**存在这条边」——
与 US-509 的保守政策（并集无环）是同一张并集图，于是生效期变化、ECN 改期、修订发布、头发布都不改变它，
维护入口只剩发生项写入（AC#4 / #8 / #9）。代价是可达性对具体上下文只是上界，路径须在递归时按上下文过滤，
不成立的路径**不能**当作有效结果返回。

**AC#8 是增量维护里比 AC#4 难的那一半。** 插入只需补「父的祖先 × 子的后代」；删除不能直接删对应的祖先—后代对，
因为同一对物料可能经由别的发生项连通（BOM 是多重图，US-507 AC#1）。判据回到剩余的边：
对受影响的祖先—后代对，用递归 CTE 在删除后的并集图上重检是否仍可达，只移除不再可达的那些。AC#9 的端点更新等价于一删一插。

**截断与完整性。** `truncated` 是给浏览用的诚实信号，不是部分成功：数量、成本与导出都要求完整结构，
拿到截断结果必须拒绝（AC#11），不能把前 10,000 条路径的数量当作总需求。

规模判断（**推断**，未在本仓实测）：边 < 10^5、深度 < 20 时递归 CTE 通常够用，
阶段 B 的触发条件是 where-used 成为实测热路径，不是预防性优化。
