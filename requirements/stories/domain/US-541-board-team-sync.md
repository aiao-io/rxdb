# 用户故事：团队版看板：Supabase 同步与身份

## 作为/我想要/以便

**作为** 一个具名团队的成员
**我想要** 看板在团队多设备间同步——我离线拖了任务，回网后同事能看到，而不是互相覆盖
**以便** 团队共用一块板推进工作，离线也是常态

## 价值待证

**本故事不随 [epic-011 解锁记录](../../epics/epic-011-task-board-domain-model.md#价值待证整个-epic)
解锁，保持价值待证**（与 BOM 的 US-513 阶段 B 同型）。入场条件是
[domain-research 的判据](../../domain-research/task-board.md#入场条件什么信号才值得立项)：
**出现具名团队「离线拖拽任务、回网后互相覆盖」的具体症状**，或 owner 决定把演示推进到团队版。
写出具体症状之前不得凭 Epic 惯性排期（CONVENTIONS「价值待证」）。

## 范围边界

### In Scope

- **Supabase 同步**：板 / 列 / 任务 / 标签经 [US-218](../adapter/US-218-supabase-rls-push-integrity.md) /
  [US-220](../adapter/US-220-supabase-update-push-semantics.md) 已交付的 Supabase 适配器同步
  （RLS 推送完整性、UPDATE 落库语义、逐实体回执均已 Done）
- **身份与单团队写权限**：接入登录 / 退出状态、服务端确认的单团队成员资格及本地离线会话；
  应用服务在每个看板写入口校验身份、成员资格与会话有效期。US-027 仅区分公开 / 系统写入口，
  不提供用户身份或成员授权；通用角色与所有权写授权（US-029）不是前置
- **远端写入边界**：部署与该团队对应的 Supabase RLS，按服务端身份和成员记录校验业务写入；
  沿用 US-218 的日志表写入收口，客户端声明的作者 / 团队 ID 不能替代服务端授权
- **离线并发合并规则**：离线双端移动同一任务 / 编辑同一任务回网后的合并——[US-535](US-535-cross-column-move-ordering.md)
  的单人语义是其设计输入，本故事定义与实现冲突语义（本地优先冲突检测底座见
  [US-308](../collaboration/US-308-branch-isolation-conflict.md)，多成员协作语义见
  [epic-006](../../epics/epic-006-working-tree-commits.md) 已交付的工作树与 commit graph，
  身份与远程提交协议**另做**——2026-10-18 优先级评审核对后的事实）
- **最小协作范围**：一个明确配置的团队、一块共享板；该团队成员可协作编辑，非成员不得推送。
  成员配置由受信管理入口维护，不交付板级角色、组织或邀请管理

### Out of Scope

- 多租户、通用角色 / 所有权写授权（US-029 价值待证）、板级角色与按成员区分的行级读隔离；本故事只承诺单团队共享数据集，
  不得将它部署为包含非公开数据的多团队混合全量同步库
- 评论 / @ 提醒 / 实时协作（引擎外通道，epic 非目标）
- 跨板全局搜索的工作区版本（[US-538](US-538-board-task-search.md) 只承诺板内；本故事立项时
  一并评估）
- 工作区 / 组织 / 邀请管理

## 技术笔记

**已有的是同步原语，应用协议仍待交付。** 双向同步（epic-002）、Supabase RLS 推送完整性
（US-218 / US-220）与本地冲突检测（US-308）已交付；它们不自动提供登录、成员授权、离线会话
或团队冲突规则。epic-006 的作者由调用方提供，不能拿作者字段当登录凭据。本故事立项后先冻结
身份与待推队列的绑定、会话有效期、服务端成员策略和冲突协议，再进入实现；不得把这些记为
「只接线」或宣称引擎已覆盖全部团队底座。

**应用门禁、实体入口声明、服务端授权各有落点。** US-027 的 `both / system` 只判断实体操作
是否允许公开入口调用，不读取当前用户、团队或角色。看板应用服务在 US-534 的共同写门禁（单人版只有「恢复中」）上叠加只读、身份与成员判定，为创建 / 更新 / 删除 /
移动 / 本列排序 / 撤销重做统一检查登录身份和成员写资格，在产生本地变更前拒绝无资格操作；UI
禁用只是同一状态的反馈。US-027 继续防止公开误写系统实体。服务端 RLS 则以实际认证身份和
服务端成员记录决定推送能否落库，且普通客户端不能直接写 `rxdb_change`；两层不能相互替代。
这套单团队应用协议不要求完整 US-029，也不新增通用 RBAC 抽象。

**离线写入有明确期限。** 只有先在线验证过的同一成员、在应用定义且验收冻结的离线会话有效期
内才允许离线写；初次未登录、明确退出、会话到期或已知被移除均拒绝新写入。离线时无法获知的
远端撤权不承诺立即生效；回网先重新校验，校验失败暂停推送，远端最终仍由 RLS 拒绝越权操作。
待推变更绑定原用户与团队，重开不丢失，切换用户不得串用队列或改署名。退出 / 到期保留已有
待推变更和可见状态，不能静默丢弃，也不能继续以缓存身份推送。

**冲突规则的定义和实现全部属于本故事。** US-535 只提供单人移动输入和排序不变量。立项时为
以下情况冻结可重复验证的决策表：不同字段并发修改、同字段冲突、同任务双端移动、移动与目标列
删除并发、修改与任务删除并发。不同字段修改保留双方结果；同字段或位置冲突须有确定仲裁和
持久化双方候选值 / 作者 / 解决记录；到达顺序、设备本地时钟或未记录的「最后写入」不能成为
隐式规则。每种回网顺序与重放都必须收敛，且不得产生跨板移动、孤儿或重复排序键。具体仲裁与
恢复旧值的交互在立项时冻结，不把未定义规则提前塞进单人首轮。

**同步不承诺成员间限读。** `rxdb_change` 不受业务表 SELECT 策略约束，本故事的共享数据集仅含
该团队均可读取的板；不能宣称业务表 RLS 自动完成按成员或租户限读。若立项场景要求非成员不能
读取同一同步端点上的数据，须先验证该端点对共享数据集的准入控制；验证不通过就停止接入并另行
评估限读路径，不能直接把私有数据放入全量同步。已有 US-218 / US-220 只证明写入拒绝与日志正确。

**关闭条件**：身份 / 成员门禁、有限期离线会话、用户与待推队列隔离、服务端 RLS 与日志权限
均实测；并发规则先冻结后实现且覆盖全部决策表；双端收敛、无静默覆盖；被拒写不复推；重开与
回网不丢待推变化。以上条件只在价值待证解除并完成立项评审后进入排期，本次文档完善不构成解锁。
