# 用户故事：rxdb-model 表单字段错误提示与保存失败归因（三端对称）

## 作为/我想要/以便

**作为** 使用 rxdb-model 实体表单新增、编辑数据的用户  
**我想要** 在出错属性旁看到能理解、能指导修正的提示，并能快速定位所有未解决的问题  
**以便** 保留已经填写的内容，改对后继续保存，无需理解数据库错误或反复猜测哪个属性有问题。

## 具体症状与现状依据

用户反馈：在管理模板的 `/entities/assets/Asset` 页面新增同名资产，提示包含
`sqlite-wasm execute() failed for SQL`、完整 INSERT 语句与
`UNIQUE constraint failed: assets$asset.name`，没有在「名称」属性旁提示重复。
这是用户提供的现场，尚未在本次需求编写中通过浏览器独立复现。

源码核对：

- [`Asset` 的实体元数据](../../../apps/rxdb-admin-template-angular/src/app/entities/asset-entities.ts)声明
  `name` 的 `displayName: '名称'`、`unique: true`、`required: true`，具备生成属性文案的业务信息。
- [`EntityDetail.#saveErrorMessage`](../../../packages/rxdb-model-angular/src/entity-detail/entity-detail.ts)、
  [React `saveErrorMessage`](../../../packages/rxdb-model-react/src/entity-detail/entity-detail.tsx) 和
  [Vue `saveErrorMessage`](../../../packages/rxdb-model-vue/src/entity-detail/EntityDetail.vue)
  都直接使用 `error.message`；现有错误面板会把底层错误原文展示给用户。
- [`FormFieldValidationError`](../../../packages/rxdb-model/src/entity-form/interfaces.ts)已经包含
  `field` 与 `message`；[`validateForm`](../../../packages/rxdb-model/src/entity-form/form-validation.ts)
  已逐字段生成错误，尚需把这些归因用于字段展示。
- [`EntityDetail.onFieldChanged`](../../../packages/rxdb-model-angular/src/entity-detail/entity-detail.ts)
  当前直接执行 `this.formErrors.set(null)` 和 `this.saveError.set(null)`，修改任意字段都会清空错误。
- [US-104](US-104-validation-feedback.md)交付对话框错误面板，明确将字段级内联提示移出其范围；
  本故事承接新增能力，不将旧故事已通过的验收当成本故事的验收证据。

**归属**：公共能力属于 `rxdb-model` 与 `rxdb-model-{angular,react,vue}`。
资产页面仅用于复现与端到端验收，不在该页面硬编码同名资产提示。

## 范围边界

### In Scope

- 三端 `EntityForm` 的字段错误展示，以及 `EntityDetail` 新增、编辑流程的错误归因、摘要与定位。
- 已有必填、类型、格式、范围等校验错误，与保存时返回的可识别存储约束错误采用同一展示规则。
- 单字段唯一冲突与可可靠归因的多字段约束；字段归属必须以结构化错误和当前实体元数据为依据。
- SQLite WASM 与 PGlite 唯一冲突的实际写入验收；其他来源能否归因须按证据声明，不扩大支持范围。
- 无法归因到可编辑属性的错误使用表单级提示，保留供开发者定位问题的原始错误。
- 错误出现时机、修改后的状态更新、失败保留输入、重试、取消与迟到结果隔离。
- 三端交互、公共错误语义与对外接口一致；提示支持现有国际化能力与键盘、读屏操作。

### Out of Scope

- 新增资产名称的业务规则，或改变数据库唯一性、大小写、空白、空值等既有判定语义。
- 保存前异步查重、自动改名、静默覆盖记录、弱化存储层约束。
- 重写校验规则、字段解析规则、整个表单库或全部适配器错误体系。
- 表格单元格编辑、批量导入、查询失败、全站通知系统及新的日志平台。
- 未经真实验收宣称所有适配器、所有远端服务都能定位约束涉及的属性。

## 建议交互方案

### 字段旁提示与表单摘要

| 场景 | 展示位置 | 推荐文案与交互 |
| --- | --- | --- |
| 新建资产名称重复 | 「名称」输入框下方 | 「名称已存在，请使用其他名称。」；输入框标记错误，提交失败后定位该字段 |
| 必填未填 | 对应输入框下方 | 「请输入名称。」；使用当前属性显示名称 |
| 字段值不符合已有规则 | 对应控件下方 | 说明当前规则及可行修正，例如「采购价格不能小于 0。」；不新增业务校验 |
| 多个属性分别出错 | 每个属性下方 + 表单内容起始位置的摘要 | 「有 3 项需要修改」；按表单顺序列出可点击的属性与原因 |
| 联合唯一或其他已知多字段约束 | 相关属性附近 + 一条去重的摘要 | 「名称与分类的组合已存在，请调整其中一项。」；不误报为两个属性分别不唯一 |
| 错误只涉及隐藏、只读或当前不可编辑属性 | 表单摘要 | 给出可执行说明；不把焦点移到无法编辑的控件，也不为解决错误暴露隐藏属性 |
| 已知权限或连接问题 | 表单级提示 | 说明原因及下一步，例如「没有保存权限，请联系管理员。」或「连接中断，请恢复连接后重试。」 |
| 无法确认原因 | 表单级提示 | 「保存失败，请重试；若仍失败，请联系管理员。已填写内容已保留。」；不直接拼接未知异常原文 |

字段下方是主要修正入口；摘要用于导航和无法落到字段的问题。
单字段错误不额外堆叠一条包含同样长文的全局通知；同一约束在摘要中只计一次。
提示不只依赖颜色，错误文字与控件之间有可被辅助技术识别的关联。

### 错误出现与消失

- 首次打开表单时不展示尚未触发的校验错误。字段首次失焦后，或用户提交后，展示已有校验规则发现的问题。
- 提交失败时主动揭示错误：单字段错误定位该字段；多项错误将焦点移到摘要，摘要可导航至对应控件。
  属性位于尚未展开的分组或页签时先展开或切换，再滚动和聚焦；无法编辑时停留在摘要。
- 编辑有错误的字段时，按原规则重新校验；已解决的本地错误清除，仍未解决的错误继续展示。
  修改无关字段不能清掉其他属性的错误。
- 修改被存储层拒绝的字段或其约束依赖字段后，将这条旧保存错误移除并等待再次保存确认；
  不把“已修改”展示成“唯一性已通过”。修改其他字段不影响该错误。
- 保存失败保留对话框、草稿和其他字段内容，允许修正后重试；取消、成功保存或切换记录后清理对应错误。
- 保存期间修改字段时，迟到结果不得给不同的新值挂上旧字段错误；关闭、换记录、重新打开后的表单
  不接收上一轮保存的错误或焦点操作。诊断仍保留原始失败。

## 验收标准

所有 AC 当前均未实现、未验收；三端同义执行，不能用其中一端通过替代其他端。

| # | 前置条件 | 操作 | 预期结果 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 新增或编辑表单刚打开，用户尚未编辑或提交 | 查看表单 | 不出现未触发的校验错误，不因打开表单移动焦点到错误位置 | ⬜ |
| 2 | 必填属性为空，或输入违反该属性已有的类型、格式、范围规则 | 属性失焦或点击保存 | 原因显示在该控件下方，使用属性显示名称；提交发现无效时不执行保存且表单保持打开 | ⬜ |
| 3 | 已存在名称相同的资产，新增表单其余字段合法 | 输入同名并保存 | 实际写入被唯一约束拒绝；「名称」下显示「名称已存在，请使用其他名称。」并标记错误，不展示 SQL、物理表名、驱动前缀或调用栈；无重复记录写入 | ⬜ |
| 4 | 编辑已保存资产，唯一字段未改变；另有一条名称不同的资产 | 先保存未改名记录，再将其改为另一条记录的名称并保存 | 不把自身误判为重复；真正冲突时在名称属性下提示，其他输入保留且原记录未被覆盖 | ⬜ |
| 5 | 两个及以上可编辑属性存在独立校验错误 | 点击保存，再用键盘操作摘要链接 | 全部属性有内联提示；摘要按表单顺序列出错误并获得焦点；链接能展开相关分组或切换页签并滚动、聚焦对应控件 | ⬜ |
| 6 | 联合唯一或既有结构化约束能可靠定位多个属性 | 提交违反约束的数据 | 提示说明属性间的组合关系；相关属性均能找到原因，摘要对同一约束只计一次，不误报每个属性各自不唯一 | ⬜ |
| 7 | 错误涉及隐藏、只读属性，或缺少可靠字段归属 | 保存被拒绝 | 表单级展示可理解提示，不随意挂到其他字段，不把焦点移到不可编辑控件，不显示内部字段、SQL 或隐藏值 | ⬜ |
| 8 | 因权限、连接问题或未知异常保存失败 | 查看提示并重试 | 已知原因给出相应行动建议，未知原因用受控通用文案；草稿保留且允许重试，原始异常可经开发者诊断入口获得 | ⬜ |
| 9 | 多个属性已有校验或保存错误 | 修改一个属性，再修改无关属性 | 仅重新校验或清除受本次变更影响的错误；无关错误保留，摘要数量同步；字段被编辑不等于存储约束已经通过 | ⬜ |
| 10 | 保存失败后全部字段仍在表单内 | 修正错误并再次保存 | 原有输入保持；保存成功后按现有流程关闭或完成编辑，相关错误清除，结果只有一次成功写入 | ⬜ |
| 11 | 保存请求尚未完成 | 修改相关值，或取消、切换实体、重新打开表单后再收到旧失败 | 旧失败不标记不同的新值，也不修改新表单的错误、摘要和焦点；原始失败仍可诊断 | ⬜ |
| 12 | 错误已展示 | 取消后重新打开，或切换到另一条记录 | 不残留上一次表单的字段错误、摘要、保存错误或计数 | ⬜ |
| 13 | 内联或摘要错误出现 | 仅用键盘和辅助技术读取并定位 | 控件暴露无效状态并关联错误文本；读屏能获知提交失败，提示不只靠颜色；每次文字更新不抢走正在输入的焦点 | ⬜ |
| 14 | 已显示错误，当前语言或属性显示名称变化 | 切换语言或更新显示元数据 | 自有提示和摘要随当前语言与属性显示名称更新，错误归属与输入保留，不回显数据库原文 | ⬜ |
| 15 | 三端使用同一实体和同一组错误场景 | 分别新增、编辑；宿主直接消费 EntityForm 并传入字段错误 | 三端错误归属、出现与清理规则、定位和公共接口同义；独立表单也能显示字段错误；已有提交、取消和校验事件保留其契约 | ⬜ |
| 16 | SQLite WASM 与 PGlite 分别使用真实实体和唯一约束 | 执行重复新增、重复改名，并覆盖合法预校验后才发生的并发撞名 | 两种后端均将实际写入拒绝转成相同字段提示；存储层约束仍是最终判定，不靠保存前查询或模拟异常证明后端支持 | ⬜ |

状态符号：⬜ 未开始 / ⚠️ 进行中或有保留 / ✅ 通过。

验收证据：待实现后补充。用户现场仅证明具体症状；本次源码核对仅证明现有处理链路，均不替代 AC 验收。

## 技术笔记

### 错误归因与展示职责

建议流程为：保存错误 → 可确认的约束信息 → 公共表单错误语义 → 三端字段提示与摘要。

- `rxdb-model` 统一错误结构、属性归属、关联属性、文案与错误状态更新规则；沿用现有
  `FormValidationResult` / `FormFieldValidationError` 能力，新增接口在三端保持同义。
  具体接口名称在实现设计时确定，不让三端各自解释 SQL 文本。
- 优先使用引擎已有的结构化错误与实体元数据。核心已有
  [`RxDBCheckViolationError`](../../../packages/rxdb/src/RxDBError.ts)及
  [`RxDBExclusionViolationError`](../../../packages/rxdb/src/RxDBError.ts)，
  唯一冲突识别已有
  [`isUniqueConstraintViolation`](../../../packages/rxdb/src/system/migration.ts)，
  但该函数返回布尔值，单独使用不能给出冲突属性。
- 唯一冲突若需要补足稳定的字段信息，在 core / adapter 的既有错误归一边界做最小补充，
  与本故事的公共包改动一起评审、验证；本故事的产品归属仍是 `rxdb-model`。
  数据库方言识别不进入三端组件，不靠异常消息中偶然出现的 `name` 或 SQL 列清单猜测属性。
- 对无法可靠归因的错误显式保留“未归因”状态，用表单级受控提示；保留原始异常及其原因链，
  不静默吞错，也不将未知异常伪装成字段校验失败。
- 保存错误关联提交时的记录、字段值与请求批次，避免迟到结果污染当前输入；沿用现有草稿生命周期保护。
- `EntityForm` 承担具体控件的文本、无效状态和定位，`EntityDetail` 承担保存错误接入与表单摘要协调；
  宿主应用不依赖物理表名，也不复制错误转换逻辑。

### 验证方案

1. 先写失败用例：以真实重复资产名称固定问题，并用现有多字段校验固定“修改无关字段不能清空其他错误”。
2. 公共层单测覆盖单字段 / 多字段归因、未知错误、错误来源与字段值关联、按关联属性更新及文案重算。
3. 三端组件测试覆盖字段提示、独立 EntityForm、摘要导航、输入保留、重试及迟到结果隔离。
4. 真实 SQLite WASM 与 PGlite 写入验证数据库错误来源；三端浏览器流程验证错误归属和实际用户操作。
5. 按受影响项目运行 lint / typecheck / test 与仓库覆盖率门禁，并执行三框架 API 对称检查；
   未取得证据的后端或交互维度保持未验收状态。
