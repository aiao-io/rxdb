# 用户故事：本地数据库一致性备份与恢复

## 作为/我想要/以便

**作为** 使用本地适配器保存业务数据的应用开发者
**我想要** 在数据库运行期间生成可验证的一致备份，并安全恢复到兼容的新存储位置
**以便** 在设备迁移、存储损坏或误操作后恢复数据库状态，明确知道备份是否完整、恢复是否成功，以及哪些外置内容需要另行备份

## 现状与证据

Electron SQLite、Electron PGlite 与 Tauri SQLite 的故事均将数据库导入、导出、热备份和损坏修复排除在范围外：
[US-207](./US-207-desktop-local-database.md)、[US-208](./US-208-electron-pglite-data-directory.md)、
[US-210](./US-210-tauri-sqlite-local-database.md)。桌面文件存储的验收路径是退出应用后复制整个应用数据目录，
见 [US-504](../plugin/US-504-electron-local-file-storage.md) AC#3 与
[US-505](../plugin/US-505-tauri-local-file-storage.md) AC#3；这不是可由应用调用的一致性备份接口。

浏览器侧连这条路都没有。仓库里唯一的数据库导出入口曾是 DevTools Settings 的数据库下载：它在 OPFS 里搜索 SQLite 文件直接热拷贝。
[US-904](../future/US-904-devtools-native-storage-contract.md)（`Done`）把它作为不安全入口停用，browser / Electron / Tauri 的
`settings` provider 对 `export` 恒回 `export_unsupported`（[`read-only-settings.ts`](../../../packages/rxdb-devtools/src/provider/read-only-settings.ts)），
并在 Out of Scope 写明「可靠导出需要 adapter 参与阻止重连并生成一致快照，必须另立故事」——本故事就是那条故事。
PGlite 自带的 `dumpDataDir()` / `loadDataDir` 在仓内也没有调用方，复验：
`grep -rlE 'dumpDataDir|loadDataDir' packages/*/src apps/*/src --include='*.ts'` 无结果。

本故事只认领数据库快照与恢复。`rxdb-plugin-storage` 管理的外置文件内容不属于数据库归档；
调用方必须能识别该限制，不能在外置文件未备份时报告“完整应用备份成功”。

加密库的认证域由 [`RxDBAdapterPGlite.#initEncryption()`](../../../packages/rxdb-adapter-pglite/src/RxDBAdapterPGlite.ts)
传入 `rxdb.config.dbName`，[`buildAAD()`](../../../packages/rxdb-adapter-encrypted/src/envelope.ts)
将数据库认证域纳入认证数据。因此，移动存储位置与更改加密身份是不同操作，首版只支持前者。

## 范围边界

### In Scope

- 从已连接的本地数据库生成有版本、有完整性校验的快照；以一个已提交事务边界为准。
- 保存全部持久化数据库状态，包括用户表、关系、系统表、变更历史、数据库对象及适配器内部元数据；恢复后能够继续读写和使用原有历史。
- 恢复到未使用、未连接且可独占的兼容目标存储；兼容性由明确的支持矩阵判定。
- 对加密字段保持存储态密文，保留解锁必需的非秘密元数据；密钥、口令及 key provider secret 不进入归档。
- 使用流式或等效有界内存方式处理大型数据库，支持取消，处理输入 / 输出错误、空间不足及恢复时的进程中断。
- 通过可判别的结果和错误表达兼容性、完成状态、恢复限制及外置文件边界。

### Out of Scope

- 不同 adapter 之间或不同数据库引擎之间的数据迁移、格式转换及 schema / change-codec 自动升级。
- 覆盖或合并非空数据库、选择性恢复实体、JSON / CSV 导入导出。
- 加密认证域更名、密钥轮换、恢复时解密再加密；密钥生命周期仍由 [US-803](../future/US-803-local-encryption.md) 管理。
- 远端权威适配器（HTTP / Supabase）及实验性微信小程序适配器。
- `rxdb-plugin-storage` 的外置文件本体、任意应用文件、整机 / 应用设置备份。
- 损坏数据库的自动修复；损坏或不完整归档只允许拒绝，不得猜测性恢复。
- 桌面任意路径授权、系统文件选择器和备份 UI；调用方提供受控的输入 / 输出流及目标位置。

## 恢复与完成语义

### 目标与独占

“空目标”指不存在或不含任何数据库内容的未使用存储位置。已初始化的引擎目录、系统表或元数据，即使没有业务记录，也不视为空目标。
恢复入口不能依赖先执行会建表或迁移的普通 `connect()`；目标配置与预期 schema 由调用方预先提供。

内存目标只承诺当前实例内可用；实例结束后须从归档重新恢复。跨重启的持久化及未完成状态检查只适用于持久化目标，
内存目标以新实例重新恢复同一归档验证独立可用性。

“未连接”覆盖所有可能访问同一底层存储的实例、标签页、窗口和进程。必须先取得目标的独占使用权，再检查空状态，
并保持独占直到恢复完成或失败处理结束；期间其他连接及恢复请求必须被拒绝。无法保证独占的组合不得声明支持恢复。

### 校验与失败原子性

归档必需元数据与目标配置在写入目标数据库前完成兼容性检查。全量摘要、载荷格式及归档声明与实际数据库状态的一致性，
必须在恢复库对普通连接可见前验证完成；允许使用隔离的临时存储，不要求整份归档驻留内存。

恢复只有在数据库完整、验证通过并完成该后端承诺的持久化后，才可对普通连接可见。失败时不暴露半恢复库，
不修改已有数据库，也不删除其他操作或应用拥有的文件。可处理的错误应清理本次临时资源并允许重试；若清理失败，
须返回可判别的待清理状态并拒绝连接，后续可安全清理后重试。

恢复进程中断后，重新打开目标只能得到完整且已验证的恢复库，或可判别的未完成状态；未完成状态必须支持安全清理后重试，
不得通过自动初始化将半恢复内容掩盖为空库。中断可能发生在完成持久化但尚未返回成功结果时，重新打开的判定不得依赖原调用进程仍存活。

### 成功与取消

备份成功要求快照、元数据和完整性信息全部生成，并且输出端确认完成；只创建流或写出部分内容不算成功。
输出端确认的具体含义及持久化责任须在 API 文档中明确。恢复成功要求满足前述校验、持久化和可连接条件。
成功提交边界前的取消必须终止操作并执行失败处理；已完成操作不会因迟到的取消回退。错误不得返回成功结果，不完整输出不得被恢复入口接受。

备份失败或取消后，源数据库仍可正常读写，不遗留本操作持有的事务、锁或句柄；成功快照之后发生的源库写入不属于该归档。

### 加密与兼容性

加密库允许更换设备或物理存储位置，但必须保留原数据库认证域（当前为 `rxdb.config.dbName`）及实体身份。
认证域写入归档元数据，并在恢复前匹配；不匹配时拒绝。保留 `rxdb_db_keyring` 的 salt、kid、KDF 标识、verifier 等非秘密元数据。
备份和恢复不要求解锁，恢复库默认保持锁定；缺少或错误的密钥只导致解锁失败，不改变已恢复的密文。

支持矩阵必须逐项列出 adapter 标识、源 / 目标存储后端、运行环境、引擎版本 / 必需扩展、RxDB 版本以及 system schema / change-codec 版本。
相同引擎或相同 adapter 族不自动代表兼容；首版只承诺矩阵中同一 adapter 的组合。
归档记录格式版本、上述兼容性信息、schema 指纹、加密认证域（适用时）及完整性摘要。
schema 指纹的规范化规则与必需元数据在 plan 阶段冻结；未知版本、缺失依赖或未声明的组合必须拒绝。

## 技术笔记

阶段 A 的方案冻结前必须完成以下验证；不能仅凭原生 API 名称推定能力满足需求：

- **PGlite 内存与一致性**：当前 [PGlite 依赖声明](../../../packages/rxdb-adapter-pglite/package.json)为 `^0.5.8`。
  本地安装的 0.5.8 中，`dumpDataDir()` 返回完整 `File / Blob`；其 `tarUtils.createTarball()` 汇集目录文件后组装 tar，
  `loadTar()` 通过 `file.arrayBuffer()` 读取完整输入。可在安装包 `dist/*.js.map` 的 `sourcesContent` 中定位这些符号复验。
  必须验证满足公共契约的快照与恢复路径，不能把原生返回值包装为流后宣称有界内存。
- **资源预算**：按支持后端定义新增峰值内存、块大小、最大单字段 / 条目、临时空间需求及测试数据规模；测试计入解压、校验、WASM 与跨进程缓冲。
  后端不满足预算时不得声明支持；容量受限交付必须先调整本故事的阶段范围及 AC，不能在实现中静默缩减。
- **原子恢复**：比较目标独占、隔离验证、持久化和对外可见的实现方式，验证进程中断与清理重试。
  临时存储的授权、空间不足处理及清理责任属于方案的一部分，不预设所有后端都具备文件 rename 能力。
- **契约冻结**：明确归档容器、摘要覆盖范围、schema 指纹规则、兼容矩阵、取消与成功提交边界及稳定错误分类。
  备份可为一致性暂时阻塞写入，但须明确等待、超时及事务内调用的处理，避免死锁或无限等待；公开方法名与传输实现留给 plan 决定。

备份必须保留数据库内部状态，不能仅用 `findAll()` 导出实体后重建；否则会丢失 `rxdb_change` 等历史与同步语义。
加密元数据结构以 [`KeyringRow`](../../../packages/rxdb-adapter-encrypted/src/keyring-storage.ts) 为依据，归档不导出 keyring secret。
新增公开 API 时同步 TSDoc、API baseline、类型兼容测试与覆盖率；核心包覆盖率按 90% 门槛，其他包按 80% 门槛。
