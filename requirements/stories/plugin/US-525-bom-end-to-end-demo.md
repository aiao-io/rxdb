# 用户故事：BOM 端到端 demo：一份数据集走完全域

## 作为/我想要/以便

**作为** 要判断这套 BOM 模型「设计对不对」的评审者与第一批接入者
**我想要** 一台电动滑板车的完整数据集在一个能一键起起来的应用里跑完——多重边、虚拟件、替代组、
副产与废料、工序分摊、ECN 生效期、EBOM↔MBOM 重构、成本卷算，**同一份数据，不换样例**
**以便** 每个展开量旁边并排显示它的七步手算式，算错的时候当场看见差在第几步，
而不是拿到一个看起来正常、要到 MRP 下单才发现不对的数字

## 范围边界

### In Scope

- **分层种子**：同一台车按阶段分层装载，每层只**追加**该阶段 schema 已存在的实体（A：物料 / 修订 / 头 / 行与位号；

  加层不扰动旧结构），受影响的路径（如阶段 B 加入工序损耗后的投料）在新阶段给出新值
- **算式面板**：选中任一展开行，按 [US-511](US-511-bom-quantity-semantics.md) 七步公式
  逐步列出中间值与单位（`P` / `P'` / `G` / `G'` / `G''` / 换算 `D` / 穿透），每步标出取自哪个字段；各阶段可用步骤见上表
- **手工 golden 表**：`packages/rxdb-plugin-bom/src/testing/scooter-golden.ts`，每条路径发生项、每个阶段的单位、七步中间值、最终数量，
  以及材料 / 加工 / 制费 / 抵减与总额，**全部手写**，不调用被测 kernel 生成
- **评估日（as-of date）显式入参**：页面顶部输入，驱动 [US-508](US-508-bom-view-resolution.md)
  的生效期过滤；**不读系统时钟**
- **直连写入入口**：绕过应用层校验直接写库的按钮，用来证 [US-509](US-509-bom-dag-cycle-detection.md)

## 技术笔记

**一份数据集，不是十五份样例。** 这是本故事唯一不可让步的形态要求。
epic-009 的 18 条故事各有自己的 AC，但每条都是**单点断言**：替代组加权对、损耗乘序对、
可达性剪枝与生效期二次过滤对。BOM 的实际缺陷出在这些东西**同时发生**的地方——
一只带替代组的电阻，挂在有工序损耗的 SMT 工序上，父件是虚拟线束，整机又在 ECN 生效日前后各展开一次。
每条 AC 配一个干净的孤立样例，这类组合缺陷永远照不出来。
所以种子是一台完整的滑板车 `SC-100`：位号、替代、虚拟件、多输出、工序、序列追溯、双图重构
各自落在这台车的**不同真实部位**上，而不是十五个互不相干的迷你 BOM。

**每个数字并排一条手算式。** BOM 算错不会崩——它给出一个看起来完全正常的数字，
要到 MRP 多下了 400 颗螺钉才有人发现。算式面板把 [US-511](US-511-bom-quantity-semantics.md)
七步公式的每步中间值摊开，并标出每步取自哪个字段（`h.assembly_scrap` / `l.component_scrap` /
`op.scrap` / `r.default_phantom`）。这和 [US-214](../adapter/US-214-http-browser-demo.md)
的「协议流量面板」是同一招：把**本来不可见的中间态**摆到页面上，让错误在发生处显形而不是在下游。

**评估日必须是显式入参，这是 demo 逼出来的 API 约束。** AC#10 要求把机器时钟调开一天、
展开结果不变。做不到就说明展开实现内部读了 `Date.now()`——那样的实现对过去日期的解析会漂，e2e 也只能在一天之内绿。
这条约束最初是把各故事放进一个能跑的应用才暴露出来的，现已落成 [US-508](US-508-bom-view-resolution.md) 的
AC#7（`as_of_date` 必填）与 AC#8（改系统时钟结果不变），AC#10 是它在页面上的复现。

**AC#5 的两条路径必须得到同一个错误码。** US-509 AC#5 要证的是约束**在存储层成立**，直连写入入口证的是「绕过应用层也被拒」；
表单那一条证的是反面——应用层**没有**重复一份环校验。若表单走自己的校验器报自己的错，存储层的触发器在正常路径上
就成了从不触发的死代码，两份逻辑迟早分叉，而且没有任何用例会发现。所以两条路径必须报同一个存储层错误码；
vitest 另有一条反证：卸掉触发器后，表单写入成环边**成功**。US-509 AC#9 的 `union_only` 标记是插件对存储层错误的补充，
不是第二道校验。没有直连入口，AC#5 在 demo 里是演不出来的——这也是为什么它是 In Scope 的一项，而不是调试便利设施。

**与 [US-522](US-522-bom-tri-framework-ui.md) 的分工**：US-522 交付**可复用绑定**，
关闭条件是三端同 API、单端缺失即未完成；本故事交付**一个应用**，关闭条件是一份数据集
把上述断言当场演出来。两条的前置也不同——US-522 要等三框架绑定，本故事阶段 A 只等首轮切片。
demo 单端即可，先例是 US-214（`status: Done`，只有 Angular 前端）：
本仓铁律「三框架 API 必须对称」约束的是**包的导出面**，不是 demo app 的数量。

**种子落插件而非 app**：`packages/rxdb-plugin-bom/src/testing/scooter-dataset.ts`。
理由是 vitest 用例与 demo 共用同一份数据后，demo 就是那批单测的**可视化视图**——
单测断言的数字和页面上显示的数字来自同一组输入，两边对不上时先怀疑的是实现而不是样例。
放进 app 则两边各自演化，很快就不再是同一台滑板车。

**共享输入，不共享预期。** 若算式面板、预期数字与生产结果都由同一个 kernel 重算，同一个乘序或单位错误会三边一起绿。
所以 `scooter-golden.ts` 是手写的独立 oracle：数量单测、存储 conformance、三框架合同与 playwright 都只拿它**比较**，
没有一处从被测 kernel 生成 expected。缺成本报错（AC#15）证明不了卷算正确，AC#14 是正向成本 oracle。
16 条 UI 用例也不替代数据库与数学层的组合测试，它们在各自故事里另测。

## 价值待证

同 [epic-009](../../epics/epic-009-bom-domain-model.md#价值待证整个-epic)，但本故事在两点上与其余 18 条不同，
按 [CONVENTIONS 的病灶数 ≥ 抽象数](../../CONVENTIONS.md#价值待证) 必须写明：

- **它不新增抽象**。全部行为都归属到已有故事，判据分母为零——本故事永远不会因「抽象超过病灶」被拦。
- **它也不解锁 epic-009**。epic 的解锁条件是「客户 BOM 数据集，或一个**要上线的** BOM 应用」，
  demo 两者都不是。它是解锁**之后**的验收手段，不是提前启动的理由。
  把 demo 当成解锁依据就是循环论证：demo 需要插件存在，而插件正等着解锁。
