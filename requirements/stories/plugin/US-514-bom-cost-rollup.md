# 用户故事：成本卷算

## 作为/我想要/以便

**作为** 成本会计
**我想要** 按拓扑逆序一遍算出材料 + 加工 + 制费 − 副产抵减
**以便** 标准成本可复算、可逐层追溯

## 范围边界

### In Scope

- 自底向上按**拓扑逆序**单遍卷算
- 四项构成：材料（`consume` 行 × 子件单件成本）、加工（工序工时 × 费率）、制费、副产抵减
- **成本有量纲**：`batch_cost(n, L)` 是节点 n 生产 L 个基准单位的整批成本；`unit_cost(n) = batch_cost(n, L_n) / L_n`，
  `L_n` 是 n 的 BOM 头上的标准成本批量 `cost_lot_qty`（卷算必填，缺失即拒绝）；父件只乘子件的 `unit_cost`，
  不乘根级累计展开量
- **成本有单位**（见技术笔记「单位」）：`cost_lot_qty` 以头的 `base_uom` 计，`unit_cost` 是「币种 / 头 `base_uom`」；本层需求 `req(l, L)`
  以子件库存单位计，相乘前按 [US-511](US-511-bom-quantity-semantics.md) 第 7 步**同一个**换算（行级覆盖优先于物料级）转到子头 `base_uom`。
  外购叶子的价格带 `price_uom`，与库存单位不同时按物料级换算；缺换算即拒绝，不默认 1。价格、费率与明细行都带单位与币种
- 主产物就是头的父件；副产品的产出量、单位与缩放规则由 [US-513](US-513-bom-coproduct-byproduct.md) 定义，本故事只乘 `credit_price`
- **成本节点 = 已解析的头**：拓扑节点与缓存键是「已解析的 `bom_header`（隐含修订、类型、组织、备选）+ 影响计算的上下文
  （`as_of_date`、币种、费率日）」，不是裸 `item_id`
- 加工费按工序的三个工时量折算（都来自 [US-524](US-524-routing-master-model.md)）：`setup`（每批）与 `fixed`（固定）一批一次，
  `run`（每件）乘该工序的**加工量** `W_op`（装配损耗后、再过本工序起的工序损耗，见 US-511「装配损耗级联到工序」），不是无损耗的 L；
  三者在工序的 `time_uom` 下求和，再换算一次到费率的计费单位 `rate_uom`，然后乘费率。
  两个单位同为时间量纲才换算（同量纲按 US-511 单位制的标准系数），缺换算或量纲不兼容即拒绝，不默认 1
- 价格、费率、工时、`cost_lot_qty` 与结果按 [US-511 十进制值合同](US-511-bom-quantity-semantics.md#技术笔记)存取与导出；
  一次卷算的全部读取在同一个快照里完成（[US-508](US-508-bom-view-resolution.md)「确定性的前提」）
- 单一币种：一次卷算只接受上下文币种的费率与价格，币种不符即拒绝，不做汇率换算
- 逐层成本明细可展开审计；结果在 [US-508](US-508-bom-view-resolution.md) 的 manifest 上追加用到的费率、价格与 `cost_lot_qty`
- 环存在时报错而非死循环；遇 [US-510](US-510-bom-multilevel-explosion.md) 的 `truncated` 或 US-508 的 `unresolved` 结构即拒绝

### Out of Scope

- 费率与作业类型的主数据维护（→ [US-524](US-524-routing-master-model.md)）
- 实际成本与差异分析（属事务域）
- 副产品成本分配方法学的选择（只消费给定的 `credit_price`）
- 多币种与汇率

## 技术笔记

```
batch_cost(n, L) = Σ_{consume 发生项 l}  conv_l(req(l, L)) × unit_cost(child(l))            -- 材料
                 + Σ_{工序 op}           hours(op, L) × rate(op.activity, op.work_center, ctx) -- 加工
                 + overhead(n, L)                                                            -- 制费
                 − Σ_{by_product b}      out(b, L) × credit_price(b)                         -- 副产抵减

unit_cost(n)     = batch_cost(n, L_n) / L_n          L_n = n 的 cost_lot_qty，单位 n.base_uom；结果单位 = 币种 / n.base_uom
req(l, L)        = US-511 第 2～6 步、以 P = L 求出的**本层**需求（子件库存单位）；遇 phantom 则在本节点内继续穿透
conv_l(x)        = 子件在上下文里有头：按 US-511 第 7 步同一换算（行级覆盖优先）转到子头 base_uom；
                   外购叶子：按物料级换算转到其价格的 price_uom；缺换算即拒绝
hours(op, L)     = setup + run × W_op(L) + fixed，在 op.time_uom 下求和，再换算一次到费率的 rate_uom
                   setup（每批）、fixed（固定）一批一次，不随 L 与 W_op 缩放；run（每件）乘加工量
W_op(L)          = US-511「工序加工量」：P'(L) 依次过 op（含）至末工序的工序损耗
out(b, L)        = US-513 的副产量（随 P'(L) 缩放，定量者按批），按物料级换算转到 credit_price 的 price_uom
```

**单位。** `req(l, L)` 以子件库存单位计，`unit_cost` 按子头的 `cost_lot_qty` 折成「每头基准单位」，两者在
[US-511](US-511-bom-quantity-semantics.md) AC#9 那样「库存按件、头按盒」的物料上差一个包装倍数：1 盒 = 10 件、整批 20 / 盒，
父件要 2 件，直接相乘得 40，正确是 0.2 盒 × 20 = 4（AC#12）。所以相乘前把需求换到成本的基准单位，且用的是数量展开**同一个**换算——
行级覆盖在数量里生效、在成本里不生效，两边就对不上（AC#14）。AC#7 的数值全部单位相同，测不出这一类错，换算由 AC#12～#14 单独覆盖。

**加工量不是 L。** US-511 写明装配损耗级联到工序：要得到 L 件合格品，加成制 10% 时要加工 110 件，变动工时就是 110 小时（AC#15）；
按 `run × L` 算只得 100。工序自身的损耗按投料同一方向放大它之前（含自身）的工序加工量（AC#16）；`setup` 与 `fixed` 按批，不随加工量缩放（AC#18）。

**为什么父件乘 `unit_cost` 而不是乘展开量。** 材料项不能写成 `Σ qty_eff × cost(child)` 且 `qty_eff` 取 US-511 展开结果：
展开结果是**根级累计绝对需求**，`cost(child)` 又已经包含了子件以下的全部消耗。反例：A 用 2 B、B 用 3 C、C 单价 1，
正确材料成本 6；根级展开给出 C 总需求 6，若把它当 B 的局部用量，B 成本得 6、再乘 A→B 的 2 得 12，
**双计数**（Decimal 探针复现）。所以成本 kernel 只用**本层局部系数** `req(l, L)`，它与 US-511 共享第 2～6 步的同一份实现——
卷算不重新实现数量逻辑，否则两处会漂——但不吃全局展开结果。

**为什么要 `cost_lot_qty`。** 定量用量、固定损耗、`setup` 与固定工时都是「每批一次」的量，单件成本取决于按多大的批算。
不定基准批量，「单件成本」就不是一个数而是一个函数；把固定费用当线性系数摊到一件上，就默默选了「批量 = 1」。
所以每个头显式声明标准成本批量，子件的 `unit_cost` 在它自己的 `cost_lot_qty` 上求；根件可另按任意批量求 `batch_cost`（AC#9）。

**节点只算一次，但「节点」不是物料。** 同一物料的 D / E 修订、不同组织或备选，BOM 不同、成本也不同；
用 `item_id` 做缓存键会让先算的那个覆盖后算的（AC#8）。虚拟件不是成本节点：它的子件需求在父件节点内穿透计入，
于是行级 phantom 覆盖不会让同一个虚拟件在不同父件下共享一个错误的缓存值。

加工项的 `setup` / `run` / `fixed` / `rate` 与 `time_uom` / `rate_uom` 一个都不在 BOM 侧，它们来自
[US-524](US-524-routing-master-model.md) 的路线本体；
[US-520](US-520-bom-routing-operation.md) 只提供「哪一行归哪道工序」的挂接。
两条都是本故事的前置，缺任一条则加工项无从计算。费率按上下文的费率日取值（US-524 的费率生效区间），
与 `as_of_date` 一并进缓存键。

**拓扑逆序单遍是 DAG 约束存在的唯一实质理由**：没有环才能保证每个节点在其所有子件算完后恰好算一次。
AC#4 要求卷算自身也能检出环，而不是依赖 US-509 —— 写入期约束可能因迁移或直连被绕过，
计算期不做防御就会变成死循环而非报错。

AC#6 遵守本仓「无 fallback 兜底」铁律：缺成本以 0 计会产出一个看起来正常的错误数字，
这比报错难发现得多。但只验缺失报错证明不了卷算正确，AC#7 / #9 是正向数值 oracle。
