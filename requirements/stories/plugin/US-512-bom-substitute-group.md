# 用户故事：替代组与替代策略

## 作为/我想要/以便

**作为** BOM 工程师
**我想要** 替代关系作为「组」存在、策略挂在组上
**以便** MRP 能按概率分摊需求，且单向可替代不被误当成双向

## 范围边界

### In Scope

- `bom_substitute_group` 作为一等实体：`strategy`（priority / proportional / manual）、`allow_mix`；隶属某张 `bom_header`；
  带可空 `ecn_in_id`（ECN 在已发布头下新建组时填，首轮恒空，见 US-515 表 × 操作矩阵）
- 组成员是**同一头**下的行发生项（[US-507](US-507-bom-graph-skeleton.md)），成员侧：`role`（`primary` / `substitute`）、
  `substitute_priority`、`usage_probability`、`equiv_qty`
- **替代方向落在数据结构上**：每组恰好一个 `primary` 成员，它是原始需求对象；替代只从 `primary` 指向各 `substitute`。
  替代件之间、替代件对 `primary` 都不存在替代关系，不需要另建关系表
- **共同需求基准**：`equiv_qty` = 满足 1 单位 `primary` 需求所需的该成员数量（成员自己的单位）；分摊守恒按 `primary` 需求量计，
  不把不同物料的裸数量相加
- 展开时按策略分摊或择一；`manual` 的选择由 `ResolutionContext`（[US-508](US-508-bom-view-resolution.md)）传入
- 聚合约束（恰好一个 primary、priority 不并列、proportional 概率合计为 1）在头的**发布转移**及 ECN 的发布、已发布后的改期与取消上校验，
  ECN 侧校验的是该次转换后的**运行投影**（[US-515](US-515-bom-change-management.md) 技术笔记「转换后运行投影」）；单行的非法策略组合（AC#10）与成员跨头（AC#11）在保存时即拒，
  与 US-507 位号聚合同一机制
- **按生效域切片校验**（见技术笔记「切片」）：成员引用的发生项各有生效域，所有成员发生项的区间端点把时间轴切成若干原子切片；
  聚合约束对**每个**切片里生效的成员分别成立，不把跨期的旧成员与新成员一起相加。运行期只读评估日所在切片，不再按有效期重分配
- **成员随发生项走**：ECN 用新发生项替换某成员的发生项时，为新发生项在同一组里新建成员行；引用已截止发生项的旧成员**保留**，
  过去的切片仍可查询，不靠删旧成员补救。同一发生项至多属于一个组。组的 `strategy` / `allow_mix` 发布后不可改，要改由 ECN **整组重发**：
  截止全部成员的发生项、引入新发生项，新组的成员只引用这些新发生项（AC#14）
  （写入形态见 [US-515 表 × 操作矩阵](US-515-bom-change-management.md#已发布头的写入协议)）
- `usage_probability` 与 `equiv_qty` 按 [US-511 十进制值合同](US-511-bom-quantity-semantics.md#技术笔记)存取；`usage_probability` 要在存储层求和，
  域收窄为 `[0, 1]`、小数至多 9 位，合计按定点整数精确比较（AC#15）

### Out of Scope

- 临时代用（带审批与限量的例外流程）——属事务域，不进 BOM 主数据
- 替代件的采购/库存联动
- 任意有向替代图（A 可代 B、B 可代 C 的传递链）——需要时以真实样本另立，本故事只支持以 `primary` 为中心的星形

## 技术笔记

**替代料不能用「平行边 + 行属性」表达**，三条理由：

1. `strategy` 与 `allow_mix` 是**组的属性**，不是行的属性——放在行上就会出现同组各行策略不一致的非法态；
2. 单向可替代需要方向，边上放不下；
3. `usage_probability` 的合计约束（AC#5）需要一个能承载「组」这个整体的实体。

**方向为什么用 `primary` 而不是数值优先级。** 数值优先级能表达全序择优，表达不了任意有向关系与不可比项：
「A 可用 B 代、A 可用 C 代、B/C 互不可代」用单一优先级会额外推导出 B↔C。真实替代组的方向几乎总是
「设计指定的那颗」→「允许的替代」，所以把方向做成结构：组里恰好一个 `primary`，替代只从它出发（AC#3）。
`substitute_priority` 只在 priority 策略下决定择优顺序，不承担方向语义。

**策略组合的结果全部写死，不留给实现猜：**

| strategy     | `allow_mix = true`   | `allow_mix = false`         |
| ------------ | -------------------- | --------------------------- |
| priority     | 最高者不足时按序补足 | 只取当日有效的最高者        |
| proportional | 按概率分摊           | 非法组合，保存即拒（AC#10） |
| manual       | 按调用方给的分配     | 按调用方给的唯一选择        |

priority 下「不足」指调用方在 `ResolutionContext` 里给了可用量上限；不给则不存在不足，只取最高者。

**AC#5 拒绝而不归一化**，与 [US-520](US-520-bom-routing-operation.md) AC#4 的分摊比例同一裁决。
归一化看起来更友好，代价是它会把两种录入错误变成同一个静默结果：漏录一行（0.5/0.3 → 归一成 0.625/0.375）
与录错小数点（0.5/0.03 → 0.943/0.057）都会得到一个合法的比例，而分摊结果与录入者的意图相差甚远。
拒绝并回报实际合计值，则录入者一眼能看出漏了多少。

**切片：聚合校验作用于哪个集合。** 成员引用的是发生项，而发生项有生效域。primary 的 o1 在 11-01 截止、o2 同日接续，两者都是该组成员：
任一时点都只有一个 primary，但「全部已存成员」里有两个；若按整组校验，合法的跨期替换发布不了，删旧成员又会丢掉过去日期的替代关系（AC#12 / #13）。
所以校验单位是**切片**：取组内所有成员发生项生效域的端点（日期；[US-518](US-518-bom-unit-lot-effectivity.md) 落地后含序列 / 批次），
在每个原子切片里检查恰好一个 primary、priority 不并列、proportional 合计为 1 与策略组合。组内没有任何生效成员的切片不校验、
也不产生需求（整组被接替的前后，AC#14）——豁免只适用于组在别的时段有生效成员的情形，零成员或从无 primary 的组仍拒绝（AC#11）；有成员却缺 primary 的切片仍拒绝（AC#9）。

**切的是哪条时间线。** 存储里的区间是「假设全部草稿 ECN 已发布」的候选时间线（[US-515](US-515-bom-change-management.md)），
不能直接拿来切：两张草稿 ECN 同日分别把 0.5/0.5 改成 0.6 与 0.4，候选切片合计为 1，可只发布其一时运行结构是 1.1。
所以 ECN 侧的切片取自**本次转换后的运行投影**——目标 ECN 取转换后的状态与生效日，其余 ECN 保持真实状态，未发布的引入排除、
未发布的截止不生效——不借另一张草稿凑出合法合计（US-515 AC#23 / #24）。

**改期与取消同样要重新校验。** ECN 改期移动的是本行替换对的共同边界，同一逻辑行上的切片组成不变，但它与**组内其他行**的边界相对位置变了：
priority 组 A/B/C 为 1/2/3，E1 于 11-01 把 B 改为 4、E2 于 12-01 把 C 改为 2，两次发布都合法；取消 E1 或把它推到 12-15，
12-01 之后（或 12-01～12-15）就成了 1/2/2。两张 ECN 改的是不同逻辑行，「同一逻辑行后继」与 US-515 AC#12 都拦不住，
所以已发布 ECN 的改期与取消走与发布同一个运行投影聚合入口，失败整次回滚（US-515 AC#25）。阶梯、位号、工序分摊复用同一入口。

早先的写法是「发布校验原始录入集合，运行时某成员按有效期退出后剩余子集按比例重分配」。按切片校验之后，每个可运行切片在发布时已经合法，
运行期没有「退出后重分配」这回事：某成员到期而其余成员不改，留下的切片合计不为 1，发布即拒绝（AC#6 ①）——这正是 AC#5「拒绝而不归一化」
在时间维上的同一裁决。概率要跨期变更，就由 ECN 在同一日期替换相关发生项并给出新概率（AC#6 ②）。

**AC#5 的落点是发布转移，不是 CHECK。** 合计为 1 是跨行聚合，CHECK 只看单行，
[US-030](../core/US-030-declarative-storage-constraints.md) 也把跨表断言列为 Out of Scope；
若每插一个成员就校验，第一条 0.5 就必然失败，合法组永远建不出来。所以与 [US-507](US-507-bom-graph-skeleton.md) AC#5 一样，
在 `bom_header` 的 `draft → released` 转移上由插件触发器整组校验，发布后的成员不可直连改写。

`bom_substitute_group` 的唯一键是 `(bom_header_id, code)`——替代组隶属于某张 BOM，不跨 BOM 复用；
成员必须是同一头的发生项（AC#11），可复用已有组合外键能力，不自造规则 DSL。
跨 BOM 复用的互换关系属于物料主数据的互换组，是另一个概念，不在本故事。
