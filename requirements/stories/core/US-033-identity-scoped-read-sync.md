# 用户故事：按授权分区同步（只读）

## 作为/我想要/以便

**作为** 用 RxDB + Supabase 做本地优先应用的开发者
**我想要** 数据按授权边界分区（公开区、每个租户一个区），每个身份只能拉到自己能读的区，在能读的区里再按实体同步规则挑选要同步的行，换账号时本机数据互不可见
**以便** 没登录的访客能离线浏览选中的公开数据，登录用户离线拥有自己有权限的数据，同一个后端服务权限不同的用户

## 现状（`b8e0e6601`）

- **共享日志不分授权。** `rxdb_change` 对全部登录者可读（[US-225](../adapter/US-225-supabase-sync-protocol-access-baseline.md) 的适用边界），日志同步只适用于所有登录者可见范围一致的数据。
- **实体同步规则只是筛选，且条件变化时不可靠。** `SyncType.Filter` 的 `remote.filter` 是函数，每次拉取重新求值，`syncManager.pull()` 也接受调用方传入的 `filter`。但：
  - 拉取进度每个实体只有一个，不记录当时的条件：

    ```ts
    const syncId = `${namespace}:${entity}:${branchId}`;
    ```

    条件放宽后，进度之前、刚变得匹配的行永远拉不到。

  - 离开条件的行不会自动从本地删除，要手动调 [`syncManager.cleanupExpired()`](../../../packages/rxdb-plugin-sync/src/cleanup-expired.ts)，遇到不能取反的操作符会报错（`Cannot invert operator`）。
- **换账号不隔离。** 同一个本地库换了身份，上一个账号同步下来的行仍在本地。

## 范围边界

### In Scope

- **分区规则**：业务表的生成列 `rxdb_bucket`，表达式由应用写（例如 `CASE WHEN visibility = 'public' THEN 'public' ELSE 'tenant:' || tenant_id END`），服务端计算，客户端改不了。日志记下每条变更所在的区；一行换区时，旧区记一条不带行内容的「移除」，新区记完整写入。
- **读授权**：SQL 函数 `rxdb_caller_buckets()` 返回调用者能读的区。平台默认给 `public` 与 `user:<auth.uid()>`，应用按自己的成员表补上租户区。带分区的日志行只对能读该区的身份可见，anon 能读公开区。没有分区列的旧表维持 US-225 的行为。
- **按区拉取**：每个区一个进度。加入一个区时，先记下快照点，再按区从业务表拉快照（同样受 RLS 约束），之后从快照点增量拉；退出一个区时，本地整块删掉该区的行。
- **实体同步规则筛选**：在能读的区里按 `remote.filter()` 挑行。进度与条件指纹绑定：条件放宽时，对新匹配的范围补拉快照；条件收窄，或拉到的变更让某行离开条件时，自动删掉本地不再匹配的行，跳过未推送的行。
- **每个身份一个本地库**：第一次与远端交换数据时绑定身份（anon 或用户 id 的不可逆摘要），之后身份对不上就停止同步并报错，本地数据不动；同一用户刷新令牌不算变化。提供按身份算库名的工具。
- **测试**：公开行、两个租户、两个用户与 anon 的 SQL 回归和真栈契约测试。
- **文档**。

## 技术笔记

- **为什么是分区日志，而不是以身份直读业务表再对账**：直读对账（QueryCache）只覆盖查过的范围，加入、退出租户要对全部可见行做对账，大列表每次同步都要拉回全部元数据，Supabase 下也不能写远端。按区记日志后，加入与退出租户是整个区的下载与丢弃，换租户、公开改私有是两条增量，离线与写入都沿用日志同步已有的游标、幂等推送与串行化追加。
- **授权与筛选分开**：分区由服务端算、由 RLS 裁决能读哪些区；实体同步规则只在能读的区里挑行，客户端改规则扩大不了授权。
- **快照与增量的一致性**：先读快照点（已提交的最大日志 id；`rxdb_change_serialize_append` 让日志 id 顺序等于提交顺序，在途事务的 id 一定更大），再拉快照，再从快照点增量。快照可能已包含快照点之后的修改，增量按 id 顺序重放后最终收敛。
- **进度存在哪**：同步插件自己的表，键为区 × 实体 × 条件指纹，不新增核心导出（核心命名门禁）；身份绑定优先复用 `rxdb_migration` 水位行。
- **RLS 性能**：日志的策略写成 `bucket IN (SELECT public.rxdb_caller_buckets())`，函数 `STABLE`、语句内只算一次；日志补 `(bucket, id)` 索引。应用的成员判断放进 `SECURITY DEFINER` 函数，成员表建 `(user_id, tenant_id)` 索引，策略里用 `(SELECT auth.uid())`。
- **自动清理**：拉到的每条变更按规则判断修改后的行是否仍匹配；条件收窄时，正向算出本地仍匹配的集合、删除差集，不依赖给条件取反，避开不能取反的操作符。
- **行换区**：日志触发器比较 `OLD.rxdb_bucket` 与 `NEW.rxdb_bucket`，不同就写两条：旧区一条不带 `patch` / `beforeData` / `afterData` 的移除，新区一条完整写入。
