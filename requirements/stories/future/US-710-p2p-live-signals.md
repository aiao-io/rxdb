# 用户故事：实时信号

## 作为/我想要/以便

**作为** 在局域网里与同事协作编辑同一份数据的用户
**我想要** 看到谁在线、谁正在编辑哪一条，并在同事推送后马上知道有新变更
**以便** 避免两人同时修改同一条，并及时拉取。默认冲突策略按整条变更「后写的赢」，会静默覆盖其中一方的修改

## 解锁条件

价值待证（[epic-012](../../epics/epic-012-p2p-lan-collaboration.md#价值待证)）。出现以下任一信号即可提请解锁：

- 具名团队报告「同时编辑同一条，被静默覆盖」的实际案例；
- 协作场景需要不依赖服务端实时服务的在线状态。

## 范围边界

### In Scope

- **在线状态**：会话两端的设备与用户，以及当前所在视图（由应用自定义的轻量标识）。
- **编辑标记**：实体级的「正在编辑」标记，带过期时间；断线或过期后自动消失。
- **变更提示**：对端推送成功后，广播哪些实体有新变更。收到后按 epic-012 规则 R2 处理，不直接落库：
  - QueryCache 实体：调用 [`RxDB.invalidateRemoteEntity`](../../../packages/rxdb/src/RxDB.ts)。这是为任意推送通道设计的公开入口，见 [US-023](../core/US-023-querycache-remote-invalidation.md)。
  - 走变更日志的实体：调用 [`SyncManager.checkRepositoryUpdates`](../../../packages/rxdb-plugin-sync/src/SyncManager.ts)，向服务器核实可拉取的数量。
- **只在内存**：以上信号全部只在内存里，不写本地库，也不写同步实体。
- **三框架绑定**：Angular / React / Vue 提供对称的在线列表、在线状态、编辑标记接口（名称实现时定）。
- **浏览器多标签页**：
  - 同一设备只保持一条会话，由主标签页持有（复用 `@aiao/utils` 的 [`LeaderElection`](../../../packages/utils/src/@browser/leader-election.ts)）；
  - 其它标签页经 BroadcastChannel 收发信号。

### Out of Scope

- **字段级编辑预览**（显示对方还没推送的改动）：候选扩展，需要单独评估它与工作树的关系。
- **光标与文本协同编辑**：仓库的代码编辑器是单人编辑，没有 CRDT 依赖。
- **强制锁**：编辑标记只是提示，不阻止写入；强制锁需要排序者参与。

## 技术笔记

- **提示只用来核实**：伪造的提示最多让接收方多做一次向排序者的核实（AC#5），不会污染本地数据。这也是信号层可以对同一团队内所有已认证设备开放的原因。
- **与服务端实时服务的关系**：Supabase 适配器已有服务端实时通道。本故事的独有价值在三点：局域网延迟、服务器失联后已建立会话仍能继续，以及 HTTP 适配器这类没有在线状态服务的后端。**推断**：没有具名场景时，这三点不足以单独立项，见「解锁条件」。
- **标签页归属**：主标签页关闭时会话随之结束，新的主标签页重新建连。重连期间信号丢失可以接受，因为它们只是提示。
- **依赖**：US-708 会话层；三框架绑定包，见 epic-012「包划分」。
