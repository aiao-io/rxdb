# 任务看板领域模型

## 愿景

交付一款可静态托管的**单人任务看板**，作为 RxDB 的完整演示应用：从空库建板、建列、建任务，
到排序、详情编辑、撤销重做、重开与备份恢复，形成可操作的闭环。Angular / React / Vue 提供等价交互；
独立 Angular demo 用同一份确定性数据验收功能组合。

产品范围参照 Trello；卡片编辑、列头菜单与键盘操作参照 GitHub Projects，具体约束由
[US-531](../stories/domain/US-531-board-tri-framework-ui.md) 定义。团队同步另行，评论 / @ 提醒 / 附件不进首版。

## 为什么单列一个 Epic

Board / Column / Task 是应用领域模型。它消费现有实体、仓储、事务、排序、历史与搜索能力，
不为看板增加通用查询原语。现有底座与领域层要做的工作分开列明：

| 产品功能      | 已有底座                                                            | 本 Epic 的领域工作与边界                                                           |
| ------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 单卡 / 列拖拽 | US-028 分组排序域与 `Repository.reorder()`；US-031 共用落点判定先例 | 同板校验、坐标换算与失败反馈；单卡使用已有事务入口                                 |
| 批量改序      | US-008 事务执行器、公开排序键生成与校验函数                         | 在 executor 内读取完整列、校验目标排列并写排序键；不能在事务内嵌套门面 `reorder()` |
| 编辑与撤销    | US-302 事务级 durable undo、会话级 redo                             | 一次保存一个事务；取消零写；标签引用与字段一起撤销                                 |
| 备份恢复      | US-217 一致快照与同 adapter 空目标恢复                              | 首轮使用 PGlite 主线程 `idb://` 持久化连接；启动恢复入口、新空目标恢复成功后切换   |
| 任务搜索      | US-702 / US-703 全文引擎、搜索句柄与三端绑定                        | 板级搜索源收齐命中、关联列归属后过滤分页；现有 collection scope 不提供行级隔离     |
| 团队版底座    | US-218 / US-220 Supabase 推送完整性，US-308 本地冲突底座            | 身份、成员写权限、RLS 接线与冲突规则仍需设计，归价值待证的 US-533                  |

首轮按上述公开能力实施，不预设引擎增量已经完成。实现若发现必须改底座，先修订对应故事，
将 `packages/*` 改动提取为独立 PR，经评审先合入 main，领域分支再从 main 合回；遵守
[候选领域合并治理](../../AGENTS.md#候选领域合并治理)。

## 目标

- [ ] 板、列、任务与 board 级标签归属明确；跨板移动拒绝，列归属在应用服务入口创建后不可改。
- [ ] 单卡与列可拖拽，整列重排原子提交；失败恢复原顺序，撤销恢复整个业务事务。
- [ ] 三端均能从空库完成创建、编辑、删除确认与取消；支持键盘等价操作、只读上下文与明确状态反馈。
- [ ] PGlite 主线程持久化连接上走通导出、启动恢复、新空目标切换、失败保留原库与重开闭环。
- [ ] 搜索仅返回当前板任务，分页不漏项，切板与数据变更不会让迟到结果复活。
- [ ] 同一份种子数据贯穿 demo 与自动化验收；US-533 保持价值待证，不影响单人版关闭。

## 默认决策（第 0 步复核）

1. **单人零后端**：首轮无账号、无同步；demo 使用 PGlite 主线程 `idb://` 持久化连接，三端基础闭环
   用同一支持组合验收。其他连接形态按能力表拒绝或提示，不能用不支持代替首轮备份闭环。
2. **任务直接挂列**：task 无独立 `boardId`，board 由 column 推导；列归属由应用服务入口守住，
   直连 SQL 仅验证外键存在性。移动服务拒绝不存在的列和跨板移动；标签只引用任务所在板的定义。
   全部应用写入口共用宿主可写上下文门禁，实体 CRUD 声明只作为进一步限制。
3. **排序域 = 列**：task 以 columnId 分组，column 以 boardId 分组；单卡 / 列拖拽用门面 `reorder()`，
   批量重排只用一个 executor 的读写，不能嵌套门面事务；选中项按新顺序填回原槽位。
   详情一次保存也是一个业务事务；删除确认在事务外，确认后在事务内按 ID 复核删除集合。
4. **备份一等公民**：归档可下载带走；只恢复到同 adapter、未初始化、未连接且独占的新空目标。
   恢复成功后才切换当前库，失败保留原库；首次启动可在建表和 seed 前进入恢复流程。
5. **首版边界**：无评论 / @ 提醒 / 附件 / 工作流自动化；保留 Trello 式列实体，
   截止日仅为纯日期，不按列名推断任务已完成；多视图与结构化筛选不进首版。
6. **团队版独立**：US-527 只定义单人移动语义；身份、成员权限、离线并发合并规则的定义与实现
   全部随 US-533。US-027 只区分公开 / 系统写入口，不提供用户身份授权。

- 多视图工作台（表格 / 画册 / 日历 / 表单）；与工作台融合的方向留在
