# 任务看板领域模型

## 愿景

交付一款可静态托管的**单人任务看板**，作为 RxDB 的完整演示应用：从空库建板、建列、建任务，
到排序、详情编辑、撤销重做、重开与备份恢复，形成可操作的闭环。Angular / React / Vue 提供等价交互；
独立 Angular demo 用同一份确定性数据验收功能组合。

产品范围参照 Trello；卡片内联编辑、列头菜单与键盘操作的交互参照 GitHub Projects，具体约束由
[US-531](../stories/domain/US-531-board-tri-framework-ui.md) 定义。团队同步另行，评论 / @ 提醒 / 附件不进首版。

## 为什么单列一个 Epic

Board / Column / Task 是应用领域模型。它消费现有实体、仓储、事务、排序、历史与搜索能力，
不为看板增加通用查询原语。现有底座与领域层要做的工作分开列明：

| 产品功能      | 已有底座                                                                    | 本 Epic 的领域工作与边界                                                                                               |
| ------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 单卡 / 列拖拽 | US-028 分组排序域、`Repository.reorder()` 与邻居换算 `reorderTargetForDrop` | 同板校验、指针坐标到落点的换算（新建，三端共用一份）与失败反馈；US-028 只交付 core API，看板跨列拖拽 UI 由本 Epic 交付 |
| 本列排序      | US-008 事务执行器、公开排序键生成与校验函数                                 | 在一个 executor 内重读整列、按截止日或标题算出顺序并写排序键；不能在事务内嵌套门面 `reorder()`                         |
| 编辑与撤销    | US-302 事务级撤销（范围是本次会话）与会话级 redo                            | 一次保存一个事务；取消零写；标签引用与字段一起撤销；单页刷新或重开后此前的事务不再可撤销                               |
| 备份恢复      | US-217 一致快照、连接前恢复到同 adapter 空目标                              | 首轮使用 sqlite-wasm 主线程 `vfs: 'idb'` 持久化连接；恢复到新库名，整页重载后读回成功才切换                            |
| 任务搜索      | US-702 全文引擎（FTS5 含中日韩单双字索引）、搜索句柄与三端绑定              | 板级搜索源一次取全命中、与当前板任务求交后分页；现有 collection scope 不提供行级隔离                                   |
| 团队版底座    | US-218 / US-220 Supabase 推送完整性，US-308 本地冲突底座                    | 身份、成员写权限、RLS 接线与冲突规则仍需设计，归价值待证的 US-533                                                      |

首轮按上述公开能力实施，不预设引擎增量已经完成。实现若发现必须改已有包（`packages/rxdb*` 等）的底座，
先修订对应故事，将这部分改动提取为独立 PR，经评审先合入 main，领域分支再从 main 合回；新建的
`packages/rxdb-plugin-board*` 是领域功能本身，随领域分支评审。遵守
[候选领域合并治理](../../AGENTS.md#候选领域合并治理)。

## 目标

- [ ] 板、列、任务与 board 级标签归属明确；跨板移动拒绝，列的板归属在应用服务入口创建后不可改。
- [ ] 单卡与列可拖拽，本列排序原子提交；失败恢复原顺序，撤销恢复整个业务事务。
- [ ] 三端均能从空库完成创建、编辑、删除确认与取消；支持键盘等价操作与明确状态反馈。
- [ ] sqlite-wasm 主线程持久化连接上走通导出、启动恢复、切换到新库、失败保留原库与重开闭环。
- [ ] 搜索仅返回当前板任务，分页不漏项，切板与数据变更不会让迟到结果复活。
- [ ] 同一份种子数据贯穿 demo 与自动化验收；US-533 保持价值待证，不影响单人版关闭。

## 默认决策（第 0 步复核）

1. **单人零后端**：首轮无账号、无同步；demo 与三端宿主使用 sqlite-wasm 主线程 `vfs: 'idb'` 持久化连接
   （能力表 `VFS_CONFIGS` 声明 `idb` 可在主线程运行且支持多连接；US-217 阶段 B 支持主线程备份与连接前恢复；
   搜索走 FTS5 中日韩单双字索引）。OPFS 专用 Worker、IDB SharedWorker 等不在备份矩阵内的组合如实拒绝，
   不能用它们代替首轮备份闭环。多个标签页可同时打开，多页写入的正确性以第 0 步实测为准。
2. **任务直接挂列**：task 无独立 `boardId`，board 由 column 推导；列归属由应用服务入口守住，
   直连 SQL 仅验证外键存在性。移动服务拒绝不存在的列和跨板移动；标签只引用任务所在板的定义。
   全部应用写入口共用「恢复中暂停写入」门禁，实体 CRUD 声明（US-027）只作为进一步限制；
   只读宿主与身份授权归 US-533。
3. **排序域 = 列**：task 以 columnId 分组，column 以 boardId 分组；单卡 / 列拖拽用门面 `reorder()`，
   本列排序只用一个 executor 的读写，不能嵌套门面事务。本列排序是一次性动作，不是持久排序模式。
   详情一次保存也是一个业务事务；删除确认在事务外，确认后在事务内按 ID 复核删除集合。
4. **备份一等公民**：归档可下载带走；只恢复到同 adapter、未连接的新库名，恢复后整页重载、读回成功才切换，
   失败保留原库；首次启动可在建表和装载演示数据前进入恢复流程。归档只恢复到实体结构指纹一致的版本。
5. **首版边界**：无评论 / @ 提醒 / 附件 / 工作流自动化；保留 Trello 式列实体，
   截止日仅为纯日期，不按列名推断任务已完成；撤销只覆盖本次会话；多视图与结构化筛选不进首版。
6. **团队版独立**：US-527 只定义单人移动语义；身份、成员权限、离线并发合并规则的定义与实现
   全部随 US-533。US-027 只区分公开 / 系统写入口，不提供用户身份授权。
