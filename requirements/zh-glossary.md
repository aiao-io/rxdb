# 中文注释词汇约定（zh-glossary）

> 配套 `AGENTS.md` 「`packages` 下 JS/TS 文件中的注释使用中文」。
> 本文是**项目内 JS/TS 注释与 TSDoc**的词汇规约：哪些词该用、哪些词要换、哪些词保留。
> 新人第一次改 packages 中文注释前先看；reviewer 在看注释 diff 时按本文档对线。

**作用域**：默认只检查 `packages/**/*.{js,jsx,ts,tsx,mjs,mts,cjs,cts}` 中的注释和 TSDoc。
README、Rust、测试标题、API 标识符和用户可见文案不自动套用本规约；确需覆盖时在对应项目的文档中单独声明。

---

## 通用原则

1. **按语义选词，不做全局字面替换** — 同一个词在事务、并发、UI、文件系统上下文中可能需要不同译法。
2. **优先用领域标准译** — `live query` = 活查询；同步 `watermark` = 同步水位线；`host`、`claim` 需按上下文补充限定词。
3. **避免口语和文学化表达** — 只有在它会掩盖技术关系时才改；不要把清晰的领域惯用语机械替换成生硬的书面词。
4. **首次出现处给出最小定义** — 按模块或 API 符号计算首次出现，不按整仓库的行号计算。
5. **英文 ID 不决定中文译法** — `MIGRATION_CLAIM_RETRIES` 的注释应说明“通过唯一键 INSERT 竞争迁移执行权”，而不是只重复 `claim` 的字面翻译。

## 三档对照

### 🔴 必改

| 原文                           | 推荐写法                                 | 适用语境 / 理由                                                    |
| ------------------------------ | ---------------------------------------- | ------------------------------------------------------------------ |
| 占坑 / 抢不到 / 占坑冲突       | 认领执行权 / 认领失败 / 执行权竞争       | 迁移通过唯一键 `INSERT` 竞争执行权；避免把“抢占”误解为强制夺取资源 |
| 顶账                           | 把其他事务队列当作当前队列 / 代用        | 事务事件归属；不要改成语义不清的“凑数顶上”                         |
| 回呼                           | 回调                                     | callback 的统一译法                                                |
| 惊动订阅者                     | 通知订阅者 / 触发发射                    | RxJS 状态流；“唤醒”会暗示线程或调度器唤醒                          |
| 单趟                           | 单次 / 一轮                              | 迁移或批处理的轮次；按上下文选择                                   |
| 他 tab                         | 其他 tab                                 | 跨标签页通信                                                       |
| 钉住契约 / 钉死状态 / 钉在一起 | 约束或固定 / 卡死或锁死 / 绑定或保持一致 | 测试契约、并发状态、两个值的关联不是同一语义                       |
| 吃掉数据                       | 替换数据 / 抹掉数据                      | 只有确定是占位符替换或数据丢失时才使用对应词                       |
| 占着资源                       | 占用资源                                 | 文件句柄、连接、队列等资源；普通叙述可保留“占着”                   |
| 挂在 RxDB 上                   | 注册到 RxDB / 由 RxDB 持有               | 分别表达注册关系和生命周期归属                                     |
| 清了再连                       | 清理后重连                               | 仅在实际命中该短语时改                                             |

### 🟡 可改可不改

| 原文             | 候选                           | 备注                                                      |
| ---------------- | ------------------------------ | --------------------------------------------------------- |
| 撑爆             | 超出上限 / 超出 URL 限制       | 容量或请求长度上下文                                      |
| 撑满             | 用尽预算 / 达到上限            | 等待预算、并发槽位等上下文                                |
| 落地             | 保留 / 持久化 / 已生效         | 持久化和状态生效可保留；Promise 使用“已完成”或“已 settle” |
| 死对象           | 已释放对象 / 已失效对象        | 按实际是释放还是失效选择                                  |
| 死实例           | 已失效实例 / 已部分拆卸实例    | 不要一律改成“已失败实例”                                  |
| 死胡同           | 死循环 / 死锁 / 无法继续的路径 | 只有技术原因明确时才具体化                                |
| 拦 / 拦下 / 拦腰 | 拦截 / 阻止 / 截断             | 请求、状态守卫、解析器分别处理                            |
| 走完 / 走到      | 完成 / 到达该分支              | 保留控制流含义，不做全局替换                              |
| 入 / 进          | 入栈 / 入队 / 写入             | 有明确容器时补足宾语                                      |

### 🟢 保留（项目内已统一 / 领域共识）

| 词                 | 出处                 | 理由                                                           |
| ------------------ | -------------------- | -------------------------------------------------------------- |
| 纪元               | rxdb / utils         | 一次 `init() → #shutdown()` 的连接生命周期                     |
| 宿主               | 多个项目             | `host` 的上下文译法；需说明是 RxDB、应用、DOM 元素还是桌面进程 |
| 活查询             | rxdb / rxdb-test     | 项目内既有术语（live query）                                   |
| 同步水位线         | rxdb / supabase      | 每个实体的 `sinceId` 游标                                      |
| 迁移执行标记       | rxdb                 | `rxdb_migration.name` 中已执行的迁移集合                       |
| 系统版本标记       | rxdb                 | schema / change codec 的固定版本标记                           |
| 就绪门             | sqlite-core          | `ready()` 的项目内标准术语                                     |
| 半成品             | 多个项目             | 准确、简洁                                                     |
| 半拆 / 半装        | rxdb                 | 准确、简洁                                                     |
| 放行               | 多个项目             | 含义清晰                                                       |
| 退回去             | rxdb                 | 逆序拆卸的"退"字很贴                                           |
| 裸                 | electron             | 准确（raw BEGIN）                                              |
| 桩                 | client-generator     | 标准（stub）                                                   |
| 钩子               | 多个项目             | 标准（hook）                                                   |
| 管道 / 管子        | electron / encrypted | 准确（pipe）                                                   |
| 切片               | sqlite-script        | 标准（slice）                                                  |
| 拦截 / 阻止 / 截断 | 多项目               | 按对象语义选择，不设全局禁词                                   |
| 落 / 落到          | 多项目               | 表示控制流或结果落入目标分支时可保留                           |
| 走 / 跑到          | 多项目               | 表示控制流时可保留                                             |
| 报成 / 报到        | rxdb                 | "报成断开" 准确                                                |
| 闸                 | sqlite-core          | 准确（gate）                                                   |
| 桥                 | electron             | 准确（bridge）                                                 |

## 按项目分组的示例

以下只记录已核对的注释语境，不是完整词频清单。新增或删除词时先更新上面的语义表，再补充这里的示例。

### `packages/rxdb`（核心）

- 迁移竞争：**占坑**、**抢不到**、**占坑冲突**；统一改为“认领执行权 / 认领失败 / 执行权竞争”。
- 事务与事件：**顶账**改为说明队列归属；**回呼**改“回调”；**惊动订阅者**改“通知订阅者”；**单趟**按“一次 / 一轮”选择；**他 tab**改“其他 tab”。
- 纪元、活查询、同步水位线、半成品、半拆、放行保留，但首次出现要有最小定义。

### `packages/utils`

- 词：连接纪元、`connection-epoch`、scope 过期
- 🟢 全部保留；`lifecycle-scope.interface.ts` 的「重新取得当前纪元的作用域」已是项目内标准译

### `packages/rxdb-adapter-sqlite-core`

- 词：就绪门（`ready()` gate）、放行、半成品、撑满、撑爆、裸
- 🟢 就绪门、放行、半成品、裸 保留
- 🟡 撑满 / 撑爆 按语境改为“用尽预算 / 超出上限”。

### `packages/rxdb-adapter-electron`

- 词：半成品桥接、管子、桥、宿主、**钉住**
- 🔴 “钉住”按语境改为“约束 / 固定 / 卡死”，不要全局替换成“锁死”。
- 🟢 半成品、管子、桥、宿主 保留

### `packages/rxdb-adapter-supabase`

- 词：同步水位线（`sinceId`）、**撑爆**、活查询
- 🟢 同步水位线、活查询保留
- 🟡 “撑爆”按语境改为“超出上限 / 超出 URL 限制”。

### `packages/rxdb-adapter-tauri`

- 词：Rust 宿主、传输层、`node:sqlite` 宿主
- 🟢 全部保留（标准术语）

### `packages/rxdb-adapter-pglite`

- 词：宿主、拦腰截断、影子表
- 🟢 宿主、影子表保留；“拦腰截断”只在确实表达解析或字符串截断时保留。

### `packages/rxdb-angular` / `react` / `vue`

- 词：宿主（统一）、挂入管道、占位值、`shallowRef`、`markRaw`、销毁钩子
- 🟢 全部保留（标准前端术语）

### `packages/rxdb-plugin-search`

- 词：**钉在一起**、短路、漂移检测放行
- 🔴 “钉在一起”改“绑定”或“保持一致”，按两值关系选择。
- 🟢 短路、放行 保留

### `packages/rxdb-plugin-storage`

- 词：宿主、三处宿主改动
- 🟢 全部保留

### `packages/rxdb-plugin-workspace`

- 词：其他 tab、**占着**旧版本
- 🔴 “占着旧版本连接”改“占用旧版本连接”；不泛化到非资源语境中的“占着”。
- 🟢 跨 tab、阻塞保留

### `packages/rxdb-plugin-graph`

- 词：已拆掉的纪元、**挂在 rxdb 上**
- 🔴 “挂在 RxDB 上”按语境改“注册到 RxDB”或“由 RxDB 持有”。
- 🟢 纪元 保留

### `packages/rxdb-client-generator`

- 词：桩（stub）、半成品、死循环、孤儿节点
- 🟢 全部保留

### `packages/rxdb-devtools`

- 词：**吃掉了**要调试的数据
- 🔴 “吃掉了”改“替换了”或“抹掉了”，按实际行为选择。
- 🟢 缓冲区、附着、快照 保留

### `packages/rxdb-test`

- 词：活查询、清理后重连
- 🟢 活查询保留；只有重新发现“清了再连”时才改为“清理后重连”。

### `packages/code-editor*`

- 词：宿主、`Compartment`、facet
- 🟢 全部保留（CodeMirror 既有术语）

## 首次出现处的解释清单

| 术语         | 锚点                                                           | 最小解释                                                              |
| ------------ | -------------------------------------------------------------- | --------------------------------------------------------------------- |
| 纪元         | `RxDB.#connection_scope`                                       | 一次 `init() → #shutdown()` 的完整连接生命周期；作用域不跨纪元复用    |
| 宿主         | `IRxDBPlugin.install(scope)` 或具体 `host` 类型                | 说明宿主是谁：RxDB 实例、应用、DOM 元素或桌面进程，不使用全局单一定义 |
| 认领执行权   | `RxDB.#runMigrations` / `MIGRATION_CLAIM_RETRIES`              | 通过唯一键 `INSERT` 竞争迁移执行权；冲突时整批回滚并重试              |
| 同步水位线   | `IRxDBAdapter.pullChangesBatch` 的 `sinceId`                   | 某个实体已处理到的远程 change ID，不包含该 ID 本身                    |
| 迁移执行标记 | `rxdb_migration.name`                                          | 已成功执行的迁移名称集合，不等同于同步水位线                          |
| 系统版本标记 | `RXDB_SYSTEM_SCHEMA_WATERMARK` / `RXDB_CHANGE_CODEC_WATERMARK` | 固定的系统 schema 或 change codec 版本，不等同于远程游标              |
| 就绪门       | `RxDBAdapterSqliteBase.ready()`                                | `connect()` 完成、表结构就绪后才放行的等待门                          |

“首次出现”按模块或 API 符号计算。不要在规范中写易失效的行号；代码移动后只需确认锚点仍存在。

## 词频与清单维护

词频不是术语规范的一部分，不能用一次扫描结果决定评级。需要统计时使用上面的命令，记录扫描范围和日期；不要把静态数量提交进本文档。

项目分组也不是完整库存。删除或改动注释时，以当前扫描结果和语义表为准，再更新项目示例。

## 维护规则

- 改一份注释前先按作用域运行检索命令，确认该词的上下文没有冲突含义。
- 新增非标准术语、容易误解的口语或跨模块词义时，登记“语境、推荐写法、反例”；普通 API 名和已有领域标准词不要求逐个登记。
- 首次出现的解释跟随模块或 API 锚点维护，不绑定行号；术语表只记录稳定概念。
- 旧注释改动时顺手按本文档对线，单点改动即可，不必一次扫全仓；只有跨模块词义变更才做全量扫描。
- reviewer 检查三件事：作用域是否正确、替换是否保持语义、首次出现是否给出最小定义。
