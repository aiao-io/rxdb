## 已知的需求覆盖缺口

- `@aiao/rxdb-adapter-miniprogram` 的**微信路径**由 [US-209](stories/adapter/US-209-miniprogram-adapter.md) 覆盖（`Done`）：本包已在 [coverage-baseline.json](../scripts/audit/coverage-baseline.json) 中留下趋势基准（**注意：覆盖率硬门槛一直生效**，`coverage-check.mjs` 按包类型卡 80%/90%，与是否在 baseline 中无关；baseline 只用于「比上次低」的软警告）、[compatibility.md](../website/docs/compatibility.md) 补了能力边界专节、根 README 不再声称支持 Alipay、[examples/README.md](../examples/README.md) 声明示例不在 CI 覆盖范围。
- **非微信小程序平台仍无实现**（支付宝 / 抖音 / 百度 / QQ）。Taro 示例保留了多端 `build:*`，适配器构造函数却只认 `wx` + `WXWebAssembly`。缺口由 [US-211](stories/adapter/US-211-multi-miniprogram-platforms.md) 认领（Backlog，三阶段：先抽宿主契约再按可行性门禁放行）；阶段没关之前文档仍写「仅微信」。
- ~~**`exports` 子路径入口的导出表面不受 API baseline 保护**~~ **已于 2026-08-24 补齐**（本条同日改写）。[US-601](stories/tooling/US-601-subpath-api-surface-baseline.md) 交付后，[api-surface.mjs](../scripts/audit/api-surface.mjs) 扫的是**每个公开入口**：30 个公开包共 44 个入口（30 个主入口 + 14 个子路径），基线格式扩为 `{ entries: { ".": [...], "./sub": [...] } }`，子路径的符号增删与入口整体消失都按与主入口相同的分级拦 CI。入口 → 源文件的真相源收敛到 `package.json` › `exports` › `@aiao/source` 一处，缺声明或路径写错在 `--check` / `--update` 两种模式下都硬失败。**剩下的只有 2 个资产入口**（`rxdb-adapter-miniprogram/assets/wa-sqlite.{cjs,wasm}`）：二进制 / CJS 文件没有导出表面可扫，登记在 `ASSET_SUBPATHS` 白名单里显式跳过，内容由 [wa-sqlite-integrity.mjs](../scripts/audit/wa-sqlite-integrity.mjs) 的 SHA-256 守护——**这不是缺口，是另一套守护**。`rxdb-test` 的 5 个子路径仍不计（整包非产品 API）。
- **小程序运行时的搜索能力仍无故事覆盖**。`@aiao/rxdb-plugin-search` 只白名单 `sqlite-wasm`，小程序侧能否加载 FTS5 扩展不在 US-209 范围内，见上方跨框架矩阵脚注。
- ~~**QueryCache 生产路径未接线**~~ **已于 2026-08-22 接线**（本条 2026-08-23 回填）。[US-020](stories/core/US-020-querycache-repository.md) 两阶段全关（`status: Done`）：`getRepository` 在 `sync.type === QueryCache` 时真的走 `QueryCacheRepository`，写路径 remote-then-local，缓存质量（orphan 删除、指纹含模式、SWR SQL、错误分类）一并交付。此前的病症「配置了是空操作，find 打本地、写入污染 local changelog」已不存在。supabase 的 ducks 见 [US-203 AC#6](stories/adapter/US-203-supabase-adapter.md) ✅ / [US-006 AC#6](stories/core/US-006-reactive-queries.md) ✅。**HTTP 远程适配器（[US-212](stories/adapter/US-212-http-adapter.md)）原本挂在本条上的两档发布门禁随之全部解除**（[roadmap 约束 10](roadmap.md#排期约束)），该包现在零前置、关闭阶段 A 即可发 `stable`。**阶段 A 已于 2026-08-23 关闭**，具名适配器计数随之由 9 改为 10（US-212 AC#21 已回填）。**接线当时暴露的两条新缺口（RV-001 / RV-002）已于同日修复**，见下两条。
- ~~**`offlineFallback` 在 supabase 上不可用**~~ **已于 2026-08-23 修复**（RV-001 `Fixed` 后删档，本条 2026-08-24 回填）。病症是 supabase 把包括传输失败在内的所有错误一律包成 `SupabaseDataError`（无数字 `status`、非 `TypeError`），[`isNetworkError`](../packages/rxdb/src/repository/network-error.ts) 五条判据一条不中 → 恒判非网络错误 → 断网时抛异常而不是返回缓存。现在由 [postgrest-error.ts](../packages/rxdb-adapter-supabase/src/postgrest-error.ts) 的 `classify_postgrest_error` 分类：postgrest-js 的 `status === 0`（fetch 根本没成功）→ core 的 `NetworkOfflineError`，其余一切非 0 状态码都是远端给的**回答** → `SupabaseDataError`。**判据是 `status` 而不是嗅探 message**，放宽 core 的 fetch 失败正则会把 message 里带 `load failed` 的 RLS 错误误判成离线。读路径、写路径（`executeRetryableWrite` 重试耗尽后才分类）与断网命中缓存的端到端用例都在 [querycache-error-contract.spec.ts](../packages/rxdb-adapter-supabase/src/__tests__/querycache-error-contract.spec.ts) / [transient-write-retry.spec.ts](../packages/rxdb-adapter-supabase/src/__tests__/transient-write-retry.spec.ts)。**这是已发布包的用户面变更**，迁移说明见 [supabase 传输失败错误类型迁移](../website/docs/migration/supabase-network-errors.md)。HTTP 包从一开始就按 [US-212 AC#12/#13](stories/adapter/US-212-http-adapter.md) 满足同一口径。
- ~~**`fetchMetadata` 的「单次发射 + `complete`」契约没写下**~~ **已于 2026-08-23 写下**（RV-002 `Fixed` 后删档，本条 2026-08-24 回填）。`QueryCacheRepository` 用 `forkJoin` 并联远端 metadata 与本地行，于是适配器必须把所有分页拼成一次发射再 complete：多次发射 = 只留最后一页 = 大规模假孤儿；不 complete = 查询永久挂起。抽象声明 `Observable<QueryCacheEntityMetadata[]>` 对两者沉默，supabase 满足它只因 `from(promise)` 的结构巧合。契约现写在面向适配器作者的 [`RxDBAdapterRemoteBase.fetchMetadata`](../packages/rxdb/src/rxdb-adapter.ts) TSDoc 里（与上一条的错误分类并列为两条**承重**契约），[US-212 AC#23](stories/adapter/US-212-http-adapter.md) 为 HTTP 包冻结同一条。
