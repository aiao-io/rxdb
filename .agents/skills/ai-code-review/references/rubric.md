# 评审标准

本文件的摘要会进覆盖单元键：这里任何改动（包括错别字）都会让已有覆盖全部失效、需要重审。改判定标准时才改它。

## 报什么

只报有触发路径的缺陷：写得出「什么输入或时序下、哪段代码、产生什么错误结果」。

- 行为错误：结果错、数据丢失或损坏、状态不一致、错误被吞掉、资源泄漏。
- 兼容性：用户可见行为或公开 API 变了，却没按 [versioning-policy](../../../../requirements/versioning-policy.md) 声明。
- 异步与并发：竞态、重入、取消或卸载后迟到的结果、订阅未释放、事务边界。
- 安全：注入、越权、凭据或个人数据泄露、路径穿越。
- 仓库铁律（根 AGENTS.md、CLAUDE.md）：
  - Angular / React / Vue 同功能同 API，单端缺失算缺陷；
  - 不加 fallback 兜底掩盖问题；
  - 新行为有测试，新导出有 TSDoc；
  - 嵌套不超过 3 层。
- 测试缺口：已声明的行为没有测试，或测试断言不到它声称验证的东西。

## 不报什么

- lint、typecheck、prettier 能抓到的问题。
- 纯风格偏好，或说不出后果的「可以更好」。
- 找不到触发路径的推测：在终端列为待核实线索，不建记录。
- 根因在本次范围以外的问题：在终端说明线索，不冒称审过那个项目。

## 严重程度

| 级别 | 含义                                                   | 例子                                           |
| ---- | ------------------------------------------------------ | ---------------------------------------------- |
| P0   | 数据丢失或损坏、安全漏洞、主流程不可用；阻断合并与发布 | 迁移在常见库上删掉用户数据；未授权可写他人记录 |
| P1   | 常见条件下行为错误，或违反仓库铁律；合并前修           | 三框架缺一端；离线重放丢写入；并发写互相覆盖   |
| P2   | 边界条件或少见路径出错、吞错、测试缺口；排期修         | 空结果分页越界；catch 之后静默返回默认值       |
| P3   | 有具体后果的可维护性问题；顺手修                       | 误导性命名让调用方传错参数；重复实现已出现分歧 |

拿不准时取较低一级，并在「问题与影响」里写明为什么不是更高一级。

## 证据写法

- 每条问题写清触发条件、影响和可定位证据：路径与行号、符号、短代码片段、调用链、复现方式。
- 源码位置写成行内代码（如 `packages/x/src/a.ts:120`）并注明快照 SHA，或用带提交 SHA 的 GitHub 永久链接。
  不写指向源码的相对 Markdown 链接：记录永久保留，`pnpm audit:requirements` 会校验相对链接与行号，代码一改 CI 就红。
- frontmatter 的 `anchors` 写 `path#symbol`（没有符号只写路径）。新建记录前先在同项目目录 grep `anchors` 查重。
