The kind of a commit node

## Remarks

The two kinds other than `normal` are **system root nodes**: `baseline` is generated by the one-time enable migration
for every locally fully-materializable branch (FR-021/049); `branch_baseline` is generated by `createBranch(branchId, fromChangeId)`
and by the first materialization of metadata-only remote branches (FR-017/044). The two are the **only exceptions**
to FR-008/009 — only they may have no user author, no user message, and an empty ChangeSet.

The kind must be its own column and cannot be inferred from "`author` is empty": that would collapse the two root node
kinds into one, while FR-044's materialization barrier requires recognizing `branch_baseline` separately; worse,
it would make an ordinary commit whose author happened not to be recorded indistinguishable from a system root node,
and the empty-ChangeSet gate would then fail for the former too.
