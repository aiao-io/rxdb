The kind of a commit node

## Remarks

The two kinds beyond `normal` are **system root nodes**: `baseline` is generated by the one-time enable migration for every local fully-materializable branch
(FR-021/049), `branch_baseline` by `createBranch(branchId, fromChangeId)` and the first materialization of a metadata-only
remote branch (FR-017/044). The two are the **only exceptions** to FR-008/009 — only they may have
no user author, no user message, and an empty ChangeSet.

The kind must be a dedicated column, not inferred from "`author` is empty": that would collapse the two root nodes into one kind,
while FR-044's materialization barrier requires recognizing `branch_baseline` alone; worse, it would make "an ordinary commit whose author happened not to be recorded"
indistinguishable from a system root node, and the empty-ChangeSet gate would fail on the former too.
