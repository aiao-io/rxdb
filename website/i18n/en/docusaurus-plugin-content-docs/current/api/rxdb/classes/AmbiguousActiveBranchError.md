# AmbiguousActiveBranchError

Defined in: [packages/rxdb/src/system/active-branch-guard.ts:160](https://github.com/aiao-io/rxdb/blob/b5232040240cf1ccfbab0ebf9ba882a4af8268a0/packages/rxdb/src/system/active-branch-guard.ts#L160)

More than one row in `RxDBBranch.activated` is true.

## Remarks

The first-enable migration rolls the **whole migration back** when hit (FR-048). The guard itself does **not** "pick one to keep":
with two active rows, "who is the current branch" has no answer, and the wrongly guessed half would be written into the
commit graph as another branch's history while the user sees nothing wrong.

It only carries the branch ids — the diagnosis must answer "which two conflict", not what is inside them.

Stable error code, always `'ambiguous_active_branch'`

#### Remarks

A literal rather than `CommitErrorCode.ambiguous_active_branch`: that code table ships with the commit capability into
`@aiao/rxdb-plugin-working-tree`, while this guard is a branch topology invariant that stays in the core. The core depending
on a plugin for a single string would make "not installing the plugin" impossible again.

The two sides cannot drift: the code table is a const object, not an `enum` (see the rationale stated by the plugin-side
`commit-error-codes.ts`), so the members' static types are ordinary string literals, making this literal value-compatible with `CommitErrorCode`;
and the code table side has a test pinning the key-value pairs to be byte-for-byte identical.

Defined in: node\_modules/.pnpm/@types+node@26.6.6/node\_modules/@types/node/globals.d.ts:67

The `Error.stackTraceLimit` property specifies the number of stack frames
collected by a stack trace (whether generated by `new Error().stack` or
`Error.captureStackTrace(obj)`).

The default value is `10` but may be set to any valid JavaScript number. Changes
will affect any stack trace captured _after_ the value has been changed.

If set to a non-number value, or set to a negative number, stack traces will
not capture any frames.

### captureStackTrace() \{#capturestacktrace\}

```ts
static captureStackTrace(targetObject, constructorOpt?): void;
```

Defined in: node\_modules/.pnpm/@types+node@26.6.6/node\_modules/@types/node/globals.d.ts:51

Creates a `.stack` property on `targetObject`, which when accessed returns
a string representing the location in the code at which
`Error.captureStackTrace()` was called.

```js
const myObject = {};
Error.captureStackTrace(myObject);
myObject.stack; // Similar to `new Error().stack`
```

The first line of the trace will be prefixed with
`${myObject.name}: ${myObject.message}`.

The optional `constructorOpt` argument accepts a function. If given, all frames
above `constructorOpt`, including `constructorOpt`, will be omitted from the
generated stack trace.

The `constructorOpt` argument is useful for hiding implementation
details of error generation from the user. For instance:

```js
function a() {
  b();
}

function b() {
  c();
}

function c() {
  // Create an error without stack trace to avoid calculating the stack trace twice.
  const { stackTraceLimit } = Error;
  Error.stackTraceLimit = 0;
  const error = new Error();
  Error.stackTraceLimit = stackTraceLimit;

  // Capture the stack trace above function b
  Error.captureStackTrace(error, b); // Neither function c, nor b is included in the stack trace
  throw error;
}

a();
```
