# rxdb-model-angular

## Headless bindings

When there is no default presentation layer, inject the shared controllers from `@aiao/rxdb-model-angular/headless`:

```ts
import { injectEntityForm } from '@aiao/rxdb-model-angular/headless';

const { controller, snapshot } = injectEntityForm(() => ({ fields: fields(), data: data(), mode: 'edit' }));
controller.setField('title', value);
```

`snapshot()` is a read-only Angular signal; options may be a plain object, a signal, or a getter. Pass a signal/getter when the value needs to follow the host signal, and updates to inputs and field/mode changes with identical content will not overwrite an unsubmitted draft; subscriptions are cleaned up automatically when the `DestroyRef` is destroyed. Using only the headless entry points does not require VTable or Tailwind.

The Angular component set for RxDB Model: entity-metadata-driven list, detail, form, dialog, editable table, and visual query builder. All domain logic comes from the framework-agnostic core package [`@aiao/rxdb-model`](https://github.com/aiao-io/rxdb/tree/main/packages/rxdb-model); this package only carries the Angular component shells and the CDK/browser integrations.

## Headless state and async actions

`injectEntityForm`, `injectQueryBuilder`, `injectEntityList`, `injectEntityDetail`, `injectEntityDialog`, and `injectQueryTable` return `{ controller, snapshot }`. Switching the list query, ordering, or page clears the old page, then `refresh()` calls the data source; stale requests never write back. Batch deletion may partially succeed, with successful items converging first and failure reasons returned via `AggregateError.errors`. Detail saving rejects duplicate calls, and late results from input switches, cancellation, or closing never overwrite a new session.

The default QueryBuilder, list, and detail do not yet fully reuse the new controllers; headless history/manual ordering and complete standalone UI examples for all three frameworks are still pending. See Headless entity capabilities for the full state contract, interaction responsibilities, and progressive migration.

### `EntityDetailComponent` edit behavior

- Edit mode loads the instance from the Repository by `entityId`. While the edit target is not ready (loading or load failed), the internal form actions are hidden, only "Cancel" remains below the tabs, and submission is blocked; once ready, the form resets to the loaded instance, and input made while it was not ready is discarded.
- `fixedFormData` values only merge into create drafts and pass-through forms without an instance; in edit mode with a loaded instance, the corresponding fields are only marked read-only and show the instance's own values.

The above matches the React side. On these two points the Vue side is a framework difference: input is allowed while the edit target is loading, and once ready it merges into the form and is persisted on the next submission; in edit mode `fixedFormData` is layered on top of the instance data for display (the corresponding fields are likewise read-only, and saving does not rewrite the original values on the instance).

## Styling conventions (important)

Component templates use **Tailwind CSS v4 + daisyUI v5** class names; this package **does not ship compiled CSS** (no reset, no theme, no bundled daisyUI). It only registers its own templates as Tailwind scan sources, and the consuming app's style pipeline generates the utility classes, keeping the app theme authoritative.

Consumer integration (requires your own Tailwind pipeline):

```css
@import 'tailwindcss';
@plugin 'daisyui';
@import '@aiao/rxdb-model-angular/tailwind.css';
```

Projects without a Tailwind pipeline render the components unstyled — this is documented behavior.

## Usage

```ts
import { EntityListComponent } from '@aiao/rxdb-model-angular';

@Component({
  imports: [EntityListComponent],
  template: `<rxdb-entity-list name="Todo" namespace="public" />`
})
export class TodoPage {}
```

Undo/redo requires `@aiao/rxdb-plugin-history`: once the host installs that plugin, `EntityListComponent` automatically gains undo/redo capability (without the plugin the buttons stay disabled and no error is raised).
