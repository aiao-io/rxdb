# Framework usage

The three binding packages only render: the app creates the shell with `createAdminShell` from `@aiao/rxdb-admin`, and the DOM structure, CSS class names, `aria-*` and `data-testid` attributes are identical across the three frameworks, sharing the same `admin.css` — so one end-to-end suite runs against all three. The only differences are the framework idioms.

## Wiring up styles

Shell styles are generated by the app's Tailwind + daisyUI pipeline; the packages ship no compiled styles. Import the binding package's `tailwind.css` (so Tailwind scans the classes used inside the components) and the core package's `admin.css` in your style entry:

```css
@import 'tailwindcss';
@import '@aiao/rxdb-admin-react/tailwind.css'; /* or -vue / -angular */
@import '@aiao/rxdb-admin/admin.css';

@plugin 'daisyui' {
  themes:
    light --default,
    dark --prefersdark,
    dracula;
}
```

The themes passed to `createAdminShell({ themes })` must match the daisyUI themes enabled here.

## React

```tsx
import { createAdminShell } from '@aiao/rxdb-admin';
import { AdminLayout, AdminShellProvider } from '@aiao/rxdb-admin-react';
import { Database } from 'lucide-react';
import type { ReactNode } from 'react';
import { Outlet, useLocation, useNavigation } from 'react-router-dom';

const shell = createAdminShell<ReactNode>({
  brand: { title: 'Workbench' },
  navigate: url => void router.navigate(url)
});
shell.attach(); // Bind to the browser before first render: theme and layout variables are in place on the first frame

function Layout() {
  const location = useLocation();
  const navigation = useNavigation();
  return (
    <AdminLayout
      menu={menu}
      url={`${location.pathname}${location.search}`}
      navigating={navigation.state !== 'idle'}
      brandIcon={<Database size={16} />}
      renderMenuExtra={node => <span className="badge badge-ghost badge-xs">{counts[node.id]}</span>}
    >
      <Outlet />
    </AdminLayout>
  );
}

export const App = () => (
  <AdminShellProvider shell={shell}>
    <Layout />
  </AdminShellProvider>
);
```

The menu is `MenuNode<ReactNode>[]`; icons are sized by the app. Read shell state with `useAdminStore(store)`; translate shell text with `useAdminText()`.

## Vue

```ts
// shell.ts
export const shell = createAdminShell<Component>({
  brand: { title: 'Workbench' },
  navigate: url => void router.push(url)
});

// main.ts: shell.attach() first, then createApp(App).mount()
```

```vue
<template>
  <AdminShellProvider :shell="shell">
    <AdminLayout :menu="menu" :navigating="navigating" :url="route.fullPath">
      <template #brand-icon><Database :size="16" /></template>
      <template #menu-extra="{ node }">
        <span class="badge badge-ghost badge-xs">{{ counts[node.id] }}</span>
      </template>
      <RouterView />
    </AdminLayout>
  </AdminShellProvider>
</template>
```

The menu is `MenuNode<Component>[]`; icons are `@lucide/vue` components rendered by the shell at 16px. React's `brandIcon` / `renderMenuExtra` / `headerStart` / `headerEnd` are the `brand-icon` / `menu-extra` (scoped parameter `{ node }`) / `header-start` / `header-end` slots in Vue. Read shell state with `useAdminStore(store)` (returns a readonly `ref`); translate with `useAdminText()`.

**Do not wrap the shell in `ref()` / `reactive()`**: it is a class instance with `#private` fields, and Vue's deep proxy cannot read private fields. `AdminShellProvider`'s `shell` cannot be replaced during a component's lifetime; when it must be replaced, add a `key` to the Provider.

## Angular

```ts
export const shell = createAdminShell<AdminIcon>({
  brand: { title: 'Workbench' },
  navigate: url => void router.navigateByUrl(url)
});

bootstrapApplication(App, { providers: [provideZonelessChangeDetection(), provideAdminShell(shell)] });
```

```html
<rxdb-admin-layout [menu]="menu" [menuExtra]="extra" [navigating]="navigating()" [url]="url()">
  <svg [lucideIcon]="Database" [size]="16" brandIcon></svg>
  <router-outlet *rxdbAdminPage />
</rxdb-admin-layout>
<ng-template #extra let-node><span class="badge badge-ghost badge-xs">0</span></ng-template>
```

`provideAdminShell(shell)` binds to the browser during environment initialization (before any component renders). The menu is `MenuNode<AdminIcon>[]` (`AdminIcon` is `@lucide/angular`'s icon input) and **must be a stable reference**; the shell renders icons at 16px. Read shell state with `injectAdminStore(store)` (returns a `Signal`); translate with `injectAdminText()` — both must be called within an injection context.

## API comparison

| Capability          | React                          | Vue                                     | Angular                                                     |
| ------------------- | ------------------------------ | --------------------------------------- | ----------------------------------------------------------- |
| Provide the shell   | `<AdminShellProvider shell>`   | `<AdminShellProvider :shell>`           | `provideAdminShell(shell)`                                  |
| Read the shell      | `useAdminShell()`              | `useAdminShell()`                       | `injectAdminShell()`                                        |
| Subscribe to stores | `useAdminStore(store)` → value | `useAdminStore(store)` → readonly `ref` | `injectAdminStore(store)` → `Signal`                        |
| Shell text          | `useAdminText()`               | `useAdminText()`                        | `injectAdminText()`                                         |
| Layout              | `<AdminLayout>`                | `<AdminLayout>`                         | `<rxdb-admin-layout>`                                       |
| Menu icon type      | `ReactNode`                    | `Component`                             | `AdminIcon`                                                 |
| Router outlet       | `children`                     | default slot                            | default projection; refresh/recreate needs `*rxdbAdminPage` |
| Brand icon          | `brandIcon`                    | `brand-icon` slot                       | `[brandIcon]` projection                                    |
| Menu item extra     | `renderMenuExtra(node)`        | `menu-extra` slot (`{ node }`)          | `menuExtra` input (`TemplateRef`, `let-node`)               |
| Top bar extensions  | `headerStart` / `headerEnd`    | `header-start` / `header-end` slots     | `[headerStart]` / `[headerEnd]` projections                 |

### Refresh = remount

"Refresh" in the top bar and tab context menu must recreate the page content. React and Vue put a `key` on the page container, and the router outlet rebuilds with it. Angular's `<ng-content>` projection belongs to the parent view, so the layout cannot rebuild it — put the page content in `*rxdbAdminPage` so the layout instantiates it as a template; without that directive, refresh only rebuilds the `.admin-page` container and the projected content itself is not rebuilt.

## Testing

`@aiao/rxdb-admin/testing` provides a fake window, fake document, and `createTestShell` that do not depend on a browser; component unit tests in all three frameworks build on it. In Vue, when mounting with `@vue/test-utils`, do not pass the shell through `props` (VTU deep-proxies props and private fields become unreadable); provide it through a render-function closure instead.
