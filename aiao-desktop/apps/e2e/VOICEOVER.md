# 本机读屏验收

对应 ADESK-US-108 AC#6。浏览器里的 `ariaSnapshot` 和 axe 通过，只证明自动断言通过。本清单验收真实的 VoiceOver 播报；真实键盘是否被 macOS / 浏览器截获，另用 `verify-keyboard` 验收，不能拿浏览器协议事件替代。

## 环境与准备

在仓库根执行 `pnpm nx run aiao-desktop-web:serve-static`，用本机 Chrome 的普通标签页打开 `http://127.0.0.1:4411/?boot=0`。它托管正式构建，具备 COOP / COEP。记录构建提交和工作区是否有修改，不使用开发服务器的结果替代。

记录 macOS、Chrome、VoiceOver 版本、界面语言、键盘导航设置和日期。开启 VoiceOver（⌘F5），关闭 Quick Nav，确认 Tab 跟随键盘焦点。Chrome 与系统的键盘导航选项要允许聚焦所有控件。不要更改个人数据：测试使用这个本地来源，操作结束关闭测试标签页并恢复原来的 VoiceOver 开关和导航设置。

`VO` 表示 Control + Option。每一步听取实际播报，必要时用 VO + F3 复读当前项。可在 VoiceOver Utility 打开字幕面板，逐字记录名称与角色。字幕与实际声音不一致时，以实际声音为准，并登记差异。

## 结果记录

每次完成后，在 `requirements/evidence/<日期>/` 新建记录，逐条保留实际播报、结果和异常，并在 `requirements/verification-report.md` 引用。记录至少包含：

- 执行日期、操作者、提交短 SHA 与工作区改动说明。
- macOS / Chrome / VoiceOver 版本、语言、键盘导航设置和使用的 URL。
- V01～V14 各自的原始播报与结论，必要时附字幕截图。
- 是人工操作还是由工具驱动真实 VoiceOver；不要把工具驱动称为真实物理键盘。
- 开关、焦点与测试数据的恢复结果。
