# 用户故事：Tauri 安装版与首次启动

## 作为/我想要/以便

**作为** 想长期使用 Aiao Desktop 的个人用户
**我想要** 从官方发布物安装一个可以独立启动的桌面应用
**以便** 不必先打开浏览器或记住网页地址就能进入自己的桌面

## 范围边界

### In Scope

- macOS 与 Windows 的官方安装包、目标架构、版本号、发布来源和完整性信息。
- 在受支持的干净设备上安装、取消安装和重试安装。
- 安装后从操作系统的应用入口启动独立窗口，关闭进程后再次启动仍能进入 Aiao Desktop 外壳。
- 首次启动不依赖用户预装 Node.js、pnpm、开发工具或单独打开浏览器。
- 核心桌面外壳和已随安装版交付的本地资源在没有网络时可以启动；需要网络的远程内容继续显示真实的联网边界。
- 首次启动需要的操作系统权限、网络访问和本地数据权限有可读说明，并按最小范围配置。

### Out of Scope

- 浏览器工作区迁移、安装版数据目录的完整契约和跨来源导入，见 [ADESK-US-011](ADESK-US-011-tauri-local-workspace-migration.md)。
- 安装版升级、回退、卸载后的数据保留与删除，见 [ADESK-US-012](ADESK-US-012-tauri-update-and-uninstall.md)。
- Linux、移动端、Electron 和通过应用市场安装第三方 Web 应用。
- 系统级全局快捷键、托盘常驻、文件关联、开机启动和原生通知等额外集成。
- 后台自动更新、企业分发和用户自定义安装源。

## 验收标准

| #   | 前置条件                       | 操作                                       | 预期结果                                                                                      | 状态 |
| --- | ------------------------------ | ------------------------------------------ | --------------------------------------------------------------------------------------------- | ---- |
| 1   | 生成一个候选发布版本           | 查看官方发布物                             | 能识别支持的操作系统、架构、版本、来源和完整性校验信息；不支持的组合有明确说明                | ⬜   |
| 2   | macOS 或 Windows 干净设备      | 运行对应安装包并完成安装                   | 不需要浏览器、Node.js 或 pnpm；安装完成后系统应用入口出现 Aiao Desktop，且没有半安装记录      | ⬜   |
| 3   | 安装成功且设备暂时没有网络     | 启动 Aiao Desktop                          | 出现独立应用窗口并进入桌面外壳；核心本地资源可用；远程内容按联网状态显示，不伪造已加载        | ⬜   |
| 4   | Aiao Desktop 已运行            | 关闭应用进程后再次启动                     | 应用可以重新启动并进入同一安装版；启动失败时显示可操作的错误信息，不静默切换到浏览器版        | ⬜   |
| 5   | 安装、首次启动或资源初始化中断 | 重新运行安装包或启动应用                   | 不把未完成的安装或初始化标记为可用版本；用户可以重试，已有可用版本和本地数据不被清除          | ⬜   |
| 6   | 查看安装版的权限与隐私说明     | 检查首次启动和运行时权限                   | 只申请已声明的能力；拒绝或不可用时说明受影响的功能和恢复路径，不授予未声明的 shell 或全盘权限 | ⬜   |
| 7   | 实现完成                       | 在 macOS 与 Windows 真实设备上运行安装冒烟 | 安装、启动、离线启动、退出重开和失败重试均有对应设备证据；浏览器 e2e 结果不能代替安装验收     | ⬜   |

## 验收证据

待实现后补充 macOS 与 Windows 的安装包标识、真实设备、执行命令、产物校验和失败复验记录。

## 技术笔记

- 使用 Tauri 2 作为桌面宿主，前端复用 `aiao-desktop/apps/web` 的产品界面和共享运行时，避免为安装版复制一套桌面业务逻辑。
- 宿主权限通过 Tauri capabilities 明确声明，CSP、IPC 命令和本地资源边界在安装版单独验收。
- 安装包构建、签名或校验、真实设备启动和浏览器正式构建属于不同证据层，不能互相替代。
- 具体安装包格式、签名主体、支持架构和构建 target 在实现计划中冻结，并回填到 AC#1 的证据。

## 实现文件

- `aiao-desktop/apps/tauri/` — 待创建的 Tauri 宿主与配置
- `aiao-desktop/apps/web/` — 共享前端构建产物与安装版接线
- `aiao-desktop/apps/e2e/` — 浏览器行为回归；安装版另建真实设备 smoke 入口
- `aiao-desktop/requirements/` — 安装版范围、平台矩阵和验收证据
