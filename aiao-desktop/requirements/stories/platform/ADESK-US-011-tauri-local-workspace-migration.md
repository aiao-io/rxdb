# 用户故事：Tauri 本地工作区与显式迁移

## 作为/我想要/以便

**作为** 已经在浏览器版使用 Aiao Desktop 的用户
**我想要** 把自己的桌面工作区明确迁移到 Tauri 安装版，并知道数据保存在哪里
**以便** 安装桌面应用后可以继续使用文件、内置应用和本地设置，而不会因为换运行时丢失成果

## 范围边界

### In Scope

- Tauri 安装版使用独立、可说明的操作系统应用数据目录保存桌面数据库、用户文件体和应用设置。
- 本地数据库、文件体和目录记录在应用重启后保持一致；写入中断时不能报告一个缺少文件体的成功状态。
- 复用或扩展现有完整备份格式，提供从浏览器工作区导入到 Tauri 工作区以及从 Tauri 工作区导出的明确入口。
- 导入前校验版本、路径、内容校验和范围；校验完成后再原子切换活动工作区。
- 导入失败、取消、中断、空间不足或权限拒绝时保留当前工作区，并给出可重新操作的结果。
- 清楚区分浏览器工作区、Tauri 工作区、远程集成应用自己的数据和用户导出的备份文件。
- 安装版迁移后，已有核心本地文件、桌面布局、内置应用记录和设置可以继续使用；不把远程应用来源下的数据伪装成本地备份内容。

### Out of Scope

- 浏览器版与 Tauri 版之间的实时同步、自动合并和后台冲突解决。
- 远程集成应用自己的 Origin 数据、第三方账号凭据和终端运行时镜像的迁移。
- 对任意本机目录的持续访问、文件系统全盘授权和把用户目录直接当作应用数据库。
- 跨不兼容 schema 的任意降级、手工修改 SQLite 文件和跨设备账号恢复。
- 安装版升级、卸载后的保留或删除选择，见 [ADESK-US-012](ADESK-US-012-tauri-update-and-uninstall.md)。

| #   | 前置条件                                  | 操作                                  | 预期结果                                                                                  | 状态 |
| --- | ----------------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------- | ---- |

| 2   | 浏览器版已有文件、应用记录和设置           | 导出备份并在全新 Tauri 工作区导入       | 导入后的本地文件、目录、支持范围内的应用记录和设置与备份一致，数据来源和导入结果可确认       | ⬜   |
| 3   | Tauri 工作区已有数据                        | 导入损坏、截断、路径非法、超限或不兼容包 | 导入被拒绝，当前数据库、文件体和设置保持不变，错误指出修复或重试方向                     | ⬜   |
| 4   | 浏览器版和 Tauri 版同时存在                 | 分别修改两侧工作区并重新打开             | 两侧数据不自动互相覆盖；界面能识别当前工作区和数据来源，用户必须通过显式导入或导出迁移数据 | ⬜   |
| 5   | 导入或本地写入过程中发生中断、空间不足或权限拒绝 | 重新启动并检查工作区                   | 不报告部分成功；临时数据可清理或继续恢复，原工作区仍可打开，用户可以在修复后重试           | ⬜   |
| 6   | Tauri 应用数据目录不可用或权限被撤销           | 启动应用并执行读写操作                 | 显示真实的存储不可用状态和恢复路径，不静默换到其他目录或其他存储后端                   | ⬜   |
| 7   | 迁移和本地持久化实现完成                      | 在 macOS 与 Windows 真实设备上导入、重启和恢复 | 真实设备证据覆盖数据库、文件体、设置、失败回滚和工作区隔离；源码单测不能单独关闭本故事 | ⬜   |

## 验收证据

待实现后补充备份包样本、数据目录标识、macOS 与 Windows 真实设备记录、迁移失败复验和结果摘要。

## 技术笔记

- Tauri 侧复用 `@aiao/rxdb-adapter-tauri` 与 Rust 宿主的 SQLite 连接能力，桌面数据库不能通过多个 IPC 调用伪造跨连接事务。
- 工作区导入使用临时目录和临时数据库完成校验，全部通过后再切换活动目录；活动工作区不能被半成品覆盖。
- 备份包格式与浏览器版已有完整备份故事保持一致。若需要新增 Tauri 专属元数据，应增加版本字段并保留旧包的拒绝路径。
- 用户选择的外部文件导入仍由独立的文件授权故事负责，不把 Tauri 的宿主权限直接暴露给内置应用或集成应用。

## 实现文件

- `aiao-desktop/apps/tauri/` — Tauri 宿主、数据目录和 IPC 接线
- `aiao-desktop/apps/web/src/app/data/` — 工作区存储抽象和迁移入口
- `packages/rxdb-adapter-tauri/` — Tauri SQLite 平台能力
- `aiao-desktop/apps/e2e/` — 浏览器备份格式与行为回归
- `aiao-desktop/requirements/evidence/` — 真实设备迁移和故障恢复证据
