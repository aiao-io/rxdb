# 用户故事：多标签页实时互通

## 作为/我想要/以便

**作为** 同时在两个标签页里打开 Aiao Desktop 的人
**我想要** 一个标签页里的改动立刻出现在另一个标签页
**以便** 两个窗口像同一台机器，改动不用刷新才看得到。

## 范围边界

### In Scope

- 磁盘、系统设置与应用数据的跨标签页即时可见：一个标签页的写入，另一个标签页的 Finder、桌面图标与活查询在数秒内更新。
- 跨标签页写同一个库的安全：两个标签页共用同一个 OPFS 库文件，写路径有跨标签页串行化（Web Lock 或等价机制），并发写同一路径不损坏库，后写可见。
- 终端虚拟机每标签页一台的现状保留；终端改动按现有扫描同步写回库，另一个标签页经库即时看到。
- 冒烟用两个浏览器上下文同时打开正式构建验收。

### Out of Scope

- 两台虚拟机的实时镜像、跨标签页终端会话迁移。
- 跨设备同步、CRDT 冲突合并、离线写入队列。

## 技术笔记

- 关键风险是同一个 OPFS SQLite 库文件被两个标签页的 worker 同时打开（可能出现 SQLITE_BUSY）：写路径需要跨标签页串行化；`FileSystem` 里已有一个跨标签页的 `DISK_LOCK` Web Lock（抹掉磁盘用），可扩展到全部写路径——注意要包住 repository 层（`RxdbDiskStore` 的读写），不只是 `FileSystem` 的串行队列，否则两个标签页的 worker 仍可能同时写库。
- `RxdbDiskStore` 的内存索引在收到其他标签页的写入广播后失效重建；同标签页内的界面更新沿用现有活查询。
- 广播通道用 BroadcastChannel（同源跨标签页）；RxDB 的本地库在两个标签页各持一个连接，广播只负责「通知刷新」，不代替数据库一致性。
