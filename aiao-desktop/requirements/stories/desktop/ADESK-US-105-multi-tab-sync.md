# 用户故事：多标签页实时互通

## 作为/我想要/以便

**作为** 同时在两个标签页里打开 Aiao Desktop 的人
**我想要** 一个标签页里的改动立刻出现在另一个标签页
**以便** 两个窗口像同一台机器，改动不用刷新才看得到。

## 范围边界

「标签页」指浏览器标签页，每个标签页各有自己的内存索引与一台虚拟机；「终端标签」指 Terminal 窗口里的标签（[D-09](../../decisions.md#d-09终端按需复制磁盘)）。

### In Scope

- **并发写安全（阶段 A）**：两个标签页共用同一个 OPFS 库文件，所有写路径经跨标签页串行化（Web Lock 或等价机制）；并发写同一路径不损坏库，两边最终一致。串行化要包住 repository 层（`RxdbDiskStore` 的读写），不只是 `FileSystem` 的串行队列。
- **共享可写资源的盘点（阶段 A）**：除 SQLite 库文件外，Vivari 自己的文件系统镜像也在 OPFS（D-09）。每个标签页一台虚拟机时，两台虚拟机的镜像互不覆盖、互不损坏；storage 插件的文件体是随机名平铺的，写入互不冲突。
- **实时可见（阶段 B）**：磁盘、系统设置与应用数据的跨标签页即时可见：一个标签页的写入，另一个标签页的 Finder、桌面图标与活查询在数秒内更新。
- 终端虚拟机每标签页一台的现状保留；终端改动按现有扫描同步写回库，另一个标签页经库即时看到。
- 冒烟用**同一个浏览器上下文里的多个页面**验收。不同浏览器上下文的存储（OPFS、BroadcastChannel、Web Locks）互相隔离，不能代表多标签页；夹具见 [ADESK-US-008](../platform/ADESK-US-008-smoke-suite.md)。

### Out of Scope

- 两台虚拟机的实时镜像、跨标签页终端会话迁移。
- 跨设备同步、CRDT 冲突合并、离线写入队列。
- 更保守的做法：主标签页独占写、单标签页独占（见技术笔记「未选的替代方案」）。

## 技术笔记

- 关键风险是同一个 OPFS SQLite 库文件被两个标签页的 worker 同时打开（可能出现 SQLITE_BUSY）：写路径需要跨标签页串行化。`FileSystem` 里已有一个跨标签页的 `DISK_LOCK` Web Lock（抹掉磁盘用），可扩展到全部写路径——要包住 repository 层（`RxdbDiskStore` 的读写），不只是 `FileSystem` 的串行队列，否则两个标签页的 worker 仍可能同时写库。
- `RxdbDiskStore` 的内存索引在收到其他标签页的写入广播后失效重建；同标签页内的界面更新沿用现有活查询。
- 广播通道用 BroadcastChannel（同源跨标签页）；RxDB 的本地库在两个标签页各持一个连接，广播只负责「通知刷新」，不代替数据库一致性。
- Vivari 的文件系统镜像也在 OPFS，两个标签页各一台虚拟机时它是第二个共享可写资源。镜像要按标签页分区，或用别的方式避免互相覆盖；Vivari 是否已按实例分区没有确认（推断），实现前先实测两个标签页同时启动终端的行为，AC#2 以实测结果为准。

**未选的替代方案**：主标签页独占写（Web Lock 选主，其余标签页只读并提示）和单标签页独占（第二个标签页提示后不加载库）。它们风险更小，但第二个标签页不能编辑、甚至不可用，与「像同一台机器」的价值不符。全量互通做不到时（例如 Vivari 镜像无法分区），再回到这两档重新评审。
