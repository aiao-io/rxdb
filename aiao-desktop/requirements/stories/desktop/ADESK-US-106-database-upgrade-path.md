# 用户故事：旧库升级路径

## 作为/我想要/以便

**作为** 长期使用 Aiao Desktop 的人
**我想要** 桌面升级后原来的文件、设置与应用数据都还在，新功能的数据自动补齐
**以便** 发新版不丢数据，也不用担心升级把库「抹掉」。

## 范围边界

### In Scope

- 浏览器级升级验收：用上一版正式构建首次打开并写入数据，再换成当前版本打开，断言数据保留、新数据域按 `seed:<domain>` 标记补写、不覆盖用户改动。冒烟目前每次从空 OPFS 开始，这个盲区在验收台账里已列。
- 升级清单制度化：新增实体或数据域时，必须补建表、补种子并通过升级验收，写进故事的技术笔记与验收台账。
- 不兼容时用户可见：库结构损坏或无法升级时给出明确错误与恢复建议，不静默清库；抹掉磁盘仍是显式入口。
- 连续升级可重复：每个版本按同一清单升级，同一库连升两级也成立。

### Out of Scope

- 备份、导出与跨设备迁移（原未来方向的既有边界）。
- 从第一版 Web Desktop 或其他产品迁移数据。
- 跨大版本的自动数据改写工具。

## 验收标准

| #   | 前置条件                                                 | 操作                                 | 预期结果                                                                       | 状态 |
| --- | -------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------ | ---- |
| 1   | 用上一版正式构建首次打开，写文件、设置与备忘录           | 换成当前版本打开                     | 文件、设置、应用数据原样保留，没有页面错误                                     | ⬜    |
| 2   | 旧库缺少当前版本新增的数据域（模拟新增实体）             | 当前版本首次打开                     | 新数据域按 `seed:<domain>` 标记补写一次，旧域内容不被覆盖，刷新后不重写       | ⬜    |
| 3   | 库文件存在但结构不兼容（模拟缺表）                       | 打开桌面                             | 给出明确错误与恢复建议，不静默清库；恢复入口可见                               | ⬜    |
| 4   | 升级流程固定                                             | 连续升级两个版本（v1→v2→v3 各打开一次） | 每步数据完整，步骤可重复执行                                                   | ⬜    |

状态符号：⬜ 未开始 / ⚠️ 进行中或有保留 / ✅ 通过

验收证据：第 1、2、3 条由 `aiao-desktop-e2e:e2e` 的升级检查组覆盖；验收入口有两条——发布前保留上一版产物、冒烟用旧版建库再换新版打开，以及单测夹具用旧 schema 建库文件再经当前实体打开。第 4 条由同一入口的连升两步覆盖。

## 技术笔记

- [D-07](../../decisions.md#d-07系统数据存在本地-sqlite) 的按域种子标记已经支持「新域补写」，缺的是浏览器级验收与升级清单；sqlite-wasm 的建表由 RxDB 处理，但已有库上的变化（新表、新种子）必须在浏览器里实跑过才算数。
- 冒烟当前每次从空 OPFS 开始，升级检查组要单独管理浏览器配置：先旧版建库，再新版打开，中途不抹掉。
- 「上一版产物」的取得方式（发布流水线保留产物，或 CI 用旧 commit 构建）在实现时定，写进技术笔记。

## 实现文件

- `aiao-desktop/apps/e2e/src/smoke.mjs` — 升级检查组与旧版产物入口。
- `aiao-desktop/apps/web/src/app/data/seeds.ts`、`desktop-database.ts` — 补写与不兼容时的错误入口。
- `aiao-desktop/requirements/verification-report.md` — 升级验收证据。
