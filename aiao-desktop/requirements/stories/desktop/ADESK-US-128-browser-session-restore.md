# 用户故事：浏览器关闭后恢复工作区

## 作为/我想要/以便

**作为** 在浏览器里使用 Aiao Desktop 的人
**我想要** 关闭浏览器后再次进入 Aiao Desktop 时恢复上次打开的应用窗口
**以便** 不用重新打开 Finder、编辑器、终端和集成应用，继续上次的工作。

## 范围边界

### In Scope

- 保存最近一次可恢复工作区的窗口快照，包括应用 ID、多个同应用窗口、窗口位置与大小、最小化 / Zoom 状态、层叠顺序、前台窗口和应用开窗参数（例如 Finder 路径、当前文件）。
- 窗口发生变化时持续防抖保存，并在 `pagehide`、页面进入隐藏状态和浏览器正常关闭前刷新待写快照。恢复不能依赖 `beforeunload` 一定触发。
- 再次进入时按以下优先级选择恢复来源：
  1. 当前标签页存在 US-104 的标签页布局时，优先恢复该布局。
  2. 当前标签页没有可用布局，且没有其他活跃的 Aiao Desktop 标签页时，恢复最近一次浏览器会话快照，并由当前标签页取得恢复权。
  3. 已有其他活跃标签页时，新标签页从空桌面开始，沿用 US-104 的行为，避免重复恢复同一组窗口。
- 浏览器重新打开多个标签页时，每个带回原标签页会话标识的标签页继续按 US-104 恢复；没有会话标识的标签页最多有一个取得浏览器会话快照，不能把同一组窗口重复到多个标签页。
- 恢复内置应用和集成应用的窗口外观与开窗参数。集成应用重新握手，终端、游戏和最小化应用沿用 US-104 的延后加载策略。
- 单个窗口恢复失败时跳过该窗口并提示原因，其他窗口继续恢复。应用下线、打开的文件被删除、集成应用无法就绪都不能阻塞桌面启动。
- 用户在浏览器关闭前主动关闭的窗口从快照中移除。所有窗口都被主动关闭后，下一次进入遵循现有默认 Finder 规则，不重新打开旧应用。
- 快照只保存在当前浏览器 Origin 的本地数据中，不上传应用列表、文件路径或窗口状态。

### Out of Scope

- 应用内部滚动位置、选中项、表单输入、运行中游戏状态和未保存文档内容。未保存内容继续由各应用的草稿与关闭保护故事负责。
- 账号登录状态、跨设备同步、跨浏览器同步、跨 Origin 迁移和原生操作系统窗口恢复。
- 浏览器自身的标签页顺序、标签页 URL、浏览历史和浏览器会话列表。
- 用户清除站点数据、使用不保留站点数据的隐私环境或浏览器阻止本地存储后的恢复保证。此时沿用现有存储不可用提示和新桌面启动流程。
- 恢复开关、恢复历史版本和多个历史工作区。当前只保留最近一次可恢复工作区。

## 验收证据

已完成本地实现、单元测试和正式 Chromium 持久浏览器上下文验收。

- 单元测试通过 `aiao-desktop-web:test`，`browser-session-restore.spec.ts` 覆盖标签页租约、最近活跃来源、快照并发写入、关闭释放和损坏数据边界。
- 正式构建上的 `aiao-desktop-e2e:e2e --group=browser-session-restore --parallel=1` 通过。报告见 [Aiao Desktop 验收台账](../../verification-report.md#adesk-us-128-浏览器关闭后恢复工作区)。
- 持久浏览器上下文实际关闭 Chromium 进程后重新进入，浏览器窗口恢复、最近活跃标签页胜出、活跃标签页不重复领取、显式关闭窗口不恢复、损坏快照从新桌面启动、单窗口失败不阻塞其余窗口均通过。
- 本轮验收范围仍按 D-19 限定为桌面 Chrome。US-108 的 VoiceOver 人工播报验收继续按用户要求延期。

## 技术笔记

- 沿用 `WindowLayoutStore` 的 `WindowRecord`、`buildWindows`、`parseLayout`、`restoreSteps` 和 `resolveOpenOptions`，避免为浏览器重启再造一套窗口序列化格式。
- 在 `SystemPreference` 增加独立的持久化键 `windows:resume`，保存版本、写入时间、最近活跃标签页来源和完整窗口快照。它与 `windows:layout:<tabId>` 分开，不能让浏览器会话快照覆盖现有标签页布局。
- 增加浏览器会话协调器，使用 `sessionStorage` 中的标签页标识、同源 `BroadcastChannel` 和带过期时间的活跃标签页租约判断“已有桌面标签页”与“可领取的浏览器会话”。领取和快照写入经现有 Web Locks / 偏好写入锁串行化。
- 最近活跃标签页在 `focus`、`pageshow` 和可见性恢复时更新来源。多个标签页各自有布局时，浏览器关闭重进只选择最近活跃的一份作为无标签标识入口的恢复源，不拼接多个标签页的窗口。
- 浏览器会话恢复成功后保留最新快照，下一次浏览器关闭仍按当前窗口状态生成新快照；显式关闭窗口会先从当前布局和最近工作区快照中移除，避免旧窗口反复出现。
- 新增快照版本校验、未知版本保留、损坏记录跳过与原子替换路径，兼容 US-106 的升级和旧库保护。恢复期间继续禁止空桌面覆盖持久化快照。
- 由于浏览器不保证任何单一关闭事件都能执行，正常运行时以防抖写入为主，`pagehide` / `visibilitychange` 只负责补写最后一份内存快照。异常崩溃时恢复最近一次已成功提交的完整快照。

## 实现文件

- `aiao-desktop/apps/web/src/app/services/window-layout.ts` — 复用窗口收集、恢复和关闭前刷新入口。
- `aiao-desktop/apps/web/src/app/services/window-layout-model.ts` — 增加浏览器会话快照版本与解析规则。
- `aiao-desktop/apps/web/src/app/services/browser-session-restore.ts` — 建议新增，负责活动标签页租约、恢复权领取和最近活跃来源。
- `aiao-desktop/apps/web/src/app/data/preferences.ts` — 复用本地偏好串行写入和跨标签页通知。
- `aiao-desktop/apps/web/src/app/pages/desktop-page.ts` — 启动时选择标签页布局、浏览器会话快照或默认 Finder。
- `aiao-desktop/apps/e2e/src/smoke.mjs` — 新增浏览器关闭重进、并发标签页和失败恢复检查组。
