# Aiao Desktop 后续方向

## 当前孵化

先用门禁与冒烟守住产品结构和既有桌面行为（[ADESK-EPIC-001](epics/ADESK-EPIC-001.md)、[ADESK-EPIC-002](epics/ADESK-EPIC-002.md)），再按具体场景扩展。

## 候选方向

以下方向都需要具体使用场景、能力缺口和独立验收范围后再立故事，不随当前故事自动承诺：

- **窗口布局跨刷新保留**：打开的窗口、位置与大小在刷新后还原。磁盘、设置与应用数据已由 [ADESK-US-102](stories/desktop/ADESK-US-102-local-data-and-real-disk.md) 存进本地库，窗口布局可以照同一套偏好表接入。
- **正式部署**：静态托管 web 产物。托管方必须返回跨源隔离所需的两个响应头（[D-05](decisions.md#d-05终端依赖跨源隔离)），还要说明外网内容的来源与隐私。
- **跨浏览器验收**：在 Safari 与 Firefox 上跑冒烟，以及触屏、窄屏下的交互。
- **单元测试与覆盖率**：为窗口管理、虚拟文件系统、会话状态等服务补单元测试，并接入仓库的覆盖率门槛。
- **应用目录**：集成应用的运行时安装、卸载、更新与回退（第一版 Web Desktop 做过一套，可参考）。前提是有第二个以上的集成应用，以及「谁批准入口」的运营流程；在此之前登记表随构建发布（[D-10](decisions.md#d-10应用分三类登记在同一张表里)）。
- **宿主服务**：桌面经 Orbit 向集成应用提供能力，例如打开磁盘上的文件、通知中心、浅色 / 深色外观联动、窗口标题同步，以及代办应用在 iframe 里做不了的弹窗（OAuth 登录）与文件选择。每项都要先定 Orbit 请求的名字、权限与失败语义（[D-12](decisions.md#d-12集成应用的接入契约)）。
- **与集成应用同站部署**：桌面部署到 aiao.io 下时，Aiao Code 的存储不再分区，桌面里与直接访问看到的是同一份项目，GitHub 登录状态也能共用；依赖正式部署。
- **外网内容本地化**：壁纸随构建分发；地图与天气在无网时给出明确的占位说明。
