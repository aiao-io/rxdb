# Aiao Desktop 后续方向

## 当前孵化

先用门禁与冒烟守住产品结构和既有桌面行为（[ADESK-EPIC-001](epics/ADESK-EPIC-001.md)、[ADESK-EPIC-002](epics/ADESK-EPIC-002.md)），再按具体场景扩展。

## 候选方向

以下方向都需要具体使用场景、能力缺口和独立验收范围后再立故事，不随当前故事自动承诺：

- **跨刷新保留状态**：窗口布局、虚拟文件与设置在刷新后保留。这会打破「只存在内存中」的边界；存储可以评估仓内 RxDB 平台能力，用 `capabilities` 引用。
- **正式部署**：静态托管 web 产物。托管方必须返回跨源隔离所需的两个响应头（[D-05](decisions.md#d-05终端依赖跨源隔离)），还要说明外网内容的来源与隐私。
- **跨浏览器验收**：在 Safari 与 Firefox 上跑冒烟，以及触屏、窄屏下的交互。
- **单元测试与覆盖率**：为窗口管理、虚拟文件系统、会话状态等服务补单元测试，并接入仓库的覆盖率门槛。
- **外网内容本地化**：壁纸随构建分发；地图与天气在无网时给出明确的占位说明。
