# aiao-desktop 多语言集成方案（macOS 式，基于 @aiao/rxdb-i18n）

> 状态：**定稿 v1**（2026-11-24；已通过完整性+可行性双评审，关键决策已拍板）
> 依据：四路并行研究（引擎契约 / 桌面盘点 / 运行时与 macOS 语义 / 门禁与测试）+ 双评审修订记录（附录 B）

## 1. 结论摘要

1. **直接复用已交付的 `@aiao/rxdb-i18n` + `@aiao/rxdb-i18n-angular`**（仓库根 US-911 已 Done，阶段 A~D 全绿）。aiao-desktop 的工作是「接线 + 建目录 + 文案目录化」，不需要新增引擎能力。
2. **产品现状是英文**：界面全部英文硬编码（macOS 仿真基线），中文仅存在于约 270 条服务错误消息与代码注释；现有 e2e 全按 en-US 断言。因此英文目录必须逐字保留现有文案，e2e 先钉 locale 再谈切换。
3. **已拍板**（§7）：首批中英双语（zh-Hans + English）；回退基线英文（defaultLocale:'en'）；应用内完整「Language & Region」设置分区；三阶段分期实施。
4. **两个评审修正的关键设计**：
   - **中文目录必须双注册**：BCP 47 父链 zh-CN→zh 推不出 zh-Hans（locale.ts:19-30 实测），defaultLocale:'en' 下 zh-CN 设备的链是 ['zh-CN','zh','en']——只注册 zh-Hans 会导致中文系统首启显示英文。必须把同一份中文目录同时注册为 locale 'zh'（覆盖 zh-CN/zh-TW/zh-HK 父链）与 'zh-Hans'（覆盖直接上报 zh-Hans 的设备），并在 Language & Region 面板对 availableLocales 做 'zh'→zh-Hans 归并去重（dev demo 是通过库缺省 defaultLocale:'zh-Hans' 兜底才"看似"支持 zh-CN 的，桌面不能照搬）。
   - **初始化时序串行而非并列**：I18n.init 的 db.connect 引导会补建全部实体表，不持 STARTUP_LOCK——并列运行会与另一 Tab 被锁保护的升级交错，单 Tab 内还会让 probeSchema 的「缺表损坏」探测被静默掩盖。改为 I18n.init 在 DesktopData.ready 之后执行（或纳入 STARTUP_LOCK）。
5. **跨 Tab 走库原生**：RxDBTabsGateway 由 core 在 RxDB.init 时自动装配（桌面未设 multiInstance），无需桥接桌面 Preferences/TabSync；阶段 3 按库原生做双实例验证。
6. **范围**：外壳 + 三屏（BootScreen/LockScreen/data-problem）+ 设置 + 30 个内置应用 + 服务错误消息。种子/磁盘样例数据（数据非 UI）、Aiao Code 与静态 HTML 游戏内部文案、PWA 静态安装元数据不在 v1。

## 2. 现状与依据（要点）

- **引擎契约**：`I18n` 运行时（t/resolve/setLocale/formatNumber/formatDate/formatRelativeTime/inspect/destroy；locale$/availableLocales$/changes$/errors$）；`i18nEntities()` 四实体（I18nSettings/MessageEntry/RemoteMessageEntry/MissingMessageEntry，均 SyncType.None + log:false）必须在 RxDB.init() 前入 config.entities；Angular 绑定 provideI18n / useI18n / useI18nOptional / I18N（locale 是 Signal，t() 内部 track 自动重渲染，绑定包无 pipe）。I18n.init() 幂等调用 db.init()/db.connect()（adapterName 读 config.sync.local.adapter）并建 singleton 行；构造默认 defaultLocale='zh-Hans'、deviceLocale=navigator.language、namespace='app'（桌面必须显式 defaultLocale:'en'）。
- **桌面落点**：`apps/web/src/app/data/entities.ts` 的 DESKTOP_ENTITIES（唯一进 config.entities 的汇总）；`desktop-database.ts` 适配器 'sqlite-wasm' 已配 sync.local.adapter；`app.config.ts` 现为内联 `createDesktopDatabase` 工厂（需抽模块级单例 getter）；设置应用 `general-pane.ts:51` 已有 'Language & Region' 桩（死条目，无点击行为；注意 Wallpaper 已占用 'g-globe' 图标，新分区需另选图标）。
- **治理**：桌面需求体系无任何语言故事；verify 的 requirements-check 门禁要求先立故事（建议 **ADESK-US-213**，现存最大编号 212，放 stories/desktop/）；roadmap.md:60 要求改产品边界同步 decisions.md；CONVENTIONS 要求故事带 capabilities 引用。
- **e2e**：`harness/session.mjs` 的 createSession 未钉 locale（默认 en-US），contextOptions 是唯一注入点且覆盖 chromium/firefox/webkit 三引擎（webkit 走持久 profile 同一透传）；调用点有两个（runner.mjs 与 backup-storage.mjs），改 createSession 内部默认值一处覆盖两处；英文断言散布 helpers.mjs、shell.mjs（日历 weekday 用 en-US 对比）、settings-workflow.mjs、a11y.mjs；e2e 拦全部外网 → 翻译目录必须静态打包。
- **单测**：vitest include 是 src/**/*.spec.ts（41 个 apps 下 spec + 75 个 services 下 spec，48 个用 TestBed）；useI18n() 无 provider 即抛 → 需 fake runtime 桩（对齐 packages/rxdb-i18n-angular/src/**tests**/use-i18n.spec.ts）；覆盖率 perFile 80% 的 include 不含 src/app/i18n/（新目录无门槛负担，但仍需 TDD 测试）。

## 3. 方案设计

### 3.1 目录与命名空间

- 命名空间 `'desktop'`（aiao-desktop 自有目录）；生态命名空间 'rxdb-model'/'rxdb-admin' 仅当桌面复用对应组件时追加（当前桌面是自绘 macOS 组件，不复用 → 不追加）。
- 目录文件：`apps/web/src/app/i18n/messages-zh.ts`、`messages-en.ts`（Readonly<Record<string,string>>），`desktop-i18n.ts` 导出 `createDesktopI18n(rxdb)` 与 catalogs。
- **中文目录双注册**：同一份中文消息注册为 `{locale:'zh'}` 与 `{locale:'zh-Hans'}` 两份目录（同一 messages 对象）；English 注册 `{locale:'en'}`。
- key 规范：`域.场景.短键`（`shell.menu.about`、`settings.search.placeholder`、`finder.emptyFolder`、`shell.toast.trashEmptied`、`error.github.token`）。参数化消息用 ICU 插值：`"window.status.opening": "Opening {name}…"`。**v1 目录只用简单插值，不含 plural/select**（实施时评估计数类文案，如菜单栏「1 update」，确需复数再单独列清单）。英文目录 = 现有硬编码原串逐字（模板化串按参数形式改写，语义不变）；中文目录新译。
- **zh 术语规范：以 Apple 官方简体中文界面译名为准**（访达/系统设置/聚焦/启动台/废纸篓等；根 requirements/zh-glossary.md 作用域不含用户可见文案，不直接套用）。术语表列入阶段 1 交付物。
- 特殊字符陷阱：'Wi‑Fi' 的 U+2011 不换行连字符等，目录复制时保持原文。

### 3.2 初始化时序（串行）

1. `createDesktopDatabase` 抽成模块级单例 getter（provideRxDB 与 provideI18n 共用同一实例）。
2. `entities: [...DESKTOP_ENTITIES, ...i18nEntities()]`（必须在 RxDB 实例构造前拼好）。
3. `app.config.ts`：`provideI18n(() => createDesktopI18n(getDesktopDatabase()))` + `provideAppInitializer(() => inject(I18N).init())`。
4. **时序（评审修正）**：I18n.init 的 db.connect 引导不持 STARTUP_LOCK，不得与 DesktopData.start 并列——实现为 I18n.init 等待 DesktopData.ready 后再执行（或把 i18n 引导纳入 STARTUP_LOCK 范围），首屏渲染前完成；确保 probeSchema 的损坏探测不被 connect 的静默补建掩盖。
5. `<html lang>` 订阅 changes$ 更新（先例 dev-rxdb-http app.config.ts:38）；注意 zh-CN 设备上 locale$='zh-CN'（文案来自 'zh' 目录），lang 按设备链写、不强制归一。document.title 用目录 key（品牌名 "Aiao Desktop" 保留原文，macOS 亦不译系统名）。
6. 退出：app.onDestroy → i18n.destroy()（destroy 不销毁宿主库）。
7. 注入器：provideI18n 挂在根注入器；阶段 1 验证 29/30 个懒加载应用（registry.ts D-18）经窗口挂载链（window-layer / Orbit 宿主）解析 I18N 的路径成立。目录经 app.config 引入 → 全部进 eager 主包（可接受，目录体积见 §6.6）。

### 3.3 语言偏好与跨 Tab

- **载体：库契约 I18nSettings singleton**（SyncType.None + log:false；历史隔离专项已验：不进 undo/diff/commit，切分支/restore/discard 不回退——与桌面 ADESK-US-102/105/106 语义兼容）。setLocale() 自动持久化，首次建行冻结 deviceLocale，已存在的用户选择永不被覆盖。
- **跨 Tab：库原生**。RxDBTabsGateway 由 core 在 RxDB.init 时自动装配（桌面未设 multiInstance），无需桥接桌面 Preferences/TabSync。阶段 3 做库原生双实例验证（参照 dev-rxdb-angular-e2e/i18n.spec.ts 第二标签页用例）。
- **availableLocales 归并**：双注册后 availableLocales 含 'zh'，Language & Region 面板需把 'zh' 归并到 zh-Hans 展示（列表 = 去重后的语言，切换动作始终 setLocale('zh-Hans')）。
- **无「跟随系统」重置**：setLocale 无 null/reset 路径（源码实测），v1 面板不提供「跟随系统」选项；初始状态即跟随系统（devicePreferredLocale=null），用户一旦手动选择即持久覆盖。后续如需重置，给 rxdb-i18n 补 reset API（触及 api-baseline，diff 随提交）。

## 5. 测试与门禁

- **e2e**：locale 钉定在 createSession 内部默认值；language.mjs 限 chromium（D-19；firefox/webkit 的期望写进 limitations 基线登记）；shell.mjs 日历 weekday 断言改用应用侧同 locale；断言语言时按设备链语义（zh-CN 设备 lang='zh-CN'、文案来自 zh 目录）。
- **单测**：testing/ 共享 fake I18n runtime 桩（BehaviorSubject+vi.fn）与 provider；目录/回退/协商用静态 `new I18n({ catalogs })`（含 zh-CN→zh、zh-Hans、de-DE→en 三条链的钉死测试）；48 个 TestBed spec 的桩接入量在阶段 1 评估；覆盖率 perFile 80%（src/app/i18n/ 不在 include 内，仍按 TDD 写测试）。
- **门禁**：`pnpm nx run aiao-desktop:verify` 全链（新增 audit 残留硬编码扫描项）；不改 packages/rxdb-i18n* 则不动 api-baseline 与包级覆盖率门禁；构建预算以 **1.3mb 警告线**为自查口径（错误线 1.5mb）。

## 6. 风险与开放点

1. **zh 双注册的可用性副作用**：availableLocales 多出 'zh'——面板必须归并展示，否则出现重复中文项；zh-TW/zh-HK 设备经父链落入简体 'zh' 目录，v1 可接受但须在故事中写明。
2. **benchmark-smoke 硬失败**：新默认组新键使 A/B 的 extra 非零直接 exit 1；阶段 1 必须完成 smoke-keys 基线再生并提交，否则 bench 门禁先红。
3. **init/connect 时序**：已改串行（等 DesktopData.ready 或纳入 STARTUP_LOCK）；另注意 I18nSettings 首建写发生在 SchemaGuard enable 之前，是启动期写守卫的一处已知例外，写入方案注释。
4. **旧库升级账本**：i18n 四表由 connect 自动补建、不进 SCHEMA_STEPS，但 schema-fingerprint 快照与版本账本若覆盖实体清单需重新基线——阶段 1 即更新指纹快照。
5. **文案量估算**：桌面约 10^3~10^4 条文案，zh 目录可能上百 KB；阶段 2 全量目录化后实测 initial 体积，落进 1.3~1.5mb 会持续告警。
6. **Intl 与 t() 的 locale 源不一致**：zh-CN 设备上 locale$='zh-CN'（Intl 用 zh-CN），文案命中 'zh' 目录——formatDate/formatNumber 与目录天然脱钩（库设计），e2e 与面板展示按 locale$ 断言。
7. **错误消息甄别成本**：约 270 条中文串中部分为开发向/正则误捕获，需人工甄别后再目录化。
8. **懒加载注入器**：阶段 1 验证窗口挂载链上 I18N 解析路径；目录进 eager 主包对首屏体积的影响随 §6.5 一并实测。

## 附录 A：研究结论摘要

### A.1 引擎契约（@aiao/rxdb-i18n / rxdb-i18n-angular，0.0.28）

- 公开面：I18n（I18nRuntime）、I18nOptions、i18nEntities()、四实体、canonicalizeLocale/buildLocaleChain/catalogMessages/messageId/resolveMessage 纯函数、inspection 类型、@aiao/rxdb-i18n/testing 的 assertI18nRuntimeSmoke；Angular 侧 I18N/provideI18n/useI18n/useI18nOptional/useI18nRuntime/I18nBinding（locale: Signal，无 pipe）。
