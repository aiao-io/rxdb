# A03 数据保障实现顺序

依据：ADESK-US-111，当前完整目标的 A03；A01/A02 已完成，A04～A09 仍须继续。

1. 产品归档格式：二进制头、受限 JSON 清单、数据库归档与文件体分段；清单和每段 SHA-256；拒绝路径穿越、重复、截断、尾部垃圾、超限和版本不符。256 MiB 总包上限，不用 base64 扩大内存。
2. 存储代际：保留现有默认数据库/文件根，新增有验证的活动代际指针。恢复在独立 Worker 中创建新数据库和文件目录，避免同一 realm 的实体绑定冲突。校验后才切换 localStorage 的活动指针，旧代际不就地覆盖。
3. 快照：持有现有磁盘跨页锁，调用 adapter.backup 获取一致数据库，然后读取文件根中的完整字节；数据库归档明确不含文件体，产品层一起包装。
4. 恢复协调：开始前校验包与用户确认；保护未保存文档。临时目标有持久记录，失败清理，进程中断后旧指针仍有效；清理失败保留记录供下次恢复重试。旧页写入检查代际，不能写到恢复后的目标。
5. 磁盘工具：真实容量估计、持久存储状态、OPFS 检查、导出/导入/进度与错误、真实 First Aid；抹掉前关闭协商，明确磁盘卷抹除与完整桌面数据重置的区别；均不冒充清空整个 Origin。
6. 中断保障：复用卷的先清 seed 标记再抹掉流程；补文件体与元数据的引用核查、孤儿清理和批量操作中断的日志/恢复。
7. 验证：模型先红后绿；正式构建上跨 Origin 恢复、字节/应用记录/偏好核对、坏包不改旧数据、阶段中断与重试、旧页拒写、配额/OPFS/Worker 注入、键盘与 axe。随后归档所有证据、更新需求和 A03，再继续 A04。

恢复只接受同一桌面 schema；跨版本沿用先用匹配构建恢复再升级的规则。远程来源应用、游戏 localStorage、终端运行时镜像与账号凭据明确排除。真实物理设备与账户交互的人工任务维持原边界。

实施发现：平台 sqlite-wasm 原备份矩阵只支持主线程 memory / idb，产品当前的 OPFS + Worker 被明确拒绝。A03 因此同时补公共适配器的专用 Worker OPFS 路径，复用完整备份共享套件验证。产品恢复 Worker 在自身 realm 中直接持有 OPFS 连接，恢复后同一连接验证 schema、文件引用与逐字节结果，最终销毁；不创建嵌套 Worker。公共适配器的远程 Worker 恢复要求 caller-owned，避免临时连接关闭时终止 Worker 而无法验证、重连和失败重试；client-owned Worker 导出仍支持。SharedWorker 和 idb Worker 不扩大支持范围。

中断协议：导入与复制先把所有新目标登记在 `disk:pending-batch`，失败、重启或下一次磁盘操作时在跨页磁盘锁内撤回本批目标。为使旧构建停止忽略新协议而继续写入，schema 从 `2026111701` 升到 `2026111702`，结构指纹不变。恢复拒绝带未完成批次或无有效磁盘完成标记的数据库，避免首次挂载再次删除刚恢复的内容。

完整桌面重置：数据损坏阻断页的明确确认写入 `aiao-desktop:erase-pending`，先切到新的空代际，再删除本产品所有代际的 SQLite / IndexedDB 数据库及文件目录。恢复、启动、磁盘和写入锁共同排除并发写入；失败保留日志，重开自动继续。名称匹配包含平台的 `@0_1` 后缀，且不清除其他应用的 OPFS、localStorage、缓存、终端镜像或已下载备份。活动指针损坏也可从此入口恢复。正常磁盘卷抹除继续使用先删除种子完成标记再重建的协议，保留应用记录与偏好。
