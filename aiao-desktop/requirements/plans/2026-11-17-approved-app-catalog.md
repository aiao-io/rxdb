# A04 运营批准应用目录

授权：用户要求完成所有不需要人工干预的任务。前置 A03 已完成；对应 ADESK-US-207。

选择随桌面发布的同源静态目录，构建固定 SHA-256；不提供任意 URL 安装入口。目录每项含稳定应用 ID、包标识、版本化 HTTPS 入口、说明和两层权限。无效条目独立拒绝；重复身份拒绝，不能通过顺序覆盖授权。版本入口要求 `/releases/<version>/` 路径且无 query/hash；发布方必须保持这些入口不可变，桌面不把 URL 外观当作远端代码不可变性的密码学证明。

初始正式目录为空：现有 Aiao Code 只有滚动线上入口，不能虚构可回退版本。目录加载、批准校验、安装/更新/卸载/回退和持久化由正式构建的受控目录夹具验收；添加实际远程发布版本需要运营和发布方提供批准条目，这属于外部输入。不会为了让商店看起来有内容自动信任第三方 URL。

实现顺序：

1. 纯目录校验和安装状态转换，红绿单测；安装状态只存 ID/版本/上版，不接受数据库授予能力。
2. 可响应的统一登记表，预装清单保持不变，批准的可选应用叠加；启动时在文件投影前载入安装集。
3. 同源目录读取和已批准缓存；离线或目录失败不破坏已安装入口。失败显示原因与重试。
4. 安装/更新/回退/卸载采用明确确认与未保存协商；持久化和 Applications 投影在磁盘锁下收敛，失败可重试。跨页改变停止旧实例并撤回旧授权。
5. App Store 替换演示书架；Applications、Launchpad、Spotlight、Dock 与宿主都读取同一登记表。预装应用不可卸载；卸载保留用户文件和远程应用自己 Origin 的数据。
6. 专用 Orbit 实例只允许该已安装应用的精确 HTTPS Origin；更新、回退、卸载均结束原实例后使用新入口和权限。避免引入公共 Orbit 的新 API。
7. 正式构建上完整生命周期、离线缓存、非法目录、包冲突、失败与取消、跨页授权收回和键盘/axe；全门禁与证据归档。
