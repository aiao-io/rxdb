# 用户故事：数据变更 PR 创建与生命周期

## 作为/我想要/以便

**作为** 任务作者
**我想要** 把任务分支提交成一个类似 GitHub PR 的数据变更请求
**以便** 指定目标共享分支、持续追加提交并经过团队审核后再合并数据。

## 范围边界

### In Scope

- 一个 PR 记录来源任务、目标共享分支、已同步来源版本、目标版本及当前合并候选；候选未就绪时明确显示待生成。
- 支持草稿、请求审核、关闭、重新打开和合并状态。
- PR 在请求审核后仍可追加提交；来源、目标或候选变化使检查与批准过期，不清除尚未解除的阻塞意见。
- PR 详情可让团队成员看到标题、说明、作者、当前版本和目标共享数据上下文。
- 关闭 PR 不改变共享数据，也不删除提交和讨论；合并后 PR 进入只读历史状态。

### Out of Scope

- 直接连接 GitHub 代码仓库、把数据 PR 当作代码 PR 或自动创建 GitHub issue。
- 首版拆分同一任务为多个可独立合并的记录级 PR。

## 验收标准

| #   | 前置条件                                     | 操作                               | 预期结果                                                                          | 状态 |
| --- | -------------------------------------------- | ---------------------------------- | --------------------------------------------------------------------------------- | ---- |
| 1   | 任务已有服务端确认的同步版本且作者有提交权限 | 创建 PR 并填写标题、说明和目标分支 | 记录任务、已接收来源头及目标头；提示未纳入的本机修改，共享数据不变                | ⬜   |
| 2   | PR 是草稿或待审核且任务追加提交              | 同步新提交                         | 同一 PR 更新来源头及提交列表，旧候选/检查/批准过期，讨论和阻塞意见保留            | ⬜   |
| 3   | 作者准备请求审核但候选或检查未就绪           | 点击请求审核                       | 可进入待审核并开始讨论，显示实际同步版本及候选/检查阻塞；候选通过前不能批准或合并 | ⬜   |
| 4   | PR 已关闭                                    | 有权限的作者重新打开               | 保留提交和讨论；重新验证候选、权限与审核聚合，不自动恢复旧绿色状态                | ⬜   |
| 5   | PR 已合并                                    | 尝试追加或重新打开原 PR            | 保留只读历史，后续变更需要新任务及新 PR                                           | ⬜   |
| 6   | 多名成员同时查看 PR                          | 接收状态、提交和候选更新           | 显示同一服务端当前版本；迟到事件不把 PR 降回旧版本                                | ⬜   |
| 7   | 同任务分叉已另存为新任务                     | 查看原 PR 并为新任务创建 PR        | 原 PR 不被重指到分叉；新 PR 明确关联新任务、原始祖先和新来源头                    | ⬜   |

验收证据：本地实现与验证记录见 [协作实现与验收记录](../../plans/collaboration-implementation.md)；仍需补齐本故事未关闭的逐条三端/部署证据 PR 状态机、持续追加提交、关闭/重开和跨客户端状态同步用例。

## 技术笔记

PR 是持久化协作对象，保存来源/目标、生命周期、当前候选和修订号。C02 定义同步覆盖范围，C04/C05 定义候选与审核聚合。请求审核不要求候选先完成，但批准必须等待 210/211 的最终候选与检查；不能只用来源 commitId 表示完整审核版本。

## 实现文件
