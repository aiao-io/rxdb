# 用户故事：团队操作权限与服务端隔离

## 作为/我想要/以便

**作为** 团队管理员、编辑者、审核者或合并者
**我想要** 分别授予查看、编辑提交、评论、审核、合并和成员管理权限
**以便** 团队可以按职责协作，且任何客户端都不能绕过服务端规则写入数据。

## 范围边界

### In Scope

- 在团队和目标分支范围内授予查看、编辑/提交、评论、审核、合并、成员管理六类操作权限。
- 评论权、审核权和合并权可以独立授予并叠加；被指定为审核人不自动获得合并权。
- UI 的可见性和服务端授权使用同一权限结果；服务端重新校验每个真实操作。
- 业务表、变更日志、任务分支、提交、PR 和 Realtime 频道按团队及可见范围隔离。
- 普通客户端一律不能直接写共享业务表、共享头或合并审计，包括管理员和合并者；业务变化只通过授权原子合并入口。
- 可信初始化只创建空分支与治理元数据，不为业务导入或同步开放例外写通道。

### Out of Scope

- 字段级脱敏、复杂 ABAC、外部身份目录和跨团队委托。
- 将权限判断交给前端缓存、角色名称或可伪造的 `userId`。

## 验收标准

| #   | 前置条件                                                  | 操作                                                   | 预期结果                                                                            | 状态 |
| --- | --------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------- | ---- |
| 1   | 管理员配置查看、编辑/提交、评论、审核、合并和成员管理权限 | 查看权限矩阵并分别操作                                 | 六项权限独立生效，可叠加；其他权限不隐式授予未配置操作                              | ✅   |
| 2   | 成员被指定为审核人但没有合并权                            | 审核并直接请求合并                                     | 可以按权限审核，UI 和服务端均拒绝合并                                               | ✅   |
| 3   | 用户无目标团队或分支操作权                                | 通过 UI、伪造上下文或直接请求读写                      | 服务端明确拒绝，业务数据、PR、日志和同步状态无越权变化                              | ✅   |
| 4   | 用户切换团队或目标分支                                    | 查询业务、提交、PR、讨论、日志和订阅                   | 只读取和订阅当前授权范围；不能通过旧上下文扩大访问                                  | ⚠️   |
| 5   | 具有管理员、编辑或合并权限的普通会话                      | 绕过 PR 直接插入、更新、删除共享数据、共享头或合并审计 | 所有直接写入均被拒绝；合法数据和有合并权也不能绕过候选、检查、审核及原子事务        | ✅   |
| 6   | 成员被移除或权限被收回                                    | 用旧页面或缓存会话重试操作                             | 按最新服务端权限拒绝；客户端收到拒绝后锁定相应上下文并停止其队列                    | ✅   |
| 7   | 三端使用相同权限                                          | 分别操作查看、编辑、评论、审核、合并及成员管理         | 入口、拒绝语义和服务端结果一致                                                      | ⚠️   |
| 8   | 导入、恢复和任务同步请求企图写入共享目标                  | 绕过 UI 发送请求                                       | 服务端拒绝目标错配；只有 212 的合并入口可改变共享业务数据，可信初始化不导入业务内容 | ✅   |

验收证据：HTTP 与服务端单元验证身份、六项权限和伪造请求拒绝；PostgreSQL 集成验证管理员也不能直写共享数据、共享头、审计及版本通知表，陌生人不能读取；三端浏览器验证审核者无合并入口。#4/#7 尚缺跨团队实时订阅与全部六项权限组合的三端浏览器矩阵。 详见 [协作实现与验收记录](../../plans/collaboration-implementation.md)。✅ 表示已有本地验收证据；⚠️ 表示组合场景或部署证据尚不完整，均不等同于故事已交付。

## 技术笔记

权限是服务端事实，共享写入遵循共享契约 C06。RLS、RPC、Realtime 和任务同步均按真实身份与上下文授权；共享业务表对普通会话只读，合并权只授权进入受控事务，不转换为共享表写权限。策略与阻塞意见的管理操作也须按 C05 验证并审计；最终合并的并发授权由 212 验收。
