# 用户故事：本地数据上下文隔离与显式导入

## 作为/我想要/以便

**作为** 已登录的 Admin 使用者
**我想要** 明确选择团队并决定是否导入已有本机数据
**以便** 保留 local-first 使用习惯，同时避免登录后把匿名数据、样例数据或其他团队数据意外上传。

## 范围边界

### In Scope

- 以用户、团队、应用和当前数据上下文隔离本地库、缓存、查询、草稿与同步队列。
- 首次接入团队时明确提供“使用空的团队数据”与“预览后导入已有本机数据”等选择。
- 导入前显示记录数量、实体范围和潜在冲突；确认后导入为待审核的本地变更或任务草稿。
- 按共享契约 C01 恢复或锁定对应上下文；保留内容不代表过期冷启动、退出后或其他账号可读取。

### Out of Scope

- 自动合并匿名库与团队共享数据、跨团队导入和字段级迁移向导。
- 直接把导入内容写入共享数据；导入后的合并由数据 PR 故事验收。

## 验收标准

| #   | 前置条件                                 | 操作                                      | 预期结果                                                                          | 状态 |
| --- | ---------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------------- | ---- |
| 1   | 本机已有匿名数据，用户首次登录并选择团队 | 进入工作台                                | 不自动上传、删除或合并旧数据；先要求选择数据上下文，匿名模式仍独立可用            | ✅   |
| 2   | 用户选择导入已有本机数据                 | 预览并确认导入                            | 显示数量、实体及冲突；内容进入当前团队任务工作树，不立即提交、上传或改变共享数据  | ✅   |
| 3   | 用户在两个团队之间切换                   | 查看列表、搜索、草稿和同步状态            | 只读取当前团队；原团队已保存内容保留，切回后在有权时恢复，不串缓存或队列          | ✅   |
| 4   | 原用户退出或会话自然失效                 | 按 C01 分别热续作、离线冷启动和在线重认证 | 已保存草稿始终保留；仅矩阵允许的上下文可解锁，过期冷启动和主动退出不展示原内容    | ✅   |
| 5   | 上下文刷新或另开标签页                   | 查询、保存和同步                          | 使用同一身份/团队/应用/任务键，重新执行冷启动判定，不借其他标签页遗留内存越过锁定 | ✅   |
| 6   | 三端使用相同账户和团队                   | 执行首次接入、切换和导入                  | 确认语义、隔离边界和共享数据结果一致                                              | ✅   |
| 7   | 账号 A 有待发送队列或在途回执，切换到 B  | 处理通知、恢复队列或加载本机任务          | B 不能访问或发送 A 的内容；A 的迟到结果只关联 A 上下文，待 A 重新验证后查询恢复   | ✅   |

验收证据：IndexedDB 单元验证用户/团队/应用/任务的物理隔离、并发写入和持久化锁；controller 验证账号切换及迟到请求；三端浏览器验证双团队切换后各自草稿恢复、跨团队 API 拒绝、预览确认导入且原匿名库和共享头保持。 详见 [协作实现与验收记录](../../plans/collaboration-implementation.md)。✅ 表示已有本地验收证据；⚠️ 表示仍缺外部环境证据，均不等同于故事已合入或已部署。

## 技术笔记

上下文键必须进入数据库名、偏好键、同步过滤和缓存索引，不能只存在于框架内存中。C01 定义解锁条件，C02 定义导入后的保存/提交状态。账号切换停止旧订阅和未发送队列，已提交远端的请求通过原幂等键查询，不把取消请求误当回滚。

## 实现文件

本故事的产品实现位于私有包 `rxdb-admin-template/packages/collaboration/`，三端通过 `/collaboration` 路由接入同一共享 UI。具体入口（2026-11-18 起，ADMIN-US-221）：团队库按「用户 × 团队 × 应用」分库，见 `rxdb-admin-template/packages/collaboration/src/client/team-database.ts`、`task-ledger.ts`；匿名导入见 `src/client/import-anonymous.ts`；回归用例在 `e2e/collaboration.spec.ts`。

验收记录与未关闭边界见 [协作实现与验收记录](../../plans/collaboration-implementation.md)。故事保持 `In Review`，不把本地实现或测试结果直接等同于已合入、已部署的 `Done`。
