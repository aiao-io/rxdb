# 用户故事：数据 PR 讨论、评论与变更定位

## 作为/我想要/以便

**作为** PR 作者、评论者或审核者
**我想要** 在变更上下文中讨论并把评论定位到具体记录、字段和提交版本
**以便** 团队能围绕数据事实沟通，知道哪些问题必须处理后才能合并。

## 范围边界

### In Scope

- PR 详情提供“讨论、提交、数据变更、检查”四个页签。
- 评论可以定位到实体记录、字段及来源提交或最终候选版本，并支持回复、标记处理和重新打开。
- 普通评论用于记录意见，不阻塞合并；标记为“必须处理”的问题阻塞合并。
- 新提交或候选变化后保留旧定位；未解决的必须处理线程继续阻塞，已解决线程的锚定结果变化时要求重新确认。
- 讨论权限与 PR 可见范围、团队和当前版本一致。

### Out of Scope

- @mention、站内通知、邮件通知、富文本附件和讨论搜索；后续增强见 [ADMIN-US-214](ADMIN-US-214-comment-notifications.md)。
- 实时在线成员和当前查看记录；见 [ADMIN-US-215](ADMIN-US-215-presence.md)。

## 验收标准

| #   | 前置条件                             | 操作                             | 预期结果                                                                                        | 状态 |
| --- | ------------------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------------- | ---- |
| 1   | 用户有权查看 PR                      | 打开并切换四个页签               | 讨论、提交、数据变更和检查分别呈现，保留当前 PR 和版本上下文                                    | ⬜   |
| 2   | 用户有评论权限                       | 对记录字段或最终冲突结果发表评论 | 记录来源提交或 candidateId、字段、快照和作者，能回到对应版本的值                                | ⬜   |
| 3   | 线程已有参与者且操作人具评论处理权限 | 回复、标记处理或重新打开         | 保留回复与处理历史、操作者和时间，状态变化可追溯                                                | ⬜   |
| 4   | 存在普通评论和必须处理线程           | 查看合并条件                     | 普通评论不阻塞；未处理的必须处理线程明确阻塞并定位来源                                          | ⬜   |
| 5   | 作者追加提交或重新生成候选           | 查看历史评论及合并条件           | 旧评论不移动；未处理阻塞继续保留，已解决的必须处理线程若锚定字段/记录结果变化或消失则重开待确认 | ⬜   |
| 6   | 用户无当前 PR 评论权限               | 新增、回复或改变处理状态         | UI 和服务端拒绝，已有讨论不变                                                                   | ⬜   |
| 7   | 三端打开同一 PR                      | 查看定位、处理状态和历史         | 内容、字段、候选及阻塞结果一致                                                                  | ⬜   |
| 8   | 审核者另有要求修改结论               | 解决一条必须处理线程             | 只更新线程，不自动清除 209 的要求修改；两个阻塞来源独立显示与验收                               | ⬜   |

验收证据：待实现后补充四页签、字段级评论、版本保留、必须处理阻塞和权限负例用例。

## 技术笔记

定位保存实体、主键、字段、来源提交或 candidateId 及必要快照，不能只保存行号。候选变化后对锚定结果比较，已解决的必须处理线程按 AC #5 重新打开；普通旧评论保持历史且不阻塞。线程处理与审核结论是独立状态，任何一个仍阻塞都不能合并。
