# 用户故事：数据差异展示与合并前检查

## 作为/我想要/以便

**作为** PR 审核者或合并者
**我想要** 看懂整单数据差异并看到合并前检查结果
**以便** 在数据进入共享分支前发现完整性问题，而不需要直接比较底层数据库或 SQL。

## 范围边界

### In Scope

- 展示新增、修改、删除记录以及字段前后值，按实体、记录和提交组织。
- 展示关联删除影响、关联完整性、唯一性和编辑/删除冲突等检查。
- 检查结果使用业务语言，包含失败原因和需要处理的记录定位。
- 检查绑定来源提交版本和目标共享版本；任一版本变化后标记过期并重新检查。
- 检查失败或过期时阻塞合并，但不阻止团队查看问题并继续讨论。

### Out of Scope

- 自动替用户决定冲突值、字段级访问控制和任意 SQL 差异编辑器。
- 首版只保证整单任务差异，不承诺记录选择器式部分提交。

## 验收标准

| #   | 前置条件                                    | 操作                     | 预期结果                                                                       | 状态 |
| --- | ------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------ | ---- |
| 1   | PR 有当前来源提交和目标共享版本             | 打开“数据变更”页签       | 清楚列出新增、修改、删除，显示记录身份和字段前后值；没有把未变化字段伪装成修改 | ⬜   |
| 2   | 草稿删除了带关联记录的父实体                | 查看差异和检查           | 显示可能受影响的关联记录和删除影响，使用业务可理解的描述                       | ⬜   |
| 3   | 草稿包含重复值、缺失关联或非法编辑/删除关系 | 运行合并前检查           | 每项问题有明确状态、原因和定位；检查失败阻塞合并                               | ⬜   |
| 4   | 目标共享分支在检查后产生新版本              | 再次打开 PR              | 原检查标记为过期，必须针对当前目标版本重新计算，不能继续显示旧的通过状态       | ⬜   |
| 5   | 检查正在运行或服务端返回错误                | 查看 PR 检查页签         | 显示进行中或失败原因；未得到当前版本的通过结果时不能合并                       | ⬜   |
| 6   | 三端打开同一版本的差异                      | 对照实体、字段和检查状态 | 展示顺序、值语义、阻塞原因和版本标识一致                                       | ⬜   |

验收证据：待实现后补充新增/修改/删除、级联影响、完整性负例、目标头变化和检查失败的集成用例。

## 技术笔记

差异生成必须以共同起点、来源当前版本和目标当前版本为输入，不能只比较客户端当前快照。检查结果应带版本指纹，服务端合并前重新验证。用户界面可以用表格和摘要呈现，但不能隐藏字段级前后值或关联删除影响。

## 实现文件

- `rxdb-admin-template/apps/react/src/app/data-pr/diff/` — 差异分组、字段前后值和检查页签。
- `rxdb-admin-template/apps/angular/src/app/data-pr/`、`rxdb-admin-template/apps/vue/src/app/data-pr/` — 三端等价入口。
- `packages/rxdb-plugin-working-tree/` — 分支比较和变更读取能力。
- `supabase/` — 服务端完整性检查与版本指纹。
