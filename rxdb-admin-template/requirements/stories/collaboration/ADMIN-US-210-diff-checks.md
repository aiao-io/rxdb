# 用户故事：数据差异展示与合并前检查

## 作为/我想要/以便

**作为** PR 审核者或合并者
**我想要** 看懂整单数据差异并看到合并前检查结果
**以便** 在数据进入共享分支前发现完整性问题，而不需要直接比较底层数据库或 SQL。

## 范围边界

### In Scope

- 展示新增、修改、删除记录以及字段前后值，按实体、记录和提交组织。
- 展示关联删除影响、关联完整性、唯一性和编辑/删除冲突等检查。
- 检查结果使用业务语言，包含失败原因和需要处理的记录定位。
- 初步检查记录 B/S/T；完整合并检查绑定最终 candidateId、结果和 schema/策略版本，冲突解决前不能声称最终通过。
- 来源、目标、冲突选择或相关规则变化后，检查过期并对新候选重新运行。
- 检查失败或过期时阻塞合并，但不阻止团队查看问题并继续讨论。

### Out of Scope

- 自动替用户决定冲突值、字段级访问控制和任意 SQL 差异编辑器。
- 首版只保证整单任务差异，不承诺记录选择器式部分提交。

## 验收标准

| #   | 前置条件                                      | 操作                 | 预期结果                                                       | 状态 |
| --- | --------------------------------------------- | -------------------- | -------------------------------------------------------------- | ---- |
| 1   | PR 有当前来源提交和目标版本                   | 打开数据变更页签     | 列出新增、修改、删除和字段前后值，不把未变化字段算作修改       | ✅   |
| 2   | 任务删除了有关联记录的父实体                  | 查看差异和检查       | 显示受影响记录、删除及级联影响                                 | ✅   |
| 3   | 最终候选含重复值、缺失关联或非法编辑/删除关系 | 执行服务端检查       | 返回问题原因和定位，失败阻塞批准与合并；不能只验证原始来源提交 | ✅   |
| 4   | 来源、目标、冲突选择、schema 或策略版本变化   | 重新打开 PR          | 旧检查过期，针对新候选重检，不沿用相同来源头的旧通过结果       | ✅   |
| 5   | 检查运行中、服务失败或冲突未解决              | 查看检查页签         | 显示待处理或失败状态；初步检查不能冒充最终候选检查通过         | ✅   |
| 6   | 三端查看同一候选                              | 对照字段、检查和版本 | 展示顺序、值语义、阻塞原因和候选标识一致                       | ✅   |
| 7   | 来源提交合法但手工冲突值造成唯一性或引用违规  | 生成候选并重检       | 针对最终结果失败，旧来源检查和批准不能授权该结果               | ✅   |
| 8   | 检查 C1 的请求迟到返回，PR 已切到 C2          | 接收结果             | 历史可记录 C1 结果，C2 不得被标绿；服务端只认当前候选的检查    | ✅   |

验收证据：records/engine 验证字段差异、唯一性、引用、类型、手工最终结果检查和候选失效；三端浏览器覆盖跨实体级联删除的最终差异、候选检查，以及服务失败保持未通过、按原幂等键恢复检查。 详见 [协作实现与验收记录](../../plans/collaboration-implementation.md)。✅ 表示已有本地验收证据；⚠️ 表示仍缺外部环境证据，均不等同于故事已合入或已部署。

## 技术笔记

C04 的 candidateId 是最终检查身份；B/S/T 的初步差异只是输入。210 先定义差异和候选检查接口，211 接入候选生成及冲突后的重检，209 在完整链路后才可验收批准。平台 US-312 不包含产品三方冲突解决或服务端检查；这些仍需本产品实现。

## 实现文件

本故事的产品实现位于私有包 `rxdb-admin-template/packages/collaboration/`，三端通过 `/collaboration` 路由接入同一共享 UI。具体入口：`rxdb-admin-template/packages/collaboration/src/records.ts`、`src/server/governance.ts`、`src/client/pr-view.ts`、`src/server/engine.spec.ts`。

验收记录与未关闭边界见 [协作实现与验收记录](../../plans/collaboration-implementation.md)。故事保持 `In Review`，不把本地实现或测试结果直接等同于已合入、已部署的 `Done`。
