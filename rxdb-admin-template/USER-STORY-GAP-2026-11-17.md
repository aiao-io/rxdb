### 3.3 建议新增的产品级功能（当前无任何故事覆盖）

以下为本次分析建议补入的产品故事，按优先级分组。编号为建议编号，正式创建时按 CONVENTIONS.md 分配。

#### P0 · 阻塞交付闭环

1. **生产部署与运维闭环（建议 ADMIN-US-217）**
   问题：19 条 In Review 故事共同阻塞在「未正式部署」。产品目前没有覆盖 Supabase 项目部署、迁移自动执行、环境配置与 secrets 管理、staging 环境、部署后逐条 AC 验收的故事。
   建议 AC：迁移脚本在干净 Supabase 项目可重复执行；部署流水线自动跑迁移；环境变量集中管理且前端不含 secret；部署后跑一轮三端完整 e2e 与 RLS 验收；发布记录与回滚预案。
   依赖：US-001、US-201～216 的实现。

2. **生产冒烟与监控（可并入 ADMIN-US-217）**
   问题：无错误上报、无可用性探针。作为 Admin 模板，接入 Sentry 类错误监控与健康检查值得一条轻量故事。

#### P1 · 产品完整性（Admin 模板通用能力，当前完全缺失）

3. **自助创建团队/组织（建议 ADMIN-US-218）**
   问题：US-202 明确 Out of Scope「自助创建团队界面」，当前团队只能靠可信服务端初始化+邀请。作为模板产品，使用者无法自助建团队是硬限制。
   建议 AC：登录用户可创建团队（配额内）、自动成为管理员；创建后可直接邀请成员；服务端防滥用（频率限制/验证邮箱）。

4. **账号与个人设置页（建议 ADMIN-US-219）**
   问题：US-201 有重新认证入口，但无账号管理界面。缺：修改/验证邮箱、查看并注销活跃会话、账号注销与数据处置说明。
   建议 AC：设备会话列表与远程注销；改邮箱后旧邀请匹配规则明确；注销账号的团队数据处置策略（管理员移交或锁定）。

5. **数据导入导出增强：CSV 导入/导出（建议 ADMIN-US-220）**
   问题：本地备份恢复（归档文件）已有，团队云端数据没有批量导出/导入通道；CSV 是 admin 高频格式，当前无任何故事。
   建议 AC：实体列表按当前筛选导出 CSV；导入走任务草稿（复用 US-204 的预览+不直写共享数据语义）；字段映射与错误报告；编码与大数据量分页。

6. **批量操作与回收站（建议 ADMIN-US-221）**
   问题：无批量删除/修改、无软删除/回收站故事。admin 使用中高频，且与协作模型有交互（批量操作如何进入任务草稿）。
   建议 AC：列表多选批量编辑/删除进入当前任务草稿；删除默认软删除并可在期限内恢复；恢复/清理同样走 PR 审核路径。

7. **通知中心统一页面（建议 ADMIN-US-222）**
   问题：US-214 落地了通知数据、未读状态与跳转，但通知入口分散在 PR 视图内；缺独立的通知中心页（列表、批量已读、按团队/类型筛选）。
   建议 AC：全局入口显示未读计数；按团队/PR/提及过滤；跨团队隔离与权限一致。

8. **无障碍（a11y）产品级门禁故事（建议 ADMIN-US-223）**
   问题：react-e2e 已有 `admin-shell.a11y.spec.ts`、`workbench.a11y.spec.ts`，但没有产品故事把三端 a11y 统一纳入验收门禁，协作新增 UI（PR 四页签、评论、审批）的 a11y 未被任何故事约束。
   建议 AC：三端共享 a11y 套件覆盖外壳、实体页与协作页；键盘可达、对比度、ARIA 标签；新页面接入 a11y 检查纳入 PR 模板。

9. **性能预算持续门禁（建议 ADMIN-US-224）**
   问题：T04（大日志量查询预算）、T05（构建体积）做过一次性验证，但预算没有变成 CI 持续门禁，也没有故事约束新增页面的性能预算。
   建议 AC：首屏体积与 Dashboard 查询预算进入 CI；协作页（PR 列表、差异页）纳入预算；超预算需显式豁免记录。

#### P1 · 协作深度（各故事 Out of Scope 中的高价值项）

10. **记录级部分提交/多 PR 拆分**
    出处：US-205「首版不提供部分记录选择器」、US-207「首版拆分同一任务为多个可独立合并的记录级 PR」。
    建议：任务草稿按记录/实体勾选生成提交；同一任务可开多个 PR 或按记录集拆 PR。

11. **字段级权限与数据脱敏**
    出处：US-203 Out of Scope「字段级脱敏、复杂 ABAC」。
    建议：敏感字段按权限脱敏显示与导出；字段级只读/可编辑授权；与六类操作权限正交。

12. **审批流增强：自动分配审核人、审批代理**
    出处：US-209 Out of Scope「首版自动选择审核人、审批代理」。
    建议：PR 创建时按团队规则推荐/分配审核人；审核人休假代理；与 US-216 多级审批衔接。

13. **共享版本浏览与版本间对比 UI**
    出处：US-213 已有历史与恢复草稿，但只读浏览的版本间差异对比、时间线视图仍简陋。
    建议：共享版本列表页；任意两版本差异视图；从任意版本一键创建恢复草稿（已有）完善为列表入口。

#### P2 · 增强与扩展

14. **Webhook / 外部集成**：合并、评论、成员变更事件推送到外部系统（webhook + 签名校验）。
15. **深链分享**：PR、记录、通知的分享链接与打开（当前邀请链接由管理员复制，PR 分享无故事）。
16. **报表与图表**：统计口径确认后的资产状态分布、维护费用等概览（已列为候选，需真实场景）。
17. **富文本评论与附件**：US-208 Out of Scope「富文本附件」。
18. **组织层级/跨团队共享**：US-202 Out of Scope，P2，等团队规模场景出现。
19. **移动端完整验收故事**：US-102 覆盖桌面/移动导航，但无完整移动端体验验收（表单、协作页、离线）。
20. **OAuth / 企业 SSO**：已在 future-requirements 登记，邮箱 OTP 稳定后立项。
21. **独立仓库启动模板 / CLI**：已在 future-requirements 登记，协作闭环稳定后立项。

## 5. 代码评审发现对故事的影响（见 CODE-REVIEW-2026-11-17.md）

- **US-201 需回填**：离线冷启动后 `autoRefreshToken` 永久失效（controller.ts:67，P1），锁出时丢弃编辑缓冲——修复后需重验 AC#4/#5 的「离线打开后再联网」场景；AC#2/#3 的外部环境证据（SMTP 投递、验证码自然过期）仍待真实环境补验。
- **运维故事（建议 217）应包含**：工作区状态无界增长治理（receipts/audit/notifications 修剪、快照分页）、admin_audit 索引、请求体超时——评审发现的这些运维项是「长期运行后可用性」的硬条件，建议直接写进 217 的 AC。
- **工程门禁类新故事/任务**：协作词条逐键校验门禁（api.ts:45 已漏一条）、TSDoc 公开面门禁（model.ts 等）、三端测试深度对齐（页面级单测）、Playwright 失败产物出库——属工程任务，不必单独成故事，但建议并入 US-217 或作为 PR 检查项。
- **邀请 token 进 URL query（admin-view.ts:85）**：涉及安全卫生，建议在 US-202 范围内以 AC 修订或小故事方式收敛（token 移 fragment）。

## 6. 与平台故事的衔接

- 产品故事继续用 `capabilities` 引用平台能力（如 US-526 工作台、US-527 备份恢复、US-910 数据级翻译），不在产品内复制平台故事。
- 数据级多语言翻译（平台 US-910）在真实业务实体（US-101）落地时需在产品端接线，建议作为 US-101 的前置备注而非新故事。
- a11y 与性能门禁建议产品级建故事，但实现复用仓库级 e2e/a11y 基础设施与根需求门禁机制。
