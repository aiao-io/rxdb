## 后续优化建议，待确定范围

### T04 · P1 · 最近活动的大日志量查询成本

现状：[dashboard-activity-source.ts](../../src/app/pages/dashboard-activity-source.ts) 对当前分支的匹配日志执行 `findAll`，由 [dashboard-model.ts](../../src/app/pages/dashboard-model.ts) 聚合后截取五个操作单元。显示五条并不代表只读取五条。

- [ ] 先测量千条、万条、十万条日志下的读取行数、查询与聚合耗时、页面可交互时间和内存，建立三端可比较的基线，再确定预算及优化方案。
- [ ] 评估按操作单元读取或分批读取的方案；必须保留事务边界、同毫秒排序、当前分支隔离、撤销及重做失效状态。
- [ ] 针对跨批次事务、一个事务超过五条、分支切换和刷新持久化先写测试，再实现并比较性能结果。

验收条件：五个操作单元结果与现有语义一致，读取成本满足事先约定的预算，三端共享用例通过。禁止直接对原始日志 `limit 5`，以免截断事务或不足五个操作单元。
