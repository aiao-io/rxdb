# 路线图

本页回答「接下来做什么、什么必须排在什么前面」。故事状态与关闭条件见[状态概览](status-overview.md)，范围决策与外部条件见[决策](decisions.md)，证据分层见[验收记录](verification-report.md)。决策确定、计划完成、代码实现和真实环境验收分别记录。

## 产品主路径

**给团队的局域网文件池：账号下所有设备与成员的文件资产一屏可见，按需点对点拉取，字节不走服务器，无人在线时回退云端。** 产品本质是「云盘式资产视图 × P2P 零存储传输」。技术底座是根 requirements 的 epic-011 六条故事（rxdb:US-704～US-708、US-713）与 epic-012 立项池（US-709～US-712），本目录只维护产品化增量。

## M1 当前任务顺序

M1 是浏览器侧能完成的 MVP 补齐项，五件事各有归属：

| 工作线                                       | 下一步                                                                                                           | 前置与边界                                                                                             |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 管理后台（rxdb:US-713）                      | AC#11 等首次 CI 运行确认；上线正式环境（执行 secret 与 SQL，见[验收记录](verification-report.md)）；清理测试账号 | 本机管理页与 /admin 分离；管理身份用 Worker secret 白名单，不降级放行                                  |
| 回退内容加密（POOL-US-101）                  | 实现已合入；补 AC5 的端到端篡改验证，AC6 随 rxdb:US-705 续传补验，阶段 D 在正式环境复验 AC1、AC2                 | 依赖 rxdb:US-706 回退路径与 rxdb:US-708 会话层；服务器不可读是验收硬线；旧客户端明确报错不落明文       |
| 断点续传（rxdb:US-705 范围）                 | 按 US-705 承诺补齐；加密分块与续传的交互在 POOL-US-101 的 AC 里一起验收                                          | 续传是传输层能力，不单独建产品故事                                                                     |
| 自定义域名 + 独立部署线                      | 工程项：wrangler 绑定 pool.aiao.io、发布脚本与回滚点更新                                                         | 域名也是品牌前提；workers.dev 在大陆不可达（D-06）                                                     |
| 速率限制 + 举报 + 邀请制 beta（POOL-US-102） | 实现已合入；补 AC9 的真栈限流存储与日志检查                                                                      | 服务端断言，不是前端隐藏；滥用治理是 M1 必选（Firefox Send 死因的解药）；M1 验收的滥用演练在本故事闭环 |

**非 MVP**：桌面端（M2）、TURN 跨网（D-07 预留）、移动端、国内合规基础设施（D-06）。
