## 1. 一句话定位

**给团队的局域网文件池：账号下所有设备与成员的文件资产一屏可见，按需点对点拉取，字节不走服务器，无人在线时回退云端。**

目标市场：10–100 人团队的内部大文件共享（设计稿、视频素材、模型、数据集、构建产物）。产品本质是「云盘式资产视图 × P2P 零存储传输」，两端的好处都拿：直传的速度与隐私 + 云盘的账号与持久性。

## 2. 立项依据（为什么现在做）

- **市场规模**：全球文件共享软件 ~112 亿美元（2025）→ 264 亿（2031），CAGR ~15%，「点对点」为增长最快细分；安全文件传输细分 Top 10 份额仅 ~20%，无垄断者。
- **空白确认**（调研 29 个产品后的结论）：没有一家同时具备「账号/历史/持久清单 + 可靠传输 + 内容加密 + 可持续商业模式」，每家至少缺两环——而我们已上线的正是「账号 + 持久清单 + P2P 多源直传 + 校验隔离 + 服务器回退」这个组合，**市场空白是真的**。
- **行业窗口**：Snapdrop/ShareDrop 被收购后 P2P 代码下架、社区反噬；WeTransfer 免费档砍到 10 次或 3GB/30 天且强制注册；奶牛快传 2026-01 停服；Resilio 被收购。存量产品在收缩，信任型工具在缺位。
- **零先例风险同样明确**：纯浏览器 P2P 传输至今没有一家跑通订阅变现——立项要赌的不是「有没有需求」，而是「团队场景能否付费」。本方案按低成本渐进验证来设计。

## 3. 目标用户与核心场景

**P1 团队/工作室**（设计师、视频、研发小组）：把大文件分发给同事，不想传网盘（限速/泄露）、IM（压画质/过期）、服务器（吃带宽）。
**P2 单人多设备**：公司/家里机器之间按需取文件，不装同步软件。

核心场景（按优先级）：

1. 团队内分发大文件——「共享即发布」，同事一屏看到、按需拉取
2. 跨设备取文件——家里机器拉公司机器上的素材
3. 内网/弱网环境——断外网时局域网照传（epic-011 愿景的原生场景）
4. 无人持有时回退——服务器副本兜底，不依赖任何一台机器在线

**反场景（明确不做）**：陌生人一次性分享（无账号体系的产品定位）、目录级双向同步（Syncthing 的地盘）、移动端（首版不做，iOS Safari 对大文件直传有公认瓶颈）。

### MVP（产品化 v1）——必须补齐的五件事里浏览器侧能完成的

1. **管理后台 US-713**——滥用治理是 Firefox Send 死因的解药，必须进 MVP 而不是收尾项
2. **回退内容加密**——R2 明文落盘是隐私叙事硬伤，补齐方式：客户端加密后上传
3. **断点续传**——US-705 承诺的一部分，大文件体验的及格线
4. **自定义域名 + 独立部署线**——workers.dev 与 supabase.co 在大陆不可达，域名也是品牌前提
5. **速率限制 + 举报 + 邀请制 beta**——控制滥用与成本，验证真实团队使用

**非 MVP**：桌面端（v2）、TURN 跨网（预留决策 D7）、移动端、国内合规基础设施（D6）。

### 版本规划

- **v1（MVP）**：浏览器版 + 上表 5 项，邀请制 beta 上线
- **v2（桌面端）**：Electron 优先（办公主力是 Win/mac；US-707 阶段 B 验收口径：1 GiB 大文件、断外网传输、离线 TTL），Tauri 补位，局域网发现增强；形态可行性见 §7
- **v3（纵深或下放）**：epic-012 协作能力（库克隆/实时信号）走团队纵深；C 消费级下放为远期选项（D1 已定 A）；Chrome 扩展作为增量渠道（企业强制分发，见 §7）

## 6. 技术路线与复用家底

- **协议层**：`@aiao/rxdb-plugin-p2p`（会话层、分块校验、续传接口、多协议复用）已随 PR #172 合并——v2 桌面端直接复用同一会话层
- **服务端**：Cloudflare Worker + DO 信令 + R2 回退，已上线运行（版本 aa0962b2，8/8 验收）
- **账号/清单**：Supabase Auth + rxdb-plugin-sync + wa-sqlite 本地库，已上线
- **桌面端**：仓库已有 `rxdb-adapter-electron` / `rxdb-adapter-tauri` 与 dev-rxdb-electron / dev-rxdb-tauri 双进程经验
- **工程**：monorepo CI / e2e / 发布配方齐全；增量投入集中在产品故事，不在基建
- **成本结构（护城河）**：P2P 直传边际成本≈0（信令 DO + Supabase 免费档）；成本只发生在回退（R2 存储，Cloudflare egress 免费）。云中转竞品（WeTransfer 式）的成本随用量线性涨，我们的不涨——这是「零存储」模式的结构性优势

## 7. 形态路线：浏览器 → 桌面端 → Chrome 扩展（可行性已查证）

产品有四种运行形态，常驻能力与天花板不同，路线按「浏览器（M1）→ 桌面端（M2）→ Chrome 扩展（增量）」推进：

| 形态            | 常驻能力         | 覆盖                        | 角色                                                     |
| --------------- | ---------------- | --------------------------- | -------------------------------------------------------- |
| 浏览器页面      | 开页面才在线     | 全平台免安装                | MVP 形态                                                 |
| Electron 桌面端 | 托盘常驻、真后台 | Win/mac                     | v2 先行：与浏览器同内核、开发最快，阶段 B 验收口径已定义 |
| Tauri 桌面端    | 托盘常驻、真后台 | Win/mac/Linux               | epic 三运行时承诺；轻量常驻的长期形态                    |
| Chrome 扩展     | 浏览器开着才在线 | Chrome/Edge，企业可强制安装 | 轻量伴侣 / B2B 分发渠道                                  |

**Tauri 可行**：仓库已有 `rxdb-adapter-tauri` 与 `dev-rxdb-tauri`（macOS WebView 验证过），wa-sqlite 是 WASM 照跑；协议层不用改——桌面传输走 TLS TCP，US-708 双进程夹具已验收，Tauri 侧只需把 TCP 服务放进 Rust 进程（plugin/command）。加分：二进制与内存比 Electron 小一个量级（常驻托盘成本低），原生文件系统绕开 OPFS 配额与逐出（1 GiB 目标的正确归宿）。代价：Rust 工具链、WKWebView/WebView2 双 WebView 差异、独立 CI lane。结论：Electron 先行、Tauri 随后补齐；长期只保一个常驻形态时 Tauri 更合适。

**Chrome 扩展可行但天花板明确**（关键事实已查证）：MV3 service worker 不能直接建 `RTCPeerConnection`（[W3C webrtc-pc #230](https://github.com/w3c/webrtc-pc/issues/230)、[ServiceWorker #1522](https://github.com/w3c/ServiceWorker/issues/1522) 长期未决）；官方正解是 [Offscreen Document](https://developer.chrome.com/blog/Offscreen-Documents-in-Manifest-v3)（Chrome 109+，`WEB_RTC` reason），且官方确认离屏页允许嵌跨源 iframe（CSP 放行 `frame-src` 即可）——**嵌自己域名的 iframe 跑现有前端核心**：文件与页面同源 OPFS，现有已共享文件零迁移、代码零改动。保活：SW 挂信令 WebSocket，心跳重置 MV3 的 30 秒空闲计时；离屏页被浏览器回收时用 SW 心跳 + `getContexts()` + `chrome.alarms`（≥30 秒）自愈重建，偶尔出现秒级~30 秒级离线窗口，断点续传可接续。能做到：**不开 p2p 页面也能对「页面里共享过的现有文件」持续做种与接收**；企业 Chrome 策略强制安装是现成的 B2B 分发渠道。做不到：Chrome 关掉即离线；无原生局域网发现（mDNS/UDP）；任意本地目录文件不可读；Firefox 另构建、Safari 需配宿主 App。

## 8. 商业化假设

- **模式假设**：免费个人档（设备数上限、回退单次 ≤100MB）+ Team 席位订阅（管理后台、回退配额与更大单文件、保留期、优先支持）
- **定价锚点**（第三方口径已标注）：文叔叔 VIP ~¥450/年、Send Anywhere ~$6–10/月、Tailscale $8/用户/月、WeTransfer Starter €8/月、奶牛快传 Pro ¥99–799/年 → **建议 Team 档 ¥30/席位/月（约 $5）起步**，beta 期间验证转化率后再定
- **收入假设**：该品类无 P2P 订阅先例，**首年不设收入硬指标**，目标是把「团队愿意为回退 + 治理付费」验证掉（M3 复盘）
- **注意**：Send Anywhere 的订阅变现不顺、Snapdrop 的社区无法货币化都是前车之鉴——付费点必须挂在「管理、配额、保障」上，而不是「传输」本身

## 10. 风险与对策

1. **滥用（Firefox Send 死因）**：恶意软件/钓鱼分发可以直接杀死产品 → M1 管理后台必选、速率限制、举报；账号体系本身就是门槛
2. **LAN 连不上**（组播屏蔽的办公网）：A 定位下是可接受边界 → 桌面端局域网发现 + US-712 枢纽兜底；团队出现跨网需求再议 TURN（D7 预留）
3. **变现无先例**：→ 低成本渐进（直传零成本撑免费档）、付费点挂在管理与配额上、不押首年收入
4. **国内不可达**：workers.dev / supabase.co 大陆直连不通 → D6 已定：首期只做海外与有代理能力的团队（aiao 现有用户群）；国内立项待首期验证后单独评估
5. **可持续性**：本赛道基础设施普遍由个人硬撑 → 我们的边际成本结构 + 邀请制控量，先算清单次回退成本再放量
