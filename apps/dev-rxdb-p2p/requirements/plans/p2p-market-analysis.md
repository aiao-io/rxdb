# dev-rxdb-p2p 产品化：市场调研与对比分析

> 调研日期 2026-11-05。竞品数据来源：官网/官方 FAQ/GitHub + 第三方评测，关键事实附来源链接（完整版见本报告附录），GitHub 星数等为当日 API 快照。查不到的一律标注「待核」，未编造。

## 一、产品现状速写（codex/p2p-file-share 分支）

**愿景（epic-011）**：公司内网里，大文件在已持有副本的机器之间点对点直传——元数据（谁有什么）走同步、字节流不经服务器；断外网时局域网照传；没有 peer 在线时回退服务器直下。

**已落地**（浏览器半边，线上 8/8 验收全绿，live 于 aiao-rxdb-p2p.aiao.workers.dev）：

- 同账号多设备登录（Supabase Auth），设备登记 + 文件持有清单经 rxdb-plugin-sync 同步——**持久化的「谁有什么」视图**
- WebRTC DataChannel 局域网直传；**多源分块下载**（块图区分 A/B 来源）、逐块 SHA-256 校验、**坏 peer 隔离**
- 心跳失联检测（6 秒超时）、Ed25519 连接票据、OPFS 本地存储
- 服务器回退：Cloudflare Worker `/api/files/:hash` + R2（单次上传 ≤100 MB）
- 会话层（US-708）：一对设备一条已认证会话、多协议复用，已随 PR #172 合并
- `/manage` 本机管理页；管理后台（US-713）、桌面端（Electron/Tauri）、断点续传在计划内

**明确非目标**：不做 STUN/TURN（无公网 P2P）、不做目录级双向同步（非 Syncthing 式）、不做字节级持久加密（链路加密有，落盘加密另有 US-803）。大文件目标：浏览器 ≥256 MiB、桌面 ≥1 GiB。

## 二、市场全景

- 全球文件共享软件市场 ~112 亿美元（2025）→ 264 亿（2031），CAGR ~15%，「点对点」被列为增长最快细分；安全文件传输（SFT）细分 56.9 亿（2026）→ 83.4 亿（2031），Top 10 厂商份额仅 ~20%——**高度碎片化，无垄断者**。
- 行业事件：LimeWire 2025-02 收购 Snapdrop/ShareDrop 转云存储（社区反噬，Trustpilot 2.5/5）；WeTransfer 2024-12 被 Bending Spoons 收购后免费档砍到 10 次或 3GB/30 天且强制注册；Resilio 2026-03 被 Nasuni 收购；**奶牛快传 2026-01-10 停服**；Pixel 10 与 AirDrop 互通（2025-11）。

## 四、最接近竞品逐个短板（要点）

1. **PairDrop**（形态最接近）：跨网时官方明言须信任其服务器；无账号、无历史；公共实例由单个维护者自费承担，无商业模式。
2. **Wormhole.app**（E2EE 最强）：≤5GB 实为加密服务器暂存（非 P2P）；>5GB 要求双方同时开页面、依赖 NAT 打洞；闭源不可自托管；Pro 档迟迟未上线。
3. **file.pizza**（最纯粹的浏览器 P2P）：无应用层 E2EE；大文件受浏览器内存约束；无账号无历史；靠捐赠。
4. **ToffeeShare**：E2EE 仅 DTLS；打洞失败走官方中继即内容过其服务器；双人业余团队，可持续性天花板。
5. **Send Anywhere**：唯一有账号+付费档的「直传」老牌，但链接模式实为服务器中转、48 小时过期；传输加密无官方说明；PLUS 停服→Email Add-on 说明变现也不顺。
6. **Tailscale Send**：功能强但**只能在自己设备间传**，不能发给别人，且绑定 Tailscale 订阅。

**横向归纳**：没有一家同时具备「应用层 E2EE + 可靠跨网 + 账号/历史/持久清单 + 可持续商业模式」，每家至少缺两环；纯浏览器 P2P 传输**没有任何一家跑通订阅变现**；该赛道基础设施普遍由个人/微型团队硬撑（magic-wormhole 作者明言成本高就关服务器）。

## 五、我们的独特处与缺口

### 独特处（市场空白点，调研第五节逐条对应）

1. **持久清单 = 云盘式资产视图 × P2P 零存储**：市场结论「没有产品把 P2P 的直传速度/零存储与云盘式的账号资产结合」——这正是我们已做的东西：账号 + 同步清单（谁有什么）+ P2P 取字节 + 服务器回退。
2. **多源并行 + 完整性校验 + 坏源隔离**：块级 SHA-256 校验、篡改 peer 自动隔离、多源块图——所有竞品（含 Send Anywhere）都没有这个组合；file.pizza 的「续种」只是转发，无校验叙事。
3. **账号 + 会话层**：设备登记、Ed25519 票据、一对设备一条已认证会话——为滥用治理（管理后台 US-713）打了地基，这是 Firefox Send 因滥用关停的教训里最关键的一环。
4. **回退兜底**：无 peer 在线时服务器直下，比纯 P2P 产品的「双方必须同时在线」可靠一个量级。

### 缺口（按优先级）

1. **跨网能力**：非目标里明确不做 STUN/TURN——局域网屏蔽组播的办公网（访客 WiFi 隔离）直接连不上（README 自认）。这是当前产品最大硬伤：LAN-only 把市场锁死在内网/团队场景。
2. **无内容级 E2EE**：链路加密有（DTLS），但 R2 回退的文件是明文落盘——隐私叙事有硬伤（Wormhole.app 的对照太明显）。补齐=客户端加密后上传。
3. **平台面**：只有浏览器半边。桌面端（大文件目标 1 GiB）在 US-707 阶段 B；移动端完全没有；Safari/iOS 对大文件直传有公认瓶颈。
4. **断点续传**：计划内未做；Send Anywhere/Taildrop 都有。
5. **国内可达性**：workers.dev 与 supabase.co 在大陆网络直连不通（已知，需代理）——奶牛快传停服留下的国内真空目前**接不住**，要么换基础设施要么做合规域名。
6. **变现路径**：全行业无先例，需要自己设计（见下）。

## 六、定位选项

**A. 团队文件池 / 内网文件网格（推荐）**：账号 + 持久清单 + 局域网直传 + 服务器回退，卖给小团队/工作室——「谁有什么文件」一屏可见、按需拉取、不走服务器带宽。直接竞品其实没有：Syncthing 是同步不是传输且无账号体验，Resilio 企业版 $7,500/年起，Tailscale Send 只限自己设备。与 epic-011 愿景、现有非目标（不做公网 P2P）完全一致，不需要推翻设计。

**B. 公开免装传输工具**：对标 Send Anywhere/ToffeeShare，需要推翻「不做 STUN/TURN」的非目标、建公共中继，面对零变现先例的拥挤赛道。不推荐。

**C. 混合云盘叙事**：同一引擎换个消费级包装（「零月费大文件传输」），等 A 的团队场景验证后再考虑下放。

## 七、风险清单

1. **滥用风险（Firefox Send 先例）**：恶意软件/钓鱼分发可以直接杀死产品。US-713 管理后台必须进 MVP（处置账号、删服务器副本、踢下线），并加速率限制与举报。
2. **变现无先例**：该品类目前只有捐赠、被收购转型、停滞三种结局。更现实的商业定位可能是获客/生态入口（SwissTransfer 之于 Infomaniak、Taildrop 之于 Tailscale），而非订阅直接盈利。
3. **LAN-only 是最大产品风险**：若目标客户实际是「跨办公室/在家办公」，直连成功率就是生死线——需要桌面端局域网发现（US-712 局域网枢纽）兜住，或者明确接受 TURN。
4. **国内市场窗口**：奶牛快传 2026-01 停服是真真空，但我们的基础设施在国内不可达，接窗口的前提是重构部署面（备案、国内 CDN/存储、合规），成本不低。
5. **运营可持续性**：本赛道基础设施普遍由个人硬撑；我们的 Worker/DO/R2/Supabase 账单随用量线性涨，免费放开前要先算清单次传输成本。

## 八、结论一句话

**市场上没有「账号化持久清单 + P2P 多源直传 + 完整性校验 + 服务器回退」的产品，空白是真的；但跨网、内容加密、桌面端、国内可达、滥用治理这五件事不补齐，产品化就停在 demo。**
