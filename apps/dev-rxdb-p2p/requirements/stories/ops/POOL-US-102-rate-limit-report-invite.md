# 用户故事：速率限制、举报与邀请制 beta

## 作为/我想要/以便

**作为** 部署 aiao-pool 的产品运营者
**我想要** 服务端速率限制（按账号与 IP）、用户举报入口与后台处置闭环、邀请制注册门槛
**以便** 在 M1 邀请制 beta 期间控制滥用与回退成本，并在举报后闭环处置（对应 M1 验收的滥用演练）

现状的痛点：滥用治理是 Firefox Send 死因的解药，立项方案把它列为 M1 必选项；现在接口没有服务端限流（只有前端行为），用户遇到恶意文件没有举报入口，注册没有邀请门槛——成本与滥用都只能事后手写 SQL 处置。

## 范围边界

### In Scope

- **服务端速率限制（不是前端隐藏）**：按账号（或设备）与 IP 双维度，覆盖三组 Worker 接口——信令 hello（每账号每分钟）、回退上传/下载（次数与每日流量）、管理接口（`/api/admin/*`，防爆破）。超限返回 429 + `Retry-After`，不同账号/设备互不影响。计数经限流 Durable Object（SQLite 持久，跨 isolate 共享窗口）。
- **免费档默认配额（假设值，M3 定价校准）**：回退单次 ≤100MB（rxdb:US-706 已有）；每账号每日回退流量 1 GiB、回退上传 20 次/日；每账号信令并发连接 8；管理接口失败尝试 10 次/5 分钟。所有数值集中在服务端配置，改一处生效。
- **举报**：文件行与账号的举报入口（原因分类：恶意软件/钓鱼、侵权、骚扰、其他）→ Worker 收举报，只存目标 `contentHash` 或账号 id、分类、举报人与时间，**不存文件内容与举报正文** → 管理后台（rxdb:US-713 扩展）看到举报列表并处置（删副本、封账号、清持有声明）→ 处置后举报归档。同一对象同一账号重复举报去重。
- **邀请制 beta**：账号激活码模型——注册后未激活账号只能登录与浏览，不能共享、上传回退与下载；管理员在管理后台发码、作废；码一次性、作废即时生效。激活状态经 `p2p.activate_invite`（一条语句完成校验/标记/登记）落 `p2p.activated_users`，只对 service_role 开放；客户端与 Worker 以调用者身份经 `p2p.is_activated()` 查询。门禁是部署配置 `POOL_REQUIRE_ACTIVATION`（生产开启，本地开发与 e2e 默认关闭）；开启时信令 hello 与回退接口拒绝未激活账号（403），管理员豁免，共享入口由产品界面隐藏。
- **滥用演练（M1 验收标准之一）**：e2e 剧本——模拟恶意文件分发 → 用户举报 → 管理员在后台处置 → 副本删除、账号封禁、在线设备断开（rxdb:US-713 已有能力）全部生效，演练报告留档。

### Out of Scope

- **清单写入的数据库级门禁**：共享的持有声明写入仍由 RLS 约束（本人设备），不另设「未激活不可写清单」的数据库策略——未激活账号被挡在信令与回退两道服务端门禁之后，且界面没有共享入口；如需数据库级硬门禁，另立故事。
- **内容自动审查**：不做恶意软件/版权自动扫描与机器学习判定；举报人工处置。
- **审计日志**：处置只在响应里回报结果，不落审计库。
- **配额计费与付费档切换**：M3 商业化（D-03）范围；本故事只做免费档默认配额。
- **举报的对外处理流程**（下架通知、申诉渠道）：只做产品内举报→处置闭环。
- **IP 维度的复杂语义**（代理穿透、NAT 共享 IP 的精确归因）：按 IP 限流是粗粒度防线，误伤边界在实现时以「账号维度优先、IP 维度兜底」处理。

## 验收标准

| #   | 前置条件                          | 操作                        | 预期结果                                                                     | 状态 |
| --- | --------------------------------- | --------------------------- | ---------------------------------------------------------------------------- | ---- |
| 1   | 某账号高频发起信令 hello          | 直接请求 `/api/signal`      | 超限后 429 + `Retry-After`（服务端断言，不靠前端隐藏）；其他账号不受影响     | ✅   |
| 2   | 某账号回退上传/下载超过日配额     | 继续上传/下载               | 429 + `Retry-After`；另一账号正常；窗口重置后恢复                            | ✅   |
| 3   | 错误凭据连续请求管理接口          | 脚本直连 `/api/admin/*`     | 429 防爆破；正确管理员不受影响                                               | ✅   |
| 4   | 用户举报一个文件/账号             | 提交举报                    | 服务端只存目标标识、分类、举报人与时间；不存文件内容与举报正文；后台列表可见 | ✅   |
| 5   | 管理员处置举报（删副本 / 封账号） | 后台处置                    | 副本删除、账号封禁与在线设备断开全部生效；处置后举报归档，不可重复处置       | ✅   |
| 6   | 未激活账号 / 无码账号             | 共享文件、上传回退、下载    | 被拒并提示需邀请码；登录与浏览可用；错误邀请码被拒                           | ✅   |
| 7   | 管理员发码；某码已被使用或作废    | 用码激活；复用/作废码再激活 | 码一次性；作废即时生效；后台可单个/批量发码                                  | ✅   |
| 8   | 恶意文件分发剧本                  | 跑滥用演练 e2e              | 举报 → 处置 → 副本删除 + 账号封禁 + 在线设备断开全绿，演练报告留档           | ✅   |
| 9   | 限流计数与日志                    | 检查服务端存储与日志        | 计数与日志不含文件内容、内容密钥或举报正文                                   | ⚠️   |

验收证据：AC1～AC8 已在本地真栈 e2e 上关闭（[governance-limits](../../../../dev-rxdb-p2p-e2e/src/demo/governance-limits.spec.ts)：信令 hello 短窗口超限被拒且他账号不受影响；[governance](../../../../dev-rxdb-p2p-e2e/src/demo/governance.spec.ts)：回退配额 429、管理接口防爆破 429、举报→处置闭环、邀请码一次性与作废、滥用演练封禁路径；[governance-gated](../../../../dev-rxdb-p2p-e2e/src/demo/governance-gated.spec.ts)：未激活被挡与激活放行）；AC9 只有单元证据（计数器键只含 scope + 账号/设备或 IP，不含内容），缺对真栈限流存储与日志的逐项检查。前端 UI 截图不充当限流证据。

## 技术笔记

- 接入点现状（本分支源码）：信令在 Worker `server/` 的 `/api/signal`（Durable Object）；回退上传/下载 `/api/files/:hash`（R2，单次 ≤100MB）；管理接口 `/api/admin/*` 只认 `ADMIN_USER_IDS` 白名单，`p2p.admin_*` 函数只有 `service_role` 能执行（见 [rxdb:US-713](../../../../../requirements/stories/future/US-713-p2p-admin-console.md)）。限流器与邀请码存储沿用同一条服务端信任边界。
- 方案要点：限流计数放 Worker（KV 或 DO SQLite，按窗口重置）；账号维度用 Supabase 用户 id 或设备 id，IP 维度用 CF 头（`CF-Connecting-IP`）；四组接口阈值集中在一处配置，M3 定价时只改配置。
- 平台依据：Cloudflare Workers 免费计划有请求与 CPU 上限，限流同时保护自身成本；R2 egress 免费，成本压力在存储与调用次数——免费档配额按「单次回退成本可算」设置（成本结构见 [立项方案](../../plans/p2p-product-proposal.md) §6/§10）。
- 证据层级：单元（限流器状态机）< 本地真栈（真实 Worker 路由 + Supabase）< 正式环境；限流 AC 一律以服务端响应断言，不用前端 UI 状态代替。
