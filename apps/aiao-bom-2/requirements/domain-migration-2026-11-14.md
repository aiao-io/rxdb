# 领域工作区与迁移运行说明

日期：2026-11-14。本次提供独立工作区和可回退迁移工具，旧站替换需完成统一评审。自动化演练使用隔离数据库，不代表已迁移用户浏览器的真实数据。

## 数据与入口

| 内容              | 入口 / 存储                              | 契约                                                                                   |
| ----------------- | ---------------------------------------- | -------------------------------------------------------------------------------------- |
| Canvas 结构工作台 | `/`；IndexedDB `aiao-bom-2-workspace-v1` | 来源结构、用户草稿、视图及版本快照；数量来源和制造确认独立标识                         |
| 领域工作区        | `/domain`；SQLite `aiao-bom-2-domain-v1` | 复用原领域内核与共享 `modules/bom-workspace`；实体、ECN、发布、生效域、实例与历史      |
| 备份与迁移        | `/transfer`                              | 领域数据库完整逻辑归档，含实体及系统历史；不包含 GLB 或结构工作台的独立 IndexedDB 文档 |
| 旧版              | 原入口；SQLite `dev-rxdb-bom`            | 独立连接与文件；重置只删除当前文件                                                     |

两版通过路由配置分别实例化服务和页面状态。结构工作台不会把分类树或 CAD 父子关系自动当作制造 BOM。

## 结构草稿进入领域

1. 在结构工作台创建或导入草稿，选择明确的装配根。
2. 修正缺失和歧义数量，确认参考量及制造父子关系。
3. 从导出对话框选择“预览领域导入”。系统分类节点、物料环、单位冲突、同物料不同子结构会被拒绝。
4. 在 `/transfer` 核对装配、修订及记录数，然后执行“校验并写入领域草稿”。业务记录经公共 BOM 导入验证后原子写入。
5. 进入领域展开页核对，再明确勾选和发布。导入本身不发布。

当前领域 UI 使用 `org-x`；转换器支持其他组织，但界面暂不提供组织切换。发生位置对应关系保存在 `domain:receipt:<datasetId>:<revisionNo>`，包含源 key、sourceRef 与领域父件 / 行号。领域记录和对应关系位于不同数据库，领域提交后对应关系保存失败会显示错误；需要检查领域待发布记录后再决定重试。

Decimal 始终按字符串传递。同父重复物料保留为不同行；相同物料的相同子结构复用定义。领域最终需求仍按库存单位精度取整，原发生项小数保留在导入和导出中。

## 旧库迁入顺序

1. 在旧数据所在的同一浏览器、同一 origin 打开包含备份入口的旧版 `/transfer`，下载完整领域备份；保留原文件及界面显示的 SHA-256。
2. 在独立新版 `/transfer` 选择归档，执行“校验并迁入新库”。工具使用官方逻辑归档流，校验校验和、schema 和引擎兼容性，恢复到一个全新数据库。
3. 恢复及 hydrate 全部成功后才切换本地活动库指针。失败不改变当前活动库，也不覆盖原文件。
4. 核对领域统计、待发布草稿、Decimal、ECN、实例换件和历史；再次下载归档，比较数据条目与排序后的 schema 定义。
5. 刷新页面确认活动库身份保留。需要回退时执行“回退到保留的原库”，再核对原库。
6. 保存原归档和旧发布产物，沿用已有立项授权，经过 PR 最终统一评审和验收后，独立安排生产切换。

独立部署 origin 无权直接读取旧站浏览器数据库。旧生产版本若尚未提供备份入口，需先在旧 origin 提供兼容导出入口；本次没有部署或替换旧站。浏览器库不能通过复制新站 URL 自动迁移。

活动指针为 `bom:active-database:<配置库名>`，上一库为同 key 加 `:previous`。恢复目标基础名是 `bom-r-` 加无连接符 UUID，为 SQLite 内部后缀保留长度。回退切换指针，不删除数据库。

## 已实现保护与边界

迁移等待既有连接和领域操作完成，期间拒绝新领域操作与重置。损坏归档拒绝后当前库继续可用。恢复归档限制 500 MiB；导出通过流读取，但下载 Blob 目前在内存聚合，不承诺任意规模归档。多标签页操作同一领域库仍须由使用者协调，不提供跨标签页切换共识。

E2E 在隔离旧库装入种子，追加自定义 Decimal 草稿并执行真实 PACK-001 → PACK-003 换件后备份，再向新版恢复。检查所有逻辑数据条目原文、实体身份、schema 定义和指纹；并验证坏归档拒绝、刷新、回退和旧库原样保留。生成证据位于 `apps/aiao-bom-2-e2e/test-output/evidence/migration.json`，正式验收摘要另行归档。

该归档是逻辑归档，不能把帧拼成 SQLite 二进制文件；应使用 `RxDBBackupArchiveReader` 解析。
