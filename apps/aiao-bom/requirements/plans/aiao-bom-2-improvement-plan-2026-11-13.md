# aiao-bom-2：大规模 BOM 与 3D 工作台改善方案

日期：2026-11-13（Asia/Shanghai）。结论：✅ 值得做。

实施状态（2026-11-13）：已创建独立 `aiao-bom-2` 和对应 E2E 项目，落地 VTable 结构工作台、真实整车与零件模型、草稿编辑及导入导出。实测与剩余替换门槛见[实施验收记录](../../../aiao-bom-2/requirements/implementation-report-2026-11-13.md)。本文保留完整产品方案，下文目标不自动视为全部完成。旧 `aiao-bom` 的页面、数据库、部署入口保持原状。研究计数与来源哈希见[数据核查记录](aiao-bom-2-data-audit-2026-11-13.json)。本计划不替代 story 的状态管理。

## 1. 产品目标与默认决策

做制造工程师日常使用的 BOM 核心工作台：在同一份评估上下文中浏览几万个发生项，进入某个系统或装配，切换平铺列表，查看并操作对应 3D，再完成结构编辑、差异核对和导出。主工作区围绕结构表展开，现有计算能力通过选中行、工具栏和详情面板接入。

- 独立应用命名 `aiao-bom-2`，默认沿用当前 Angular 技术栈，另建对应 E2E 项目。
- 主表使用仓库现有 `@visactor/vtable@1.26.8`；3D 使用 Three.js 与 GLTFLoader，按需加载 Draco / Meshopt 解码器。
- 展示容量以 **50,000 个发生项**为首轮硬验收，100,000 个发生项作为压力边界。不同物料数、结构边数、展开路径数、当前可见行数分别记录。
- 同一选择、过滤条件、当前范围和列配置贯穿树表、系统内浏览、平铺列表和 3D。
- 原始公开资料保留来源及原文；缺失的制造事实在产品中明确呈现，进入计算或编辑发布前经过校验。
- 新应用完成业务回归、规模验收、数据兼容和统一评审后再安排替换。新旧应用并存期间使用独立数据库身份。

这是 **Group 层面的资产候选覆盖率**。按主清单 `v` 中至少一个完整变体件号与资产标识精确相交统计，为 1,139 个 Group；依然不代表所有市场、版本和发生位置都已匹配。本轮未逐个下载并加载全部 1,644 个独立模型。

`2,028` 是主清单与资产目录合并后的七位数字 GID 集合；它不能替换 `1,424` 作为正式主 BOM 总数。其他编号也不能因不符合七位规则而丢弃。

### 2.2 装配关系与数据缺口

- 主清单 503 行没有用量；`1319317` 的用量为 `2,3 件`，`3602561` 为 `1,4 件`。原样保留，并显示缺失 / 歧义，不能默认取 1 或解析成小数。
- 主清单 `l` 字段包含 `共用件()`、`法规专属(US)` 等文本，不能拿来做树深度。
- 数字 GID 详情中有 1,022 条 `parent` 线索，其中 996 条的父 Group 可在主清单找到，只有 109 条父件完整编号与主清单变体字符串精确相交。截短为七位号只能产生候选关系。
- 采购层级的 813 个位置中，82 个 GID 出现在多个父节点下；607 个 GID 中只有 484 个与主清单相交，主清单另有 940 个 GID 未被该采购层级覆盖。
- 采购层级无数量；其 EU / US 列是具体件号。不能从有无件号推导单车用量，也不能复制成 CN / AU 的真实装配结构。
- 来源主清单 `mk.WH13` 等字段表示适用标记；详情 `mk.eu` 和资产 `models.eu` 表示件号。需要两个独立字段。
- 当前页面显示 `2026-12` 版本标签，晚于核查日 2026-11-13；保留为来源声明的版本，不声称其已于 2026 年 12 月正式发布。

### 2.3 整车模型可以提供什么

整车 GLB 有 8,790 个节点带 `item_id` / `system_id`，8,788 个带 `parent_id` / `depth`；可提取 1,876 个不同 `item_id`、96 个不同 `system_id`。根节点声明 Y-up、毫米，以及 EU X9D13C 配置。

这些标识能支持零件高亮、系统隔离和 CAD 结构导航，但不能直接生成可计算的制造 BOM：

- glTF 场景实际只有 72 个节点带子节点，其中一个车根直接挂 6,364 个子节点。场景树与业务装配树并不相同。
- extras 中有 167 个不同 `parent_id`，其中 96 个不在 `item_id` 集合中；系统节点需要作为来源引用处理，不能假装已取得完整父件档案。
- 来源还带 `approx`、`outlier`、`removed_by_pose_fix`、`_gen2Superseded` 等标记。先保留并展示，再按明确的模型策略决定可见性与可选性。
- 两桥共用一个 `E-axle.glb`，同一 Group 也可能关联不同模型文件。资产、模型内部节点、业务物料和使用位置需要分别建模。
- 个别独立零件 GLB 没有节点名称或 extras，只能靠资产目录的显式映射定位；不能要求所有文件都靠 mesh 名称自动识别。

### 2.4 WorkBuddy 查看器的补充价值

实际页面通过 iframe 加载公开备件查看器，底层仍使用 Windrose 的整车 GLB、独立零件 GLB 与 `spare-parts-data.js`。已看到节点定位、独立模型叠加、隔离、透明和相机聚焦的实现。

子页面支持 `?pn=`，按完整节点名匹配后再尝试 GID 前缀；本次 WorkBuddy 外层 iframe 的 `src` 没有携带外层 `pn`。新应用应提供自己的稳定深链接与选择协议，验证加载完成后能定位到正确变体及使用位置。

备件数据的 `mk` 是市场首批备货量，价格是 FOB USD 报价；分别呈现为备货与报价字段。它们不能填补制造 BOM 缺失的单车用量或制造成本。来源的 `scale1000`、`rotX-90`、`UNRESOLVED` 等位姿状态同样需要保留，未确认位姿的模型可以单件查看，装到整车前需验证变换。

默认桌面布局左导航约 240px，右侧约 420px，均可收起与拖动调整。3D 可以扩大为独立面板或上下分屏。窄屏默认主表配合抽屉，保留固定名称列、关键操作和返回位置。

### 4.1 三种工作方式

1. **树表**：在当前结构来源内按发生位置展开。支持按 1 / 2 / 3 层展开、收起、展开所选分支、定位父项及路径。大分支“全部展开”先显示预计节点数，再执行可取消的分批展开。
2. **进入系统 / 装配**：双击或“进入”将当前范围切到该对象，面包屑保留返回路径。过滤、数量口径、导出和 3D 都采用同一范围；返回恢复滚动位置与选择。
3. **平铺列表**：默认逐发生项平铺，保留路径和使用位置。单独提供“按物料汇总”，只有相同版本、单位和有效配置才合并数量，并能展开查看来源位置。

“系统分类”“采购装配结构”“CAD 结构”是明确命名的结构来源。40 个 Family 可用于导航，但不会因出现在导航中而变成制造总成。采购结构未覆盖的物料放入“仅目录 / 待归属”工作集，仍可搜索、筛选和单件查看，不制造虚假的 BOM 边。

### 4.2 工具栏与行操作

| 分组 | 首轮能力 | 规则 |
| --- | --- | --- |
| 查找 | 名称、GID、完整件号、别名搜索；系统、市场、CB / MB / SB、冲突、缺量、有 3D 筛选 | 树搜索保留命中祖先；显示匹配数与可见行数；空结果可清除条件 |
| 结构 | 展开层级、展开 / 收起所选、进入、返回、定位父项 | 树排序只调整同级；“进入”和“筛选”分别保存 |
| 表格 | 列显隐 / 顺序 / 宽度、冻结、紧凑密度、保存视图、多选、复制 | 列设置与滚动不触发业务重算；切换视图保持稳定选择 |
| 分析 | 直接 / 累计用量、使用处、版本差异、成本、变更影响 | 区分结构数量与装配发生次数；缺少输入时给出具体原因 |
| 编辑 | 草稿内改数量 / 单位、增删行、调整顺序、批量更新、撤销 / 重做 | 同级顺序与改变父装配是不同命令；经过循环、权限、状态与单位校验 |
| 数据 | 导入预览、字段映射、错误明细、保存草稿、CSV / JSON 导出 | 原始快照只读；显式操作生成工作草稿；导出附带来源、范围及问题状态 |
| 3D | 查看所选、聚焦、隔离、透明、显隐、还原、整车 / 单件 | 加载错误可重试；不存在有效映射时显示具体原因 |

默认固定选择 / 行状态、名称树列、件号三组列；数量、单位、系统、版本、适用性、冲突和 3D 状态在横向区域显示。四市场的 CB / MB / SB 作为可切换列组。成本与更多规格通过列预设展开，避免默认塞满全部字段。

详情面板保留属性、使用处、来源和数据问题。上下方向键移动，左右方向键控制树，Enter 进入详情或开始编辑，Escape 退出当前操作。Canvas 表格还需可读的选中行摘要、可聚焦工具栏及按需 DOM 详情；真实浏览器验收键盘路径和辅助技术行为。

## 5. 数据结构与查询边界

### 5.1 四种身份

- **物料 / 变体**：内部物料 ID、原始 Group ID、完整件号、来源版本、市场和修订。Q 类编号保留完整形式。
- **BOM 使用关系**：父修订、子修订、逻辑行、发生项、数量、单位、适用条件、来源证据。公共领域层继续复用既有 BomItem / BomItemRevision / BomLineOccurrence 契约。
- **展示发生位置**：根修订及使用关系路径形成稳定 `occurrenceKey`。同一物料在两个父装配下是两行；同一父项下的重复行也不能合并。原始来源没有行 ID 时，先按快照和源节点路径建导入身份，验证后再建立内部身份。
- **3D 资产与实例**：资产版本及校验值、glTF 节点索引 / 路径、可选实例索引、世界变换、业务编号和映射状态。运行期 Three.js UUID 不作为持久标识。

底层物料使用关系是有向图；在特定根、市场、日期、配置下投影为树。系统分类是单独的成员关系。模型通过多对多映射连接到物料 / 发生位置，不写入 BOM 父子关系来迁就场景结构。

原始 snapshot、来源字段和错误记录先保存在应用的导入工作区；只有关系、数量与单位已通过校验的记录才进入可计算 BOM。支持仅浏览与建立待完善草稿，不能为了通过领域校验而偷偷补上默认数量。

### 5.2 一个状态与查询通道

工作区状态包含数据集 / 来源版本、根对象、市场 / 日期 / 配置、当前范围、结构来源、显示模式、筛选 / 搜索、同级排序、展开状态、选择、列配置及模型模式。

查询服务按范围返回根、子项、平铺窗口、计数与祖先定位，采用稳定顺序和带版本的游标。过滤和排序在查询层执行；树过滤保留祖先，子节点加载尊重过滤条件。数量展开、成本等计算按显式条件独立运行，单纯浏览与选择不触发全量爆炸计算。

选择按 `occurrenceKey` / 物料身份保存，VTable 的行坐标只在事件发生时解析。异步查询带 generation / 取消信号；排序、切换系统后，旧请求不得把结果写到新的行坐标。

URL 保存可分享的根、范围、市场、模式、筛选和所选件号 / 发生位置；列宽和面板尺寸保存在本地视图设置。分享深链接必须等待相应数据及模型准备好再执行定位。

## 6. VTable 与数万节点的实现策略

官方文档已核对树列 `tree: true`、`children: true`、`TREE_HIERARCHY_STATE_CHANGE` 与 `setRecordChildren`；本地 1.26.8 的声明包含这些接口及 `setLoadingHierarchyState`。更高版本文档中的其他能力需按锁定版本核验。

- 树采用按展开加载子项，默认两层；单个父项有数万子项时继续按窗口加载，提供明确的“加载后续”控制行，它不属于业务 BOM。
- 平铺采用可见窗口与分段数据源，首轮建议每批 200–500 行，并按真实基准调整。分段数据访问和 Canvas 可见区域绘制分别验收。
- 固定行高和有界列宽；默认采用 `widthMode: 'standard'`，避免 `autoWidth` 或内部全量排序将异步数据重新拉齐。支持用户主动对选定列调整宽度。
- 展开、选择、编辑和模型加载状态按稳定 ID 维护；切换行或面板不 `setRecords` 重建整表。编辑仅更新受影响记录与统计。
- 通用视图投影不做每行深拷贝、每行 Observable、每行 DOM 模板或在每次选择时遍历整棵树。索引与后代集合按数据版本缓存。
- 耗时的导入、索引和投影在 Worker 中分批执行；数据库操作遵守现有后端所有权与连接模型。主线程与 Worker 间只传当前窗口或紧凑结果。
- 对高复用子装配和深层结构设置路径 / 深度 / 时间预算。触达预算时显示截断位置和原因，不把部分结果标成完整结果。

现有 `view-projection.ts` 缓存了 snapshot 索引，但折叠切换仍会从完整快照生成路径节点。先保留业务身份和计算契约，再用基准决定分页读取与增量投影的改动位置；不能仅更换绘制控件便声称数万节点性能已解决。

```mermaid
  C --> Q[按范围与条件查询]
  Q --> T[VTable 树表与列表]
  T --> W[工作区选择状态]
  W --> M[资产与节点映射]
  M --> V[Three.js 场景]
  V -->|拾取节点与实例| W
  W -->|定位祖先与选中行| T
```

1. 表格选中具体发生位置后，经映射查询对应场景节点；有精确位置映射就高亮该位置。只有物料级映射时，显示“该物料的全部模型位置”，不伪装为单个装配位置。
2. 点击 3D 先得到资产版本、节点路径 / 索引与实例，再查业务映射；一对多时列出候选使用位置，选定后展开祖先并滚动到行。
3. 进入系统同时过滤表格与场景，基于明确的 `system_id` 映射隔离。它不依赖 glTF 存在一个完整系统父节点。
4. 主清单完整件号、市场、修订优先匹配；GID 前缀匹配只生成“Group 级参考”候选，保留歧义状态。EU 整车在其他市场下仍标明“EU 参考模型”。
5. 优先展示整车现有节点；独立模型可在单件视图加载。向整车叠加需要已确认单位、坐标轴和装配变换，未确认就显示具体状态。
6. 面板打开才加载渲染代码；标准整车模型约 24.68 MiB，高清约 56.48 MiB，明确进度、取消和重试。重型渲染只占用一个活动视口，缩略图按需生成并缓存。
7. Draco / Meshopt 解码按资产需要启动；模型下载、解码、场景建立和可交互分别计时。按视口控制像素比，采用请求驱动渲染，隐藏面板停止渲染。
8. 几何和材质按资产复用，高亮需要可还原且不污染共享材质；切换模型释放 GPU 资源并设缓存预算。射线拾取限定可选对象并按数据规模验证空间加速需求。

首轮交付轨道旋转、缩放、预设视角、聚焦、隔离、透明、显隐和重置。爆炸仅在有 `wr-explode/1` 等已核实元数据时开放；任意模型的中心偏移不能被称为真实拆装顺序。测量、剖切和装配工艺作为后续增强，不阻塞核心表格联动。

模型管理默认登记远程来源与缓存状态，关键演示资产在部署前固化到受控来源并校验。表格离线与模型离线分别验收；模型未缓存时明确提示。外部 WorkBuddy iframe 可保留为来源入口，正式工作台通过自身渲染器与选择通道联动。

## 9. 性能与正确性验收

以下为拟定目标，**不是本轮实测结果**。使用固定参考设备与生产构建，记录 OS、浏览器、CPU、内存、视口、节点形状、列数、网络与缓存状态。交互指标报告 p50 / p95，至少 20 次有效样本。

| 场景 | 首轮验收目标 |
| --- | --- |
| 已导入 50k 发生项，20 列，不加载 3D | 数据库就绪到首屏可操作 p95 ≤ 1 秒；冷启动与首次导入另计 |
| 已加载分支展开 / 收起、树 / 平铺切换 | 缓存命中 p95 ≤ 150ms；需要读取的数据操作 p95 ≤ 500ms |
| 当前范围索引搜索 / 筛选 | 输入 debounce 后到可操作结果 p95 ≤ 300ms；记录数据库查询与绘制耗时 |
| 连续滚动与选中行 | 参考设备持续滚动平均 ≥ 50 FPS，p95 帧耗时 ≤ 32ms；主要操作无 > 200ms 主线程阻塞 |
| 表格与已就绪 3D 双向选择 | p95 ≤ 150ms；相机动画时长单独记录 |
| 内存与资源 | 纯表格 50k 时 JS heap 增量初始预算 ≤ 200 MiB；GPU 另计；模型 / 面板切换 20 次后资源数不持续增长 |
| 100k 发生项 / 50 层结构 | 可进入指定分支、定位末项、取消查询；触达显式预算时给出完整性状态 |

测试数据至少覆盖：真实来源样本、均衡树、单父项 50k 子项、50 层深树、高复用 DAG、同父重复物料、多个市场变体、同 GID 多模型、Q 标准件、缺量 / 歧义量、父件缺失、循环输入、慢请求交错。

正确性回归特别验证：树与平铺不丢发生位置；物料汇总不重复累计；树过滤不使祖先丢失；范围变更后导出内容一致；刷新时草稿和选择可恢复；错误父关系不能发布；旧异步结果不覆盖新范围；失败模型可重试；表格无 3D 时仍能完成核心业务。

应用与新增非核心模块覆盖率 ≥ 80%，核心公共包 ≥ 90%，公共 API 三框架对称。真实浏览器覆盖生产构建、键盘操作、375px 窄屏、COOP / COEP、解码 WASM / Worker、远程资源 CORS 与本地重开；受支持浏览器分别留证。

## 10. 替换旧版的硬门槛

- 新应用具备独立地址、构建、数据库、E2E 与预览部署；旧站仍能独立运行和回归。
- 旧版结构 / 数量 / 成本、两时点改版核对、映射、导入导出、实例追溯等已交付用户流程，在新工作台均有可达入口并通过对应回归；增强项可以后续交付。
- Windrose 主清单 1,424 个 Group 全部可查，补充目录与采购层级分别计数，导入异常无静默丢弃。
- 50k 发生项、20 列、3D 同开时性能与资源预算通过；100k 压力边界有报告。
- 3D 联动区分精确发生位置、物料全部位置和 Group 参考；市场 / 版本错配和未确认位姿可见。
- 新旧库迁移先备份，验证草稿、Decimal、发生项身份、历史数据和导出重入；保留可回退副本，不让新旧应用直接共写同一库。
- 领域改动与公共包改动完成同一 PR 的范围评审、受影响检查和统一验收。部署切换单独执行，切换前保留旧产物与回滚入口。
