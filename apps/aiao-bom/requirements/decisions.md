# Aiao BOM 决策

| 编号 | 决策                                                             | 执行条件与边界                                                                                 |
| ---- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| D-01 | 应用目录及 Nx 项目使用 `aiao-bom`，浏览器回归使用 `aiao-bom-e2e` | 应用短前缀 `BOM`；开发端口继续 `4311`，构建产物跟随新项目目录                                  |
| D-02 | 应用只负责工作流、领域接线和展示                                 | 计算、约束、种子与 golden 留在 `packages/rxdb-plugin-bom*`；公共包变更与领域功能同 PR 评审合入 |
| D-03 | 保留浏览器持久化标识 `dev-rxdb-bom`                              | 避免项目改名创建空库；继续保留显式重置，跨 origin 与真实历史库迁移分别验证                     |
| D-04 | 当前产品为单人本地 BOM 工作台，以生产改版核对为主线              | 结构、成本、反查、数据与实例能力独立可达；样本演示不证明真实企业需求                           |
| D-05 | story YAML 为应用状态真相源，平台引用写 capabilities             | 应用内部硬依赖写 dependsOn；四份派生视图和所属 epic 随状态同步并运行门禁                       |
| D-06 | 验收按结构、单元、浏览器、真实环境分层记账                       | 应用完成本地验收后等待 PR 评审合并；不从平台 Done 推导应用完成                                 |
| D-07 | 离线承诺限定在已成功载入的核对页                                 | 改批量离线重算可测；冷启动、全站缓存与离线刷新需单独立项                                       |
| D-08 | 根 US-525 保留平台组合验收的原编号与证据语义                     | 应用当前需求由 BOM-US-101 / 102 / 201 / 301 接管；旧验收编号供平台测试和历史引用使用           |
| D-09 | Cloudflare 使用 Workers Static Assets 发布生产 browser 目录      | SPA 路由及 COOP/COEP 随产物部署；本地 Wrangler 和公网使用同一部署验收套件                      |
| D-10 | 部署凭据不进入仓库，跨 origin 数据独立                           | 本机通过 Wrangler 登录；自动化通过环境注入账号与 Token；新域名不自动迁移本地旧数据             |
