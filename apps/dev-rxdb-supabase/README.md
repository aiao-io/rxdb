# Supabase RxDB demo

## 一键本地开发

在仓库根目录执行（需要 Node.js 26+、pnpm 与已启动的 Docker）：

```bash
pnpm nx dev dev-rxdb-supabase
```

一条命令依次完成：

1. 检查固定端口 4203（应用）与 4204（测试起始页）没有被占用；
2. 起本 checkout 专属的隔离 Supabase 栈并初始化数据库（即 `rxdb-adapter-supabase:test-env`，与适配器测试、远端 e2e 共用），再叠加 Supabase Studio；
3. 应用以远端同步模式热更新运行，连上这套栈；首次打开是不登录的访客，右上角可切换身份；
4. 应用与起始页都就绪后，浏览器打开测试起始页：测试入口、Studio、连接参数和常用测试命令都在页上，支持一键复制。

| 服务              | 地址                                    |
| ----------------- | --------------------------------------- |
| 测试起始页        | <http://127.0.0.1:4204/>                |
| 应用              | <http://localhost:4203>                 |
| Supabase API 网关 | `http://localhost:<端口>`，见测试起始页 |
| Supabase Studio   | `http://127.0.0.1:<端口>`，见测试起始页 |

Supabase 与 Studio 的宿主端口由 docker 按 checkout 分配（RV-036），多个检出目录可以各起一套；起始页显示本次的实际地址。
Studio 无需登录即可读写整个库，只发布在 127.0.0.1。

- 不需要自动打开浏览器：`AIAO_DEV_OPEN=false pnpm nx dev dev-rxdb-supabase`。
- 固定端口被占时直接失败，并列出占用进程的 pid、命令与目录，不自动换号。
- Ctrl-C 停止应用与起始页；Supabase 容器继续运行并保留数据。Nx 被强制终止时，各常驻进程经
  `scripts/dev/supervise.mjs` 在数秒内自行退出，不会留下孤儿进程占住固定端口。
- Supabase 日志不混进这个终端（工作区关了 Nx TUI，init-db 的 DDL 日志会刷屏），需要时另开终端：
  `docker/supabase-ci-compose.sh logs -f --tail 50`。
- 停止容器并保留数据：`docker/supabase-ci-compose.sh stop`；删除容器与数据：`pnpm nx run rxdb-adapter-supabase:test-env-down`。

开发链脚本的测试：`pnpm nx run dev-rxdb-supabase:dev-test`（`test` 依赖它，CI 一并执行）。

## 配置来源

远端同步是 **dev-server 独有能力**：`import.meta.env` 只有 Vite dev server 会注入。

生产构建（`nx run dev-rxdb-supabase:build`，即 `serve-static` 和 e2e 用的产物）在构建期就把
`import.meta.env` 定死为**不含任何 Supabase 配置**的常量（见 `project.json` 的
`build.configurations.production.define`），所以产物恒为 local-only，环境变量和工作区 `.env`
都影响不了它。要改这个行为，改 `define`，不要指望环境变量。

## Local-only mode

Local-only mode does not require Supabase and keeps all Todo data in the browser database.

```bash
pnpm nx run dev-rxdb-supabase:serve-local
```

`serve-local` 会从子进程环境里删掉 `VITE_SUPABASE_*` 并设 `NX_LOAD_DOT_ENV_FILES=false`，
工作区 `.env` 里残留的 Supabase 地址不会再被 Nx 灌回来（这曾让 e2e 静默连上远端而 flaky）。

## Remote sync mode

Start the repository Supabase stack. Its host API port is `54331` (the container listens on `8000`).

```bash
docker compose -f docker/docker-compose.ci.yml up -d
```

Set the browser-facing URL and anonymous key in the shell or the workspace `.env`, then start the guarded remote target:

```bash
VITE_SUPABASE_URL=http://localhost:54331 \
VITE_SUPABASE_KEY='<anon-key>' \
pnpm nx run dev-rxdb-supabase:serve-remote
```

`serve-remote` fails before starting Angular when either variable is missing or the configured Supabase URL is unreachable. Extra Angular dev-server options are forwarded, for example `--port 8312`.

### 身份：访客、匿名用户与演示账号

启动时只读出浏览器里保存的会话，不替用户登录（epic-015：公开数据给 anon，不靠匿名账号）。右上角切换身份：

| 身份       | 会话                         | 能做什么                                                              |
| ---------- | ---------------------------- | --------------------------------------------------------------------- |
| 访客       | 没有会话，以 anon 访问       | 商品目录只同步公开区里关注的分类，其余公开商品在线浏览；Todo 只存本机 |
| 匿名用户   | `signInAnonymously()`        | 数据库角色 authenticated，演示 Todo 的日志推送与拉取                  |
| Alice、Bob | 邮箱口令登录，第一次用时注册 | Alice 在星河零售、Bob 在极光百货，各自还同步所在租户的内部商品        |

本地库按会话身份命名并绑定（US-035）：切换身份就是登录或退出之后重新加载，打开那个身份自己的库。
会话按浏览器保存、所有标签页共用：在一个标签页换了身份，其他标签页会提示重新加载；它们还开着上一个身份的库，
同步会被身份守卫拦下并报身份不匹配，本地数据不动。

Todo 走未分区的日志同步，只对登录身份开放（US-225），所以访客的 Todo 只存本机，点 Todo 页上的「匿名登录」即可同步。
匿名登录要求远端项目开启匿名用户：仓库的 CI 栈（`docker/docker-compose.ci.yml`）已开启；`docker/.env` 里是
`ENABLE_ANONYMOUS_USERS=true`；Supabase 托管项目在 Authentication → Sign In / Providers 里打开 Anonymous Sign-Ins。
开启匿名登录等于让任何访客都能读到未分区的同步日志，生产部署应关闭它，改用正式登录。

演示账号的口令写在前端代码里（`src/app/supabase-session.ts`），注册依赖项目关闭邮箱确认（CI 栈是自动确认），只用于本地隔离栈。

### 顶栏：本页的撤销与整机的推拉（epic-016）

Todo、商品目录、订单三页的撤销、重做、操作历史与推拉都在顶栏，页面进来时登记、离开时撤回（首页什么都不登记）：

- **左边是本页的**：「撤销」「重做」旁写着作用域（本页：Todo / 商品 / 订单），只撤这一页的修改；焦点不在输入框里时
  ⌘/Ctrl+Z、⌘/Ctrl+Shift+Z 同效。操作历史在页面左侧一栏，宽屏默认开着，顶栏最左边的开关收起或打开它（窄屏默认收起，
  打开是从左边盖住页面的抽屉）；它列出本页这次打开之后的修改，展开看每个字段的改之前与改之后，还没推的标 ↑。
  订单页的作用域是客户、证件、订单、订单项与分类合起来：带证件新建的客户一次撤销连证件一起撤，
  删掉有订单的客户一次撤销全部回来（US-316、US-318）。
- **右边是整机的**：「拉取」「推送」作用于当前身份的整个本地库，三页是同一组命令；↓N、↑N 是整机的待拉、待推数。
  在任一页推送，别的页没推的修改会一起推上去，推上去至少一条之后，之前的修改都不能再撤销。
  不能点的按钮悬停就能看到原因（比如「没有待推送的修改」）。切换身份只是一个下拉框，身份的说明在它的悬停提示里。
- **同步中心**（↕ 开关）：当前身份、本地库与分支，按实体分列的待推待拉，推送会带上的每一项修改（按页面分组），
  最近一轮的结果与被拒的推送；有被拒的推送时开关上有红色数字。

右侧面板（同步中心、商品页的模拟服务端变更）同一时刻只开一个：宽屏占一栏、不挡页面，窄屏是盖住页面的抽屉，点遮罩或按 Esc 收起。
推拉结果、撤销重做的失败、写入成功都弹在右下角的消息里：成功的几秒后自己消失，有被拒的与失败的留到你关掉。
↓N 刷新页面之后也是准数：自己推上去的修改按本地记下的远端 id 认出来，不算待拉；分区同步的商品按游标之后的真实条数算（US-233）。

## 商品目录：按身份授权的同步

`/catalog` 演示 epic-015 的第一批故事：按授权分区同步（US-033）、每个身份一个本地库（US-035）、规则之外的公开数据在线浏览（US-036），
以及在本机改商品、推送之前撤销重做（US-034）、远端变更历史（US-229）与同一租户里的管理员和员工（US-234）。

数据模型：参考夹具 `catalog_items` 与公开视图 `catalog_items_public` 在 `docker/sql/03-business-tables.sql`；
演示用的租户、成员关系与成员权限、按成员关系扩展的 `rxdb_caller_buckets()` 与 `rxdb_caller_grants()`、
按 `edit` 判定的写策略与种子数据在 [`supabase/catalog-demo.sql`](supabase/catalog-demo.sql)，由 `docker/init-db.sh` 与 CI
在初始化链里加载。已经起好的本地栈重新加载一次它与生产权限脚本即可（第一次加载时成员表加上权限列，
Alice、Bob 在各自登记的租户补成管理员，其余成员是员工）：

```bash
docker/supabase-ci-compose.sh exec -T db psql -U postgres -v ON_ERROR_STOP=1 --single-transaction \
  -f - < apps/dev-rxdb-supabase/supabase/catalog-demo.sql
docker/supabase-ci-compose.sh exec -T db psql -U postgres -v ON_ERROR_STOP=1 -f - < docker/sql/production/rxdb-change-grants.sql
docker/supabase-ci-compose.sh exec -T db psql -U postgres -c "NOTIFY pgrst, 'reload schema'"
```

公开商品在 `public` 区，租户内部商品在 `tenant:<租户>` 区；anon 对成本价没有列权限。

1. Alice 在「本机同步的商品」里新建一件星河零售的商品，或给一件已同步的商品点「编辑」改售价：

管理员与员工（US-234）：同一个租户里，管理员（`read + edit + manage`）能改商品、调整成员权限，员工（`read`）能同步、

演示账号第一次登录时加入各自的默认租户，由服务端按登记的邮箱授予管理员（`demo_tenant_initial_admins`）；
其他人自助加入都是员工，加入请求只写 `tenant_id`，写不到权限列。

1. Bob 登录：「身份与权限」写着「极光百货 · 管理员」；极光百货的商品能新建、编辑、删除、公开 / 收回，有「历史」。
2. Alice 在「模拟服务端变更」里加入极光百货并拉取：多出「极光百货 · 员工」，极光百货的内部商品同步进本机、成本价可见；
   它们的写入口是灰的，标着「员工只读」，没有「历史」；新建表单的租户只列星河零售。顶栏的撤销、重做与推送不受角色影响。
   试完退出极光百货，回到初始状态。
3. 另一个窗口切到匿名用户 X，加入极光百货：X 是员工，「成员与权限」里只有自己的角色、没有改权限的按钮。
   Bob 打开「模拟服务端变更」→「成员与权限」，在 X 那一行点「管理员」（X 的「身份与权限」里有用户 id，列表里是它的前 8 位）；
   X 点顶栏的「拉取」之后，极光百货商品的写入口与「历史」出现。Bob 再点「员工」，X 拉取之后又变回只读。
4. 降权之后推送被拒：X 当管理员时在本机改一件极光百货的商品先别推送，Bob 把 X 设为员工，X 点「推送」：远端拒绝，
   本机这件商品按远端对齐，同步中心的「被拒的推送」列出它，之后写入口变灰。降权之前留下的修改照样能撤销、重做。
5. 最后一个管理员撤不掉：Bob 是极光百货唯一的管理员时，在自己那一行点「员工」，面板里报「不能撤掉最后一个管理员」。
6. 断网重开：X 当管理员时拉取过一次，在浏览器开发者工具的 Network 面板里把 Supabase 的地址（`VITE_SUPABASE_URL`）
   加进请求拦截（Request blocking），再刷新页面：连不上远端，授权快照从本地库读回，极光百货商品的写入口照样在，改动落在本机。
   Bob 这时把 X 设为员工；X 取消拦截、点「推送」：远端拒绝、本机对齐，写入口变灰。

本机判定（US-234 阶段 B）：商品实体 `CatalogItem` 声明了作用域与所需权限（一行属于 `tenant:<tenantId>`，增删改都要 `edit`，
与商品的三条写策略同口径）。授权快照由 Supabase 适配器读 `rxdb_caller_grants()` 交给引擎（`rxdb.grants`）：远端连接时、
每轮同步进门时、本页改了成员关系之后各刷新一次，存进本地库，断网重开沿用上次的快照。商品页的写入口按声明与快照逐行派生，
演示里没有自己的判定；员工就算绕过界面、在控制台里调商品的 `save()` / `remove()`，本机也当场 `PermissionDeniedError`，
不留待推修改。

本机判定只是快速失败，安全边界在服务端的 RLS：两次刷新之间（比如刚被降权、还没同步）本机仍按旧快照放行，
那时写下的修改推送时被拒、按回执对齐。员工绕过本机直接写远端同样被拒（新建报 42501，修改、删除改到零行），
改自己的成员行、插带权限的成员行也都被拒；改权限只经服务端的 `demo_set_member_permissions`，退出只经
`demo_leave_tenant`，两者守同一个「至少留一个管理员」：唯一的管理员要先把别人升为管理员才能退出。

「模拟服务端变更」以当前身份直接写远端业务表（RLS 只放行你有 `edit` 的租户的商品，员工所在租户的商品不在这里列）；
自助加入、退出租户只为演示方便，真实应用由管理员或服务端维护成员关系。恢复初始演示数据（成员关系不动）：

```bash
docker/supabase-ci-compose.sh exec -T db psql -U postgres -c 'SELECT public.demo_catalog_reset()'
```

## 关系数据：订单的推拉同步

`/orders` 演示有外键关系的数据怎么推拉（US-227）：客户 1—n 订单 1—n 订单项，订单项 n—n 分类，客户 1—1 证件；
删订单带走订单项，删客户带走订单与证件，删分类带走它的关联，删证件只把客户的证件引用置空。
表、外键、RLS 与同步登记在 [`supabase/orders-demo.sql`](supabase/orders-demo.sql)，与商品目录一样由 `docker/init-db.sh`
与 CI 在初始化链里加载；实体在 [`src/app/orders/order-entities.ts`](src/app/orders/order-entities.ts)，不走代码生成，
本地声明与服务端同样的删除动作（多对一一侧 `CASCADE`；客户的证件引用 `SET NULL`、证件的持有人 `CASCADE`）。

已登录身份共享全部订单（演示的是外键关系，不是按身份授权）；anon 没有这些表的权限，访客的订单只存在本机。
实体按「子在前」注册（订单项、订单、证件、客户），全量推送照样把父行排在前面（US-037）。

页面按关系嵌套着画：客户卡片里是证件与订单，订单下面是订单项与挂着的分类，删父行时整棵子树一起消失。
怎么试写在页面顶部的「怎么测」里（US-235）：按场景（推送、级联删除、拉取、外键被拒、多对多、撤销、两人并发、访客）
列出步骤与每一步应该看到什么，照着做就行。除了「两人并发」，一个窗口就够，几个帮手：

- **生成示例数据**（页头）：一次写下一位带证件的客户、他的一张订单与两条订单项，同一个事务——一次撤销、一次推送。
- **未推送**：本机新建或改过、还没推送的行标着「未推送」，刚挂上的分类标成黄色；推送之后消失。删了什么看同步中心的待推送。
- **远端数据**（页头开关，右侧面板）：直接读 Supabase 里的六张表，按同样的嵌套展示；远端有、本机还没有的行标「本机没有」，
  每轮推拉结束自动重读。面板里的「在远端删除客户」「在远端删除订单」「模拟别人新建一组」以当前身份直接写业务表：
  同步触发器把它们连同外键级联删掉的行记进日志，日志不带本机的 clientId，拉取时就像别人推上来的。

比如外键被拒：推送一位客户，在远端数据里删掉他（先别拉取），本机给他新建一张订单再推送——远端的外键拒绝它，
同步中心的「被拒的推送」里是这张订单（依赖未满足，23503），页面上方指出是哪位客户已不在远端，这张订单从本机撤掉；
拉取之后客户也会消失。

「两人并发」要两个浏览器（一个登录 Alice，一个隐身窗口登录 Bob）：两边都先别拉取，给同一条订单项挂同一个分类再各自推送，
都推得上去，拉取之后两边都只有这一个关联。关联行的 id 由两端 id 派生（US-228），同一对在远端只有一行；
中间表 `"DemoCategory_DemoOrderItem"` 按契约建表（`id` 唯一、两端外键作主键），同步配置跟随两端：访客的两端只存本地，
关联也只存本地。

客户与证件互相持有外键（US-038）：同步层在可空的客户一侧断环，推送时客户的证件引用先写空，同一请求里再补写；
拉取时两行在一个本地事务里落库。页面只在两边的引用对得上时显示证件号。访客能在本机新建客户、订单与订单项：
它们只存本机，不算待推送（↑ 没有数字、推送不可点），拉取只拉公开商品，不发推送请求。

顶栏的「推送」「拉取」是整机的，三页一样；撤销、重做只作用于本页。
