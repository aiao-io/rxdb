## Orbit 运行内核的交付判据

以 DESKTOP-US-301～308 为准，至少能独立审查以下内容：固定上游来源、实际内核源码、独立构建产物、框架无关公共契约、实例身份分离、版本化资源、多实例路由、生命周期清理、明确故障边界、受控授权与消息作用域，以及三框架和现有文档站回归。

调研已读取的上游提交为 `c45932998c0602f34454df8d3e29f4d33a38446a`。实施时先评估该提交并固定采用的基线；记录其与最终采用版本的差异。优化项来自桌面产品的需求，不默认认定上游相应能力缺失或存在缺陷。

运行内核命名为 Orbit，主包 `@aiao/orbit` 通过三个可选子路径提供框架适配；桌面外壳、应用和协作服务另行实施。保留 MIT 版权与上游第三方声明；来源和许可证随源码和发布产物可追溯。不把上游旧浏览器自动降级、示例工程、无任务依据的嵌套和共享能力全部搬进首版。

现有 `modules/orbit` 是内部通信协议，不能作为“已经内化无界运行时”的证据。迁移必须保持原文档站及 Angular / React / Vue 演示的主题与路由行为，不能用新产品需求覆盖旧消费方的回归。

## 2026-11-07 运行基础实施决定

D-21：采用原生可见 iframe 文档与 Web Component 外壳，重写无界运行子集；不代理 Document/Node，也不在宿主重写子应用 CSS。三框架通过同包子路径共用生命周期契约。完整导航、浮层边界、自定义缓存与未交付范围见 [实施记录](../../../specs/001-web-desktop-product/runtime-implementation.md) 和 [来源与取舍](../../../packages/orbit/UPSTREAM.md)。这是实现选择，不改变双模式桌面和最终产品验收范围。

D-22：Orbit 是独立维护的运行内核，Wujie 仅为起始设计基线与灵感来源；包名、API、消息协议、运行标记、自定义元素及注入上下文均采用 Orbit 命名。README 说明灵感来源，UPSTREAM 固定参考提交并保留许可证；不继承完整上游 API 兼容承诺。
