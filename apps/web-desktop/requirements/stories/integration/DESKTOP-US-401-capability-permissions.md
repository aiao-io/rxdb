# 用户故事：桌面能力授权与撤销

## 作为/我想要/以便

**作为**安装和使用应用的用户，**我想要**按应用了解、授予和撤销桌面能力，**以便**控制应用通过桌面服务访问文件和系统操作。

## 范围边界

### In Scope

- 桌面服务默认拒绝、首次调用授权、应用版本权限差异。
- 一次性或持久授权、设置中撤销、明确的信任边界。

### Out of Scope

- 把协作式授权当恶意代码沙箱、拦截应用所有原生网络与浏览器 API 调用。

## 验收标准

| #   | 前置条件                           | 操作                   | 预期结果                                                                         | 状态 |
| --- | ---------------------------------- | ---------------------- | -------------------------------------------------------------------------------- | ---- |
| 1   | 应用尚未获授文件或剪贴板能力       | 首次调用桌面服务       | 先显示应用名称、来源、能力和访问范围；拒绝返回明确错误且无副作用                 | ⬜   |
| 2   | 应用声明必需和可选能力             | 用户拒绝可选能力       | 其余功能仍可用；必需能力被拒绝时说明无法继续的具体任务                           | ⬜   |
| 3   | 用户授予一次性访问                 | 完成所选操作或退出实例 | 授权失效，不复用于下一实例；持久授权按 appId 和批准来源保存                      | ⬜   |
| 4   | 应用已有授权                       | 设置中撤销             | 后续服务调用立即拒绝，未完成写入事务取消或明确完成边界，不继续持有可复用访问句柄 | ⬜   |
| 5   | 授权请求未声明、来源变化或新增能力 | 调用服务或更新         | 拒绝未声明能力，来源变化使旧授权失效；新增能力需再次确认                         | ⬜   |
| 6   | 用户查看能力说明                   | 阅读权限边界           | 明确权限控制桌面服务入口；应用仍属于可信协作代码，不声称能阻止同源恶意脚本       | ⬜   |

状态符号：⬜ 未验证 / ⚠️ 进行中或有保留 / ✅ 有同层级证据。

验收证据：尚无实现或产品验收证据；本轮只完成需求编写。实施时按 [分层验收台账](../../verification-report.md) 逐 AC 登记用例、构建版本、环境和结果，失败分支同样需要证据。
