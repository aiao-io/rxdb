# 用户故事：内置文本编辑器与保存闭环

## 作为/我想要/以便

**作为**需要记录内容的用户，**我想要**在独立 Web 应用里编辑并保存文本文件，**以便**验证桌面从启动、编辑到恢复的完整工作流程。

## 范围边界

### In Scope

- 纯文本与 Markdown 源文编辑、新建、打开、保存、另存为和脏状态。
- 多实例不同文档、同一文件版本冲突、基本撤销重做。

### Out of Scope

- 富文本排版、完整办公套件、自动执行 Markdown 内 HTML 或脚本。

## 验收标准

| #   | 前置条件                        | 操作                           | 预期结果                                                     | 状态 |
| --- | ------------------------------- | ------------------------------ | ------------------------------------------------------------ | ---- |
| 1   | 文本编辑器作为独立 Web 应用安装 | 新建文档并输入中文             | 在隔离实例中可编辑，窗口标题反映名称与未保存状态             | ⚠️   |
| 2   | 新文档尚未保存                  | 选择保存并指定目录和名称       | 原子写入文件字节，成功才清除脏状态；文件选择取消则保持原状态 | ⚠️   |
| 3   | 文件已保存                      | 关闭再从文件管理器或编辑器打开 | 内容一致，重命名后仍通过稳定文件 ID 定位，不误建重复文件     | ⚠️   |
| 4   | 同一文件被两个实例打开          | A 保存后 B 继续保存旧版本      | B 收到版本冲突，可重新加载或另存为；不静默覆盖 A 的内容      | ⚠️   |
| 5   | 当前文档未保存或存储写入失败    | 关闭、退出或更新               | 统一保护未保存内容；写入失败保持脏状态和可恢复的编辑内容     | ⚠️   |
| 6   | 文档已打开且有历史编辑          | 使用撤销、重做及另存为         | 历史只影响当前实例；另存为创建新文件，原文件内容不改变       | ⚠️   |

状态符号：⬜ 未验证 / ⚠️ 进行中或有保留 / ✅ 有同层级证据。

验收证据：已进入产品实施；当前源码和自动化旅程见 [应用说明](../../../README.md)。仍需按 [分层验收台账](../../verification-report.md) 逐 AC 登记用例、构建版本、环境和结果，失败分支同样需要证据。

本机 Chromium 正式产物已有两模式中文保存/关闭/刷新、取消选择、双实例冲突与重新加载证据。`e2e/editor.spec.ts` 补充独立撤销/重做、另存为保留原稿、保存 QUOTA 后草稿与脏状态保留及重试，以及重命名/跨目录移动的取消和按原文件 ID 恢复后继续保存；刷新同时核对稳定会话窗口 ID，运行实例 ID 随重建更新。完整支持环境、IME、系统快捷键和全部剩余分支仍需按台账验收。
