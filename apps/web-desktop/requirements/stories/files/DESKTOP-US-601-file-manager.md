# 用户故事：虚拟文件系统与文件管理器

## 作为/我想要/以便

**作为**桌面用户，**我想要**在文件管理器组织本地桌面文件，**以便**像使用桌面一样存放和查找工作内容。

## 范围边界

### In Scope

- 浏览器内持久文件与目录、列表、面包屑、新建、重命名、移动和基础搜索。
- 稳定文件身份、版本、元数据与权限边界。

### Out of Scope

- 默认访问本机磁盘、把路径当操作系统绝对路径、网络盘和云盘同步。

## 验收标准

| #   | 前置条件                             | 操作                     | 预期结果                                                                       | 状态 |
| --- | ------------------------------------ | ------------------------ | ------------------------------------------------------------------------------ | ---- |
| 1   | 文件管理器首次启动                   | 浏览默认目录             | 显示空态和新建入口，明确这是浏览器内桌面存储，不冒充用户操作系统磁盘           | ⚠️   |
| 2   | 用户新建目录和文件                   | 重命名并移动后刷新       | 内容、类型、稳定文件 ID 和更新时间保持正确；重名时要求用户明确选择，不静默覆盖 | ⚠️   |
| 3   | 用户把目录移入自身后代或输入非法路径 | 执行操作                 | 拒绝并解释原因，目录树无环且文件内容保持                                       | ⚠️   |
| 4   | 当前目录有多个文件                   | 搜索名称并导航面包屑     | 显示当前目录范围内的匹配项；空结果有提示，键盘可以定位和选择                   | ⚠️   |
| 5   | 应用只被授予一个文件或目录           | 通过桌面服务访问其他区域 | 拒绝越界及路径穿越，不能仅凭猜测文件 ID 获得权限                               | ⚠️   |
| 6   | 存储额度不足或写入事务失败           | 新建或移动文件           | 显示失败，原文件完整，无目录项与内容不一致的半成品                             | ⚠️   |

状态符号：⬜ 未验证 / ⚠️ 进行中或有保留 / ✅ 有同层级证据。

验收证据：已进入产品实施；当前源码和自动化旅程见 [应用说明](../../../README.md)。仍需按 [分层验收台账](../../verification-report.md) 逐 AC 登记用例、构建版本、环境和结果，失败分支同样需要证据。

AC2 已有本机 Chromium 两模式旅程：重命名与跨目录移动的取消保持原元数据，成功后原文件 ID 与字节保留；刷新恢复新目录，编辑器按原 ID 打开并继续保存，不生成重复文件。完整支持环境及重名组合等剩余分支仍需验收，详见 `e2e/editor.spec.ts` 与分层验收台账。

`e2e/file-manager.spec.ts` 还覆盖两模式真实空态、目录内搜索和键盘选择，非法名称/目录环拒绝，新建/重命名/移动重名不覆盖，以及新建/移动 QUOTA 和事务 abort 后的原字节、revision 与物理存储键保留及刷新重试。服务边界测试拒绝单文件/目录授权越界、路径形式 ID 和移动提交前撤权；实际授权旅程验证单窗口授权不跨文件或新实例，拒绝后原窗口仍能保存。完整支持环境、实际额度耗尽和剩余失败组合仍待验收。
