# 用户故事：运行中切换桌面交互模式

## 作为/我想要/以便

**作为**混用两种系统的用户，**我想要**不关闭应用即可切换 macOS / Windows 交互方式，**以便**根据设备与习惯调整桌面。

## 范围边界

### In Scope

- 设置中手动切换、布局与菜单切换、偏好持久化。
- 已运行实例、未保存内容、窗口边界和焦点保持。

### Out of Scope

- 同时显示两套桌面外壳、对应用业务数据做模式迁移。

## 验收标准

| #   | 前置条件                             | 操作                | 预期结果                                                                     | 状态 |
| --- | ------------------------------------ | ------------------- | ---------------------------------------------------------------------------- | ---- |
| 1   | 两个应用和一份未保存文档处于打开状态 | 切换交互模式        | 外壳、按钮位置和启动入口切换，实例标识、文档内容和脏状态不变，不重新加载应用 | ⬜   |
| 2   | 有最大化、贴靠、最小化窗口           | 来回切换两次模式    | 保存正常尺寸和最小化状态；按新工作区约束可见边界，标题栏不丢失               | ⬜   |
| 3   | macOS 模式有无窗口运行应用           | 切换到 Windows 模式 | 为这些实例恢复一个窗口，避免出现无法访问的后台实例；不丢弃其内容             | ⬜   |
| 4   | 已切换模式                           | 刷新或重新打开桌面  | 使用用户明确选择，优先于宿主操作系统推断                                     | ⬜   |
| 5   | 应用正在显示模态对话框               | 切换模式            | 对话框保持归属，焦点不进入其他窗口，取消后回到原活动窗口                     | ⬜   |
| 6   | 用户通过键盘执行切换                 | 操作完成            | 焦点落在可见的设置控件，辅助技术收到模式变更提示                             | ⬜   |

状态符号：⬜ 未验证 / ⚠️ 进行中或有保留 / ✅ 有同层级证据。

验收证据：已进入产品实施；当前源码和自动化旅程见 [应用说明](../../../README.md)。仍需按 [分层验收台账](../../verification-report.md) 逐 AC 登记用例、构建版本、环境和结果，失败分支同样需要证据。
