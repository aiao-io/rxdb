# 用户故事：应用运行环境与样式隔离

## 作为/我想要/以便

**作为**同时使用不同 Web 应用的用户，**我想要**让各应用的样式和普通全局状态互不污染，**以便**避免某个应用破坏整个桌面的显示与操作。

## 范围边界

### In Scope

- 可信协作应用之间的脚本全局、DOM、CSS 和事件作用域隔离。
- 动态样式、弹层、字体、主题以及主应用样式双向验证。

### Out of Scope

- 把同源运行环境当成恶意代码安全边界、保证 CPU 死循环与浏览器进程崩溃隔离。

## 验收标准

| #   | 前置条件                                 | 操作                   | 预期结果                                                                 | 状态 |
| --- | ---------------------------------------- | ---------------------- | ------------------------------------------------------------------------ | ---- |
| 1   | 宿主与两个应用定义相同类名和 body 样式   | 同时显示并动态改变样式 | 宿主和另一应用的布局、字体、颜色不被覆盖                                 | ⬜   |
| 2   | 两个实例为同名 window 全局变量赋不同值   | 在各实例读取和修改     | 普通全局状态保持各自值，不污染宿主或另一实例                             | ⬜   |
| 3   | 应用动态插入 style、link、字体和弹窗     | 切换及销毁实例         | 动态资源保持归属，弹窗不逃逸窗口，销毁后不留下宿主样式                   | ⬜   |
| 4   | 子应用监听键盘和指针事件                 | 分别操作不同窗口       | 只在约定作用域响应，后台应用不能收到发给前台实例的桌面命令               | ⬜   |
| 5   | 接入应用直接访问 parent 或同源浏览器存储 | 进行边界复验           | 接入报告明确这类访问不受强安全隔离保证；违反可信应用接入规范的应用不准入 | ⬜   |
| 6   | 所需隔离能力缺失或不可建立               | 尝试启动               | 明确启动失败，不静默退回无隔离渲染                                       | ⬜   |

状态符号：⬜ 未验证 / ⚠️ 进行中或有保留 / ✅ 有同层级证据。

验收证据：尚无实现或产品验收证据；本轮只完成需求编写。实施时按 [分层验收台账](../../verification-report.md) 逐 AC 登记用例、构建版本、环境和结果，失败分支同样需要证据。

## 技术笔记

沿用 Web Components 与 iframe 的隔离思路，但对同源 parent、Cookie、原生存储与执行线程不作安全隔离承诺。桌面授权是服务契约，不能约束恶意同源脚本。
