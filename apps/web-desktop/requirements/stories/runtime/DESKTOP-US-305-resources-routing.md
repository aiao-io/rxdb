# 用户故事：应用资源加载与独立路由

## 作为/我想要/以便

**作为**Web 应用开发者，**我想要**让资源和路由在桌面窗口中正确工作，**以便**保留独立部署能力并避免刷新白屏。

## 范围边界

### In Scope

- HTML 入口、静态和动态资源、相对路径、版本化缓存。
- 实例内 path、query、hash 与宿主导航协议。

### Out of Scope

- 绕过 CORS、CSP 或登录限制、对任意网站自动注入兼容补丁。

## 验收标准

| #   | 前置条件                                     | 操作                                 | 预期结果                                                                 | 状态 |
| --- | -------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------ | ---- |
| 1   | 应用部署在独立基础路径                       | 加载 HTML、CSS、图片、字体及动态脚本 | 相对地址按应用资源基址解析，样式内 URL 和动态导入有对应样例验证          | ⬜   |
| 2   | 同一应用两个实例有不同 path、query、hash     | 分别导航再恢复会话                   | 各自路由保持且不覆盖对方或桌面地址，不把机密字段复制进桌面分享链接       | ⬜   |
| 3   | 应用要求跨源资源且服务端未允许               | 启动应用                             | 清楚报告受 CORS 或 CSP 限制的资源类别与可重试动作，不提供绕过代理        | ⬜   |
| 4   | 资源返回登录页、404 或错误内容类型           | 加载应用                             | 拒绝把错误页面当作就绪应用，显示来源与错误类别且不暴露凭据               | ⬜   |
| 5   | 用户通过桌面导航协议前进、后退或打开指定路由 | 执行导航                             | 只影响目标实例；应用未经协议直接写顶层地址属于接入违规                   | ⬜   |
| 6   | 资源已按版本缓存                             | 同时运行旧版本并准备新版本           | 缓存键包含应用和版本，不混用脚本样式；取消加载不会把不完整资源标成可离线 | ⬜   |

状态符号：⬜ 未验证 / ⚠️ 进行中或有保留 / ✅ 有同层级证据。

验收证据：仓内运行内核已开始实现，代码与真实 Chromium 测试的范围见 [实施记录](../../../../../specs/001-web-desktop-product/runtime-implementation.md) 和 [分层验收台账](../../verification-report.md)。下表 AC 仍未完成完整产品验证，不因底层测试通过而自动关闭。
