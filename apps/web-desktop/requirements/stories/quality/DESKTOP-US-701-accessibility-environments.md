# 用户故事：支持环境与无障碍验收

## 作为/我想要/以便

**作为**使用不同设备和辅助技术的用户，**我想要**明确知道支持范围并完成主要任务，**以便**避免某一交互模式只有外观而无法实际使用。

## 范围边界

### In Scope

- macOS / Windows 宿主上的模式交叉验证、浏览器能力检测。
- 键盘、读屏、对比度、缩放、减少动效和输入法。

### Out of Scope

- 首版手机桌面、旧版 IE、未验证浏览器的完整兼容承诺。

## 验收标准

| #   | 前置条件                             | 操作                                   | 预期结果                                                                                                    | 状态 |
| --- | ------------------------------------ | -------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ---- |
| 1   | 真实 macOS 和 Windows 环境           | 分别运行 macOS 与 Windows 两种模式     | Chrome 和 Edge 的两套模式均完成启动、切换、编辑、保存和恢复；macOS Safari 同样验收                          | ⬜   |
| 2   | 仅使用键盘                           | 完成应用启动、移动窗口、编辑保存和退出 | 无键盘陷阱，焦点可见且顺序合理，模态关闭后恢复来源焦点                                                      | ⬜   |
| 3   | 使用 macOS VoiceOver 或 Windows NVDA | 操作窗口和授权界面                     | 正确读出名称、角色、状态和活动窗口；重要异步结果有可感知提示                                                | ⬜   |
| 4   | 1440×900 标准环境且浏览器缩放到 200% | 执行主要旅程                           | 窗口控制与菜单可达、内容不互相遮挡，文字对比度满足 WCAG 2.1 AA                                              | ⬜   |
| 5   | 使用中文输入法或减少动效设置         | 编辑和切换窗口                         | 候选和组合输入正常，减少动效生效，不以颜色作为唯一状态指示                                                  | ⬜   |
| 6   | 桌面视口小于 1024×640                | 进入或放大桌面                         | 显示调整工作区提示并保留可达的基本操作与设置；200% 缩放仍可通过滚动或紧凑布局完成主任务，不把手机视为已适配 | ⬜   |

状态符号：⬜ 未验证 / ⚠️ 进行中或有保留 / ✅ 有同层级证据。

验收证据：已进入产品实施；当前源码和自动化旅程见 [应用说明](../../../README.md)。仍需按 [分层验收台账](../../verification-report.md) 逐 AC 登记用例、构建版本、环境和结果，失败分支同样需要证据。

## 技术笔记

浏览器版本在实施验收时锁定并记录。Playwright WebKit 不等于真实 Safari 证据；Linux 自动化不等于 Windows/macOS 实机证据。
