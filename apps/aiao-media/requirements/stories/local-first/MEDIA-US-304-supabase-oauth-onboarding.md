# 用户故事：Supabase 授权接入与自动初始化

## 作为/我想要/以便

**作为** 希望把创作数据存到自己 Supabase 项目的用户

**我想要** 在 Supabase 官方页面授权，选定项目并确认初始化后，由应用自动完成连接

**以便** 无需复制 Key、执行 SQL、创建存储桶或再注册一套项目账号，就能准备好自己的同步空间

## 当前问题

现有连接入口要求用户填写项目 URL 和公开 Key、审阅并手动执行 SQL，再登录项目内账号。普通创作者难以判断是否配置成功；管理授权成功也不代表项目内同步身份、数据库权限和图片存储已经可用。当前实现见 [sync-target-settings.html](../../../src/app/account/sync-target-settings.html) 与 [sync-target.ts](../../../src/app/sync-target.ts)。

## 范围边界

### In Scope

- 提供“连接我的 Supabase”引导：官方管理 OAuth 授权 → 选择组织下项目 → 预览初始化内容 → 明确确认 → 自动初始化 → 展示连接检查结果。拒绝、取消和失败均允许返回本机创作。
- Web 使用官方授权页；Tauri 使用系统浏览器授权，并安全返回原连接会话。首次连接不要求购买平台服务、启用平台同步或手工提供 PAT、service role、secret Key、数据库密码。
- 授权范围按 OAuth 应用实际可申请的最小权限配置。若 Supabase 授权覆盖组织或多项目，界面准确说明；用户选择项目后，后端每次操作仍校验授权主体、连接、组织与目标项目的归属。
- 首版自动接入支持独立空项目和应用已初始化且版本兼容的专用项目。列出、选择和检查项目不写库；确认后才创建应用数据表、必要同步设施、私有图片 bucket、访问策略和迁移版本记录。
- 自动建立可用于项目内同步的用户身份与会话，管理授权与项目数据授权分别校验。跨设备使用同一可验证授权主体连接同一项目时，恢复同一同步身份和工作区；不按邮箱、浏览器提供的 userId 或“能看见同一项目”合并身份。
- 初始化以检查清单展示数据库、权限、bucket 和同步身份各自状态；逐步持久记录回执，重复点击、回调重放、刷新、断网和并发初始化可核对继续，不清库重来。
- 管理 OAuth client secret、管理 access/refresh token 仅在受保护的后端使用；需要的服务端凭据同样不得进入网页、桌面包、日志、备份和业务同步记录。初始化仅传配置与必要身份信息，用户草稿和原图仍由客户端直连所选项目。
- 提供停止当前设备连接、解除集成和重新授权入口，明确项目内同步会话与管理授权的撤销边界；保留本机数据和远端对象，停止或撤权不触发远端删除。

### Out of Scope

- 自动创建组织、创建收费项目、升级套餐、接受服务条款或修改账单。
- 在已有其他业务的共享项目上自动安装；任意历史 schema 自动迁移、降低版本标记或放宽现有 RLS。
- 授权或初始化成功后立即上传本机图库。原图传输与授权范围由 [MEDIA-US-305](MEDIA-US-305-supabase-image-sync.md) 验收。
- 将组织管理权限当成任意项目用户的图片访问权，或自动把已有平台账号、自有项目账号和同邮箱账号视为同一身份。

## 用户流程

1. 用户点击“连接我的 Supabase”，了解授权用途和后端会处理的管理权限。
2. 在 Supabase 官方页面登录并授权；已有有效登录时无需重复输入密码。
3. 回到应用，选择可管理的项目。无可用项目时给出官方创建项目入口，创建后重新读取，不自动创建或付费。
4. 查看项目名称、组织、将创建的对象、权限和私有存储说明；点击“初始化并连接”。
5. 应用完成初始化和项目内身份引导，分别展示检查结果。用户不需要再复制 Key、执行 SQL 或填写项目账号密码。
6. 连接就绪后进入独立的“图片同步范围”确认；用户取消时，项目已初始化但没有任何本机图片被上传。

## 交付阶段

| 阶段 | 用户价值与范围                         | 对应 AC | 关闭条件                                                |
| ---- | -------------------------------------- | ------- | ------------------------------------------------------- |
| A    | 官方授权、回调归属与项目选择           | 1–4、8  | 真实 OAuth 可返回 Web/Tauri，权限与凭据边界有正反向测试 |
| B    | 自动初始化、可恢复配置和项目内身份引导 | 5–7     | 证明无手工凭据也能获得受限项目会话；初始化中断可恢复    |
| C    | 连接状态、撤权与完整接入               | 9–11    | 两端真实全流程通过；图片同步仍由独立确认控制            |

三个阶段共用本故事。管理授权成功不能替代 B/C 阶段；项目内身份引导不可实现时，不以增加一页手工项目登录宣称完成。

## 技术笔记

- 自动接入服务端入口已接线，但尚无真实 OAuth/云项目验收。现有 [supabase-auth.ts](../../../src/app/supabase-auth.ts) 负责项目内登录，[sync-target.ts](../../../src/app/sync-target.ts) 只验证公开配置和已初始化项目；二者都不能证明管理 OAuth 与自动身份引导已完成。
- 根据 Supabase 官方集成文档，OAuth scopes 在注册应用时配置，管理令牌可覆盖获授权组织的资源，不能把产品内“选中项目”描述成 Supabase 天然签发了单项目令牌。实际项目约束必须由后端执行，权限扩展要求重新授权。
- 实施设计需先证明“管理授权主体 → 本产品连接归属 → 项目内同步用户/工作区 → 最小数据权限”的可信映射和跨设备恢复，再写自动身份引导代码。实现方式需符合 Supabase 支持的认证方式；不能将管理 token 伪装成项目 JWT、信任客户端 ownerId 或导出项目签名密钥。
- `production-bundle` 的空库守卫和迁移 SQL 可作为检查基线；bucket、权限和身份步骤需可恢复回执。自动升级只处理已识别的专用项目，不把清库作为恢复方案。
- 验证分层：单元/契约覆盖 PKCE、回调重放、项目替换和初始化状态；真实本地 Supabase 覆盖数据会话/RLS 与 SQL 恢复；真实官方 OAuth 和云项目覆盖管理授权/身份引导；Web 与 Tauri 验收各自回调。`aiao-media:requirements-check` 只证明文档结构。
- 外部前置为注册管理 OAuth 应用、配置最小 scopes 与正式回调、服务端 secret/令牌保护和独立测试项目；缺失时仍可做契约设计，不伪造真实验收通过。
