# 用户故事：多端草稿同步与冲突处理

## 作为/我想要/以便

**作为** 跨设备创作者

**我想要** 注册账号后通过 Supabase 同步草稿、作品元数据与供应商配置

**以便** 在多台设备继续创作，同时保留离线改动并看清本机文件的边界

## 范围边界

### In Scope

- 使用 `@aiao/rxdb-adapter-supabase` 与配套同步插件，在本机写入基础上同步；先验证发布版本兼容性、产品数据契约和应用接线，类型声明或上游故事 Done 不能算本仓已交付复制。
- 用户不启用同步时，本机读写不触发复制或远程数据上传；未配置账号服务时不连接 Supabase。显式配置账号后的 Auth 会话请求由 MEDIA-US-201 管理；启用复制前明确工作区/账号绑定与首次数据范围。
- 第一阶段同步草稿、作品的非敏感元数据和供应商配置；不发送 API Key、浏览器文件句柄、本地路径或可直接解引用的本地文件标识。本阶段固定排除 Key；后续如需同步凭据，另行明确范围与安全策略。
- 明确每类记录的稳定 ID、schema/revision、检查点、冲突策略和删除传播。离线修改重连后保留未确认变更，同记录修改/修改或删除/修改冲突保留可恢复版本，不仅按 updatedAt 静默覆盖。
- 删除使用可复制的 tombstone；重复推送、断网和重启可继续，不复活已确认删除的旧版本。保留期限/检查点过期恢复按 D-06 在实际场景再决策，首版不部署自动清理或 TTL，相关 AC 不提前关闭。
- 同步状态可观察，区分待同步、进行中、已同步、冲突和失败。另一设备只有作品元数据时显示“本机无原图”，不提供虚假的本机预览或下载。
- 权限失效、协议不兼容或复制失败保留本机数据并暂停远程写入。同步不调用模型、不重新生成图片，不覆盖另一个账号或未绑定的本机工作区。

### Out of Scope

- 图片文件本体上传/下载、云作品备份、团队协作与 Electron 端同步。
- 自建 Bun API/PostgreSQL 同步协议；仅安装 RxDB 包就宣称 Supabase 同步可用。
- 未确定策略便同步供应商 Key；仅同步作品元数据就宣称原图已跨设备共享。

## 技术笔记

本仓产品复制尚未接线，`LocalMediaStore.open()` 与本机实体仍使用 `SyncType.None`，依赖尚未包含 Supabase adapter 或 sync plugin。

本仓已有 Supabase adapter 与 sync plugin，平台能力见 [rxdb:US-203](../../../../../requirements/stories/adapter/US-203-supabase-adapter.md)。应用消费 0.0.28 工作区包，本机持久化和可选 Auth 会话已经验证；产品工作区绑定、数据复制与冲突语义尚未接线。底层交付状态与本产品的双设备场景分别验收，当前决策见[决策与执行条件](../../decisions.md)。

账号/工作区绑定和首次确认采用[绑定计划](../../plans/account-workspace-binding.md)；按产品 schema/RLS、稳定 ID/revision 与白名单 DTO 分阶段接线。冲突先保留双方版本并暂停该记录；tombstone 期限、清理和检查点过期恢复按 D-06 在实际场景决定，不阻断无冲突复制验证。首阶段固定排除供应商 Key、原图和本地文件标识。

`aiao-media-e2e:local-first-e2e` 验证本机工作区、离线、备份、生成状态与独立账号会话；`aiao-media:supabase-e2e` 验证真实账号会话。这些均不证明跨设备复制。首发图片验收先于同步扩展，顺序见[路线图](../../roadmap.md)。
