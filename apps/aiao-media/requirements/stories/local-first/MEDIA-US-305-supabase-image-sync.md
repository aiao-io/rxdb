# 用户故事：图片原文件同步到自有 Supabase

## 作为/我想要/以便

**作为** 希望在多台设备查看和继续使用自己图片的创作者

**我想要** 确认范围后，自动把原图同步到自己的 Supabase，并在其他设备按需取回

**以便** 换设备也能预览、下载原图，并明确知道哪些图片只在本机、哪些已经完成远端保存

## 当前问题

当前仅复制作品信息。另一设备看到作品后仍显示“本机无原图”，必须经备份文件搬运原图。作品信息同步成功也不能证明远端存在可恢复图片。现有边界见 [MEDIA-US-302](MEDIA-US-302-draft-sync.md)、[MEDIA-US-303](MEDIA-US-303-sync-targets.md) 与[作品界面](../../../src/app/local-image-mvp.html)。

## 范围边界

### In Scope

- Web 与当前承诺的 macOS Tauri 支持 PNG/JPEG 原始字节的显式上传、已授权后的自动上传、跨设备按需下载和本机恢复；单张继续沿用现有 16 MiB 上限、格式/尺寸/解码与 SHA-256 校验。
- 首次单独选择“仅同步以后保存的图片”或“同步已有及以后保存的图片”，默认不选择。已有范围预览作品数、总字节数、不可读/超限作品和目标项目；以后保存仅指确认后在当前工作区完成本机保存的新作品，重新连接不自动扩大到历史图片。
- 每个工作区只启用一个目标；按项目、项目用户、工作区和稳定作品/文件版本标识隔离。图片与必要元数据从客户端直达所选项目的私有 Storage 与数据库，不经平台 Worker/R2 中转或存储。
- 本地持久传输队列维护每张图的选择范围、源摘要、目标、进度、失败和已确认回执；图片先在本机保存，上传失败不影响原图预览、下载或继续创作，不调用生成模型。
- 文件上传、远端完整性检查、作品与文件版本关联分别确认；刷新、超时、响应丢失和多设备上传同一版本可核对恢复，不覆盖其他字节、不产生重复关联或把半成品标为已同步。
- 有界并发与分块传输，断网、刷新和应用重开可继续；支持服务端续传的项目恢复分片进度。续传会话过期时重新核对同一不可变文件身份，再重传当前文件；不清空整个传输队列。
- 原图和缩略图都保持私有。新设备先显示“远端可取回”，进入视口才读取受权预览，显式下载/保存才恢复原图；没有本机文件时不能显示“已保存到本机”，已有本机原图可离线使用。
- 展示已选图片数、已传字节、待传、失败、最近成功时间、可确认的存储/文件限制和费用承担方。未知配额显示未知；额度不足暂停传输并保留队列，不静默切到平台存储或升级套餐。
- 停止/断开、撤权和切目标使旧传输失效；本机已保存文件和远端已确认对象保留。三种删除范围分别操作：仅删本机副本、从同步图库移除、删除远端原图副本；远端对象回收须遵守下面的删除契约。

### Out of Scope

- 自动接入平台托管原图、同时把同一工作区转存多个 Supabase 目标、团队共享、公开 bucket 或永久公开分享 URL。
- API Key、管理 OAuth token、项目私钥、账号会话、本机路径、句柄和本地 blob URL 的业务同步。
- 自动删除本机文件以腾空间、对已确认原图进行压缩/重编码、自动购买容量、生成新图片以补回缺失文件。
- 按 TTL 自动 GC、重置远端修订/检查点，以及不提示删除影响就永久清除所有历史版本或账号。

## 用户流程

1. 自有项目和项目内同步身份就绪，用户打开“图片同步”。自动授权接入由 [MEDIA-US-304](MEDIA-US-304-supabase-oauth-onboarding.md) 提供，已有手工连接的兼容项目也可使用。
2. 查看项目、工作区、数据范围、图片数量与大小、Storage 限制和费用说明，明确选择历史图片是否加入。
3. 点击“确认并启用图片同步”。应用先保留本机副本，再在后台上传选择范围内的图片，逐张显示状态。
4. 另一设备连接同一身份和工作区，看到远端作品并按需预览；点击“保存到本机”后校验并落盘，完成后可离线查看和精确下载。
5. 用户可暂停、重试失败、停止自动上传或分别管理本机/远端副本；切换项目必须重新确认，旧数据不自动转存。

## 删除与冲突契约

| 操作             | 本机影响                                                           | 远端及其他设备影响                                                                                                                                          |
| ---------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仅删本机副本     | 显式确认后清理此设备文件与本机文件关联，保留远端作品记录           | 远端原图与作品信息保留；此设备不因后台扫描自动重新下载，用户可主动取回                                                                                      |
| 从同步图库移除   | 发起设备的本机原图保留，界面单列为仅本机；其他设备已下载文件也保留 | 写作品删除标记并传播，旧传输/离线编辑不能静默复活；已上传对象保留，后续物理回收另行确认                                                                     |
| 删除远端原图副本 | 本机已下载文件保留                                                 | 展示对象与保留版本影响后单独确认；先提交当前文件删除标记并使旧任务失效，再走鉴权 Storage 删除与可恢复回执；其他设备显示远端不可取回，离线冲突保留并等待选择 |

删除远端原图前检查当前关联、保留版本、冲突和待核对传输的引用。事务内解除本次明确确认删除的当前文件关联后，如仍有其他保留引用，拒绝物理删除并说明原因；拒绝时保留原图与可恢复记录。首版不跨作品物理去重，避免删除一张作品影响其他作品。D-06 的 tombstone、冲突版本和日志继续保留；旧删除/上传回执不得清理新版本，删除后重新上传需要新的明确操作与版本。无引用对象也只能经上述显式操作回收，不新增自动 GC。

## 验收标准

| #   | 前置条件                                                             | 操作                                                                          | 预期结果                                                                                                                                                                      | 状态 |
| --- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1   | 自有项目已连接，本机有历史作品                                       | 授权/初始化、打开图片同步、取消确认                                           | 无原图上传；显示项目、工作区、两种范围、历史数量/字节和费用归属，默认不选择上传范围；取消不更改本机作品                                                                       | ⬜   |
| 2   | 用户选择仅以后图片或已有及以后图片并确认                             | 新增作品、重连、切换工作区和检查网络                                          | 仅上传确认范围内完成本机保存的文件；仅以后模式不追补历史；不把浏览记录当上传授权，不向其他项目、平台存储或生成接口发请求                                                      | ⬜   |
| 3   | PNG/JPEG 原图、损坏/超限文件和 Storage/RLS 就绪                      | 上传并回读原图，检查作品关联                                                  | 字节、MIME、尺寸与 SHA-256 一致；文件回读与关联提交均通过后才显示已同步；无效文件拒绝且不改写其他作品，不以 HTTP 200 或 metadata 回执代替原图验收                             | ⬜   |
| 4   | 对象上传成功但回执丢失，或作品关联提交中断                           | 刷新、重复重试、两设备同时上传同一版本                                        | 核对相同不可变对象身份和摘要后恢复关联；无重复作品、无不同内容覆盖；部分上传或关联失败保持待确认，本机文件保留                                                                | ⬜   |
| 5   | 多张图片排队，单图分块中断/续传会话过期                              | 断网、关闭/重开应用、恢复传输                                                 | 持久队列与源/目标身份不变，有界并发；可恢复的分片继续，过期只重传当前文件并核对原身份；丢失或已变更源文件明确失败，不清空其他任务或重新生图                                   | ⬜   |
| 6   | 桶拒绝写入、项目只读、配额不足或限制无法读取                         | 自动上传与用户重试                                                            | 诊断和失败数可见，暂停对应任务，限次退避且不无限重试；未知额度不编造可用空间；原图本机功能继续可用，不自动升级套餐/切目标                                                     | ⬜   |
| 7   | 新设备无本机文件，有远端作品和大于一页的图库                         | 打开图库、滚动、翻页、离开和显式下载                                          | 分页和可见预览有界；仅视口可见卡片读预览，失效 URL 释放；远端可取回与本机保存状态独立，不把远端记录显示为离线可用，不扫描下载整个图库                                         | ⬜   |
| 8   | 远端原图可读，但网络、摘要、图片解码或本机落盘失败                   | 保存到本机、重试、重开并离线下载                                              | 校验并原子保存完成后才标本机可用，下载与上传原字节一致；失败保留已有本机原图和远端回执，重试不重复上传或生成；成功后离线可读                                                  | ⬜   |
| 9   | 用户 A/B、不同项目/工作区、匿名请求和已过期数据会话                  | 猜测对象路径、直接请求预览/原图、上传/改写/删除和篡改 owner                   | 私有 bucket 与服务端 RLS 拒绝越权，不能靠隐藏按钮鉴权；受限项目数据令牌用于传输，service role/管理 OAuth token 不到客户端，不跨项目发送用户会话                               | ⬜   |
| 10  | A 项目上传/下载尚在途                                                | 停止同步、断开、退出或切换到 B 项目/账号                                      | 停止旧任务，过期回执不落入新空间；本机与远端已确认数据保留，未确认状态可恢复；重新启用保留原范围，换目标重新确认且不自动转存 A 的远端数据                                     | ⬜   |
| 11  | 图片在两设备有本机副本且远端可取回                                   | 分别执行仅删本机、同步图库移除和删除远端原图                                  | 各自影响与删除契约一致；本机删除不删远端、不被自动重新下载；同步移除传播 tombstone 而保留各端文件；远端物理删除独立确认，无权限/引用保护拒绝时原对象保留                      | ⬜   |
| 12  | 远端删除已确认，离线设备有旧编辑/上传，或删除中断且新版本已产生      | 重连、重复删除、恢复旧上传/回执                                               | 旧任务不能复活已删除版本或删除新对象，冲突可见且保留双方与 tombstone；删除回执未知先核对，不因失败清本机；再次上传须用户明确选择新版本                                        | ⬜   |
| 13  | 应用升级前有现有 PNG/JPEG、本机备份和 metadata 同步记录              | 升级、导入旧备份、迁移队列版本并尝试旧版打开                                  | 数据库/OPFS/原生文件标识与既有备份兼容；新增传输记录不含 Key/会话，旧备份不隐式启用图片上传；未知或更高协议/schema 保留数据并拒绝不兼容读写，不降级/清库                      | ⬜   |
| 14  | 专用真实云项目、Web 和 macOS Tauri 两设备、至少一个大于 6 MiB 的原图 | 双向上传、续传、跨设备取回、离线重开、越权与删除冲突；另跑官方 OAuth 接入联验 | PNG/JPEG 原字节精确一致，独立确认与撤权边界均符合故事；真实 Storage 和实际两端接线有证据，fixture/仅 SQL/仅 metadata 同步不能替代；自动接入的完整体验需 MEDIA-US-304 同时验收 | ⬜   |

| 阶段 | 用户价值与范围               | 对应 AC | 关闭条件                                              |

| B    | 跨设备预览、取回与离线使用   | 7–10    | Web 与 Tauri 双向取回原字节；切账号/项目不串数据      |
| C    | 删除冲突、升级与自动接入联验 | 11–14   | 明确删除行为、协议兼容、云项目和官方 OAuth 全链路验收 |

阶段 A/B 可与 MEDIA-US-304 并行开展技术验证；完整关闭依赖 MEDIA-US-304 的自动接入和本故事阶段 C 的联验。对外宣称“授权后自动同步图片”须两条故事全部通过，不能用手工 Key/SQL 接线关闭自动接入体验。

## 技术笔记

- 图片同步控制器、私有 Storage 迁移和 UI 入口已接线，但尚无真实云 Storage/双设备验收。现有 [product-sync-store.ts](../../../src/local-data/product-sync-store.ts) 仅复制元数据，[browser-media.ts](../../../src/local-data/browser-media.ts) 维护本机原图；[平台 R2 交付](../../../server/cloudflare/platform-coordinator.mjs) 不属于用户自有 Supabase 文件同步。
- 根据 Supabase Storage 官方文档，私有 bucket 的上传和下载均须授权；实现需同时限定 bucket、项目用户与工作区，并拒绝路径替换、公开 URL 和越权签名。临时预览/签名 URL 不作为持久图片身份，不进入同步 DTO。
- 对象路径包含项目内用户、工作区、作品 ID 与不可变文件版本/摘要；不同版本不 upsert 覆盖，文件与记录采用可恢复提交。重试只允许可核对、可幂等的传输，不复用生图重试规则重新调用模型。
- 支持续传的 Storage 使用官方 TUS 能力，分片大小等接口参数按实施时官方文档配置；受限/不兼容项目须明确提示，不能悄悄退化并宣称已续传。大文件测试覆盖超过 6 MiB，单张上限沿用 16 MiB。
- 现有协议的 `metadataOnly` 判定和所有“原图只在本机”说明需按新能力显式版本化，保持仅 metadata 连接可用。旧客户端遇到新协议/文件版本须保留数据并安全拒绝，不通过清除兼容守卫上线。
- 验证分层：单元/契约覆盖授权范围、队列、提交和删除状态；真实本地或专用云 Storage 验 RLS/回执/续传；真实 Web/Tauri 验证原图字节、原生落盘、离线与切目标；自动授权全流程与 MEDIA-US-304 联验。文档门禁不证明任何运行行为。
