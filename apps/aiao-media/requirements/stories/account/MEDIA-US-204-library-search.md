# 用户故事：本地作品检索与按需预览

## 作为/我想要/以便

**作为** 已在本机保存多张图片的创作者

**我想要** 按提示词、模型和本地日期查找作品，分页浏览，并只读取进入视口的卡片原图

**以便** 图片增多后仍能找到作品，避免为整库或视口外卡片占用原图内存

## 范围边界

### In Scope

- `/images` 提供独立的提示词 `search`、模型 `model` 子串筛选框，与本地日期 `from`/`to` 组合。`search` 只匹配 `prompt`，`model` 只匹配 `modelId`，已填写条件之间为 AND；采用现有原生字面 `contains`，英文大小写敏感，百分号/下划线按普通字符处理。
- 日期按当前浏览器本地日解释，开始日包含本地零点，结束日覆盖整日，以其下一本地日零点为排除上界。允许只填起始或结束日；无效日历日期或起始晚于结束须明确校验，不能用 UTC 日期截断或静默改值。
- 每页固定 24 件，展示匹配总数、当前页和翻页状态。以 `createdAt` 倒序，再按作品实体唯一 `id` 倒序确定同时间顺序；排序字段不是生成任务 `jobId`。数据不变时重复读取不得跨页重复或漏项。筛选变更回到第一页；总数变化时收敛到有效页，零结果保留第 1 页状态并禁用翻页。
- 当前页只决定最多 24 张卡片的元数据；只有真实 `IntersectionObserver` 对实际视口报告 `isIntersecting=true` 的当前页卡片才申请原图预览，不扩展 rootMargin 提前读取视口外原图。视口外卡片使用固定高度占位，不因初始化整页而读取全部 24 张原图，不通过图片加载改变布局反复触发可见性。
- 冷启动恢复不遍历读取已确认 `ready` 的原图；预览、详情和备份的显式读取仍完整核对文件关联、字节数、摘要和图片格式。`saving` 必须完整回读后才能提交 `ready`，`deleting` 与原有孤儿清理继续恢复。暂时不可读或明确损坏只让本次读取失败，浏览操作不改写历史保存记录、不删除原文件。
- 卡片滚出视口、翻页、筛选、离开作品页、关闭会话或切换工作区时释放对应 Object URL。异步读取返回后再次核对卡片可见性、页/筛选与工作区世代；失效结果不能回写新视图，已创建的迟到 URL 仍须释放。
- 初始加载、重新查询、空库、筛选无结果、查询错误与单张原图读取失败分别准确显示。查询失败不能当作空库或清空全库事实；单卡片失败不阻塞其它可见卡片，不因尚未读取的页外作品判定“无本机文件”。
- 全库本机作品 metadata/ID 事实与当前页卡片/预览独立管理，继续供同步快照、`remoteOnlyWorks`、任务文件归属和显式删除使用。首次全库读取成功前保持“尚未确认”，不能推断空库、remote-only 或无本机副本；后续失败保留最近成功的归属事实，重试成功清除独立错误。页外、过滤掉或未进入视口的作品仍是本机作品，不能因裁剪视图产生同步删除/tombstone。
- 本故事新增的检索、筛选、分页、视口观察和状态切换不触发生成、上传或业务数据写入；已有显式删除、下载与提示词复用沿用 MEDIA-US-202 的行为。无需真实供应商或生产服务即可完整验收。

### Out of Scope

- 云原图/跨设备文件同步、新后端、生产 Supabase 或部署；Supabase 本轮仍仅本地。
- 大小写折叠、模糊/语义检索、全文索引、归一化字段或 schema/backfill；不修改 `packages/*`。
- 自动清理、TTL、音视频、参考图、移动真机与真实系统 IME；不扩大已有暂停范围。

## 技术笔记

原问题包括作品页缺少检索/分页、整页预览和冷启动恢复遍历所有 ready 原图。实现使用本仓 RxDB 原生 where/orderBy/limit/offset/count；全库 metadata、当前页和视口预览分别管理，不增加 schema 或 packages 改动。`WorkMetadataSession` 保留未知/成功/错误状态，避免把读取失败当作删除；同步捕获继续读取全库事实，失败时不能提交空快照。

查询契约 7 项、真实 SQLite/OPFS 浏览器 22 项（含 1,005 条 metadata 压力与 3 项冷启动/只读恢复用例）、会话/指令/metadata/实际根组件呈现测试，以及应用/e2e lint、typecheck 和生产构建均通过。最终生产构建的统一本机 Chrome E2E 为 31/31：原 28 项加新增 3 项，覆盖 50 张真实图片的 IO、末页删除/离线精确下载，以及同文档 50 张 Alice 库→Bob 空库→Alice 原库的切换。不是 1,000 张原图 UI 实测，不承诺毫秒指标。

全部 AC 的分层证据、覆盖率限制与复验入口见[实施清单](../../plans/library-search-tasks.md)及[验收记录](../../verification-report.md)。后续质量收尾在原 Vitest 配置下以 632/632 项测试将行/语句/函数/分支提升到 94.62%/86.64%/84.62%/80.06%，四项均达到 80%；E2E 未折算为 Vitest 覆盖率。Supabase 仍仅本地，本功能未部署、PR 未合并；全部 AC 已验，2026-10-25 按状态定义转为 In Review，等待 PR 评审与合并。
