## 产品目标

在持续优化现有 Web 的基础上，提供 Tauri 桌面安装版、运行在 Cloudflare 上的业务后端与管理页面，以及统一的平台账号同步服务。保持本地优先：用户不登录、不启用同步，也能继续管理本机草稿和作品、使用默认免费供应商或自己的供应商。

| 方向                      | 用户价值                                   | 后续交付范围                                                             |
| ------------------------- | ------------------------------------------ | ------------------------------------------------------------------------ |
| Web 持续优化              | 稳定、顺畅地完成图片创作和作品管理         | 创作体验、作品检索与预览、错误反馈、离线与升级可靠性                     |
| Tauri 本地安装程序        | 以桌面应用使用相同的创作能力               | 安装、原生持久化与文件访问、升级、卸载与数据保留说明                     |
| Cloudflare 后端与管理页面 | 安全代理请求，支持当前免费创作流程         | 服务端鉴权与代理、本站代理任务与业务后台；独立平台生图和计费按 D-17 暂缓 |
| 统一平台账号同步          | 注册平台账号后跨设备继续创作，无需维护后端 | 平台 Supabase、元数据与私有原图同步、账号/工作区隔离、配额和数据管理     |
| 产品目录优化              | 支撑上述功能持续迭代                       | 明确 Web、桌面、服务端、部署和基础设施职责，逐步迁移                     |

## 功能需求

### 一、持续优化 Web

- 围绕“灵感/提示词 → 生成 → 保存 → 查找 → 下载/复用”优化主流程，明确请求、生成、本机保存和同步各自的状态。
- 持续优化作品检索、分页、按需预览和大图库体验；实施时记录首屏、检索、预览和内存基线，再为具体故事制定可测量的改进目标。
- 对超时、断网、结果不确定、存储不足、同步失败给出可执行的提示；结果不确定时不自动重发可能收费的生成请求。
- 保持本地工作区、离线访问、备份恢复和旧数据升级兼容。启用平台能力后仍能辨认哪些作品只在本机、哪些数据已同步。
- 继续保留现有响应式体验；移动真机和真实桌面 IME 是否恢复专项验收，按独立范围决定，不能把此前未验项记为通过。

### 二、Tauri 本地安装程序

- 复用产品前端和数据契约，提供可下载安装、启动和退出的桌面应用。首发操作系统、架构及最低版本待定，不能以一个系统可运行代表所有系统可发行。
- 支持本地创作、作品管理、文件保存、备份导入/导出和可选同步；远程图片生成仍需联网。
- 明确原生数据库、原图目录和凭据存储边界；原生权限按实际功能开放，不向远程页面开放任意文件或系统访问。
- 浏览器版与安装版的数据不默认互通；通过已验证的备份或显式同步迁移，保留原工作区，失败时不覆盖原数据。
- 明确发布签名、macOS 公证等目标平台要求；若启用应用内更新，必须验证更新签名，并验证升级、失败恢复及数据库兼容守卫。
- 卸载前说明本机数据的保留与删除方式；升级不得隐式清空作品、凭据或工作区，重新安装的数据恢复边界须有实测证据。

### 三、Cloudflare 后端与管理页面

业务 API 和任务处理运行在 Cloudflare。优先评估 Workers、Queues，以及需要托管图片时的 R2；身份、数据库、支付渠道及是否使用外部图片供应商，在实施方案中确定。部署在 Cloudflare 不等于图片模型必须运行在 Cloudflare，也不代表基础设施和模型调用没有成本。

#### 安全代理请求

- 区分“使用用户自己的供应商凭据代理请求”与“使用平台供应商凭据提供生图服务”，请求界面明确说明凭据和提示词发往何处，以及费用由谁承担。
- 用户自有凭据仅用于其明确授权的请求，沿用当前不持久化代理 Key 的边界；不得写入任务队列、数据库、日志或同步数据。需要凭据托管或异步代理时，必须另行定义授权、加密、有效期和删除机制。代理生图任务的这四项定义见 [MEDIA-US-109](stories/generation/MEDIA-US-109-relay-durable-task.md)。
- 平台供应商凭据仅保存在服务端受保护配置中，不进入 Web/桌面产物、任务响应或管理页面。
- 上游地址由服务端允许列表约束域名、端口、协议与路径；禁止任意 URL 转发、内网/本机地址及绕过校验的重定向，覆盖 SSRF 正反向验收。
- 服务端执行身份与权限校验、速率限制、并发限制、请求/响应大小和超时限制。CORS、隐藏按钮或来源头不能替代身份授权。
- 日志和审计默认记录必要的任务标识、错误类别与用量，排除 Key、会话、完整敏感请求；正文和图片的额外留存需明确用途与保留策略。

#### 独立平台图片服务与计费（D-17 暂缓）

以下保留未来范围，不属于当前免费平台的交付或排期。平台模型、额度、积分购买与流水入口及对应 API 已移除；未来收费需求明确后重新评审，不能仅因历史实现仍在而恢复服务。默认免费供应商与本站代理继续使用现有主流程。

- 用户可查看平台提供的模型、支持的参数、免费额度、收费方式与服务限制，再确认提交。不得把用户自己的供应商调用混记为平台赠送或平台收费。
- 免费服务具备可配置额度、发放/重置规则、并发和防滥用限制；额度用尽或服务关闭时明确告知用户。
- 收费服务具备价格展示、购买/支付、余额或权益、消费记录和对账能力；按次、积分、订阅等商业模式待定。
- 额度检查、预占、结算与释放须防止并发超扣；重复提交、队列重复投递和支付回调重放不能重复扣费或重复执行已经确认完成的任务。
- 失败、取消、供应商超时或结果不确定时分别定义结算规则。结果未知时保留待核对状态，不能假定免费失败、重复扣费或自动重发。
- 平台设置总预算、供应商额度和停止接单机制；面向用户的免费额度与平台实际成本分开管理。

#### 平台生图排队与用户提示（D-17 暂缓）

以下限独立平台生图的未来范围；本站代理任务按 MEDIA-US-109 独立推进。

- 平台生图采用持久化任务记录与异步处理，接受请求后返回可查询的任务标识；用户刷新、关闭页面或换设备后可恢复查看自己的任务。
- 用户能区分排队、生成、完成、失败、取消和结果待核对；“生成完成”与“已保存到本机”分别展示。
- 排队时提示“当前繁忙、任务已进入队列”，提供可用的等待估计或队列信息；没有可靠估计时明确表示正在等待，不编造队列名次和倒计时。
- 明确公平性与优先级规则；若付费权益包含优先处理，在购买前说明，并为免费队列定义避免长期饥饿的策略。
- 支持取消尚未执行的任务；执行中的取消能力与费用规则取决于供应商，不能把页面停止等待当作上游已经取消。
- 区分队列消息重试和上游生图重试。设置并发、有限重试、超时和失败隔离；供应商调用结果未知时进入核对流程，不能因重投消息再次生图。
- 队列容量或预算不足时拒绝接单并提示稍后再试；已接单任务必须可追踪，不因连接断开或达到重试上限而静默消失。

#### 后端管理页面

- 当前继续完善用户与角色、模板、供应商策略、显式上报任务与用量。平台模型、额度、价格、支付、退款和权威流水运维随 MEDIA-US-108/205 按 D-17 暂缓，后台“平台生图与计费”入口已移除；以下相关条款仅为未来范围。
- 每个管理操作在服务端独立授权；覆盖普通用户拒绝访问、管理员撤权、账号禁用和越权请求等场景。
- 管理员可查看拥堵与失败原因，暂停接单或调整并发；对未知结果先核对，人工重试仍须经过任务和扣费幂等控制。
- 额度、价格、退款、权限及服务策略变更保留操作者和审计记录；平台权威流水与客户端显式上报统计分开呈现。
- 默认不展示用户 Key，不任意读取用户私有提示词、原图或同步数据；必要的用户授权支持流程另行定义。

### 四、统一的平台账号同步

- 按 [D-16](decisions.md#d-16统一使用平台-supabase) 统一使用平台 Supabase，用户只需注册或登录平台账号，不创建、授权或初始化自己的项目，不提供项目 URL、Key 或 SQL。自有项目接入不再属于产品范围。
- 部署方统一维护表、RLS、私有 Storage 和公开账号配置；平台承担存储与服务成本，面向用户的配额、限制与费用说明明确可见。
- 登录与启用同步分别确认。首次绑定展示平台账号、工作区、即将上传的数据和合并行为，支持取消。草稿、公开供应商配置与作品信息沿用现有 Supabase adapter/history/sync。
- 原图由 [MEDIA-US-305](stories/local-first/MEDIA-US-305-supabase-image-sync.md) 验收。用户另外选择“仅以后保存”或“已有及以后保存”，确认数量、大小与限制后才上传 PNG/JPEG 原始字节；未确认不自动上传历史图库。
- 文件先在本机保存，再直达平台 Supabase 私有 Storage；持久队列、续传、完整性检查和作品关联分别验证。另一设备按需取回，原图成功落盘前不标记本机离线可用，失败不重新生图。
- Web 与 Tauri 按平台账号和工作区隔离，退出、停止或切账号使旧复制和传输失效，迟到响应不得写入新空间；断网可本地编辑，联网后按原冲突策略恢复。
- 展示进度、待传、失败、冲突、最近成功时间、配额与保留规则；提供导出、停止和独立的远端删除入口。元数据、原图远端保存和本机恢复各自验收，生产与 Web/Tauri 跨设备未验前不宣称完整交付。

### 同步数据边界

| 数据                                   | 首阶段规划                                                  | 后续边界                                                                               |
| -------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 提示词草稿、供应商公开配置、作品元数据 | 沿用现有显式绑定和复制能力，接入统一平台项目                | 版本、冲突、删除传播与恢复须分别验证                                                   |
| 原图、缩略图等文件本体                 | 先在本机保存；平台私有原图同步纳入 MEDIA-US-305，须单独确认 | 平台文件需通过选择、限额、续传、完整性、鉴权、删除与跨设备验收，完成前不宣称原图已同步 |
| 供应商 API Key、平台私钥及用户会话     | 排除在业务数据同步与备份之外                                | 不能因切换目标或导出配置而泄露                                                         |

每个工作区只使用平台同步，首次绑定与账号/工作区切换重新确认数据范围，不跨账号自动转存数据。沿用 [D-06](decisions.md) 的冲突版本、tombstone 与日志保留规则；文件删除与旧上传重放分别验收，不以新增 TTL 绕过现有安全约束。

## 产品目录结构优化

### 现状与目标

现有 [`src/app/`](../src/app/) 中多数功能平铺，[`deploy/`](../deploy/) 同时承载部署配置与 Worker/管理 API 运行代码。随着桌面版和平台服务增加，需要按功能与运行环境明确职责。

目标结构沿用[产品目录约定](../AGENTS.md)：产品私有代码集中在 `apps/aiao-media`，E2E 留在同级 `aiao-media-e2e`。下树是目标方案，新增目录随对应功能落地，不创建空目录。

```text
apps/
├── aiao-media/
│   ├── src/
│   │   ├── app/
│   │   │   ├── studio/          创作与任务界面
│   │   │   ├── library/         作品检索、预览与导出
│   │   │   ├── providers/       用户供应商配置
│   │   │   ├── account/         身份、工作区与同步设置
│   │   │   ├── admin/           管理页面
│   │   │   └── prompts/         灵感与提示词编辑
│   │   ├── contracts/          产品共用的纯数据契约
│   │   ├── local-data/         本地存储、复制与恢复
│   │   └── platform/           浏览器与桌面环境差异
│   │       ├── browser/
│   │       └── tauri/
│   ├── src-tauri/              Rust 宿主、权限、安装与更新
│   ├── server/
│   │   └── cloudflare/         Worker API、代理、任务与业务服务
│   ├── deploy/                 部署配置与发布说明
│   ├── infra/
│   │   └── supabase/           本地环境、迁移与 RLS
│   ├── scripts/                构建、验证与运维入口
│   ├── requirements/           产品需求、设计与验收记录
│   └── project.json
└── aiao-media-e2e/              产品端到端验收
```

### 目录职责与迁移约束

- Web 与管理页继续复用同一 Angular 前端，Tauri 复用相同产品界面；只有出现独立发布或依赖隔离的实际需要时才评估拆项目。
- `src/contracts`、`src/local-data` 继续是普通目录，不创建独立包或 Nx 项目。契约不能依赖 Angular、DOM、原生宿主或服务端凭据。
- `src/platform` 只承载真实存在的浏览器/桌面差异；桌面适配按功能引入，浏览器构建不得包含原生特权实现和服务端代码。
- 将 `deploy/*.mjs` 的 Worker、管理 API 和产品服务逐步迁至 `server/cloudflare`；`deploy` 保留部署配置，`scripts` 保留流程入口，相关测试随实现就近维护。
- 先整理现有服务端与部署边界，再随功能调整前端目录和增加桌面目录；迁移提交必须同时更新导入、Wrangler 入口、静态资源路径、脚本、测试和文档引用。
- 保持现有页面 URL、存储 key、工作区 ID、数据库/OPFS 标识和备份格式兼容；目录搬迁不成为数据迁移或清库理由。
- 保留现有 Nx 使用入口；新增桌面/服务端任务优先加入产品项目。产品私有能力不预先提升到 `packages/*`，确有复用需要时再按公共包与三框架约束评审。

## 建议交付顺序与依赖

以下是建议顺序，不是发布日期承诺。Web 优化贯穿各阶段；桌面和同步工作可在各自前置满足后并行推进。

| 工作项                 | 主要前置                                    | 阶段交付                                                                             |
| ---------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------ |
| Web 优化与目录边界整理 | 现有行为和兼容基线                          | 明确优化指标，按实际改动迁移目录，现有入口持续可用                                   |

## 核心验收目标

| 范围                   | 必须证明的结果                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------ |
| Web 与目录迁移         | 现有创作、作品、离线、升级、备份和页面地址保持兼容；构建与部署入口可用               |
| Tauri                  | 在每个承诺的系统上实际安装、保存文件、重开恢复和升级；损坏更新拒绝安装，用户数据保留 |
| 安全代理               | 未授权访问、越权、非法上游与重定向绕过被拒绝；凭据不进入客户端产物、日志或队列       |
| 平台生图与计费（暂缓） | D-17 当前关闭入口和 API；未来重启须重新验收额度、支付、幂等与未知结果处理            |
| 本站代理任务           | 刷新、断网后续接同一请求；凭据不持久化，结果按授权范围取回或删除；平台排队另行暂缓   |
| 运营后台               | 普通用户与被撤权管理员均无法越权；敏感操作可审计；任务和用量来源明确                 |
| 平台账号同步           | 平台账号在两独立设备往返、离线恢复、隔离、冲突和删除测试通过；切账号不自动转存数据   |
| 数据范围               | 未授权不上传；无原图时不宣称完整云备份；断开、远端删除与本机保留行为符合已公布规则   |

本次文档结构与链接通过 `pnpm nx run aiao-media:requirements-check` 校验。后续功能需拆成可独立验收的 `MEDIA-US-*` 故事，明确 AC 与前置；涉及目录迁移时，通过 Nx 运行受影响的类型、lint、测试、构建及必要的离线/升级/部署验证。结构门禁通过不能代替真实桌面、生产授权、支付或跨设备验收。
