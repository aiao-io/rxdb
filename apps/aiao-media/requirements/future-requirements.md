整理日期：2026-10-29。依据产品负责人提出的五个功能方向，以及产品目录结构优化要求。

五个方向已进入实施，首阶段技术选择、任务和证据见[产品交付计划](plans/product-completion-20261030.md)。MEDIA-US-005/108/205/303 分别跟踪桌面、平台任务、计费运维与同步目标；[MEDIA-US-304](stories/local-first/MEDIA-US-304-supabase-oauth-onboarding.md) 和 [MEDIA-US-305](stories/local-first/MEDIA-US-305-supabase-image-sync.md) 定义待实现的官方授权自动接入与自有项目原图同步。代码接线不代表生产服务或正式发行已经验收。实现状态以 [stories 的 YAML](README.md#真相源规则) 为准。

## 产品目标

在持续优化现有 Web 的基础上，提供 Tauri 桌面安装版、运行在 Cloudflare 上的业务后端与管理页面，以及用户可自主选择的数据同步服务。保持本地优先：用户不登录、不购买平台服务、不启用同步，也能继续管理本机草稿和作品、使用自己的供应商。

| 方向                      | 用户价值                                       | 后续交付范围                                                         |
| ------------------------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| Web 持续优化              | 稳定、顺畅地完成图片创作和作品管理             | 创作体验、作品检索与预览、错误反馈、离线与升级可靠性                 |
| Tauri 本地安装程序        | 以桌面应用使用相同的创作能力                   | 安装、原生持久化与文件访问、升级、卸载与数据保留说明                 |
| Cloudflare 后端与管理页面 | 安全代理请求，直接使用免费或收费的图片生成服务 | 服务端鉴权与代理、平台生图、排队通知、额度计费、运营后台             |
| 同步到自己的 Supabase     | 授权后自动连接自有项目，跨设备取回原图         | 官方授权、选项目、确认后自动初始化、独立范围确认、私有原图同步与恢复 |
| 同步到我们的平台          | 不维护后端也能跨设备继续创作                   | 平台账号、显式同步、设备与工作区隔离、配额和数据管理                 |
| 产品目录优化              | 支撑上述功能持续迭代                           | 明确 Web、桌面、服务端、部署和基础设施职责，逐步迁移                 |

## 功能需求

### 一、持续优化 Web

- 围绕“灵感/提示词 → 生成 → 保存 → 查找 → 下载/复用”优化主流程，明确请求、生成、本机保存和同步各自的状态。
- 持续优化作品检索、分页、按需预览和大图库体验；实施时记录首屏、检索、预览和内存基线，再为具体故事制定可测量的改进目标。
- 对超时、断网、结果不确定、存储不足、同步失败给出可执行的提示；结果不确定时不自动重发可能收费的生成请求。
- 保持本地工作区、离线访问、备份恢复和旧数据升级兼容。启用平台能力后仍能辨认哪些作品只在本机、哪些数据已同步。
- 继续保留现有响应式体验；移动真机和真实桌面 IME 是否恢复专项验收，按独立范围决定，不能把此前未验项记为通过。

### 二、Tauri 本地安装程序

- 复用产品前端和数据契约，提供可下载安装、启动和退出的桌面应用。首发操作系统、架构及最低版本待定，不能以一个系统可运行代表所有系统可发行。
- 支持本地创作、作品管理、文件保存、备份导入/导出和可选同步；远程图片生成仍需联网。
- 明确原生数据库、原图目录和凭据存储边界；原生权限按实际功能开放，不向远程页面开放任意文件或系统访问。
- 浏览器版与安装版的数据不默认互通；通过已验证的备份或显式同步迁移，保留原工作区，失败时不覆盖原数据。
- 明确发布签名、macOS 公证等目标平台要求；若启用应用内更新，必须验证更新签名，并验证升级、失败恢复及数据库兼容守卫。
- 卸载前说明本机数据的保留与删除方式；升级不得隐式清空作品、凭据或工作区，重新安装的数据恢复边界须有实测证据。

### 三、Cloudflare 后端与管理页面

业务 API 和任务处理运行在 Cloudflare。优先评估 Workers、Queues，以及需要托管图片时的 R2；身份、数据库、支付渠道及是否使用外部图片供应商，在实施方案中确定。部署在 Cloudflare 不等于图片模型必须运行在 Cloudflare，也不代表基础设施和模型调用没有成本。

#### 安全代理请求

- 区分“使用用户自己的供应商凭据代理请求”与“使用平台供应商凭据提供生图服务”，请求界面明确说明凭据和提示词发往何处，以及费用由谁承担。
- 用户自有凭据仅用于其明确授权的请求，沿用当前不持久化代理 Key 的边界；不得写入任务队列、数据库、日志或同步数据。需要凭据托管或异步代理时，必须另行定义授权、加密、有效期和删除机制。
- 平台供应商凭据仅保存在服务端受保护配置中，不进入 Web/桌面产物、任务响应或管理页面。
- 上游地址由服务端允许列表约束域名、端口、协议与路径；禁止任意 URL 转发、内网/本机地址及绕过校验的重定向，覆盖 SSRF 正反向验收。
- 服务端执行身份与权限校验、速率限制、并发限制、请求/响应大小和超时限制。CORS、隐藏按钮或来源头不能替代身份授权。
- 日志和审计默认记录必要的任务标识、错误类别与用量，排除 Key、会话、完整敏感请求；正文和图片的额外留存需明确用途与保留策略。

#### 免费与收费图片生成

- 用户可查看平台提供的模型、支持的参数、免费额度、收费方式与服务限制，再确认提交。不得把用户自己的供应商调用混记为平台赠送或平台收费。
- 免费服务具备可配置额度、发放/重置规则、并发和防滥用限制；额度用尽或服务关闭时明确告知用户。
- 收费服务具备价格展示、购买/支付、余额或权益、消费记录和对账能力；按次、积分、订阅等商业模式待定。
- 额度检查、预占、结算与释放须防止并发超扣；重复提交、队列重复投递和支付回调重放不能重复扣费或重复执行已经确认完成的任务。
- 失败、取消、供应商超时或结果不确定时分别定义结算规则。结果未知时保留待核对状态，不能假定免费失败、重复扣费或自动重发。
- 平台设置总预算、供应商额度和停止接单机制；面向用户的免费额度与平台实际成本分开管理。

#### 拥堵排队与用户提示

- 平台生图采用持久化任务记录与异步处理，接受请求后返回可查询的任务标识；用户刷新、关闭页面或换设备后可恢复查看自己的任务。
- 用户能区分排队、生成、完成、失败、取消和结果待核对；“生成完成”与“已保存到本机”分别展示。
- 排队时提示“当前繁忙、任务已进入队列”，提供可用的等待估计或队列信息；没有可靠估计时明确表示正在等待，不编造队列名次和倒计时。
- 明确公平性与优先级规则；若付费权益包含优先处理，在购买前说明，并为免费队列定义避免长期饥饿的策略。
- 支持取消尚未执行的任务；执行中的取消能力与费用规则取决于供应商，不能把页面停止等待当作上游已经取消。
- 区分队列消息重试和上游生图重试。设置并发、有限重试、超时和失败隔离；供应商调用结果未知时进入核对流程，不能因重投消息再次生图。
- 队列容量或预算不足时拒绝接单并提示稍后再试；已接单任务必须可追踪，不因连接断开或达到重试上限而静默消失。

#### 后端管理页面

- 在已有管理能力上增加生产运维：用户与角色、模板、模型/供应商策略、免费额度、套餐/价格、支付与消费流水、任务与队列、失败处理、成本和服务开关。
- 每个管理操作在服务端独立授权；覆盖普通用户拒绝访问、管理员撤权、账号禁用和越权请求等场景。
- 管理员可查看拥堵与失败原因，暂停接单或调整并发；对未知结果先核对，人工重试仍须经过任务和扣费幂等控制。
- 额度、价格、退款、权限及服务策略变更保留操作者和审计记录；平台权威流水与客户端显式上报统计分开呈现。
- 默认不展示用户 Key，不任意读取私有提示词、原图或用户自有 Supabase 数据；必要的用户授权支持流程另行定义。

### 四、同步到用户自己的 Supabase

- 主流程为“连接我的 Supabase → 官方管理 OAuth 授权 → 选择项目 → 查看并确认初始化 → 自动建立项目同步身份 → 单独确认图片同步范围”。用户无需复制 Key、执行 SQL、创建 bucket 或再次注册项目内账号；自动接入由 [MEDIA-US-304](stories/local-first/MEDIA-US-304-supabase-oauth-onboarding.md) 验收。
- 初始化前展示组织、项目、实际管理授权范围和应用将创建的表、版本、私有图片 bucket 与访问策略。确认前只读检查；确认后由受保护后端执行可恢复初始化，不修改其他项目或业务对象。首版只接入空项目或版本兼容的应用专用项目；共享项目、对象冲突和高版本拒绝自动写入。
- 管理 OAuth 和项目内数据身份分别验证，跨设备恢复绑定同一可验证主体与工作区，不按邮箱或项目管理权合并已有用户。授权拒绝、回调重放、权限不足、配置缺失及部分初始化均有明确状态，不用手工项目登录替代自动身份引导的验收。
- OAuth client secret、管理 access/refresh token 以及初始化必要的服务端凭据只在受保护后端使用，不进入客户端、日志、备份或业务同步；不要求用户粘贴 PAT、service role、secret Key 或数据库密码。管理授权覆盖组织时准确说明，选定项目由后端再次限制。
- 现有 URL + publishable/anon Key 手工配置作为 MEDIA-US-303 的独立入口保留；不能在自动接入失败时静默切过去并宣称自动配置成功。
- 原图同步由 [MEDIA-US-305](stories/local-first/MEDIA-US-305-supabase-image-sync.md) 验收。连接就绪不上传图片；用户另外选择“仅以后保存”或“已有及以后保存”，看到数量、大小、私有存储限制和费用说明后确认，才能开始上传 PNG/JPEG 原始字节。
- 文件先在本机保存，再上传至用户项目的私有 Storage；本地持久队列、断点续传、完整性检查和作品关联提交共同决定同步完成。另一设备按需预览/取回，原图成功落盘前不标记本机离线可用，失败不重新生图。
- 草稿、元数据和原图由客户端直连自有项目，不经平台 Worker/R2 中转或留存。断开停止后续同步且保留本机和远端数据；本机副本、同步图库和远端原图的删除影响分别确认，保留 D-06 的日志、冲突版本与删除标记。

### 五、同步到我们的平台

- 提供可用的生产账号和同步服务，用户无需创建或维护 Supabase 项目；具体身份和存储实现由技术方案确定。
- 登录与启用同步分别确认。首次绑定展示目标工作区、即将上传的数据和合并行为，支持取消。
- 支持 Web 与 Tauri 在用户授权后跨设备恢复数据；按账号和工作区隔离，退出或切账号后停止旧会话复制，迟到响应不得写入新账号空间。
- 展示同步进度、待上传、失败、冲突和最近成功时间；断网后可本地编辑，恢复联网后按既定冲突策略继续。
- 提供配额、保留规则、导出、停止同步和远端删除入口；停止同步不等于删除远端，删除远端也不得无提示清空本机作品。

### 两种同步方式的共同边界

| 数据                                   | 首阶段规划                                                          | 后续边界                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 提示词草稿、供应商公开配置、作品元数据 | 沿用现有显式绑定和复制能力，接入所选目标                            | 版本、冲突、删除传播与恢复须分别验证                                                                         |
| 原图、缩略图等文件本体                 | 现有实现继续保持本机；自有项目原图同步纳入 MEDIA-US-305，须单独确认 | 平台文件同步另定范围；自有项目需通过选择、限额、续传、完整性、鉴权、删除与跨设备验收，完成前不宣称原图已同步 |
| 供应商 API Key、平台私钥及用户会话     | 排除在业务数据同步与备份之外                                        | 不能因切换目标或导出配置而泄露                                                                               |
| 本机路径、文件句柄、设备私有标识       | 不作为可跨设备使用的文件地址同步                                    | 新设备区分“远端可取回”和“本机可用”；远端原图未验证前不显示“原图已备份”                                       |

同步目标切换必须重新确认，不自动将一个目标的数据转发给另一个目标。自有项目图片同步首版每个工作区只启用一个目标；同时同步到自有 Supabase 和平台不在 MEDIA-US-304/305 范围内。沿用 [D-06](decisions.md) 的冲突版本、tombstone 与日志保留规则；文件删除与旧上传重放分别验收，不以新增 TTL 绕过现有安全约束。

## 产品目录结构优化

### 现状与目标

现有 [`src/app/`](../src/app/) 中多数功能平铺，[`deploy/`](../deploy/) 同时承载部署配置与 Worker/管理 API 运行代码。随着桌面版和平台服务增加，需要按功能与运行环境明确职责。

目标结构沿用[产品目录约定](../AGENTS.md)：产品私有代码集中在 `apps/aiao-media`，E2E 留在同级 `aiao-media-e2e`。下树是目标方案，新增目录随对应功能落地，不创建空目录。

```text
apps/
├── aiao-media/
│   ├── src/
│   │   ├── app/
│   │   │   ├── studio/          创作与任务界面
│   │   │   ├── library/         作品检索、预览与导出
│   │   │   ├── providers/       用户供应商配置
│   │   │   ├── account/         身份、工作区与同步设置
│   │   │   ├── admin/           管理页面
│   │   │   └── prompts/         灵感与提示词编辑
│   │   ├── contracts/          产品共用的纯数据契约
│   │   ├── local-data/         本地存储、复制与恢复
│   │   └── platform/           浏览器与桌面环境差异
│   │       ├── browser/
│   │       └── tauri/
│   ├── src-tauri/              Rust 宿主、权限、安装与更新
│   ├── server/
│   │   └── cloudflare/         Worker API、代理、任务与业务服务
│   ├── deploy/                 部署配置与发布说明
│   ├── infra/
│   │   └── supabase/           本地环境、迁移与 RLS
│   ├── scripts/                构建、验证与运维入口
│   ├── requirements/           产品需求、设计与验收记录
│   └── project.json
└── aiao-media-e2e/              产品端到端验收
```

### 目录职责与迁移约束

- Web 与管理页继续复用同一 Angular 前端，Tauri 复用相同产品界面；只有出现独立发布或依赖隔离的实际需要时才评估拆项目。
- `src/contracts`、`src/local-data` 继续是普通目录，不创建独立包或 Nx 项目。契约不能依赖 Angular、DOM、原生宿主或服务端凭据。
- `src/platform` 只承载真实存在的浏览器/桌面差异；桌面适配按功能引入，浏览器构建不得包含原生特权实现和服务端代码。
- 将 `deploy/*.mjs` 的 Worker、管理 API 和产品服务逐步迁至 `server/cloudflare`；`deploy` 保留部署配置，`scripts` 保留流程入口，相关测试随实现就近维护。
- 先整理现有服务端与部署边界，再随功能调整前端目录和增加桌面目录；迁移提交必须同时更新导入、Wrangler 入口、静态资源路径、脚本、测试和文档引用。
- 保持现有页面 URL、存储 key、工作区 ID、数据库/OPFS 标识和备份格式兼容；目录搬迁不成为数据迁移或清库理由。
- 保留现有 Nx 使用入口；新增桌面/服务端任务优先加入产品项目。产品私有能力不预先提升到 `packages/*`，确有复用需要时再按公共包与三框架约束评审。

## 核心验收目标

| 范围           | 必须证明的结果                                                                       |
| -------------- | ------------------------------------------------------------------------------------ |
| Web 与目录迁移 | 现有创作、作品、离线、升级、备份和页面地址保持兼容；构建与部署入口可用               |
| Tauri          | 在每个承诺的系统上实际安装、保存文件、重开恢复和升级；损坏更新拒绝安装，用户数据保留 |
| 安全代理       | 未授权访问、越权、非法上游与重定向绕过被拒绝；凭据不进入客户端产物、日志或队列       |
| 免费/付费生图  | 免费额度受控；并发、重复消息和回调重放不超扣/重复扣费；失败与未知结果可核对          |
| 队列           | 并发拥堵时提示排队；刷新、断网和重新登录后能追踪任务；取消、超时和失败有确定处理规则 |
| 运营后台       | 普通用户与被撤权管理员均无法越权；敏感操作可审计；任务和用量来源明确                 |
| 两种同步目标   | 各自完成两独立设备往返、离线恢复、账号隔离、冲突和删除测试；切换目标不静默转存数据   |
| 数据范围       | 未授权不上传；无原图时不宣称完整云备份；断开、远端删除与本机保留行为符合已公布规则   |

本次文档结构与链接通过 `pnpm nx run aiao-media:requirements-check` 校验。后续功能需拆成可独立验收的 `MEDIA-US-*` 故事，明确 AC 与前置；涉及目录迁移时，通过 Nx 运行受影响的类型、lint、测试、构建及必要的离线/升级/部署验证。结构门禁通过不能代替真实桌面、生产授权、支付或跨设备验收。

## 平台资料依据

通过 Context7 核对以下官方资料；这里只用于确认方案边界，不作为本产品已经交付的证据。

- [Cloudflare Queues 失败队列](https://developers.cloudflare.com/queues/configuration/dead-letter-queues/)：达到重试上限后的任务必须有处理去向；产品还需单独处理任务状态和供应商调用幂等。
- [Tauri 应用分发](https://v2.tauri.app/distribute/)与[更新插件](https://v2.tauri.app/plugin/updater/)：安装发行与更新分别处理，Tauri 更新插件要求校验签名。
- [Supabase API Key](https://supabase.com/docs/guides/api/api-keys)与[数据安全](https://supabase.com/docs/guides/database/secure-data)：公开客户端 Key 配合用户身份、RLS 和最小权限使用；secret/service role Key 不进入客户端。
- [Supabase OAuth 集成](https://supabase.com/docs/guides/integrations/build-a-supabase-oauth-integration)与[授权 scopes](https://supabase.com/docs/guides/integrations/build-a-supabase-oauth-integration/oauth-scopes)：管理授权使用 code/PKCE 和注册应用的 scopes；不是项目内用户会话，也不天然只覆盖产品中选中的项目。
- [Storage 私有 bucket](https://supabase.com/docs/guides/storage/buckets/fundamentals)与[断点续传](https://supabase.com/docs/guides/storage/uploads/resumable-uploads)：文件访问受鉴权约束，可使用 TUS 续传；产品仍须证明作用域、文件关联和删除恢复。
