# 账号与工作区绑定实施计划

## 结论与选择

D-05 采用**本机独立工作区 + 用户主动启用同步 + 远程工作区按账号隔离**。绑定、产品 RLS 与原生复制已通过真实本地验收，本轮 Supabase 仅本地，生产启用属于后续范围。关联 [MEDIA-US-201](../stories/account/MEDIA-US-201-sessions.md)、[MEDIA-US-302](../stories/local-first/MEDIA-US-302-draft-sync.md)；D-06 无限期保留冲突、tombstone 和日志，不启用 TTL 或自动 GC。

| 方案                               | 对现有用户数据的影响                                     | 结论   |
| ---------------------------------- | -------------------------------------------------------- | ------ |
| 登录即把当前本机 ID 当作账号工作区 | 切账号容易改变已有数据归属；登录造成隐式上传             | 不采用 |
| 登录即自动合并全部本机与远程记录   | 无法先确认范围，重复 ID、旧账号与文件关联难以恢复        | 不采用 |
| 显式绑定，每个账号维护独立本机副本 | 保留无需登录的本机路径，账号切换和第二设备都有可追踪边界 | 采用   |

这是基于源码和官方 Auth/RLS 文档的设计选择；当前本地实现与验收另见交付证据。登录只建立会话，不上传或改变本机数据归属。一个本机工作区只绑定一个项目、用户和远程工作区；第二台设备加入时建立独立本机副本，保留原未绑定工作区。

## 身份与数据契约

| 标识 / 记录                  | 含义与约束                                                                                                                  |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `localProfileId`             | 现有随机 UUID；用于 RxDB/OPFS 命名空间和本机 Web Lock，不冒充 Auth 用户                                                     |
| `projectOrigin + authUserId` | 按规范化 Supabase URL 和已验证用户 UUID 定位账号；不用邮箱、显示名或客户端 owner 字段认领                                   |
| `remoteWorkspaceId`          | 服务端持久工作区 ID；同账号设备共享，本机 profile ID 可以不同                                                               |
| 本机绑定记录                 | 保存 profile、项目、账号、远程工作区、协议版本及 pending/active/paused 状态；不保存 access/refresh token 或供应商 Key       |
| 本机账号索引                 | 在 profile 注册表查找当前账号已有副本；不把另一账号的内容枚举到当前页面。它是命名空间管理，不是对设备持有者的加密访问控制   |
| 同步记录                     | 独立的草稿、供应商公开配置、作品元数据 DTO，显式字段白名单；不复制通用 `LocalPreference.payload` 或把本机实体整体改成可同步 |

远程 owner 来自可信身份。RLS 用 `USING` 与 `WITH CHECK` 校验 owner/workspace，禁止普通用户转移 owner、写入别人的 workspace，或用相同记录 ID 覆盖另一账号。记录定位至少包含工作区、类型和记录 ID；本机时间不能替代服务端 revision。

供应商 DTO 只含稳定 ID、名称、HTTPS Base URL、模型与通道；排除设备语义的 `rememberKey` 和全部凭据。作品 DTO 含提示词快照、模型及真实文件属性，排除 OPFS 路径、fileId、Blob URL、句柄和原图。另一设备无原图时显示“本机无原图”。

## 首次启用流程

1. 验证当前项目与用户；验证失败保留本机操作，缓存中的 user 不能作为远程授权证据。
2. 在工作区/生成锁下检查状态。在途生成期间禁止切换工作区；退出可立即停复制，但已付费请求的结果仍保存到原工作区，不重发。
3. 保存当前草稿；CAS 冲突先让用户选择。确实无法保存的输入写入独立本机恢复记录并验证回读，不能丢弃后切换。
4. 显示目标账号、远程工作区、草稿/配置/作品元数据范围和数量，说明 Key/原图不上传。取消不改变原工作区或上传数据。
5. 未绑定工作区可以新建远程工作区；加入已有远程工作区先建新本机副本。首版不自动合并两份已有工作区，原库继续保留并可导出。
6. 先持久化 pending 意图，再以稳定请求 ID 幂等创建/加入与确认首次快照；中断后查询/继续，不创建重复工作区。
7. 服务端授权与本机绑定均确认后才置为 active 并启动复制。未确认写入保留在本机 outbox；UI 区分待同步、同步中、已同步、暂停、冲突和失败。

断网/关页发生在任一步都不能提前显示已同步。恢复核对账号、项目、工作区与 binding generation，不把 pending 绑定转给新账号。

## 退出、过期与切账号

| 事件                    | 复制与授权                                                                               | 本机内容                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 退出 A                  | 先增加 `syncEpoch`、停远程写入/outbox，取消订阅/请求，再执行 Auth 本机退出               | A 副本留盘并可继续离线编辑；只在 A 重新验证并恢复同步后发送 |
| 过期或验证失败          | 暂停，不继续远程写入或标记已同步                                                         | 原图、Key、草稿和未确认改动保留，不要求联网打开本机数据     |
| 登录 B                  | 验证 B 后选择 B 的副本或建立独立副本，不把 A 转属 B                                      | 撤销页面对 A 的预览 URL、内存状态与订阅，A 的磁盘数据保留   |
| A 请求在 B 登录后才返回 | 回调核对捕获的项目、user、workspace、binding generation 与 `syncEpoch`；失配即不写当前库 | 不将 A 数据注入 B，A 的待确认改动仍保留                     |
| 再登录 A                | 验证身份并恢复对应复制，从确认检查点继续                                                 | 保留 A 退出期间的本机编辑                                   |

保留退出后的本机使用符合 local-first 定位。设备持有者仍可访问浏览器站点数据，本方案不把退出包装成本机加密或操作系统隔离。

本机生成/文件保存与远程复制使用不同状态和 epoch，避免退出账号误丢生成结果。跨标签事件标记工作区/账号，接收方先停旧复制再应用新绑定；绑定切换使用同源工作区锁。

## D-06 保留与恢复

已实现稳定 revision、幂等变更 ID、tombstone 和无冲突往返。集成测试主动注入修改/修改、删除/修改：保留双方修订并暂停该记录，不自动按时间戳选胜者。

首发无限期保留冲突原始双方、tombstone 与原生变更日志，不部署垃圾回收、检查点 TTL 或自动过期逻辑，不重置远程序列。检查点无时间有效期；恢复仅重扫远程记录，保留本机 outbox、业务 revision 和推送确认水位，再由原生同步与 CAS 处理重放。重新扫描不等于清空冲突或采用远端覆盖本机。后续 GC 必须先具备离线设备的安全恢复协议并单独验收。

## 研究依据与源码

- [LocalMediaStore](../../src/local-data/browser-media.ts) 使用本机 UUID、`SyncType.None`；`close()`/`lockAccount()` 可关闭存储和预览，私有文件仍留在本机，产品绑定和 DTO 复制由独立控制器接入。
- [Auth 客户端](../../src/app/supabase-auth.ts) 按项目隔离会话，调用 `getUser()` 验证，使用 generation 丢弃迟到认证结果和 `signOut({scope: 'local'})`；这些不能代替复制回调的 workspace/epoch 校验。
- [当前界面](../../src/app/local-image-mvp.ts) 的 Auth 订阅会暂停旧复制并切换匹配副本；`epoch`、绑定 generation 和检查点共同隔离在途结果。
- [Supabase 退出 scope](https://supabase.com/docs/guides/auth/signout)：退出撤销刷新凭据，已发 access token 可能有效到期；不能承诺 RLS 仅凭未过期 JWT 就能即时识别所有退出。
- [服务端会话验证](https://supabase.com/docs/guides/auth/server-side/advanced-guide)：缓存中的 `getSession()` 用户不能代替身份验证；需要最新用户/会话信息时向 Auth 验证。
- [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)：可信 owner、读写双向策略，不用用户可改的 `user_metadata` 决定权限。

官方资料通过 Context7 查询；包 API 以锁定版本与本地集成为准。B1–B5、B6 的冲突保留与显式重扫均已有真实本地产品验证，不能沿用开发探针结果替代产品恢复证据。

当前证据见[本地产品交付验收](local-delivery-verification.md)和[本地 Auth/产品复验](public-delivery-verification.md)。生产服务未启用，也不把既有本地通过结果算作新检索/视口故事已验。
