# 跨用户业务后台实施计划

## 当前范围与架构

后台覆盖用户、模板、供应商策略、任务和用量，[MEDIA-US-203](../stories/account/MEDIA-US-203-business-admin.md) 维护验收范围。A1–C2 已完成真实本地实现与验证；本轮 Supabase 仅本地，生产账号/后台未部署，生产启用属于后续条件。

采用现有 Cloudflare Worker 增加受保护的 `/api/admin/*`，静态 Web 增加 `/admin`。业务数据与管理员授权放在 Supabase；本机图片创作继续不依赖后台。管理用户所需 `auth.admin` 只在 Worker 服务端执行，服务端 Key 通过 Worker secret 提供；前端和构建配置固定只接受公开 Key。

实现复用 Worker 与 Supabase Auth，独立鉴权、审计和产品数据表已纳入本地产品验收。代理边界测试不能代替后台授权/数据测试，不恢复旧 Bun API/PostgreSQL 服务。

## 权限与初始化

首版角色为普通用户与管理员，管理员资格由服务端成员记录判定。用户不能自助提权；不能根据前端 localStorage、客户端 owner、`user_metadata` 或未刷新的 JWT 角色直接放行。

每个管理请求验证用户 token，并查询当前管理员资格；之后服务端才可使用受控 admin client，按端点字段白名单返回结果。撤销管理员角色后下一次请求即拒绝。日志不记录 token、供应商 Key、原始敏感响应或密码。所有管理写操作验证 revision，并写审计记录。

首个管理员以目标项目的 Auth UUID 通过可信本机运维命令/数据库入口授予。D-03 的本机部署登录可用于部署资源，但不自动让所有应用登录用户成为管理员。首次实际需要管理员 UUID 和服务端配置时再获取；本地集成使用一次性测试账号。

禁用用户必须区分 Auth 账号限制和应用侧访问策略；已发 token 可能尚未过期，不能把刷新凭据撤销宣称为所有 RLS 请求立即失效。对需要实时封禁的产品 API/RLS 查询服务端账号状态；对纯本机内容不承诺远程擦除。

## 对象、数据来源与行为

| 对象       | 可信数据来源                                      | 首版操作与限制                                                                                                 |
| ---------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 用户       | Supabase Auth + 服务端应用账号状态                | 分页列表、详情、封禁/解禁；保护最后有效管理员，不物理删除账号                                                  |
| 模板       | `media_content_drafts` / `media_public_content`   | 校验、发布、撤回；普通用户仅可读已发布版，已有本机草稿与任务快照不随更新覆盖                                   |
| 供应商策略 | 公共策略表 + 运行中策略版本                       | 管理 HTTPS 前缀、模型兼容信息与启停；不收集用户 Key。数据库记录、Worker allowlist 和 UI 必须有可核对的生效版本 |
| 任务       | 经用户确认的产品上报/同步记录，或平台真实处理记录 | 按用户/状态/模型/通道筛选。没有上传的本机任务显示为平台不可见，不伪造完整历史                                  |
| 用量       | 应用收到的请求计数、供应商实际回报、已核验费用    | 分别汇总来源；直连未上报为未知。无供应商证据不按张数推算费用；不改变 D-02 的测试额度授权                       |
| 审计       | 服务端管理操作                                    | 操作者、目标、时间、前后 revision、结果；权限限制，不能自助删改审计                                            |

用户选择可选账号并不等于确认任务上报。新增远程任务统计前需明确 UI 里的范围确认；未启用账号/上报时，本机流程不增加远程请求。任务上报 DTO 只含必要标识、模型、通道、时间、状态与来源明确的用量，不默认上传提示词、原图、Key 或本地文件标识。

供应商策略已分开草稿与运行版本，本地代理逐请求读取已发布策略并限制目标/模型/画幅，读取失败不发送生成。未发布草稿不改变实际运行版本；生产 Supabase 未启用时，正式代理使用已发布配置的 allowlist，不声明本地数据库策略已经生产发布。

## 交付切片

| 步骤 | 交付结果                                | 必须通过的验证                                                                                     |
| ---- | --------------------------------------- | -------------------------------------------------------------------------------------------------- |
| A1   | 管理员授权与产品账号状态表、审计基础    | 真实本地 Supabase 的匿名/普通用户/管理员、伪造角色、撤销角色、跨账号访问；无 service role 入浏览器 |
| A2   | Worker 管理 API + `/admin` 用户只读列表 | 直接 API 调用与 UI 都受保护，分页、错误与超时可见；没有配置时不伪造数据                            |
| A3   | 用户封禁/解禁                           | 最后管理员保护、并发操作、在途请求与已发 JWT 边界；本机数据保留                                    |
| B1   | 模板草稿/校验/版本/发布与前台读取       | 非法节点/来源拒绝、CAS、撤回、缓存版本、静态回退；不覆盖本机输入                                   |
| B2   | 供应商公共策略及代理生效链路            | URL/模型限制、配置与运行版本一致、启停实际请求、保存失败/发布失败回滚                              |
| C1   | 用户确认的任务上报与去重                | 不上报时零产品请求；同任务稳定 ID 幂等，错账号拒绝，断网重启继续，无 Key/原图/路径                 |
| C2   | 跨用户任务筛选与用量报表                | 数据来源、普通用户隔离、未知用量、重复上报、时区/日期边界、审计与隐私字段白名单                    |

A1–C2 均已有真实本地服务、产品浏览器与 Worker 分层证据，见[本地产品交付验收](local-delivery-verification.md)。切片表定义范围，不是尚未实现的待办；新增本地作品检索按独立 [MEDIA-US-204 任务](library-search-tasks.md)实施。

本轮不要求正式 Supabase 或生产管理员配置；后续启用生产服务时，才按选定项目复验授权、Auth 和运行策略，不把本地通过当成线上生效。

## 研究依据

- [现有 Auth](../../src/app/supabase-auth.ts)、[静态模板](../../src/app/image-mvp-catalog.ts)、[Worker](../../server/cloudflare/local-first-worker.mjs) 和[开发探针 RLS](../../infra/supabase/migrations/001-local-account-checks.sql)核对了当前接入点；探针表不是产品后台。
- [Supabase Auth Admin](https://supabase.com/docs/reference/javascript/auth-admin-listusers)：管理用户需要可信服务端调用，service role 不进浏览器。
- [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)：`user_metadata` 可由用户修改；JWT 中的管理员声明可能过时，因此实时权限使用服务端表。
- [API Keys 与 RLS](https://supabase.com/docs/guides/api/api-keys)：service role 绕过 RLS，使用该客户端前必须完成请求授权和端点范围校验。

官方依据通过 Context7 查询；当前本地实现与分层证据见[本地产品交付验收](local-delivery-verification.md)，真实本地 Auth 3 场景/产品 7 场景复验见[正式交付记录的本地部分](public-delivery-verification.md)。D-06 已确定无限期保留、无 TTL/自动 GC，并有显式重扫证据；生产账号/后台仍未部署。
